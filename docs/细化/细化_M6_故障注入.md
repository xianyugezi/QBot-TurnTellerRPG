### 1.2 注入隔离纪律（承接【5d】L205-208）

- 夹具内注入，**禁止黑入生产模块**：monkeypatch/patch 目标只允许测试构造的实例、注入回调或夹具内对象；禁止对生产模块做全局 patch 后不留恢复。
- 每个故障用例独立 fixture 起独立 `:memory:` 库（或 tmp_path），互不串扰（【5d】L205-208；【4a】L330）。
- 恢复路径必须在用例末尾 finally 执行：还原 mock/patch、关闭连接、清理临时文件，用例失败不允许污染后续用例。

### 1.3 三要素注释纪律

每个故障用例的 `test_*` 函数 docstring 必须显式写三要素：**注入点**（mock 哪个对象哪个方法）、**断言对象**（断言哪个字段/返回值/DB 行，含具体期望值）、**恢复路径**（finally 做什么）。缺三要素注释视为未达标（承接【批5A】P1-4 三要素要求）。

async def test_fault_case(tmp_path, monkeypatch):
    """三要素注释：注入点=…；断言对象=…；恢复路径=finally 还原…（5d L205-208）"""
    repo = await build_repo(tmp_path)        # 独立 :memory:/tmp_path（注入隔离）

## 二、脚本① fault_inject_crash.py（回复前崩溃 → 不双结算）

### 2.1 注入点 / 断言对象 / 恢复路径

- **注入点**：mock 发送出口（commands/sender.py `Sender.send` 或其注入的 `send_text` 回调）抛异常（模拟回复前崩溃）。发送出口仅是崩溃注入点、非幂等键载体（【总纲】ADR-05；【批5B】P1-4 修正）。
- **断言对象**：① 业务已提交（players/存档行已变）② 幂等键已落（`idempotency_keys` 含 (message_id, group_id, player_qid) 行）——引用 D2 IDEM-4/5、【4a】TC-06；③ 同 message_id 重发 → 幂等返回，不双结算不双扣。
- **恢复路径**：finally 还原发送回调 → 以同 message_id 重发 → 断言幂等返回 → 清理测试库。
