### 1.4 条件对象：ConditionObject（6 字段，§3.3 / §9.3）

| # | 字段 | 子字段 | 语义 |
|---|------|--------|------|
| 26 | `count` | `eq` / `min` / `max` | 段数条件：精确（eq 2）/范围（min 4）/低段（max 1） |
| 27 | `target_hp_pct` | `min` / `max` | 目标血量百分比（复合例：count min 4 且 目标HP max 50%） |
| 28 | `self_status` | `has` | 自身状态（引用 statuses.json） |
| 29 | `target_status` | `has` | 目标状态（引用 statuses.json） |
| 30 | `round` | `eq` / `min` / `max` | 回合数条件（= 战斗第 N 回合，**与段数条件区分**） |
| 31 | 复合操作符 | `and` / `or` / `not` | 嵌套 ConditionObject；任意拓扑 |

**求值语义（写死）：**
- 评估时机：指令处理时基于当前战斗状态**快照评估一次，施放后不重评**（§3.3）。
- 引用字段：战斗快照字段 + statuses.json + stats.json + 自定义注册字段（注册制，未注册仅提示不崩）（§9.3）。
- 求值失败默认"条件不满足"（安全失败不崩战斗）（§9.3）。
- 校验器：min/max 与 max_combo 矛盾、eq > max_combo、reset 模式 eq=max 死配置检测（§10.4）。

### 1.5 标签枚举与连段语义（6 值，§2.1）

| tag | 使用后连段变化 | 分级 |
|-----|---------------|------|
| `combo` 连段技 | +1 | P0 |
| `combo_preserve` 保留连段 | +0 不清零（喘息技：防御/辅助/回蓝） | P1 |
| `combo_push` 推进连段 | +N 不清零（N=1-2，配 `combo_push_amount`） | P1 |
| `interrupt` 打断技 | 对正在连段的目标清零其连段（效果执行走 effects.json） | P0 |
| `armor` 霸体 | 使用期间免疫打断（配 `armor: true`） | P0 |
| （无标签）普通技能 | 归零（打断自己） | — |

## ② 打断/霸体时序

### 2.1 回合时序（写死，条件评估依赖，§12）

```
回合开始 dot/控制结算 → 玩家行动（条件评估 + 连段结算）→ 怪物反击 → 回合结束 tick
```
- 双方指令在回合开始**声明**（指令处理时按快照评估条件一次）；结算按行动顺序（先手先结算）【细化补充：PVP 内先后手沿用战斗引擎既有行动顺序规则】。
- combo_state 入战斗快照（§9.4 / §12）；战斗结束（任何原因）连段清零（§6.1）。

### 2.2 攻击窗口（打断判定时序）【细化补充：收敛 §12"打断判定"为精确时序】

1. **判定时刻**：打断技结算时刻（行动阶段内），判定一次。
2. **生效条件**（三者同时满足）：
   - 目标"正在连段"= 目标 combo_state 存在且 `count > 0`（链活跃；防御/道具/被拒均不改连段，故目标未行动时 count 为场末值）；
   - 目标**不处于霸体**：目标本回合声明且已进入结算的技能 `armor=true`，且该技能**尚未结算完成**（"使用期间"= 行动开始 → 本次结算完成）；
   - 目标非 hold 免疫态（见 2.5）。
3. **效果**：目标 combo 清零（消息"⚡ 盾击打断连斩！连段中断"，§4.3）。
4. **霸体免疫**：目标处于霸体 → 打断失败、目标连段保留（消息"🛡 大追斩（霸体）！无视打断"，§4.3），打断技仍耗回合/MP（白费成本，§4.2）。
5. **已声明行动不受回溯影响**：派生条件按声明时快照已评估（§3.3 不重评），打断清零不影响目标本回合已声明行动的结算；从下回合起连段重新积累【细化补充：打断是节奏工具而非否决工具，与"读招博弈"一致】。
6. **多段攻击**：hits>1 按施放次数计段（§6.5），不影响打断判定时刻。

### 2.3 防御不打断（§2.2 / §1.3-2）

- 【防御】：不打断（不清零、不增长）——盾卫"防御攒大"成立（§5.3）。
- 【道具】：不打断（不耗回合的应急，不影响连段节奏）。
- 【逃跑】：成功→连段清空；失败→连段保留（防御同款）。
- 【被控制 skip_turn】：连段保留（断节奏不断积累）。
- 注意区分：打断技（对**目标**连段清零）≠ 防御/道具（对**自己**连段无影响）。

### 2.4 指令被拒不改连段（§2.2 / §6.4 / §12）

- MP 不足 / 冷却中 / 条件不满足 → **不耗回合、不改连段**，可反复尝试。
- 特例：**冷却中派生技**：自动降级为原技能 + 连段保留（防链卡死，§6.4）。
- 求值失败（条件引用缺失等）默认"条件不满足"，同样不崩战斗（§9.3）。

### 2.5 霸体代价（§4.2 / §5.2 / §13）

| 代价面 | 规则 | 引用 |
|--------|------|------|
| 派生配置代价 | 霸体派生通常配代价：更高消耗/更低伤害/更慢（`variant_override.cost` 提升、`dmg_mult` 降低，内容包逐技能配） | §4.2 / §1.3-5 |
| 校验器提示 | armor 步骤无任何代价配置 → 提示"霸体无代价，注意永动机"（提示不拒绝）【细化补充：对齐 §10.5 提示式校验】 | §13 / §10.5 |
| hold 被动态代价 | 仅 `combo==max` 时免疫打断；**大招消耗连段 → combo<max → 立即退出免疫**（需重新攒回顶，防"一次到顶永久免打断"） | §5.2 |
| 打断技成本 | 打断技本身消耗回合/MP；防错=白费（博弈成本） | §4.1 / §4.2 |
| 防失衡兜底 | PVP 连段开关（内容包可关）；PVP 演示见 §4.2 | §13 |

### 2.6 生命周期边界（补充引用）

- 战斗结束（胜利/失败/死亡/逃跑成功/怪物丢失/中断回收）→ 连段清零（§6.1）；复活不携带连段（§6.1）。
- 战斗中断恢复：combo_state 入快照还原（"连段 3/4 保持中"，§6.1）；链被删除 → 按"无链=普通技能"降级不报错（§9.4）。
- 跨战斗蓄力：默认关，内容包可开（§6.5）。
