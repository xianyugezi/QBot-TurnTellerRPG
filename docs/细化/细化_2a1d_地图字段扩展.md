## 一、gather_points 采集点字段（maps.json 节点级新增枝）—— 11 字段

> 依据：【时间天气】L150–160（maps.json 采集点字段级示例）、L405（登记「maps.json … 采集点 weather_mods」）；刷新/时段为工程补白（来源：规模对齐怪物行刷新语义【时间天气】L143-148、钓点时段语义 2c1a F-08/F-09/F-11）。

### 1.0 结构总览

```jsonc
// maps.json 地图节点内新增（节点 key = 地图 ID，与 spawns/exits 并列）
{
  "id": "gp_1",
  "item": "灵草",                                  // 产出表：单点单产出（【时间天气】L153）
  "rate": 0.3,                                     // 基础采集概率
  "rarity": "rare",
  "periods": ["dawn", "dusk"],                     // 时段偏好白名单（可选，空 = 全天）【工程补白】
  "seasons": ["spring", "autumn"],                 // 季节偏好白名单（可选，空 = 全年）【工程补白】
  "respawn_minutes": 10,                           // 刷新间隔（可选，默认 10）【工程补白】
  "weather_mods": [                                // 天气修正（可选；【时间天气】L156-159）
    {"weather": "rain",  "rate_mult": 1.5, "rarity_shift": 1},
    {"weather": "storm", "rate_mult": 0}            // 0 = 该天气下不出
  ]
}
```

### 1.1 字段表（GP-01 ~ GP-08 采集点条目 8 字段）

| # | 字段 | 类型 | 必需 | 默认 | 语义 | 引用 |
|---|---|---|---|---|---|---|

| GP-02 | `item` | string | 是 | — | 该点产出物品 id，**引用 items.json 材料类物品**（三渠道只负责「材料类 id 入包」，2c4a SRC-01 对齐）；单点单产出（产出表 = 逐点一行） | 【时间天气】L153；2c4a SRC-01 / L34/L36 |
| GP-03 | `rate` | number (0-1) | 是 | — | 基础采集概率；被 `weather_mods.rate_mult` 相乘修正 | 【时间天气】L154 |

| GP-08 | `weather_mods` | WeatherMod[] | 否 | `[]` | 天气修正列表（结构见 §1.2）；**缺省/空数组 = 该点不参与天气联动**（向后兼容，旧地图零改动可跑） | 【时间天气】L156/L168 |

### 1.2 weather_mods 条目结构（GP-09 ~ GP-11 共 3 字段）

> 语义声明为既成事实：**R25「采集点 weather_mods：rate_mult 乘采集概率（0=不出）+ rarity_shift 平移稀有度（clamp 4 档）」（细化_2a4b R25，依据【时间天气】L156-159/L203）**——本文只做字段级定型，不重定义语义。

| # | 字段 | 类型 | 必需 | 默认 | 语义 | 引用 |
|---|---|---|---|---|---|---|
| GP-09 | `weather` | string | 是 | — | 天气键，**必须 ∈ 注册天气集**（default_pool 键；校验器 V6 硬拦） | 【时间天气】L157/L335-336；2a4b R27 |
| GP-10 | `rate_mult` | number (≥0) | 否 | `1` | 采集概率倍率：`rate_mult` 乘 GP-03 基础 rate 得该天气下有效出率；**0 = 该天气下不出** | 【时间天气】L157-158；2a4b R25 |
| GP-11 | `rarity_shift` | integer | 否 | `0` | 稀有度平移：正数上调、负数下调，**clamp 4 档**（普通 / 稀有 / 金色 / ✨觉醒） | 【时间天气】L157；2a4b R25；2c4a SRC-02（✨觉醒标记 L204） |

> 判定时序（采集执行时）：先过季节/时段白名单（GP-05/GP-06，不命中 = 采集动作不可用，给空态文案同 2c1a §1.4 纪律）→ 再查当前天气的 weather_mods（命中修正 rate/rarity；无修正条目 = 原始 rate/rarity）→ 概率判定 → 入包（材料 id 走 items.json）。

## 二、chests 宝箱字段（maps.json 节点级新增枝）—— 15 字段

> 依据：【副本】L159「宝箱/采集点位置」（探索目的五要素）、L230「探索副本：地图配置（怪物/采集/宝箱/机制）完整保留」、L259「通关奖励：BOSS 掉落（三类）+ 副本宝箱 + 首次通关奖励（专属素材/称号/图鉴）」；刷新语义对齐 L261「重复挑战：入场限制默认不限（可配）；掉落重置」。

### 2.0 结构总览

```jsonc
// maps.json 地图节点内新增（与 gather_points 并列）
"chests": [
  {
    "id": "chest_corridor_1",
    "name": "石窟宝箱",
    "desc": "回廊尽头的石缝中嵌着一口旧箱，箱盖上刻着熔岩纹。",
    "contents": [                                    // 普通内容（每次开启抽取）
      {"item": "熔岩矿石", "count": 2, "chance": 0.6},
      {"item": "火晶石",   "count": 1, "chance": 0.3}
    ],
    "first_clear": {                                 // 首次开启奖励子段（仅首次，之后只走 contents）
      "items": [{"item": "熔岩金刚石", "count": 1}],
      "title": null,
      "codex": ["monster:molten_tyrant"]
    },
    "respawn_minutes": 0,                            // 0 = 一次性（不刷新）；>0 = 按分钟刷新【工程补白】
    "open_condition": null                           // 可选：开启条件（条件引擎三原语），null = 直接开启
  }
]
```

### 2.4 dungeon.json drops.first_clear 子段（P2-4 落地，结构同构）

  "normal": [ { "item": "...", "chance": 0.5 } ],
  "boss":   [ { "item": "...", "chance": 1.0 } ],
  "first_clear": {

## 三、lore.condition 字段（enemies.json / fishing.json 图鉴条目新增）—— 4 字段

> 依据：【时间天气】L222「enemies.json `lore` 条目新增可选 `condition`（复用条件引擎）：满足才显示该条情报」、L223 例（雷雨天解锁「幽灵弱点：雷元素」线索）、L224「fishing 图鉴 codex 鱼类条目同理（condition 可挂季节/时段，图鉴文案自然揭示生态规律）」、L406（登记「enemies.json lore 条目 condition 可选字段」）。
> 现状修订：细化_4d §5.1 lore 结构 = `{unlock, desc}`（【怪物】L220-224）——本文为字段级定义，**4d §5.1 按本文口径增补 `condition`（可选）**。

### 3.0 结构总览

```jsonc
// enemies.json 怪物条目内
"lore": [
  { "unlock": 30, "desc": "…常规策略提示…" },                     // 无 condition = 达阈值即显示（原语义不变）
  { "unlock": 60, "desc": "雷雨天露出破绽：弱点 雷元素",
    "condition": { "var": "weather", "op": "eq", "param": "storm" } }  // 新增：阈值 + 条件 AND
]

// fishing.json species 条目 codex 段同理
"codex": {
  "desc": "银鳞鲤，黄昏时最活跃。",
  "condition": { "var": "period", "op": "eq", "param": "dusk" }
}
```

### 3.1 字段表（LC-01 ~ LC-04 共 4 字段）

| # | 字段 | 类型 | 必需 | 默认 | 语义 | 引用 |
|---|---|---|---|---|---|---|
| LC-01 | `condition` | ConditionExpression \| null | 否 | `null` | lore/codex 条目新增可选字段；`null` = 无条件（原显示逻辑不变）；非空 = **unlock 阈值与 condition 同时满足才显示该条**（AND，缺一不显示） | 【时间天气】L222/L224 |
| LC-02 | `var` | enum | 是（condition 非空时） | — | 三原语变量键：`season` / `period` / `weather` 之一（注册表互译表 4.2.3.1 新增 3 行；扩展键须先登记后引用） | 【时间天气】L178-180/L408；2a4c §2.1 |
| LC-03 | `op` | enum | 是（condition 非空时） | `eq` | 运算符；时间天气三键仅支持 `eq`（`value` 不参与，`param==当前值 ? true : false`） | 【时间天气】L216；2a4c §2.1 L100 |
| LC-04 | `param` | string | 是（condition 非空时） | — | 枚举参数：季节 ∈ 四季、时段 ∈ 五时段（固定写死）、天气 ∈ 注册天气集（default_pool 键，校验器 V6 硬拦引用不存在） | 【时间天气】L178-180/L335-336 |

### 3.2 与条件引擎三原语对齐（LC-A ~ LC-E，5 条对齐规则）

> 条件引擎统一语法 = `{var, op, value, param}`（任务定稿 L20/L25；NPC 定稿 §4.0 L183；2a4c §2.1 L98）。时间天气三键完整形 = `{var, op:"eq", param}`，`value` 不参与（2a4c §2.1 L98/L100）。

| # | 对齐规则 | 语义 | 引用 |
|---|---|---|---|
| LC-A | **存储与校验用完整形**：`{var, op:"eq", param}`；定稿 §4.0 简写 `{var, param:X}`（L178-180）等价简写，仅编辑器/文档层可用，存档统一完整形 | 与条件引擎 {var,op,value,param} 统一语法对齐，零新机制 | 2a4c §2.1 L98 |
