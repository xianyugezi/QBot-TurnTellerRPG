## 〇、摘要与推荐（先看这一节）

### 结论一句话

**把编辑器做成服务器上的常驻服务（开机自启），再给用户一个「桌面双击」的隧道小脚本**——
用户以后只需要「双击一个图标 → 浏览器打开 `http://127.0.0.1:8090`」，全程不登录服务器、不敲命令。

### 推荐

| 排名 | 方案 | 一句话 | 适合 |
|---|---|---|---|
| ★首选 | **② systemd 常驻 + 一键 SSH 隧道** | 服务器上编辑器永远活着；用户电脑双击一个脚本开通道 | 日常使用；最安全；无证书警告 |
| 备选 | **③ nginx 反代 + HTTPS 自签 + basic auth** | 给一个公网网址，任何设备（含手机）打开即用 | 用户不想装/点任何东西，能接受"证书警告" |
| 现状 | ① 纯 SSH 隧道（手工起进程） | 现在的方式，但编辑器**已经没在跑了**（见 §一） | 临时看一眼 |
| 不推荐 | ④ Cloudflare Tunnel / 内网穿透 | 技术可行，但需用户自有域名/账号，且多一层外部依赖 | 有域名且愿意折腾时 |

> **为什么首选 ② 而不是直接开公网（③）？**
> 编辑器**本身没有任何登录/密码**（证据：`scripts/editor_host.py` 全文无登录逻辑，身份只靠启动参数 `--role owner|gm`）。
> 一旦开到公网，**唯一的门锁就是 basic auth 的账号密码**，而且这个密码**不会过期**；密码泄露 = 别人可以任意改你的内容包。
> SSH 隧道不开公网端口，等于"门根本不存在"，最省心也最安全。
> **若用户明确要"打开网址就能用、手机也要能用"，就上 ③**——§四已备好全套可复制命令。

### 用户以后只需要做的事（最简）

1. 双击桌面上的 **「编辑器隧道」** 图标；
2. 弹出黑色小窗口 → **不要关**（关掉 = 断开）；
3. 浏览器打开 **http://127.0.0.1:8090** → 开始编辑。

> 首次需要把主 agent 给的「私钥文件」和「隧道小脚本」放到用户电脑的指定位置（见 §三 Step 4，主 agent 会做成一个压缩包，用户解压即可）。

### 本次核查发现（与任务书描述不一致的地方，如实登记）

| 任务书描述 | 现场实测 | 影响 |
|---|---|---|
| 编辑器"当前长期在 `127.0.0.1:8090` 跑" | **8090 没有任何进程在监听**（`ss -ltnp` 只有 3080/3081；`ps` 无 `editor_host`） | 现状并不"在跑"；这正说明需要 ② 的 systemd 常驻 |
| 需按 nginx 自签方案的 `crypto.randomUUID` / `fence 403` 踩坑处理 | 编辑器前端 **0 处** `crypto.randomUUID`、**0 处** `isSecureContext`；`editor_host.py` 也**没有** browser-trust fence（无 Origin/Host 校验） | 这两条是 **dsh-web 专属坑**，编辑器不会遇到；但 HTTPS 仍建议保留（见 §四踩坑节） |
| 需要"必要时新增脚本" | 本次核查**不需要**改动/新增仓库任何文件（一号原则，见附录 B） | 部署产物全在服务器系统目录与用户电脑，不碰仓库 |

### 方案 ① SSH 隧道（现状 · 最干净，但已"静默停摆"）

**做法**：用户在服务器上手工 `bash scripts/editor_start.sh` 起编辑器（`127.0.0.1:8090`），再在自己电脑上
`ssh -N -L 8090:127.0.0.1:8090 root@134.175.187.200`，浏览器开 `http://127.0.0.1:8090`。

- **用户操作步骤（人话）**
  1. （原本需要技术同学先起进程）——用户自己**做不了**这步，所以现状其实依赖别人。
  2. 打开"命令提示符/PowerShell"→ 粘贴 `ssh -N -L 8090:127.0.0.1:8090 root@134.175.187.200` → 回车。
     - **截图点/看到什么**：出现 `root@…` 提示符或光标卡住不动 = 隧道通了（**这个窗口不能关**）。
  3. 浏览器地址栏输入 `http://127.0.0.1:8090` → **看到编辑器三栏界面**。
- **主 agent 代跑步骤（可复制）**
  ```bash
  # 服务器侧（本机即服务器）
  cd /root/QBot-TurnTellerRPG && bash scripts/editor_start.sh --host 127.0.0.1 --port 8090 --role owner
  # 用户侧（用户自己做；主 agent 只能给命令）
  #   ssh -N -L 8090:127.0.0.1:8090 root@134.175.187.200
  ```
- **安全评估**：★★★★★ 不暴露公网，无证书问题；隧道仅对已授权私钥开放。
- **内存占用**：≈0（进程在用户电脑；服务器侧多一个 sshd 会话，数 MB）。
- **重启后自动恢复**：❌ 编辑器与隧道都要手工重来。
- **缺点**：**这正是当前挂掉的原因**——进程是 `nohup`/前台起的，被 Ctrl+C、超时或退出登录杀掉后就没人知道（1.2 节 `/tmp/editor_*.log` 末尾的 `Terminated` 就是证据）。用户是小白，做不到"每次先起进程"。

### ★ 方案 ② systemd 常驻 + 一键 SSH 隧道（推荐）

**做法**：编辑器交给 systemd 常驻并开机自启（用户再也不用管）；用户电脑上放一个"双击即开隧道"的小脚本。
用户日常只剩"双击 → 开浏览器"。

- **用户操作步骤（人话）**
  1. 首次：解压主 agent 给的 `编辑器一键使用.zip`（内含私钥 + 隧道脚本）。
  2. 日常：**双击「编辑器隧道.bat」**（macOS 是 `.command`）。
     - **截图点/看到什么**：弹出黑色小窗口，显示 `隧道已开启，请不要关闭本窗口` 之类的提示；**不关它**。
  3. 浏览器打开 **http://127.0.0.1:8090** → **看到三栏编辑器**，开始用。
  4. 用完：关掉黑窗口即可（或直接不管它）。
- **主 agent 代跑步骤**：见 §三（unit 全文 + 命令 + 用户脚本全文 + 验证 + 回滚）。
- **安全评估**：★★★★★ 与 ① 同级（不开公网）；且进程常驻不会"悄悄死掉"——systemd 会自动拉起。
- **内存占用**：编辑器空闲约 **60–120 MB（估算**，落地后用 `systemctl show -p MemoryCurrent editor` 复核）；无 Swap 建议加 `MemoryMax`。
- **重启后自动恢复**：✅ `systemctl enable editor` 后开机自起；用户侧隧道需重新双击（正常）。
- **缺点**：隧道仍是"用户电脑到服务器"的连接，用户电脑休眠/换网络会断；黑窗口误关就断。
  → 缓解：脚本里加 `ServerAliveInterval`；断了重新双击即可；真要"零客户端"就选 ③。

### 方案 ③ nginx 反代 + HTTPS 自签 + basic auth（公网直访 · 最省事）

**做法**：复用服务器既有 nginx，新增一个 `3082` 端口的 HTTPS 站点，反代到 `127.0.0.1:8090`，
加一道 basic auth 账号密码。用户直接访问 `https://134.175.187.200:3082/`。

- **用户操作步骤（人话）**
  1. 浏览器输入 **https://134.175.187.200:3082/**。
     - **截图点/看到什么**：先弹"**您的连接不是私密连接**"之类的证书警告 → 点 **高级 → 继续前往**（自签证书，正常现象，每次浏览器会话可能都要点一次）。
  2. 弹出登录框 → 输入主 agent 给的 **用户名 / 密码**。
  3. **看到三栏编辑器**，开始用（手机浏览器同样可用）。
- **主 agent 代跑步骤**：见 §四（证书/密码/nginx 配置全文/安全组/验证/回滚）。
- **安全评估**：★★☆☆☆ **这是本方案里最需要提醒的一项**——编辑器自身零鉴权，公网只靠 basic auth 一层；
  密码不过期；一旦泄露或被爆破 = 内容包可被任意篡改（甚至导入/删除）。必须：强密码 + 建议安全组限定来源 IP + 不上 `--role gm` 就永远是 owner。
- **内存占用**：编辑器 60–120 MB（估算）＋ nginx 复用既有进程（≈0）。
- **重启后自动恢复**：✅ systemd 常驻 + nginx `enable`。
- **缺点**：证书警告（自签）；公网暴露面；密码管理负担；`client_max_body_size` 不改会导致导入大包失败（§四已修）。

### 方案 ④ Cloudflare Tunnel / 内网穿透（可行性判断：技术可行，但**不推荐作主方案**）

**做法**：服务器装 `cloudflared`，把 `127.0.0.1:8090` 通过 Cloudflare 边缘暴露成一个公网域名，**无需开服务器端口**。

- **可行性判断（基于现场证据）**
  - 服务器**未安装** `cloudflared` / `frpc`（`which cloudflared` / `which frpc` 均为空）→ 需新增安装。
  - **Quick Tunnel**（`cloudflared tunnel --url http://127.0.0.1:8090`）：零账号即可跑，但得到的是**随机 `*.trycloudflare.com` 域名、每次重启都变**，且服务直接对公网开放、**没有任何登录** → 对"稳定使用"和"安全"两条都不合格。
  - **Named Tunnel**（正规做法）：需要用户拥有**一个域名 + Cloudflare 账号**，并在 Cloudflare 控制台建 Tunnel、配 Access 策略。稳定、证书正规、可加登录；但**用户是小白**，域名/账号这步绕不开。
  - 服务器在国内（腾讯云），Cloudflare 边缘回源可能不稳；且这会给系统再加一个常驻进程与外部依赖。
- **结论**：**技术上可行，但不是当前最省事的路线**。若用户已有域名 + Cloudflare 账号，再单独立项；否则优先 ②/③。
- **安全评估**：Named Tunnel + Cloudflare Access = ★★★★☆（比 ③ 强，因为有身份层）；Quick Tunnel = ★☆☆☆☆（裸奔）。
- **内存占用**：编辑器 60–120 MB ＋ `cloudflared` 约 30–50 MB（经验值，未实测）。
- **重启后自动恢复**：✅（装成 systemd 服务）。
- **缺点**：需要域名/账号；多一层外部依赖；国内网络体验不定。

### 备注方案 ⑤（了解即可，不单独展开）

- **腾讯云 WebShell 端口转发**：在腾讯云控制台用"登录"打开网页终端，工具栏有"端口转发"，
  把本地 `8090` 转到服务器 `127.0.0.1:8090`。**不用装任何客户端**，但**必须先登录服务器控制台**，
  与"用户不登服务器"的诉求相冲突；只适合技术同学应急。
- **Tailscale / ZeroTier 等组网**：给用户电脑与服务器组一个私有网，用户访问服务器的私有 IP。
  安全性和体验都不错，但**同样要在用户电脑装客户端 + 注册账号**，比 ② 的一键脚本更重。

## 三、★推荐方案②·可执行落地清单（systemd 常驻 + 一键隧道）

> 执行者：**主 agent 在服务器本机直接跑**（本机即服务器，无需 ssh 转跳）。以下命令均可整段复制。
> 全程**不修改、不新增仓库文件**（一号原则）；只写 `/etc/systemd/system/editor.service`。

### Step 0：落地前 60 秒体检（可选但推荐）

```bash
cd /root/QBot-TurnTellerRPG
git status --porcelain                     # 期望：无输出（工作树干净，见 1.2）
/root/QBot-TurnTellerRPG/.venv/bin/python -c 'import fastapi,uvicorn;print("deps OK")'
ss -ltnp | grep ':8090' || echo "8090 空闲"   # 期望：打印“8090 空闲”
```

### Step 1：写 systemd unit（**全文**）

```bash
cat >/etc/systemd/system/editor.service <<'EOF'
# /etc/systemd/system/editor.service
# QBot 内容编辑器常驻服务（只监听本机 127.0.0.1:8090，公网不可直达；远程用 SSH 隧道）
[Unit]
Description=QBot Content Editor (FastAPI/uvicorn on 127.0.0.1:8090)
After=network.target

[Service]
Type=simple
WorkingDirectory=/root/QBot-TurnTellerRPG
Environment=PYTHONUNBUFFERED=1
# 直接用仓库自带 venv 的解释器；editor_host.py 会自己把仓库根加进 sys.path
ExecStart=/root/QBot-TurnTellerRPG/.venv/bin/python /root/QBot-TurnTellerRPG/scripts/editor_host.py --host 127.0.0.1 --port 8090 --role owner --content-root /root/QBot-TurnTellerRPG/content
Restart=on-failure
RestartSec=3
# 服务器无 Swap（见 1.1）：给个很宽松的内存上限，防极端情况拖垮整机
MemoryMax=512M
# 停机时清掉整个 cgroup，避免残留子进程占住 8090
KillMode=control-group
TimeoutStopSec=10

[Install]
WantedBy=multi-user.target
EOF
```

> **可替换写法**（想复用 `editor_start.sh` 的人话预检/报错时）：
> `ExecStart=/usr/bin/env bash /root/QBot-TurnTellerRPG/scripts/editor_start.sh --host 127.0.0.1 --port 8090 --role owner --content-root /root/QBot-TurnTellerRPG/content --python /root/QBot-TurnTellerRPG/.venv/bin/python`
> 两种都**不改仓库**；差别只在于报错信息是否经过脚本包装。默认推荐上面那种（直接 python，最可预测）。

### Step 2：启动并设为开机自启

### Step 4：用户电脑「一键隧道」（**脚本全文**）

> 主 agent 的做法：把用户已交付的**私钥**改名为 `qbot_editor_key`，连同下面脚本打成一个压缩包
> `编辑器一键使用.zip` 发给用户，并给一张"放哪里"的图。

**Windows（推荐）**——文件名 `编辑器隧道.bat`（ANSI/GBK 编码保存，避免中文乱码）：

```bat
@echo off
title 编辑器隧道 - 不要关闭本窗口
echo ==================================================
echo   正在连接服务器，请稍候（首次约 3-10 秒）...
echo.
echo   连接成功后【不要关闭本窗口】，
echo   然后打开浏览器访问：  http://127.0.0.1:8090
echo ==================================================
echo.
ssh -N -L 8090:127.0.0.1:8090 ^
    -i "%USERPROFILE%\.ssh\qbot_editor_key" ^
    -o ServerAliveInterval=30 ^
    -o ServerAliveCountMax=3 ^
    -o ExitOnForwardFailure=yes ^
    -o StrictHostKeyChecking=accept-new ^
    root@134.175.187.200
echo.
echo [隧道已断开] 想继续用，请重新双击本文件。按任意键关闭。
pause >nul
```

**放置位置（Windows）**：
- 私钥 `qbot_editor_key` → 放到 `C:\Users\<你的用户名>\.ssh\qbot_editor_key`（没有 `.ssh` 文件夹就新建）。
- `编辑器隧道.bat` → 放到**桌面**，双击即用。

**macOS / Linux**——文件名 `编辑器隧道.command`，放桌面，终端里 `chmod +x` 一次：

```bash
#!/bin/bash
KEY="$HOME/.ssh/qbot_editor_key"
echo "正在连接服务器……连接成功后【不要关闭本窗口】。"
echo "然后浏览器打开： http://127.0.0.1:8090"
exec ssh -N -L 8090:127.0.0.1:8090 \
  -i "$KEY" \
  -o ServerAliveInterval=30 \
  -o ServerAliveCountMax=3 \
  -o ExitOnForwardFailure=yes \
  -o StrictHostKeyChecking=accept-new \
  root@134.175.187.200
```
```bash
# 用户在自己电脑执行一次：
chmod +x ~/Desktop/编辑器隧道.command
# 私钥放到： ~/.ssh/qbot_editor_key ，权限收紧：
chmod 600 ~/.ssh/qbot_editor_key
```

**为什么用 `-N -L`**：`-N` = 只做端口转发不执行远程命令；`-L 8090:127.0.0.1:8090` = 把用户电脑的 8090
接到服务器的 8090。`ServerAliveInterval/CountMax` 让断网能自动发现；`ExitOnForwardFailure=yes`
避免"本地 8090 被占用"时静默假连接。

### Step 5：回滚（一键撤销，回到"没有这个服务"的状态）

```bash

ss -ltnp | grep ':8090' || echo "8090 已释放，回滚完成"
```
> 用户侧回滚：删掉桌面的 `编辑器隧道.bat`（或 `.command`）与 `~/.ssh/qbot_editor_key` 即可。
> 编辑器产生的数据都在 `/root/QBot-TurnTellerRPG/content/`，回滚服务**不动任何内容**（含 `.bak` 备份）。

## 四、备选方案③·可执行落地清单（nginx + HTTPS 自签 + basic auth · 公网直访）

> 前提：**先按 §三 Step 1–2 把编辑器做成 systemd 常驻**（监听 `127.0.0.1:8090`）。
> 本节只加"对外的一层门"。执行者：主 agent 在服务器本机直接跑。
> 现场证据：nginx 1.18.0 已装并在跑；`/etc/nginx/sites-enabled/` 只有 `dsh-web`；`3080` 与 `3081` **已被 dsh-web 占用**，
> 故编辑器另开 **3082**；`80/443` 空闲（1.3）；`htpasswd` 命令**不存在** → 用 `openssl passwd`。

### Step 1：给自己签一张证书（**全文**）

> 现场核查：`openssl version` = `1.1.1f`，支持 `-addext`；`nginx -V` 含 `--with-http_ssl_module`（均可作为本节可行性的证据）。
> **必须把公网 IP 写进 SAN**，否则 Chrome/Edge 会直接报 `NET::ERR_CERT_COMMON_NAME_INVALID`（连"继续访问"都点不出来）。

```bash
mkdir -p /etc/nginx/ssl
openssl req -x509 -newkey rsa:2048 -sha256 -days 3650 -nodes \
  -keyout /etc/nginx/ssl/editor.key \
  -out    /etc/nginx/ssl/editor.crt \
  -subj   "/CN=134.175.187.200" \
  -addext "subjectAltName=IP:134.175.187.200,DNS:localhost"
chmod 600 /etc/nginx/ssl/editor.key
openssl x509 -in /etc/nginx/ssl/editor.crt -noout -subject -dates -ext subjectAltName
```

### Step 2：设 basic auth 账号密码（**全文**）

> 建议用户名固定 `editor`；**密码由用户自己定**（见 §七）。下面命令**不回显、不进命令历史**。

```bash
read -rs -p "请输入编辑器访问密码（输完回车）：" PW; echo
printf 'editor:%s\n' "$(printf '%s\n' "$PW" | openssl passwd -apr1 -stdin)" >/etc/nginx/.htpasswd-editor
unset PW
chmod 640 /etc/nginx/.htpasswd-editor
cut -d: -f1 /etc/nginx/.htpasswd-editor      # 期望打印：editor
```

> 密码强度要求（因为这是**唯一门锁**）：≥ 16 位，大小写+数字+符号，不与 dsh-web 的 `admin` 密码相同。
> 忘记了就重跑 Step 2（覆盖即可）。

### Step 3：写 nginx 站点并启用（**配置全文**）

```bash
cat >/etc/nginx/sites-available/editor <<'EOF'
# /etc/nginx/sites-available/editor
# 公网 HTTPS 直访编辑器：3082(ssl) -> 127.0.0.1:8090，外加一道 basic auth。
# 注意：编辑器自身无登录，basic auth 是唯一门锁，务必强密码。
server {
    listen 3082 ssl;
    ssl_certificate     /etc/nginx/ssl/editor.crt;
    ssl_certificate_key /etc/nginx/ssl/editor.key;
    server_name _;

    auth_basic           "QBot 内容编辑器";
    auth_basic_user_file /etc/nginx/.htpasswd-editor;

    # 编辑器支持导入 .ttrpack（服务端上限 64MB，见 pack_transfer.DEFAULT_LIMITS）与整包 CSV；
    # nginx 默认只收 1MB，不改这里会导致“导入大包失败 / 413 Request Entity Too Large”。
    client_max_body_size 70m;
    client_body_timeout  120s;

    location / {
        proxy_pass http://127.0.0.1:8090;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        # 长操作（导入/导出/大包校验）给足时间
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;

        # —— 可选加固：只允许用户固定出口 IP 访问（用户 IP 变了会把自己挡在外面，谨慎开启）——
        # allow 1.2.3.4;
        # deny all;
    }
}
EOF

ln -sfn /etc/nginx/sites-available/editor /etc/nginx/sites-enabled/editor
nginx -t            # 期望：syntax is ok / test is successful
systemctl reload nginx
```

> **与 dsh-web 配置的两处关键差异（有据可依，别照抄错）**：
> 1. **不需要** `proxy_set_header Origin "";` 与 `Host 127.0.0.1:3081;` 那套——那是 dsh-web 的 browser-trust `fence 403` 专用补丁；
>    `editor_host.py` **没有** Origin/Host 校验（1.5），写不写都不影响。
> 2. **必须**显式设置 `client_max_body_size`（dsh-web 配置里没有这条，因为它不做大文件导入）。

### Step 4：安全组 / 防火墙（**这一步在腾讯云控制台做，用户或主 agent 均可**）

- 服务器本机：`ufw` 是 `inactive`、`iptables` 只有腾讯的 `YJ-FIREWALL-INPUT` 链（少量 REJECT 源 IP，1.4）→ **本机不用再配**。
- 真正的门是**腾讯云安全组**（在控制台，不在服务器里）：
  1. 登录腾讯云控制台 → **云服务器 CVM** → 实例 → 找到本机 → **安全组**；
  2. 打开绑定的安全组 → **入站规则** → **添加规则**；
  3. 类型 `自定义`；协议 `TCP`；端口 `3082`；来源：**建议只填用户当前公网 IP + `/32`**（最安全）；IP 不固定才用 `0.0.0.0/0`；策略 `允许`；备注 `编辑器`；
  4. 保存（**立即生效，无需重启**）。
- ⚠ **待用户核实**：本机=服务器，"从服务器 curl 自己的公网 IP"是发夹弯测试（1.4），
  **不能证明安全组状态**。请用户在自己电脑浏览器验证 3082 是否可达（§五·B）。

### Step 5：验证（curl 状态码 + 浏览器现象）

**服务器本机（先验门锁，再验内容）**：
```bash
curl -sk -o /dev/null -w 'no-auth: HTTP %{http_code}\n' https://127.0.0.1:3082/            # 期望：HTTP 401
curl -skI https://127.0.0.1:3082/ | grep -i 'www-authenticate'                              # 期望：Basic realm="QBot 内容编辑器"
curl -sk -u editor:刚才设的密码 -o /dev/null -w 'with-auth: HTTP %{http_code}\n' https://127.0.0.1:3082/   # 期望：HTTP 200
ss -ltnp | grep ':3082'                                                                      # 期望：0.0.0.0:3082 nginx
```

**用户电脑浏览器**：打开 `https://134.175.187.200:3082/`
1. 先出证书警告 → **高级 → 继续前往 134.175.187.200（不安全）**；
2. 弹出登录框 → 输入 `editor` + 密码；
3. **看到三栏编辑器** = 成功。
（若第 1 步之后浏览器仍报错、或第 2 步 401 循环，对照 §五报错表。）

### Step 6：回滚（先摘门，再删料）

```bash
rm -f /etc/nginx/sites-enabled/editor
nginx -t && systemctl reload nginx          # 先让公网入口消失
# 确认不需要后再彻底删除（可选）：
# rm -f /etc/nginx/sites-available/editor \
#       /etc/nginx/.htpasswd-editor \
#       /etc/nginx/ssl/editor.crt /etc/nginx/ssl/editor.key
# 腾讯云控制台：删除端口 3082 的入站规则
ss -ltnp | grep ':3082' || echo "3082 已关闭，回滚完成"
```
> 回滚 nginx **不影响**编辑器本体（§三 的 systemd 服务照常跑在 127.0.0.1:8090，隧道方案可继续用）。

### 本方案的踩坑清单（现场核查 + 历史教训）

| 坑 | 现象 | 处理 |
|---|---|---|
| nginx 默认 1MB 请求体 | 导入 `.ttrpack`（上限 64MB）报 `413` / 导入失败 | 已写 `client_max_body_size 70m` |
| 端口冲突 | 想复用 `3080` → `nginx -t`/启动报 `address already in use` | dsh-web 占 3080/3081（1.3），编辑器用 **3082** |
| 自签证书缺 SAN | Chrome 报 `NET::ERR_CERT_COMMON_NAME_INVALID`，无法继续 | Step 1 已把 `IP:134.175.187.200` 写进 SAN |
| 证书警告被误判为故障 | 用户以为"网站坏了" | 写进用户步骤卡：**高级 → 继续前往** 是正常操作 |
| `crypto.randomUUID is not a function` | 历史上 dsh-web 在 `http://公网IP` 下出现 | **编辑器不受影响**：前端 0 处使用该 API（1.5）；但走 HTTPS 更稳妥 |
| `fence 403`（transport failure） | 历史上 dsh-web 的 browser-trust 拦截 | **编辑器不受影响**：无 fence 逻辑（1.5），无需 `Origin`/`Host` 覆写 |
| 401 分不清来源 | 不知道是密码错还是服务没起 | 见 §五报错表：**带 `WWW-Authenticate: Basic` 的 401 = basic auth 没通过**；编辑器自身不返回 401 |
| 密码不过期 | 长期暴露风险 | 建议每季度在控制台重跑 Step 2 换密码；离职/换人立即换 |
| basic auth 证书/密码经明文网络 | 自签 HTTPS 仍加密传输 | 已用 HTTPS；**不要**改成 `http://` 公网端口 |

## 五、用户侧「最小步骤卡」（≤6 步）

### 卡 A · 日常使用（对应★方案②，推荐）

> 首次由主 agent 把 `编辑器一键使用.zip` 发给你，解压后照下面做一次；以后每天只用第 1–3 步。

1. **放好私钥**：把 `qbot_editor_key` 放进

### 常见报错对照表（用户照着查）

| 你看到的 | 它其实在说什么 | 怎么办 |
|---|---|---|
| 浏览器"**无法访问此网站 / 响应时间过长**"；命令行 `curl` 得 `000` | **网络根本没接通**（TCP 没建立）。常见：隧道窗口没开／被关了；服务器上编辑器没在跑 | 卡 A 第 2–3 步重开隧道；仍不行找主 agent 查服务 |
| 页面弹出**登录框**，输错后反复弹；`curl` 得 `401` 且响应头带 `WWW-Authenticate: Basic realm=…` | **basic auth 密码不对**（这是方案③的"门锁"） | 找主 agent 核对/重置密码（§四 Step 2） |
| 页面提示"**当前身份为只读预览，不能新增/保存**"；`curl` 得 `403` | 这是**编辑器自己的身份护栏**（GM 只读），**不是密码问题** | 顶栏「身份」切到**机主 · 可编辑**（或让主 agent 确认启动没带 `--role gm`） |
| 控制台报 `crypto.randomUUID is not a function` | 历史 `dsh-web` 的"非安全上下文"报错（http 公网访问） | **编辑器不会有这个错**（前端 0 处调用该 API）。若真出现，说明你打开的是 **dsh-web 不是编辑器**，核对网址/端口 |
| 网络面板出现 `fence 403` / transport failure | 历史 `dsh-web` 的浏览器信任拦截 | **编辑器不会有**；同上，核对是不是打开了 dsh-web |
| 导入 `.ttrpack` 时报 **413 Request Entity Too Large** | 反向代理把请求体截断了（nginx 默认 1MB） | 让主 agent 确认 §四 配置里的 `client_max_body_size 70m` 已生效 |
| 一直**白屏 / 转圈**；nginx 日志 `502`/`504` | nginx 活着但**后面 8090 的编辑器没跑** | 找主 agent：`systemctl restart editor` |
| 双击 `.bat` 后**黑窗口一闪就没了** | 隧道建立失败（私钥路径/权限/本地端口占用） | 右键"以管理员身份运行"看报错；或按窗口文字提示处理；实在不行找主 agent |
| 黑窗口报 `Permission denied (publickey)` | 私钥放错位置或不是那把 key | 核对私钥是否在 `C:\Users\你\.ssh\qbot_editor_key`，文件名别改 |
| 黑窗口报 `bind: Address already in use` | 你电脑上 **8090 端口被别的程序占了** | 关掉占用的程序；或让主 agent 换一个本地端口（如 8091）重做脚本 |
| 浏览器报 `NET::ERR_CERT_COMMON_NAME_INVALID`（连"继续"都没有） | 证书没把公网 IP 放进 SAN | 找主 agent 按 §四 Step 1 重签（本方案命令已含 SAN，正常不会遇到） |

### 安全提醒（请一定看）

1. **服务器上的编辑器没有登录功能**：谁能打开页面，谁就能改内容。所以方案③的 **basic auth 密码就是全部家当**——
   用长密码、别和别处共用、**定期换**（主 agent 可在服务器重跑一次密码命令）。
2. **包 A 更安全**：走 SSH 隧道时端口不开在公网，等于"外面没有门"。能用卡 A 就优先卡 A。
3. **不要**让主 agent 用 `--host 0.0.0.0` 把 8090 直接开到公网——那等于**不用密码把编辑器挂到网上**。
4. 私钥 `qbot_editor_key` = 你家的钥匙：**别发到群里、别丢在公共电脑**；丢了让主 agent 立刻换一把。
5. 编辑器每次保存都会自动留一份 `.bak` 备份；**大改之前先点一次保存**，这样"回退"更保险。
6. 长期不用时，让主 agent 把公网入口关掉（§四 Step 6）或停掉服务（§三 Step 5），要用再开。
