## 一、鱼王事件（金闪鱼讯 → BOSS 战 · 每日窗口纪律）

> 依据：【钓鱼】§1 M7 L21、§三 `king_event` L79、§六 鱼讯参考 L110、§八 防刷屏对策 L134。
> 数据接线（fishing.json `king` 表 K-01~K-07 与 profession.json `fishing.king_event`）已在 2c1a §三 定义；本文定义**触发时点的行为契约**与**每日窗口记账**，不重复表结构。

### 1.1 触发链路（R-01）

- 触发入口：出鱼结算轮（2c1b /收杆 结算）命中某鱼种的 `king` 行 → 判定触发概率 → 该轮鱼讯**升级为「猛烈 + 金闪」**【钓鱼】L21 / L110。
- 触发判定（确定性）：单次独立随机 `roll < king.chance`（默认 0.3）命中即触发【钓鱼】L79；随机源走种子 42 / 2026 可复现（对齐 §四 L91 与 2c1a TC-12）。
- 触发路由：命中后**中断普通出鱼结算**，进入 enemies 引擎的 BOSS 战（`king.enemy_id` 引用 enemies.json 实体）【钓鱼】L21——鱼王战完全复用怪物/BOSS 引擎，零新增。
- 未触发：该轮按普通鱼讯流程出鱼（猛烈鱼讯但无金闪）。

### 1.2 每日窗口纪律（R-02）

- 窗口计数：`king_victory_count`（当日）与 `king_trigger_count`（当日）两把计数器；**门控用触发尝试计（无论胜负），授权/补全用胜利计**（见 §二）。
- 上限：当日触发尝试 ≥ `window_daily`（默认 2）即不再产生金闪（无论上次胜负）【钓鱼】L79 / L134。
- 跨日重置：按 server 自然日（对齐 quest_daily 懒计算同源，见 2c1 T06）零点重置；跨会话懒计算，无实时计时。
- 可配性：`enabled`（总开关）/ `window_daily` / `chance` 均可配；关闭或到窗后金闪不出现、鱼讯回落为普通猛烈档。

### 1.3 讨伐结算与奖励（R-03）

- **胜利**：一次性奖励走 reward 统一发放器（金币/材料/稀有鱼具等，权重内容包可配）；`king_victory_count += 1`；计入图鉴补全条件（§二 R-05）。
- **失败**：无奖励、不进阶计数；可再次进入钓局（但当日已耗 1 次窗口额度）。
- 单次节奏约束：鱼王战结果收束在 2-3 条消息/次内（预告→进入战局→（结算）），对齐 §四 L93 与 §八 防刷屏 L134。

### 1.4 mode 约束（R-04）

- `simple` / `off` 模式：鱼王路径不可达（金闪永不出现）；配置期持 `king` 数据 → W1 黄提示不阻断【钓鱼】L67 / 2c1a V-W。
- `full` 模式：本文 R-01 ~ R-03 全量生效。

## 二、图鉴记录（codex 鱼条目冠级 · 补全 → 钓鱼王称号）

> 依据：【钓鱼】§1 M8 L22、§2.3 L46-60、§四 钓鱼王 L98、§七 登记要求·codex_state L120 / 图鉴 L126。

### 2.1 codex 条目（承接 2c1a §四，E-01）

- 字段落库（2c1a G-01 ~ G-07，本文不再重列）：`caught_count` / `best_crown` / `best_size` / `best_weight` / `min_size` / `min_weight` / `reverse_crown_count`【钓鱼】L52-56。
- 追加鱼王计数落点（E-01）：codex_state 鱼综述条目（type=fish 聚合段）追加 `king_victory_count`（累计讨伐胜利次数，默认 0）——供图鉴补全判定与钓鱼王授予读取。
- 未捕获鱼种无条目；首获创建条目并点亮【钓鱼】L125。

### 2.2 更新规则（R-05，确定性）

- `best_crown`：按玩家获取过的最优标志取**最大**者，优先级 `big_gold > gold > big_silver > silver > normal`【钓鱼】L53 / L59；**逆金冠不计入该链**（极值收藏不是等级），单独走 `reverse_crown_count`【钓鱼】L59。
- 极值：`best_size/best_weight` 取历史 max；`min_size/min_weight` 取历史 min（逆金冠刷新）【钓鱼】L54-55。
- `reverse_crown_count`：每次逆金冠出鱼 +1【钓鱼】L56。
- 写入原子性：图鉴更新与出鱼结算奖励同写「SQLite 事务 + message_id 幂等」模式（对齐 2c5a B1 同款），防双记。

### 2.3 展示格式（R-06）

- 鱼条目标注：最优冠级 + **逆金冠单独标注** `逆金冠×N`【钓鱼】L59。
- 示例：`鲤鱼 Lv3 · 最大 45.2cm/3.8kg · 金冠 · 逆金冠×1`【钓鱼】L60；模板占位符 `codex_text.best_mask` 渲染（2c1a F-13 / C-03）。
- 图鉴不写判定公式、不教攻略（阈值 5/85/95 不可见）【钓鱼】L113 / L133。

### 2.4 图鉴补全判定 → 钓鱼王授予链（R-07）

- 补全定义（硬条件，三者同时满足）：
  1. fishing.json `species[]` 中每条鱼种均有 codex 条目（`caught_count ≥ 1`）——图鉴点亮；
  2. codex 鱼综述 `king_victory_count ≥ 2`（鱼王事件讨伐胜利 2 次）【钓鱼】L98（原文「图鉴全亮（含鱼王事件 2 次）」）；
  3. 无其它内容包追加未点亮鱼种（同 1 的覆盖全集）。
- 判定时机：每一次**图鉴点亮事件**（首获或鱼王胜利计数变更）结算时检查补全——对齐 2c5 T15「图鉴点亮事件结算时检查」的授予链末端语义。
- 授予动作：补全成立 → 授予**钓鱼王**称号 → 写入 title_state 可佩戴列表 → 消息前缀 [称号] 渲染（展示通道收编 2c5 T17，不另立通道）。
- 幂等：已持有钓鱼王时重复检查不重复授予、不重复发奖励。

## 三、钓鱼产出四出口闭环

> 依据：【钓鱼】§1 M9 L23（四出口：商店 / 委托 / 品评 / 炼金）、§四 经济数值 L96-97、§八 风险对策 L132、§七 配套 L7（鱼饵=炼金消耗品）、§三 `bait_ids` L74。
> 铁律（贯穿四出口）：**冠级纯收藏不参与任何出口数值**【钓鱼】L46-48 / L132——四个出口读的都是大小/重量与鱼种基础价值，冠级仅图鉴与社交标注。

### 3.1 出口总览（E-02）

| # | 出口 | 消费方 | 语义 | 引用 |
|---|---|---|---|---|
| E-02a | 商店售出 | 商店引擎（2b3） | 鱼获 → 金币；售价 = 基础定价，无冠级加成 | 【钓鱼】L23 / L48 / L97 |
| E-02b | 委托交付 | 任务引擎（2b4 委托板） | 委托任务消耗指定鱼获（含数量/品质档），交付得奖励 | L23 |
| E-02c | 品评会 | 品评引擎（5 路 §3.3） | 鱼获投稿展示 + 评分排行，社交出口 | L23 |
| E-02d | 炼金材料 | 炼金引擎（2c4 路） | 鱼作炼金 recipe 原料（含饵料配方），回链产饵 | L7 / L74 / L96 |

> 对账锚点：四出口合计日流出 ≈ 日流入 ≈ **256 金/日**（普通饵单次期望 ≈22.8、净 +12.8，日 20 次）【钓鱼】L97；严格低于战斗，且冠级无加成，不冲击经济【钓鱼】L132。

### 3.2 出口 A · 商店售出（R-08）

- 通路：复用商店引擎交易通道（2b3），不新建；鱼获作为可售 items 挂价。
- 定价：鱼种基础单价 × 数量计算（无冠级因子）；同一尾鱼的售价与图鉴冠级**解耦**——差分保证同鱼种同大小重量不同冠级售价一致（对齐 2c1a TC-12）。
- 数据回写：售出扣 inventory、入金币账，同一事务落存档（防双扣）。

### 3.3 出口 B · 委托交付（R-09）

- 通路：复用委托任务板（任务引擎 2b4 quest 消耗逻辑）；委托条目声明「需鱼获 id + 数量 + 品质档（可选）」，接单后消耗背包鱼获。
- 集成点：委托完成条件判定的鱼获库存读取、交付即扣、奖励走 reward 发放器；品质判定档只取大小/重量区间映射的**品质**（items.json 品质四档），不取冠级。
- 兜底：无鱼获/数量不足/品质不符 → 明确提示差量，不静默。

### 3.4 出口 C · 品评会（R-10）

- 通路：品评会引擎（5 路 §3.3 投稿/展示/排行）；鱼获作为可投稿道具进入品评卡片——展示尺寸/重量/饵料偏好等社交维度。
- 语义边界：品评展示走**社交/炫耀**出口，评分维度不含冠级加成（鱼获按品质四档与极值近展示）；冠军奖励等按品评会既有规则（另文 5 路）。
- 数据回写：投稿扣背包鱼获、记录快照（防热重载丢失），对齐 5 路 T07。

### 3.5 出口 D · 炼金材料（R-11）

- 通路：鱼获作为炼金 recipe 原料（2c4 炼金引擎）；`fishing.bait_ids` 五档饵（饵_蚯蚓/面团/小鱼/黄金虫/龙涎）均为炼金产物【钓鱼】L74。
- 闭环回链：钓鱼消耗饵（1 次 1 饵，日 20 次 = 20 饵）→ 饵由炼金以鱼/素材产出【钓鱼】L96——炼金与钓鱼互为产消双端；鱼在饵料（如饵_小鱼/饵_龙涎）配方中作原料，实现「钓到的鱼 → 炼金造饵 → 再钓鱼」闭环。
- 数据回写：投料扣背包鱼获，产出饵入库存，同一事务原子完成。

### 3.6 对账与风险（R-12）

- 每日对账：聚合四出口流入/流出，校验日净流入 ≈ 256 金浮动（种子 42/2026 可复现）【钓鱼】L97。
- 防冲击红线：对账超标（远超 50 级尖峰 3374 量级）→ 启动报告黄提示；四出口任何一处不得读取冠级进数值（差分断言兜底）【钓鱼】L132。

## 四、钓鱼职业熟练度接入（7 级 · 经验倍率）

> 依据：【钓鱼】§1 M6 L20（出鱼结算 → 图鉴点亮 + 熟练经验 + 奖励）、§1 M9 L23（7 级熟练度 + 钓鱼王称号）、配套 L7（钓鱼王补位职业熟练度 7 级空缺）、§四 钓鱼王 L98。
> 承接：职业熟练度体系（proficiency.json，5a 路 A1~A4：7 级默认 见习→正式→精通→专家→大师→宗师→王、exp_sources 倍率、SP）。钓鱼职业 id 以 jobs.json 登记，走统一 proficiency 引擎，零新增。

### 4.1 熟练经验入账（R-13）

- 入账时机：出鱼结算（/收杆 结算）与鱼王讨伐胜利结算各调一次 `grant_proficiency_exp(job_id=fishing, amount, source=gather)`【钓鱼】L20。
- 倍率：exp_sources.gather（采集来源）倍率可配（对齐熟练 A4，默认 1.0）；入账经验 = 基础经验 × 倍率。
- 升级管线：经验入账 → 升级判定 → SP 发放（每级 1 点，可累积），对齐熟练 §八判定顺序；升级提示单条消息折叠。
- 原子性：入账与出鱼结算/图鉴更新同事务（2.2 R-05 同款幂等）。

### 4.2 钓鱼王称号语义（R-14）

- 钓鱼王 = 职业熟练度**第 7 级（王级）称号的补位**【钓鱼】L7——授予门槛**不靠经验**，靠「图鉴补全（核心玩法成就）」：7 级体系判据由熟练引擎的 `tier_names[6]` 与授予链（§2.4 R-07）联合驱动。
- 生效输出：拥有钓鱼王称号 → 进入 title_state 可佩戴列表 → 消息前缀 [称号] 渲染（2c5 T17）；称号加成（全属性 +X%）内容包可配，接入属性聚合。
- 按职业独立、不唯一：与其它职业王称号共存互不冲突（对齐熟练 C2 / 5 路 T15）。
- 授予时机晚于从业判据：经验升到王级职业等级 ≠ 自动得钓鱼王；钓鱼王仅在图鉴补全瞬间授予【钓鱼】L98。

### 4.3 频率与防刷（R-15）

- 每日次数：`daily_limit`（默认 20）拦截第 21 次抛竿，走 quest_daily 懒计算【钓鱼】L77。
- 经验频率：与每日次数联动（同一计数器）；防止无限制刷熟练（对齐 §八 风险 L131-134 与熟练 §九 刷级对策）。
- 消息频率：鱼王战与结算按 §四 L93 折叠 2-3 条消息/次【钓鱼】L93 / L134。
