# B 方案：编辑器默认页表自动发现（新包免配 editor.json）

> 2026-09-05 ｜ 提出背景：veinborn 新包无 editor.json → 编辑器只显示默认六页兜底（技能/职业/怪物/地图/任务/商店），equipment/items/npc/effects 等 24 页不可编辑。test_demo 有 editor.json（30 页全登记）所以全页可用。**根因：editor_registry 无 editor.json 时兜底 = 写死的 5a 六页，不感知内容包实际模块**。veinborn 定位 = 框架试金石，此缺口即它暴露的真问题。
> 状态：待新对话实施

## 一、目标

内容包未声明 editor.json 时，编辑器**按 registry.modules_raw 实际存在的模块自动生成页表**（全模块可编辑），不再只有六页。带 editor.json 的包（test_demo）行为不变（声明优先）。

## 二、现状（勘察事实）

1. `editor_registry.load_editor_registry(registry)`：modules_raw 无 "editor" 键 → `default_editor_pages()`（写死六页：skill/job/monster/map/quest/shop）—— L303-322
2. `default_editor_pages()` L244：返回 6 个 EditorPage（5a 六页）
3. **30 页母本规格** = content/test_demo/editor.json（每页含 page_id/title/icon/module_file/meta_source/validator/group/tabs/page_kind）——自动生成的映射表母本
4. **模块发现源**：`registry.modules_raw`（loader 按 manifest.modules 加载的全部模块 dict：{模块名: 解析后数据}）；loader `_KIND_FOR_MODULE` 登记模块→kind（L150-165）
5. field_meta 覆盖：effects/statuses/marks/skill_chains/action/skills/jobs/items/equipment/traits/enemies/maps/stats/formula/recipe/proficiency 有 `*_fields` 表；npc/quest/shop/checkin/dungeon/achievements/forge/fishing 走专项 models 校验器（meta 有宽松兜底——编辑器对无 meta 表模块仍可渲染通用表单？**需在实施时验证**）
6. **特殊页不适用自动生成**（需过滤/特判）：
   - `ai`/`hidden`：extends 挂载页（module_file=enemies.json/maps.json 的**子段编辑**，不是独立模块）
   - `env_event`/`log_card`：module_file=settings.json 的 object/view 形态子页（settings 已有独立页，避免重复）
   - 页与模块**非一一对应**（一个模块文件多页/多页共一模块）

## 三、方案设计

### 3.1 核心思路：模块名 → 页规格映射表 + 按需裁剪

建 `MODULE_PAGE_CATALOG`（30 页母本浓缩）：**每个「独立模块页」登记一条**（module_file 为主键或 page_id 主键），自动生成时：
1. 遍历 catalog 全部页
2. **页的 module_file 在 registry.modules_raw 存在 → 生成该页**（skill 页需要 skills.json 存在；无则跳过）
3. 特殊页（ai/hidden/env_event/log_card）**不自动生成**（它们依赖宿主页的子段结构，自动生成无意义）；但若该包**恰好有 editor.json** 仍按声明走（test_demo 不受影响）
4. 生成页继承 catalog 的 title/icon/group/tabs/page_kind/meta_source/validator（= test_demo 30 页同款配置）

### 3.2 映射表设计（新增常量，放 editor_registry.py）

```python
# 模块文件 → 页规格（30 页母本浓缩；module_file 存在才生成）
_MODULE_PAGE_CATALOG: Tuple[Mapping[str, object], ...] = (
    # 六页（原有兜底保留，meta 齐全）
    {"page_id": "skill",   "title": "技能", "module_file": "skills.json", ...},
    {"page_id": "job", ...},
    ...
    # 扩展页（equipment/items/npc/action/effects/statuses/marks/traits/
    #  skill_chains/recipe/proficiency/dungeon/achievements/slots/stats/formula/settings）
    ...
)
# 自动生成不适用页（需 editor.json 显式声明才出现）
_NON_AUTO_PAGES = {"ai", "hidden", "env_event", "log_card"}
```

### 3.3 函数改造

- `default_editor_pages()` → **保留**（兼容测试/显式调用）
- 新增 `auto_pages_from_modules(modules_raw: Mapping) -> Tuple[EditorPage, ...]`：按 3.1 规则生成
- `load_editor_registry`：无 editor 模块时 → `auto_pages_from_modules(registry.modules_raw)`（替代恒六页兜底）
- 空包（demo_blank 只有 settings/stats/formula/effects/items）→ 自动生成 5 页（settings/stats/formula/effects/items 各自页）——**比六页兜底更贴实际**，且不再出现「点开技能页空列表」

### 3.4 行为影响 & 兼容

- **带 editor.json 包**（test_demo）：声明优先，零变化 ✓
- **无 editor.json 包**（veinborn/demo_full/demo_blank 等）：页 = 实际模块自动生成。demo_full 有 equipment 无 skills → 会出现装备页、不会出现技能页（修正现六页兜底里技能页空列表的问题）
- 默认六页兜底常量 `_DEFAULT_PAGE_SPECS` 仍保留（auto 函数的规格来源），但 load_editor_registry 不再直接返回它
- tests/test_editor_registry.py `test_default_pages_when_no_editor_module` 断言要改（Registry(pack_id) 空 modules → 自动生成结果变化：空 modules → 无页 or 基础页？**需定语义：modules_raw 全空 → 返回空页表还是仍六页兜底**——建议空 modules → 空页表，避免渲染幽灵页）

### 3.5 验证

1. 单测：
   - demo_blank（5 模块）→ 恰好 5 页且页 id 对
   - veinborn（17 模块）→ 17 页左右（不含 ai/hidden 等特殊页），含 equipment/items/npc/shop/quest/action/effects/skills/jobs/enemies/maps/stats/formula/settings
   - test_demo（有 editor.json）→ 仍 30 页声明优先（回归）
   - 空 Registry → 语义定稿（空页表）
2. 浏览器实测（复用 /tmp/m12eq_host.py 模板，内容副本 /tmp/m12eq_ui）：
   - veinborn 副本 → 侧边栏出现装备/物品/NPC/行动/效果等全页
   - 点装备页 → 现有 10 件装备列表可见
   - 新建一件装备（填 id/name/slot/词条 dfn/foc/hp）→ 保存 → **读 /tmp/m12eq_ui/equipment.json 断言落盘**
3. 回归：test_editor_registry/test_web_api/test_field_meta_inject 全绿

## 四、风险 & 注意

1. **meta 空表页渲染**：无 field_meta 的模块页（如 dungeon 部分子段）自动生成后，/api/meta 返回空/宽松——前端表单是否正常？**需浏览器实测 npc/quest 页**（M12.5 说 field_meta 空表宽松注入已做——验证）
2. **validator 钩子**：auto 页带 validator 名（equipment/item 等）→ validate 端点无钩子时返回空校验（宽松语义，非缺陷）——确认 pages_crud 对未知 validator 不炸
3. **特殊页依赖宿主页**：ai/hidden 等不自动生成是**有意的**（无 editor.json 时这些子段编辑不可用——可接受，核心模块页已全）
4. **stats/formula/settings 形态**：page_kind map/object 页自动生成后读写走 whole/map 端点——demo_blank 已有这些模块，实测过 map 键写落盘（m125 批7 真包 API 点验）——低风险
