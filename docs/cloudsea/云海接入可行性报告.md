# 《云海猎团》接入可行性报告与转化映射

> 分析对象：https://github.com/xianyugezi/cloudsea-hunting-corps（原创 QQ 群异步回合制 PvE 设计稿，17 章 + 14 职业数值卡 + 380~572 任务 + 28 生态/760 怪）
> 分析日期：2026-09-02 ｜ 仓库基线：QBot-TurnTellerRPG @ 035c973（M13 收官）
> 硬约束：**不改动现有框架功能**；**不新增战斗系统模块**，战斗沿用现有回合制引擎

---

## 一、结论（TL;DR）

**✅ 可行，且战斗 100% 复用现有引擎。** 云海的「新机制」几乎全部能折叠进现有概念（marks 印记承载异常积蓄、M13 resource_axis 承载双压力轴、M13 job 引擎承载 14 职业、dungeon_boss 承载阶段状态机、effects 承载部位破坏）。需要新增的代码量 ≈ 60–100 行配置化扩展 + 1 个新指令文件包；真正的成本在**内容转译工作量**（设计稿数据 → JSON）与少量**语义妥协**（ATB 丢弃 / 部位用状态近似 / 同行兽降级被动）。

## 三、战斗机制映射表（核心：云海 → 现有引擎）

### 3.1 可直接复用（零新增代码）

| 云海机制 | 现有承载 | 说明 |
|---|---|---|
| 伤害九层公式 | damage.py 10 乘区 | H（部位易伤）→ pierce/weakness/type_affinity；E（七属性）→ weakness 表；X（异常易伤）→ marks 触发加成；D（流派）→ 技能 power/mult（M13 已加） |
| 异常九态积蓄条 | **marks 印记** | max_stack=阈值、duration=持续、触发=effects。9 异常 = 9 条 marks + effects 条目 |
| 双压力轴（压制/潮压） | **M13 resource_axis** | 玩家→怪压制 = 一侧轴；怪→玩家潮压 = 另一侧轴。stats.json 注册 2 轴 |
| 14 职业专属资源 | **M13 job + resource_axis + transform** | 蓄力阶/链值/乐章/形态值 = 数值型资源轴；狂战士形态值已有 berserker 先例 |
| 动作表/战技/绝技 | skills 技能库 | kind/power/hits/cooldown/mp_cost/effects + 派生链（combo） |
| 五流派/本命 | skills job_form/job_restrict + equipment | 技能变体 + 武器偏好字段 |
| 意图预告 | 怪物 AI（M2）意图/decide | ai 配置数据 |
| 阶段状态机 | dungeon_boss.py 多阶段先例 | 每阶段一个敌人条目 + 触发换阶段 |
| 异常乘区/直伤不吃防御 | effects dot 语义 | 现有 |
| 共生灵指令串 | effects trigger/proc 引擎 | L2 proc（M13 season_events 同款） |
| 托管/跨天 | session_mgr + battle snapshot | M13 快照续战已验 |
| 四选一 | 技能位装配（M13 skill_slots） | basic/active 槽 + 战报选项行 |
| 丰饶符 | checkin 每日奖励 + 掉落倍率 | 数据配置 |
| 主线/任务/章节 | quest + maps + dungeon | 内容包 JSON |

### 3.2 少量新代码（≈60–100 行配置化扩展）

| 云海机制 | 方案 | 代码量 |
|---|---|---|
| 部位硬度/部件破坏 | 部位 = 带独立 HP 桶的 status（shield/mitigation 近似）；清零触发既有 effect（倒地窗口 = damage_mult 状态） | ≈30 行「部位状态」注册 |
| 异常衰减/每场上限 | marks 挂 M13 resource_axis tick_round_end 衰减 hook | ≈20 行 |
| 同行兽 | 常驻 passive 状态（增伤/减伤）+ 战报图标；羁绊 = checkin 类养成 | ≈10 行 |
| 新指令集 | /接任务 /出发 /剥取 /局面 /港 等 = 新 CommandSpec + 白名单（纯新增文件） | 新文件 |

### 3.3 语义妥协（需接受）

| 云海机制 | 妥协方案 | 影响 |
|---|---|---|
| **行动条 ATB** | **丢弃**。保持回合制；SPD 差距只影响先手（pv）与命中（hit_rate） | 速度不再产生「多动」，出手次数比 1.3–1.6 不还原 |
| 部位矩阵 | 状态近似，非真实多部位独立受击 | 每部位独立选择目标的决策弱化 |
| 同行兽 ×2 + 共生灵 | 降级为被动 + proc | 多人协作面弱化（引擎 1v1） |
| 瞬御押注 | 用 guard + 条件技能近似 | 押注风险收益不完全还原 |
| 态势/钉位/扇区 | 降级为战报装饰 + 技能前置条件 | 战术深度减弱 |

## 四、落地策略建议

1. **新内容包** `content/cloudsea/`：manifest + 全部数据表，走现有 loader/validator 校验链（零红拦是硬门禁）
2. **转译顺序**：14 职业数值卡（→ jobs/skills/stats）→ 首发巨兽 + 部位/异常 → 武器/装备/符文 → 任务/地图（第 1 章 MVP）
3. **新指令文件**：qbot_rpg/commands/cloudsea_commands.py（纯新增，白名单加词，不与现有指令词面冲突）
4. **零改动承诺**：现有 content 包、现有指令、现有战斗引擎行为零变更；云海全在新包 + 新文件内
5. MVP 范围 = 设计稿 10 章 MVP（第 1 章云海之下闭环），后续按潮位分版本

## 五、风险与成本

| 项 | 评估 |
|---|---|
| 内容转译工作量 | **最大成本**：760 怪/572 任务/196 组合为体力活，可分批（每批 = 一个章节/潮位） |
| ATB 妥协 | 速度流职业（盗贼/游侠）体验打折，需数值口径重新校准 |
| 部位近似 | 「打哪儿」决策弱化，靠异常流/目标选择补偿 |
| 经济独立 | 丰饶符/三币为新增维度，与现有 shop/金币并行不互扰 |
| 无抽卡/法务 | 设计稿已过版权扫描，无风险 |
