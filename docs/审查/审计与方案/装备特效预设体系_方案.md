## 一、结论速览

1. **收集到了什么**：5 个品类（ARPG/刷宝 · MMO/团队 · 回合制/战棋 · Roguelike/动作 · MOBA/自走棋），每份 ≥30 条特效 + **逐条框架映射**（✅已有机制 file:line / 🔧需新轴 / ❌不适用）+ 来源链接。
2. **归并后约 40 条轴**，落地形态三分：**纯配置 6 条 / 引擎 knob 27 条 / 新机制仅 7 条**（其中 4 条可延后）。**轴的数量不是重点，收口才是**（设计 3 路原话）。
3. **你的"双向轴"原则被完整贯彻**：你举的**受疗轴**排在 **P0 第 2 位**（一条轴覆盖 减疗 / 禁疗 / 增疗）；另有承伤双向、治疗双向、冷却乘法、层数获取与上限等成对归并。
4. **两条 P0 缺口必须先于所有轴**（三份报告独立指向同一处）：
   - `event_dispatcher` **无 owner 归属过滤**（`event_dispatcher.py:80/:223`）→ 触发型特效会**全局误触发**；
   - **缺 `on_kill` 等事件补点**（`:58`）→ 部分触发型特效**永久落空**。
5. **最大数值风险不是膨胀，是"绕开校准"**：`panel_budget` 只覆盖 `atk/dfn/hp` → 特效轴会**抬高实际战力却不进 `equip_share`**。
   → 必须**另立"特效强度预算"**，并把**斩杀回合档位**（普通 3–8 / 精英 10–15 / Boss 40–60 回合，战斗数值层定稿 `:139-141`）定为**硬红线**。
