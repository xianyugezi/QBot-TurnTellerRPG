## 二、数值口径 · 用户授权主 agent 裁定
> 用户原话：「**数值口径你决定吧，反正又不是硬编码，到时候根据需要改就行了。**」

裁定原则：**全部做成可配（包声明/元数据），给默认值 + 可调范围**；文档写明每个数的依据与影响。

| # | 项 | 裁定 |
|---|---|---|
| **N1** | 品质经验模型 | 采用 B 路提案：`单次经验 = Σ(材料品阶基数 × 相性加成系数 × 件数边际 × 互动乘子) × 全局衰减`；cost 约束 = `总 cost 上限(按图纸档缩放) + 每材料 cost`；**参数全部落包声明** |
| **N2** | 防退化两条约束 | **必做**：① 图纸声明**等级带 + 主材料槽**；② **cost 上限随图纸档缩放**（否则出现"低阶便宜材料填满预算"的单一最优解） |
| **N3** | 总 cost 上限量级 | 默认钉在"**刚好到 10 级 + 少量冗余**"（B 路推：10 级阈值≈4040，上限≈4200，超投空间 ~4%）；**按图纸档缩放**，全部可配 |
| **N4** | 品质系数乘区 | **0.80–1.50**（面板总倍率 0.795–1.075），在"装备这一份预算"内分配；可配 |
| **N5** | 分解回收率 | 先占位：`精粹 = 投入价值 × k1(0.30–0.40) × k2(图纸档 0.40–0.60) × β^色序(β=0.5–0.7)`，与既有 `decompose_rate`（0.40→0.65）并存；标"待实际数据校准" |
| **N6** | 品质经验粒度 | 按原案"**每次打造独立**"：单次打造内累计、打造结束后清零（**不跨件累计**） |

## 三、用户新增的两条要求（本轮补充）

### 补充 1 · **装备占比 40% → 60%**
- 用户原话：「把装备占比在不改变其他数值的情况下提高到 60%，其他地方你看需要怎么调整就安排一下就行了。」
- **主 agent 裁定（执行口径）**：
  - 现状基线：面板 = `白值 7 : 装备 8 : buff 5`（合计 20 单位）→ 装备占 **40%**（依据 `docs/审查参考/阶段一数值模型v2:32` 及三路报告引用）。
  - **保持白值与 buff 的绝对数值不变**（这是"不改变其他数值"的直接含义），**放大装备贡献**至 60%：
    `装备 8 → 18`（18/(7+18+5)=**60%**），即**装备预算 ×2.25**；白值 7、buff 5 不动。
  - **连锁调整（授权范围内，主 agent 安排）**：面板总功率由 20 → 30 单位（+50%）⇒ **怪物侧与战斗数值层按同一比例重校**（目标：**保持既有斩杀回合数与手感不变**），按战斗数值层定稿的"三档推演（无buff下限/半buff中值/满buff上限）"口径重算，用既有**蒙特卡洛/斩杀回合**验证工具做**修前 vs 修后对照**。
  - **实施落点**：① 装备数值来源（词条/强化/品质乘区）的**总额度参数**上调配平；② 战斗数值层的怪物侧基线同步；③ **全部参数化**，不写死。
  - **独立成批**（数值校准批），与功能批解耦，便于回滚。

### 补充 2 · **材料相性共享给深度炼金**
- 用户原话：「材料相性这个设定可以共享给深度炼金用，相性影响药剂效果之类的。」
- **主 agent 裁定**：**相性是通用机制**，不属打造私有 →
  - 落点为**通用层**（如 `core/affinity.py` + 包声明数据），**打造与深度炼金共用同一套相性定义/池/互动规则**；
  - 深度炼金的消费方式：**相性 → 药剂效果**（效果强度/附加效果/成功率等，具体口径在炼金侧细化时定，本系统只提供**通用相性 API**）；
  - **不得**在两处各写一套相性（唯一源）；深炼金侧的接入点留出**稳定接口**，等其细化时使用。
