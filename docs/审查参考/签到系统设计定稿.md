# 签到系统设计定稿（checkin.json）

> 版本：v1.0 · 2026-08-16
> 定位：QQ 回合制 JRPG 框架内容包模块——签到 = **奖励日历**（不枚举类型），多表并存一次完成
> 来源：方案存档/商店签到/商店签到系统设计_整合联动版.md（签到部分提取转正；商店部分以《商店系统设计定稿 v1.0》为准）
> 核心：**多签到表（loop 循环 / monthly 月度 / activity 活动）× 奖励四通道（每日/连签/月度累计/补签）× 懒计算日界（默认 05:00 与 quest_daily 对齐）**
> 配套：奖励发放器唯一实现=框架 reward 解析器（与任务系统共用，条目=统一 reward 条目 schema，见 §3.2）；条件键空间新增 [签到:*] 3 键

---

## 一、设计哲学

1. **签到 = 奖励日历**：签到表是"连续登录奖励"的配置载体，一张文件一个数组（多表并存）。不枚举奖励类型——奖励 = 物品/货币/exp/声望 四元素任意组合（=统一 reward 条目 schema，见 §3.2）。
2. **一次 /签到 完成所有生效表**：常驻循环表 + 月度表 + 活动表互不冲突，各自独立计连签；活动表过期/未开始 → 自动停用（懒计算判定，不报错）。
3. **碎片化铁律**：断签不挫败——月度累计不要求连续（月底冲刺钩子）；补签为可选模块默认关；凌晨不骚扰（重置时刻默认 05:00，0-5 点仍算前一天）。
4. **只建议不限制**：所有上限可配（0=不限）；校验器只拦真正的非法值，数值提示不拦截。

## 二、指令与体验

```
/签到             → 一次完成所有生效表，汇总单条消息输出
/签到 补签        → 补签（makeup.enabled 时可用，消耗补签卡或货币）
```

- 单条消息汇总：今日奖励 + 连签天数 + 进度（"8/31"）+ 各表奖励流水（防刷屏）
- 同日重复 /签到 → "今天已签到"（幂等，不重复发奖）
- 每日奖励按天轮转；漏配天数 = 复制第 1 天兜底 + 黄色提示
- 列表模板 5 条/页上限（全局规范）

## 三、checkin.json 数据结构

### 3.1 签到表定义

```json
{
  "id": "checkin_monthly",
  "name": "月度签到",
  "type": "monthly",
  "desc": "每天签到领好礼",
  "period": { "start": null, "end": null, "cycle_days": 31, "reset_on_break": true },
  "rewards": {   // 各通道条目 = 统一 reward 条目 schema（任务/签到共用发放器，见 §3.2）
    "daily": [ { "day": 1, "items": [{ "id": "药水", "count": 2 }], "coins": 50, "exp": 20 } ],
    "streak": [ { "days": 7, "items": [{ "id": "钻石", "count": 1 }], "gem": 3 } ],
    "monthly_total": [ { "days": 15, "items": [{ "id": "强化石", "count": 3 }] } ]
  },
  "makeup": { "enabled": false, "cost": { "coins": 100 }, "max_per_month": 3 },
  "bonus": null
}
```

### 3.2 奖励四通道

| 通道 | 字段 | 规则 |
|---|---|---|
| 每日奖励 | rewards.daily[] | day 1..N 轮转（loop 表 N=cycle_days；monthly 表 N=当月天数自动；activity 表 N=固定周期）；漏配天数 = 复制第 1 天兜底 + 黄色提示 |
| 连签奖励 | rewards.streak[] | 连续签到 N 天里程碑额外给；断签重来（reset_on_break=true 默认开）则重新计数 |
| 月度累计 | rewards.monthly_total[] | 当月签满 N 天即给，**不要求连续**（碎片化铁律：断签不清零，月底冲刺钩子） |
| 补签 | makeup | 默认关（可选模块）；两通道任一满足：补签卡（物品，签到奖励/商店可卖）或货币付费 cost；max_per_month 月上限（0=不限） |

**奖励条目统一（= 统一 reward 条目 schema）**：rewards.daily/streak/monthly_total 的条目 = 统一 reward 条目 schema（任务系统设计定稿 §2.1 定义；day/days 为通道包装键，任务/签到共用发放器）——物品条目 items[]{id,count}（id ≡ item 键，引用 items.json，签到/任务奖励默认绑定）/ 货币键值（coins/gem，键空间同商店）/ exp / 声望（可选模块开启时，≡ rep）；不另立格式，同一框架 reward 解析器入账。

### 3.3 结算管线（写死，判定顺序结构依赖）

```
① 懒计算跨天判定：存档 last_date vs 今天
   同天 → "今天已签到"（幂等返回，不重复发奖）
   跨天 → streak+1；断签（间隔>1 天且 reset_on_break）→ streak 归 1
② 领 daily[day]（day = 周期内第几天）
③ streak 里程碑检查（达到 days 阈值 → 额外发奖）
④ monthly_total 检查（本月累计天数达到阈值 → 额外发奖）
⑤ 写存档：last_date / streak / month_total / signed_days[] / makeup_used
⑥ 汇总输出所有生效表：今日奖励 + 连签天数 + 进度（"8/31"）
```

### 3.4 多表并存

- 常驻循环表（loop）+ 月度表（monthly）+ 活动表（activity）可同时生效，一次 /签到 全部结算
- 活动表 start/end 由懒计算判定（未开始/已过期 → 自动停用，不报错）
- 活动加成 bonus（运营页活动管理挂"限时双倍"）在结算时统一乘算

## 四、与全系统联动

| 系统 | 联动 | 落点 |
|---|---|---|
| 任务系统 | 奖励发放器共用（统一 reward 条目 schema，任务系统定稿 §2.1；任务侧内联键值串为序列化糖，解析器等价）；签到联动奖励（任务定稿六） | quest.json reward / checkin rewards |
| 任务条件 | 新增 var 键：[签到:连续天数] / [签到:本月天数] / [签到:今日已签]（NPC 条件引擎共用） | 条件键空间（NPC 4.3） |
| 商店 | 活动币 → 活动商店（event 商店 + refresh once 时间窗）；签到奖励默认绑定不可卖（防套利） | shop.json |
| 变量体系 | [签到:*] 入变量键空间（4.2.3 登记），JS 公式可引用 | 4.2.3 键空间 |

| 级联删除 | 删物品 → 签到奖励同步移除（6.9） | 6.9 |

## 五、每日重置机制（日界统一）

### 5.1 懒计算为唯一判定

所有周期状态不依赖定时器：玩家操作时取存档周期键与当前现实时间比较，跨周期即补算（复用框架 3.6 补刷模式）。apscheduler 定时器仅做双保险（每日计数重置 + 公告推送），核心判定永远懒计算——服务器重启/离线多天不丢不炸。

### 5.2 与任务 quest_daily 三表对齐（日界统一 2026-08-15 拍板）

| 任务三表 | 语义 | 签到对齐 |
|---|---|---|
| longline_counters | 长线计数只增不减 | 签到总天数 / 累计签到（跨周期保留） |
| quest_active | 进行中任务永不清除 | 月度累计不因断签清零（碎片化铁律） |
| quest_daily | 每日计数当日行清零 | 签到当日标记 → 每日清零 |

**统一周期键**：重置时刻默认 **05:00**（可配），日期归属 = 重置时刻之后算新一天（凌晨 0-5 点仍算前一天，防凌晨断签/限购刷新骚扰）；与 quest_daily 的 refresh_time 共用同一配置键，**商店/任务/签到三表同刻对齐**（统一 refresh_time 键，历史旧刷新表述已删）。

### 5.3 存储分布

- 玩家存档（3.7，QQ 号全局）：签到状态 checkin_state（按表 ID：last_date/streak/month_total/signed_days/makeup_used）
- 换包策略（3.7 三选一复用）：同 ID 保留 / 红名显示+一键清除 / 双存档并行；签到 streak 按表 ID 保留，表删除仅黄色提示

## 六、3.18 快照原则（非会话持久状态）

签到状态**不是会话**（无互斥、无超时、不进会话管理器），但**借用 3.18 通用会话快照四项原则**登记为非会话持久状态：

- **ID+名称冗余**：存档记录 item_id + item_name 双字段（热重载/换包后旧条目仍可显示与结算）
- **version 幂等**：签到同日重复 → "今天已签到"（防双发）
- **旧配置结算**：连签 streak 按旧配置口径结算，新配置下个周期生效
- **会话回收不适用（settings lifecycle.recycle_days）**：签到状态为常驻存档不回收（僵尸回收仅限会话管理器范围：战斗/调合，见开发规则 §7.4）
- /状态 不提示签到（非会话）

## 八、4.5 校验器（checkin 行）

**硬拦（红，拒绝加载）**：
- 签到奖励物品引用不存在 / ID 重复
- 负数（补签费/奖励数）→ "奖励数量不能是负数哦"
- 结构错误（必填缺失 / JSON 格式坏）→ 人话模板

**黄提示（可加载）**：
- 签到表时间窗口已过期 / 未开始（活动表）
- streak.days > cycle_days → "连签 30 天才给，但周期只有 7 天，确认？"
- 补签费超常见区间；补签开启但无任何费用通道 → "补签不花钱？确认"
- 签到表无人引用 → "这个签到表没有绑定任何活动/默认入口？"
- 循环表缺 cycle_days → 已按默认 7 补全提示

## 九、编辑器（签到页，零代码）

- [基础] 表名 / 类型下拉（loop/monthly/activity）/ 描述
- [周期] 起止时间（活动表）/ 周期天数 / 断签重来开关 / 补签卡次数
- [每日奖励] 天数 + 奖励行（物品下拉 + 数量，或货币下拉 + 数值——结构化表单，对齐任务条件表单）
- [连签奖励] 里程碑表格（连签 N 天 → 奖励）
- [月度累计] 里程碑表格（签满 N 天 → 奖励）
- [补签] 开关 + 费用（货币键值行）+ 月上限
- [预览] 签到日历模拟：预览连续签到 N 天的奖励流水 + 断签效果，黄色提示"断签重来开启时，第 N 天断签将清零"
- 运营页活动管理可勾选绑定签到表

## 十三、验收标准

- [ ] 多表并存：loop/monthly/activity 同时生效，一次 /签到 全部结算，各自独立连签
- [ ] 断签规则：reset_on_break=true 断签归 1；月度累计断签不清零（碎片化铁律）
- [ ] 同日重复签到幂等返回"今天已签到"，不重复发奖
- [ ] 重置时刻默认 05:00（可配），与 quest_daily/商店同刻对齐；凌晨 0-5 点仍算前一天
- [ ] 发奖失败兜底：物品不存在黄字跳过不吞整次签到
- [ ] 补签默认关；开启后补签卡/货币两通道 + 月上限（0=不限）
- [ ] 校验器：引用存在（硬）/ ID 重复（硬）/ streak>cycle 提示 / 补签无费用通道提示
- [ ] 条件键空间：[签到:连续天数] / [签到:本月天数] / [签到:今日已签] 三键可被任务/NPC 条件引用
