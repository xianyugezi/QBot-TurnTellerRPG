## 〇、契约总则

### 0.1 术语表

| 术语 | 定义 | 依据 |
|---|---|---|
| 消息模板（TPL） | 对外消息的骨架文本，含占位符与固定文案；本规范以 TPL-xx 统一编号登记（§1.2），各系统渲染时按 ID 引用 | 本规范 D-05 |
| 前缀 | 玩家指令触发的回复**首行**身份标识 `Lv[等级].[玩家名] -[称号]-`，默认格式、占位符组合、显示规则全由 settings 可配 | 【前缀】L6/L34 |
| 渲染层产物 | 前缀是纯显示拼接，不改数值/判定/存档，不进指令解析器 | 【前缀】L13/L83 |
| 空称号三态 | 无称号时的三种输出口径：显示空称号文本 / 整段省略 / 仅隐占位符本体 | 【前缀】L90-92 |
| 列表分页 | 列表类回复（商店/图鉴/背包/排行榜等）**每页最多 5 条**，超 5 条分页输出，页码可输入 | 本规范 D-02 |
| 功能性标记 | 消息行首的功能语义符号：✅ 成功 / ❌ 失败；**装饰性 emoji 全局禁用**（见 §四禁用清单） | 本规范 D-01 |
| 折叠 | 正文内容超长时以省略行替代尾部条目，保留页码指引，不截断语义 | 本规范 D-03 |
| 统一文案 | 三类错误（指令出错/条件不满足/资源不足）的固定句式，全系统共用，禁止各系统自造文案 | 本规范 D-04 |

### 0.2 一句话契约

> 消息模板 = **14 条模板注册表（TPL-01~TPL-14）+ 5 条横切渲染规则**：
> ① 玩家指令回复首行渲染前缀（默认 `Lv[等级].[玩家名] -[称号]-`，空称号按三态口径输出，作者可配格式，前缀不计入正文长度限制）；
> ② 列表类回复每页最多 5 条，页码可输入翻页，页脚统一 `— 第 X/Y 页 · 共 N 条 · 输入 /指令 页码 翻页 —`；
> ③ 多行消息以「前缀首行 + 正文」组织，正文超长折叠为省略行并给页码指引；
> ④ 功能结果行首只用 ✅/❌ 两个功能性标记，装饰性 emoji（🔥🟢💥✨⭐ 等）全局禁用；
> ⑤ 三类错误统一走固定文案模板（指令不正确 / 条件不满足 / 资源不足），禁止各系统自造。
> 全部模板可被各系统渲染器引用；前缀相关字段均落在 message_prefix settings 段（【前缀】§三）。

### 1.3 占位符体系（格式模板专用）

| 占位符 | 含义 | 取值来源 | 依据 |
|---|---|---|---|
| [等级] | 玩家当前等级 | 玩家存档 level（框架 3.7） | 【前缀】L68 |
| [玩家名] | 玩家名 | 角色名（无则 QQ 昵称兜底） | 【前缀】L69 |
| [称号] | 当前佩戴称号名 | 成就批登记的佩戴称号状态（3.7 存档）；无称号 → empty_title_text | 【前缀】L70 |
| [群名] | 消息所在群名 | 当前消息群；私聊 = "私聊"（可配） | 【前缀】L71/L84 |
| [职业] | 当前职业名 | jobs.json 职业名（当前职业） | 【前缀】L72 |

- **自由组合**：任意顺序、任意重复、可只用一个（如只写 `[玩家名]` 合法），作者在 settings 的 `format` 字段配置（【前缀】L43/L74）。
- **未知占位符**：原样输出 + 校验器黄色提示「模板里有不认识的东西 [xxx]，会原样显示，确认？」，**不拦截加载**（【前缀】L75/L116-117）。
- [称号] 的特殊规则见 §1.4（【前缀】L76/L90-92）。

### 1.4 空称号三态渲染（称号空 → 三种口径，作者自选）

> 依据：【前缀】L35/L90-92；display 顺序：读取佩戴称号 → 无称号则按配置三态之一输出 → 渲染后套 `prefix_max_len` 截断检查（§3.3）。

| 配置组合 | 输出示例（阿伟 35 级无称号） | 语义 | 对应模板 |
|---|---|---|---|
| 默认（`hide_when_empty:false` + `empty_title_text:"-"`） | `Lv35.阿伟 - -` | 显示空称号文本 "-" | TPL-02 |
| `hide_when_empty:true` | `Lv35.阿伟` | 整段省略 [称号] 及其**相邻装饰符**，尾随空格清理 | TPL-03 |
| `empty_title_text:""`（不带 hide_when_empty） | `Lv35.阿伟 - -` | 仅隐藏占位符本体，装饰符（`-`/`-`）保留 | TPL-04 |

- **相邻装饰符定义**：紧贴 [称号] 占位符、无空格分隔的纯符号 token（默认格式中的左右 `-`）；整段省略时一并移除（【前缀】L91）。
- **尾随空格清理**：整段省略后若行尾残留空格（如 `Lv35.阿伟 - `），删除行尾空格再输出（【前缀】L91）。
- **缺佩戴状态按无称号渲染不报错**：成就批佩戴状态未登记/缺失时，直接走无称号分支（【前缀】L165）。

### 1.5 作者可配格式（只建议不限制）

- 作者在 settings.json 的 `message_prefix` 段改 `format` 即换格式，编辑编辑器通用设置页「格式模板 + 占位符下拉插入」（【前缀】L106/L108），**零代码**。
- 示例配置（【前缀】L127-140）：默认开箱即用（TPL-01）/ 职业版（TPL-05）/ 群名片版（TPL-06）/ 无称号整段省略+仅群聊 / 关闭前缀（`enabled:false`）。
- 显示规则字段（【前缀】L44-45/L58-59/L80-84）：`show_on_system`（系统公告豁免，默认 false）/ `per_channel`（all/group/private）/ `enabled`（总开关，默认开，内容包可关）。
- 渲染纪律：**前缀只加合并消息首行**，多行回复仅首行带前缀（【前缀】L82）；前缀不影响指令解析，解析用指令原文（【前缀】L83）。

## 二、列表分页

> 决策：D-02（补白）。适用面：所有输出条目列表的回复（商店/图鉴/背包/排行榜/任务列表/成就墙等）；单条消息承载，不拆多条（对齐【前缀】L25 汇总单条消息语义）。

### 2.1 5 条/页上限

- 列表条目每页**最多 5 条**，超过 5 条自动分页：第 1 页渲染第 1-5 条 + 页脚 TPL-08，其余条目进入后续页。
- 条数语义 = **用户可见条目数**（每条输出一行 TPL-07 骨架）；表头/分隔线/页脚不计入 5 条上限。
- 0 条时输出统一空列表文案（各系统业务自定，但**禁止 emoji 装饰**，遵循 §四）。

### 2.2 页码输入

- 页码输入形式：`/指令 页码`（如 `/商店 2`、`/图鉴 3`）；走指令参数解析，页码为最后一个整数参数。
- 页码取值范围 `1..总页数`：
  - 非法值（0/负数/非数字/超总页数）→ 输出 TPL-12（指令不正确）+ 页脚指引，**不静默翻到兜底页**（防误解）；尾页溢出输入 `999` 同理报错。
  - 统一提示示例：`❌ 指令不正确：/商店 999。输入 /帮助 查看可用指令。`（附当前页脚 TPL-08）。
- 页码输入时不重渲染前缀以外的信息，直接渲染目标页 5 条 + 页脚。

### 2.3 页脚格式

```
— 第 2/4 页 · 共 19 条 · 输入 /商店 页码 翻页 —
```

- **单页（总页数=1）不输出页脚**，减少刷屏（对齐【前缀】L17 防刷屏语义）。
- 页脚变量：`{X}` 当前页 / `{Y}` 总页数 / `{N}` 总条数 / `{指令}` 触发指令名 / `{页码}` 为 `页码` 字样（引导输入，非具体数字）。
- 页脚固定用 TPL-08，禁止各系统自造页脚格式。

## 三、消息长度控制

### 3.1 多行消息组织（前缀首行 + 正文）

- 结构固定：**第 1 行 = 前缀**（仅玩家相关回复，TPL-01~TPL-06 渲染），**第 2 行起 = 正文**（业务内容，各系统自管）。
- 一轮战斗合并策略不变：一轮战斗仍 1 条消息（玩家行动+怪物反击合并），前缀只在该消息第一行（【前缀】L17/L34/L82/L170）。
- 正文多行之间统一换行分隔；同属一条业务动作的多个结果（如战斗中的行动+反击）合并在同一条消息内，不拆多条。

### 3.2 折叠（超长条目折叠为省略行）

- 触发条件：正文条目数超过**折叠阈值**（默认 5 条，与分页上限一致，D-03）且未分页场景（如战斗日志/结算流水）：尾部超出部分折叠为 TPL-09 省略行。
- 折叠行示例：`…（其余 14 条已折叠，输入 /战斗记录 2 查看）`。
- **只折叠不截断语义**：折叠内容仍在后续页/后续条目中可查，省略行必须携带页码指引或查看指令。
- 一条消息的总渲染行数上限（含前缀/正文/页脚）默认 **16 行**；超限则按「正文尾部 → 中间过程行」优先折叠（决策：D-03 延伸，工程补白）。

### 3.3 超长处理（前缀与正文两级）

| 场景 | 处理 | 依据 |
|---|---|---|
| 前缀渲染后超 `prefix_max_len`（默认 40，0=不限） | **截断 + 黄色提示**「前缀过长已截断」；提示归属发起指令所在群，**不阻断正文输出**；正文照常渲染 | 【前缀】L48/L62/L100/L176 |

| 正文防刷屏判定 | **前缀不计入**正文长度限制：限制语义 = 正文防刷屏；前缀是作者控制的固定短文本 | 【前缀】L17/L97/L99/L176 |

## 四、功能性标记

### 4.1 ✅/❌ 语义（唯一允许的功能性 emoji）

| 标记 | 语义 | 使用规则 | 模板 |
|---|---|---|---|
| ✅ | 功能**成功** | 结果行首；动作/结果以纯文本描述 | TPL-10 |
| ❌ | 功能**失败** | 结果行首；三态失败（指令出错/条件不满足/资源不足）优先走错误模板（§五） | TPL-11 / TPL-12~14 |

- ✅/❌ 只能出现在**结果行行首**，一行至多一个；其后必须跟纯文本描述，禁止再叠装饰 emoji。
- ✅/❌ 属于功能性标记，**不算装饰性 emoji**，不在禁用清单内；其他一切 emoji 均按 4.2 禁用。
- 前缀区（TPL-01~06）**禁止出现任何 emoji 包括 ✅/❌**——前缀是纯文本身份标识（【前缀】L22）。

### 4.2 装饰性 emoji 禁用清单（全局，含正文）

- **禁用原则**：功能结果一律以文字表述；emoji 只保留 ✅/❌ 两个功能性标记（D-01）。
- **禁用清单（完整枚举，程序化校验锚点）**：🔥 🟢 💥 ⚔️ 🛡️ ✨ ⭐ 🌟 🎉 🎊 💎 🏆 ❤️ 💖 ⚠️ 🚫 📜 🗡️ 🛒 🧪 ⏰ 📅 ➡️ 🔹 🔸 ▸（半角/全角颜文字、箭头符号、星号装饰均属此类）。
- **定稿示例降级说明**：【前缀】L28-31 验收示例含 `🔥`（玩家行动行）与 `🟢`（怪物反击行）；该示例表述**不复制到实现层渲染**，实现层按本规范渲染为纯文本或 ✅/❌，如：

```
Lv35.阿伟 -斩龙者-
✅ 你施放火球术，造成 18 伤害（史莱姆 7/25）
❌ 史莱姆反击，你受到 4 伤害（HP 21/30）
你 21/30 | 史莱姆 7/25 → /攻击[技能] /道具 /防御 /逃跑
```

- 校验器与 CI 检查：渲染管线/grep 扫描输出样本，命中禁用清单任一字符 → 黄提示定位到系统与模板 ID（TC-18 依赖，D-05）。

## 五、错误消息模板

> 决策：D-04（补白）。三类错误统一文案，**全系统禁止自造句式**；错误消息首行仍按规则加前缀（玩家指令触发时，【前缀】L80）；错误行首统一 ❌ 功能性标记。

### 5.1 指令出错（未识别指令 / 参数非法 / 页码越界）

```
❌ 指令不正确：{原指令片段}。输入 /帮助 查看可用指令。
```

- 示例：`❌ 指令不正确：/攻撃。输入 /帮助 查看可用指令。`
- 原文片段截取前 20 字符，超过截断加 `…`（防刷屏，对齐【前缀】L17）。
- 适用面：未知指令、指令参数格式错、列表页码非法（§2.2）、未知子命令。

### 5.2 条件不满足（前置条件 / 等级 / 时段 / 状态限制）

```
❌ 条件不满足：{条件名}（当前 {当前值}，需要 {需求值}）
```

- 示例：`❌ 条件不满足：锻造等级（当前 2 级，需要 5 级）`
- 条件名用**可读中文名**（对齐【前缀】L114 人话模板）；数值双方必填，条件不允许多条并列不同类条件。

### 5.3 资源不足（金币 / 物品 / 体力 / 次数）

```
❌ 资源不足：需要 {资源}{数量}，当前 {当前值}
```

- 示例：`❌ 资源不足：需要 金币 500，当前 120`
- **失败无副作用**：资源不足判定失败时**不扣款、不消耗、不写存档**（对齐【前缀】L46 费用语义 + 签到契约 D-03 补签同款原则）。
- 同一动作多资源不足时，只报**第一个不满足**的资源（按配置声明顺序），不堆砌。

### 5.4 统一文案规范

- 三类错误模板固定为 TPL-12/TPL-13/TPL-14，各系统渲染器按 ID 引用，禁止在业务代码中自写等价文案。
- 错误消息默认**附前缀首行**（玩家指令触发场景），但**不附页脚/折叠行**（错误消息单行化，正文限 3 行内）。
- 错误消息不计入折叠逻辑（§3.2 仅作用于列表/流水类正文）。
