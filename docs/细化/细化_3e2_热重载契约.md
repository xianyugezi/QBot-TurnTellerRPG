## 〇、契约总则

### 0.1 术语表

| 术语 | 定义 | 依据 |
|---|---|---|
| 热重载 | 内容包配置变更后，不重启服务、不中断对局，运行中即时替换为校验通过的新配置 | 【规则】L174「编辑器保存 → 文件 mtime/哈希检测 → 该包即时生效（3 秒自动检测，或 /重载 手动）」；【框架】L42「保存即生效（热重载），无导出导入」 |
| mtime 增量校验 | 按文件修改时间/哈希比对，只对变更模块重新加载/校验，未变更模块复用（不重载） | 【规则】L176；【框架】L1618「按文件 mtime 增量校验，只重载变更模块」 |
| registry 快照 | 内存中一份**完整校验通过**的内容包注册表（ID 全局唯一登记），重载失败时回退对象 | 【规则】L175；【框架】L1617「内存保留上一份校验通过的 registry 快照，失败自动回退并人话提示」 |
| 会话快照 | 进行中对局（战斗/调合等）的持久化状态，**ID+名称冗余存储**，按旧配置结算 | 【框架】L344「快照按旧配置结算（材料 ID+名称冗余存储，防热重载失效）」；A.5 扩展【框架】L1887 |
| 旧局旧配置 | 进行中对局持旧快照继续，新对局用新配置（版本快照隔离） | 【框架】L777/L1647；【规则】L177 |
| 红色拦截 / 黄色提示 | 校验二分法：5 类非法值拒绝加载 / 数值范围等仅提示不拦截 | 【规则】L148-170；【框架】L741-746 |
| 防空转自测 | 坏包必须稳定复现拦截、热重载失败后不得无人值守空转（失败-重试-再失败打转）的防护与验证机制 | 【规则】L321/L326 精神延伸 + §5 本契约（工程补白见 BLK-5） |

### 0.2 一句话契约

> 内容包热重载 = **触发检测（mtime 轮询 3 秒 / 手动 /重载 / 导入收口）→ 原子替换管线（新配置全量校验 → 通过才指针级切换 → 失败回退上一份校验通过的 registry 快照并人话提示，绝不半套配置运行）→ 进行中对局持 ID+名称冗余的旧会话快照按旧配置结算不中断，新对局用新配置**；
> 坏包（5 类红色非法值）在进入运行态前必须被校验器稳定拦截，服务不崩、可复现、防空转。

### 0.3 决策记录（ADR，均为对定稿空白的显式收敛，标注【补白】）

| 编号 | 决策 | 理由 | 影响用例 |
|---|---|---|---|
| D-01 | 热重载轮询间隔固定**默认 3 秒**【框架】L905，「保存即生效（热重载 3 秒内）」L1544；轮询为可配项（`hot_reload.poll_interval_ms`，编辑器通用设置段），默认 3000 | 定稿仅给 3 秒语义，未给可配声明；遵循总纲「只建议不限制」，数值接口化 | TC-01/TC-03 |
| D-02 | 轮询/校验异步化：轮询由 apscheduler 定时任务驱动（与「操作时懒计算」并存），校验/加载/迁移等 >50ms 操作一律 `asyncio.to_thread` 进线程池 | 【规则】L106「所有 >50ms 操作（内容包校验、CSV 导入、zip 打包、文件 IO）必须 asyncio.to_thread 或放入 worker，禁止阻塞事件循环」；L110 定时任务统一 apscheduler | TC-05 |
| D-03 | 原子切换用**内存指针级替换**：新 registry 构建于独立对象，校验全通过后一次性替换 content 层持有的引用（`registry := new_registry`），旧 registry 对象保留给进行中对局只读引用 | 【规则】L175「内存保留上一份校验通过的 registry 快照」——指针级替换是「快照回退」的最小实现；避免逐条改写注册表造成半套状态 | TC-06/TC-10 |
| D-04 | 快照保有 **N=2 档**（当前有效 + 上一份校验通过）；连续失败 3 次自动暂停自动重载（转手动 /重载），恢复条件 = 手动触发或文件恢复合法 → 见 BLK-5【补白】 | 定稿未规定档数与失败节流；「防空转」为运行稳健性补白，不改变定稿拦截语义 | TC-09 |
| D-05 | 进行中对局的旧 registry 引用采用**引用计数**：对局创建时 +1，结束/回收（含 30 天僵尸回收）时 -1，为 0 才允许回收内存 | 【框架】L777「进行中对局持旧快照，新对局用新配置」+ L332 僵尸战斗回收——保证旧快照在最后一个对局结束前不被释放【补白】 | TC-10/TC-12 |
| D-06 | 热重载触发与 QQ 频率约束同层处理：自动重载提示与 /重载 结果提示均走统一发送出口与限频（单群每分钟 ≤20 条），**重载成功/失败提示不占用战斗结算消息配额** | 【规则】L499-501/L523；热重载是 GM/系统级事件，不是玩法消息【补白定位】 | TC-13 |

## 二、原子替换流程（ATO ×7）（F2 管线）

### 2.1 流程 F2：原子替换管线（六步，写死顺序）

```
① 写临时文件：编辑器/导入器先写 `content/<pack_id>/<module>.json.tmp` 再原子 rename 为正式名
   （单文件写入原子性）                                    【规则】L175；【框架】L1616
      ↓
② 攒批完成：全部文件写完（编辑器批量保存/导入全部通过）后才统一触发重载
   ——禁止边写边重载、禁止半批重载                         【规则】L175「全部文件写完统一触发重载」
      ↓
③ 增量筛选：按 mtime 定位变更模块集 Δ，未变更模块直接复用旧数据              【规则】L176
      ↓
④ 全量校验：以「新配置整体」跑完整校验器（红色拦截 5 类 + 黄色提示记录）
   ——校验对象是替换后的完整包，不是仅校验 Δ 文件                     【规则】L178；【框架】L763-773
   ④a 读 manifest → 按 modules 声明顺序加载                         【框架】L765
   ④b 逐模块加载 → validator 校验（引用完整性/互斥无环/数值范围）       【框架】L766-769
   ④c 注册顺序写死：effects → statuses → marks（效果家族先）→ skill_chains → action  【框架】L767-769/L136
   ④d schema_version 迁移（自动迁移链，如 内联 effects → effects.json ID 引用）【框架】L444/L776；【规则】L184
      ↓
⑤ 构建新 registry（独立对象、ID 全局唯一校验），全部通过          【框架】L770-773；D-03
      ↓
⑥ 指针级切换：`registry := new_registry`；旧 registry 对象交由进行中对局只读持有（D-05 引用计数）
   ——失败（校验红拦/异常/迁移失败）→ 不执行 ⑥，走 F3 快照回退        D-03；【规则】L178
```

## 三、快照回退（SNAP ×6）（F3 流程）

### 3.1 流程 F3：快照回退（失败路径，与 F2 同源）

```
重载失败（F2 ④/⑤ 任一红拦、异常、迁移失败）
      ↓
① 丢弃新建的未通过 registry（新对象未发布，直接弃用）                    D-03
      ↓
② 恢复内存指向 = 上一份校验通过的 registry 快照（D-04：保留 N=2 档）
   ——当前有效配置（旧配置）未被触碰，天然可用                         【规则】L175；【框架】L1617
      ↓
③ 人话提示：统一错误反馈模板（原因 + 正确用法 + 下一步）                【规则】L178/L114-116
   「校验失败，已回退旧配置：『物品『铁剑』引用的部位『双手武器』不存在』→ 编辑器修正后保存，或手动 /重载 重试」
      ↓
④ 失败记账 + 节流：连续失败计数 +1；达到阈值（默认 3）自动暂停自动重载，仅保留手动 /重载 入口        BLK-5
      ↓
⑤ 日志留痕（脱敏）：记录失败原因/触发源/时间戳，供机主排查                【规则】L1631 日志脱敏轮转
```
