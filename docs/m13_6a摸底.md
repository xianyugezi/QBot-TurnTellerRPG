## 8 contract_deviations（契约与现状不符处）

1. **契约 §0 承接的「M6 技能库」整体未落地**：细化_6a 自称承接 [规 T24/T25/T27]，但仓库 skills.json 模块、字段表、专项校验、装配存档均无——契约是「先行收口」文档，实现侧 M6 尚未执行（field_meta.py:583「技能库 M6 注入」注释证实）。
2. **V-11 与现有铁律方向相反**：契约要求「未登记字段拒绝」（红拦），而 field_meta.py:24 铁律为「未知字段默认放行」（§2.3 兜底）——skills 专项必须显式收紧，否则 V-11/TC-13 无法成立；且当前 action 表已存在未登记键（charge_* 前缀、condition obj 形态，field_meta.py:511, 520-521 注释「默认放行」），若把 V-11 推广到 action 库将破坏既有内容包。
3. **pierce 语义偏差点**：契约 §5.2 定 pierce{target:"def"|"spr"} 参数化（缺省 def），现 effects.py:1423-1428 的 pierce 无 target 键、只读 dfn（防御），无 spr 精神通道——与 ADR-6a-01 不符；damage.py:400-421 effective_con 只吃 con。
4. **action.json 内容包枚举值未契约化**：test_demo action.json 的 kind 用 basic/active、element 混用中文/英文，而契约 F03 五枚举（damage/heal/status/control/utility）与 F06 8 元素英文枚举——内容包与契约枚举口径不一致（内容包先行、契约后定，需迁移或兼容裁决）。
5. **element 引用检查缺技能路**：8 元素注册表已存在，但只在怪物八段 R3/R14 弱点/抗性引用处生效（validator.py:671-681），技能/行动 element 字段为 str 无注册表校验（field_meta.py:499）——契约 F06/V-4 要求技能路同样红拦。
6. **冷却计数无落点**：契约 §7 冷却计数随战斗状态存档，但 combo.py:865-866 冷却体系标注「M5 递延」、cooldown_remaining 无递减无存档——与契约承接表（1g2 回合末 -1、/休息 减冷却）不符。
