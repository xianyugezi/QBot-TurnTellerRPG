# 炼金系统设计定稿 v2.3（三层结构 · 全机制完整版）

> 版本：v2.3 · 2026-08-16
> 定位：QQ 回合制 JRPG 框架（v2.7+）内容包级系统设计
> 结构：**合成（跨职业）→ 炼金（职业专属）→ 深度炼金（大师解锁）** + 资源循环系统
> 机制来源：全部提取自《炼金工房》系列（A1-A26）资料
> v2.2 变更：第二轮 3 子 agent 检查——补入 9 个遗漏机制（委托/种植/特性合成/SP面板/战斗调和/品评会/代工/能量条/负面特性）+ 15 条细节（品质换算/宝石经济表/连锁映射/会话状态机/幂等/冲突规则/PP单价/分解规则等）
> v2.3 变更（设计缺漏审查修复批2A）：补【战斗即时调合 × 会话互斥】定义（D1）——即时调合=战斗内子流程（不新开会话/不挂起战斗）、产出默认自动使用（可配入包）、「限 1 次/场」入战斗快照 battle_alchemy_used。

---

> 指令分隔：遵循《指令分隔符统一规范》——数量用 *（/合成 魔力药水*10）、材料列表用 ,（/投料 赤铁矿,火药,硫磺粉）、键值用 =（触媒=爆裂壶）；/强化 禁批量 *（+N 是等级标记）

## 一、总览

### 1.1 三层漏斗结构
```
┌─ 第 1 层【合成】─────────────────────────────┐
│  跨职业快捷生产：配方+材料 → 直接得成品        │
│  解锁：任一制造职业/资源技能达到配方等级        │
├─ 第 2 层【炼金】─────────────────────────────┤
│  职业专属：需要炼金职业等级（见习起步）         │
│  核心玩法：投料/品质/特性继承/属性刻度/触媒     │
├─ 第 3 层【深度炼金】──────────────────────────┤
│  解锁条件：炼金职业等级 ≥ 大师                 │
│  完全体：20+ 机制                             │
└─────────────────────────────────────────────┘
```

### 1.2 资源循环系统（新，v2.2）
```
委托任务板（群内活跃引擎）
  ↕
采集/种植/代工（素材三渠道+长线产能）
  ↕
合成/炼金/深度炼金（三层生产）
  ↕
战斗消耗/品评会展示/装饰珠 build（消费出口）
  ↕
分解回炉/宝石经济（资源回收闭环）
```

### 1.3 边界铁律
- 合成：只产**标准版**（无特性/超特性/进化/核心类）
- 炼金：产品质/特性成品（炼金职业专属）
- 深度炼金：大师解锁，全部机制
- `synth_allowed` 字段控制配方可否被合成（深度层默认 false）

## 二、职业等级体系（tier_names 级数，默认 7 级 + SP 面板）

### 2.1 等级与熟练度
```
见习 → 正式 → 精通 → 专家 → 大师 → 宗师 → 王
                                     └─ 炼金王/铸造王/钓鱼王/收集王...
```
- **承载**：框架新增 `proficiency.json`（tier_names 数组长度即级数——默认模板 7 级，内容包可改名/可配级数 + 每职业熟练值 + 成长曲线）
- 熟练经验来源：制作（合成/炼金/锻造）+ 采集 + 战斗
- 职业等级与角色等级独立
- settings.json `job_tier_map`：称号→配方等级区间（见习 1-5/正式 6-10/精通 11-20/专家 21-30/大师 31-40/宗师 41-50/王 51+）

### 2.2 SP 技能面板（A4 技能树，v2.2 新增）
```
- 每升 1 级职业等级 → 获得 1 点 SP（可累积）
- /技能面板 查看：分支自选解锁（不是等级自动给！）
- 解锁项（内容包可配；数值=sp_panel[] 每条解锁项的 value 字段，可配/可多次）：
  · 品质上限 +10（value 默认 +10，可多次）
  · 投入次数 +1（value 默认 +1，可多次）
  · 特性位 +1（默认上限 3 普通，可配 1-6）
  · 解锁复制 / 进化 / 挑战（替代等级硬门槛或前置）
  · 采集量 +1（value 默认 +1）
  · 连锁上限 +1（value 默认 +1）
- 作用：把"等级到了自动给"改为"等级到了自己选"，成长自由度+重复可玩性
```

### 2.3 每级解锁机制明细表

| 等级 | 解锁内容 |
|---|---|
| 见习 | 合成可用；炼金层基础（投料/品质/一键投料/单批量）；调合能量条解锁 |
| 正式 | 特性继承 1 项；配方发想；种植解锁 |
| 精通 | 特性继承 2 项；属性刻度效果显现；代工助手解锁 |
| 专家 | 特性继承 3 项；触媒；配方合成；委托任务板高级委托 |
| **大师** | ⭐ 深度炼金：连锁奖励+核心镶嵌+分解回炉+量贩复制+图鉴成长+战斗即时调合 |
| 宗师 | 配方进化线+金色超特性+成品合成+觉醒+潜力+加成道具+特性合成 |
| **王** | 终极称号（炼金王）：全图鉴+专属配方+称号加成（全属性+X% 可配）+群内称号展示；品评会冠军专属 |

> 王称号：不唯一，按职业独立授予；条件=该职业图鉴全点亮；奖励=专属配方+称号加成+展示

### 2.4 调合能量条（A8 软节奏，v2.2 新增）
```
- 每次炼金/深度炼金消耗 1 格能量
- 上限：随职业等级提升（见习 5 → 王 20，可配）
- 恢复：每 30 分钟回 1 格（现实时间，碎片化友好）；休整/安全区可加速
- 定位：软节奏控制（防无限刷），不卡死体验（能量空可 /合成 保底）
- 合成不消耗能量（保底通道永可用）
```

## 三、第 1 层：合成

### 3.1 解锁
- 任一制造职业或资源技能达到配方等级 → 可合成该等级配方
- `synth_allowed`：深度层配方默认 false（可配），若开启合成仅提示"此深度配方可被合成，将绕过深度炼金玩法"
- 例：钓鱼大师 → 可合成大师级普通配方，深度配方不可

### 3.2 流程
```
[玩家] /合成 魔力药水 10
[机器人] ✅ 魔力药水 ×10（消耗：水结晶×20 + 草药×10 + 金币 100）
```
- 品质固定（标准）、无特性、无过程
- 数量上限 ≤99；**原子校验**：材料+金币全量满足才执行，否则全拒并提示差异（"缺 水结晶×5 + 金币 30"）
- 经验：每个成品 = 配方等级 ×1 熟练（可配）
- **标准珠带固定基础效果**（base_effects，无随机特性）

### 3.3 定位与成长
- 战斗玩家保底通道；合成给熟练经验（可成长）；**合成图鉴**（做过配方点亮→小加成）
- 转层钩子："炼金可继承特性做出攻/防/辅极品，同材料不同世界"

## 四、第 2 层：炼金

### 4.1 解锁与材料来源
- 炼金职业等级（见习起步）
- 材料来源：采集点（含稀有度/金色/✨觉醒标记）、出没时段稀有、怪物掉落、**商店限购**（shop.json）、**种植产出**、**代工助手产出**

### 4.2 调合流程（链式投料，可中断会话）
```
[玩家] /炼金 <配方>
[机器人] 📖 火焰弹（配方Lv5）：材料：火药×1(火2) 矿石×1 任意×1
         属性刻度：火≥6 显现"范围爆炸" | 特性位 2/3 | PP 5/5 | 投入次数 4
[玩家] /炼金 <配方> 触媒=爆裂壶
[玩家] /投料 赤铁矿 火药 硫磺粉
[机器人] ⚗️ 火+7 | 连锁 2 段 | 可继承特性：灼烧强化(PP1) 回复量+5%(PP1)
[玩家] /投料 追加 龙牙
[玩家] /继承 灼烧强化 回复量+5%
[玩家] /确认
[机器人] ✅ 火焰弹（品质 72·精良）火属性伤害 + 灼烧
```

### 4.3 核心机制（P0）

| # | 机制 | 来源 | 规则要点 |
|---|---|---|---|
| 1 | 配方调合 | A1-A26 | 选配方→投料→确认 |
| 2 | 品质 | A1-A3 | 材料品质→成品品质；**分档=quality_tiers 品质档位注册表（可配数组，档位数量 3/5/7 均可、0=不限制，校验器对档位数只提示不拦截；默认模板 4 档 普通 0-39/优秀 40-59/稀有 60-79/传说 80-100）**；品质系数=档位系数（效果×系数，见 §10.6） |
| 3 | 特性继承 | A11 | 材料带特性→选继承（默认 ≤3 项可配，消耗 PP）；**冲突规则：traits 加 group（互斥组，组内最多 1 项）+ repeatable（可否重复）** |
| 4 | 属性刻度 | A14 | `element_req: {元素: [{阈值, 效果}]}`；未达标=品质降级（差一档降一档，最低普通，绝不吞材料） |
| 5 | 链式投料 | A4/A21/A25 | **段数=相邻同属性对数**（连续 n 个=n-1 段）；段数→效果等级映射表（1 段=1 级…6 段=6 级，可配）；同属性判定=材料当前属性（触媒改变后按新属性） |
| 6 | 触媒 | A14 | 同材料+不同触媒=不同方向（精通解锁）；注册制（未注册仅提示） |
| 7 | 一键投料 | A25 | /炼金 <配方> 自动 → 自动配平（小白兜底） |
| 8 | 单件/批量 | A11 | 逐项调合（继承特性）vs 批量（平均品质、丢特性） |
| 9 | 配方发想 | A17 | 采集/战斗/调合触发→新配方（玩家级解锁表，SQLite） |

### 4.4 反馈与悬念
- 品质文字档+配方卡基准线（"品质 60 达标"）
- /炼金 面板显示 PP 与投入次数预算
- 投料反馈附可继承特性清单
- **悬念分级**：第 2 层引导语（"火系还差一点，试试多投火系材料？"）；大师级显示精确阈值（"火 42/45"）
- 术语人话化：触媒=决定方向的调料；属性刻度=属性值够高就解锁额外效果

### 4.5 失败与浪费
- 基础调合 100% 成功；未达标=品质降级产出（不吞材料）
- 第 2 层开放低级分解（回收率随等级 40%→60%，档位曲线：称号档跳变，可配）
- **分解对象限制**：仅炼金/深度炼金产出可分解（标准版不可分解或回收减半，防商店套宝石漏洞）；返还=配方材料×回收率向下取整

### 4.6 会话管理（完整状态机）
```
状态：无会话 → 会话中 → 挂起(战斗) → 恢复 → 确认/放弃（终态）
- 非法转移错误模板：
  · 无会话发 /投料 → "当前没有调合会话，先 /炼金 <配方> 开始"
  · 会话中发 /炼金 新配方 → "调合进行中！/放弃 退出 或 /调合续 继续"
  · /调合续 但已有活跃会话 → "已有一个调合会话进行中"
- 【幂等】会话 version 号；/确认 后置终态，重复确认→"已结算"
- /确认 时全量校验材料仍在背包（不足拒绝并提示差异）
- 单玩家指令串行队列（框架 15.2 复用）
- 私聊+多群同时操作：单玩家同一时间只允许 1 个调合会话（全局互斥）
- 战斗即时调合不进入本状态机（战斗内子流程，见 §七【会话互斥】）
- 无操作超时（settings lifecycle.recycle_days，可配 0=不限）→ 僵尸会话回收（材料返还）
- /深度炼金 与 /炼金 会话分开（不同会话类型）
```

## 六、装饰珠专项

### 6.1 规格
```
- 珠等级=品质档（默认模板 普通/精良/史诗/传说；档位由 quality_tiers 注册表驱动，档位数可配）；槽级 1/2/3 级
- 槽级→珠档映射：1 级=普通；2 级=精良及以下；3 级=全部
- 开槽：锻造/掉落/炼金产出开槽道具（可配）
- items.json type 补"装饰珠"；slots.json 补 slot_level
```

### 6.2 两套词条
```
- base_effects（珠基础效果）：固定数值（标准珠=只有这个）
- traits（继承特性）：品质浮动+可继承（炼金珠独有）
例：标准攻击珠=攻击+3；炼金攻击珠=攻击+3~5+可继承 1-3 特性
```

### 6.3 珠规则
- 绑定默认（防交易刷珠）；战斗中不可插拔（战前换珠=核心策略）
- 同名递减：**乘法叠加**，递减表可配（settings alchemy gem_diminish，默认第 2 颗 ×50%、第 3 颗 ×25%，0=无递减）
- 触发上限：战斗内特效触发 ≤3 次/场（按珠 ID 计，排除被动常驻）
- 珠三合一升阶：普通×3=精良 → 精良×3=史诗 → 史诗×3=传说（消耗宝石，滚雪球终点）＝合成引擎 kind=upgrade 配置实例（N 珠+消耗→珠+1 阶，字段映射见 §10.1；原数值不变）
- 指令：/镶嵌 <珠> <装备> /拆珠 <装备> <槽位>（无损）

- settings 落点（§10.6）：`战斗即时调合: {auto_use: true, per_battle_limit: 1}`（可配）

## 十、数据结构

> 品质档位由 quality_tiers 注册表驱动（settings/内容包可配：quality_tiers 可配数组，档位数量 3/5/7 均可、0=不限制，校验器对档位数只提示不拦截；默认模板 4 档 普通/精良/史诗/传说 ↔ common/uncommon/rare/legendary），跨系统引用不重复定义（炼金/强化/锻造共用）

### 10.1 recipe.json 元数据表
```
id | name | kind(craft|combine|upgrade) | level(1-99) | synth_allowed(true) | materials[{id,count}]
| cost{coins,gem} | slots(4,2-10) | element_req{元素:[{阈值,效果}]}
| effects(原子动作列表) | traits_inherit(1,1-3) | catalyst[](items type=触媒)
| combine_from[](recipe) | evolve_to{id,condition:{count,source}} | master_only(false)
```
> 【合成引擎归属（全量重叠检查组3 F2 修复）】：合成引擎 = 框架机制（代码），本系统 = 配置实例（JSON）——机制与内容分离。
> 本表 materials 字段 = 框架统一 schema 的 inputs（item 同义，仅改名，数值不变）；炼金四类「N 入→1 出」合成
> 均为框架 recipe.json `kind=upgrade` 的配置实例，字段映射如下（原机制/数值不变）：

| 合成 | kind | inputs（N 入） | cost（消耗） | output（1 出） |
|---|---|---|---|---|
| 珠三合一升阶（§6.3） | upgrade | 3×同档珠（默认档序 普通→优秀→稀有→传说，随 quality_tiers 注册表档位） | 宝石 10（gem.珠升阶） | 珠 +1 阶 |
| 特性合成（§5.2#17） | upgrade | 2 同系特性 | 宝石 20 + 材料 | 更高位特性（高品質Lv1×Lv2=更高级） |
| 成品合成（§5.2#5） | upgrade | 两成品（+材料） | 宝石 10 + 材料 | 更强成品 |
| 配方合成（§5.2#11） | upgrade | 两配方（已学） | 宝石 5 | 新配方解锁（组合表预置） |

> 锻造 3:1 素材合成 = kind=combine 实例（见锻造定稿 §5.1）。
