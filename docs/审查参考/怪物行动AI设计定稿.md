## 〇、核心规则（用户拍板，全体系基础）

```
1. 【打完一套再变】BOSS 一套行动（连招序列）完整打完，中途不被条件打断
   - 套 = 一次完整行动演出单元：连招链=一套 / 单随机行动=长度1套 / 蓄力跨回合=同一套
   - 套内：只走链推进/蓄力结算，不评估条件/状态/权重（玩家预判稳定）
   - 套间：一套结算后回合间隙，评估条件行动/状态机切换/权重修正
2. 【chain C 模型：触发 roll + 套内确定性】
   - 链节点 chance：触发时 roll 一次决定是否入队（建议 ≥80%）
   - 入队后套内确定性执行（火球 roll 成功 → 尾扫必来）
   - roll 失败 = 断链（该链进入冷却）
3. 【打断 = 套完结】玩家打断技打断连招 → 该套视为完结
   - 下一回合 BOSS 进入随机流程（不继续原套）
   - 博弈：打断=牺牲行动换拆套；收益=避开尾扫，代价=BOSS 随机化更难读
4. probability 默认值 = 0（漏配=锚点行动，只被链/条件/状态机触发）；参与随机池写 1（开关，数值不参与概率计算——概率一律 = weight 归一化）
5. 条件行动永远在套间评估，多个条件满足：priority 降序，同级随机
6. 随机概率 = 动态权重归一化（基准 × 条件修正 × 状态修正）
7. 蓄力可被打断（玩家打断技），霸体免疫打断
8. 所有字段默认值兜底，校验器只提示不拦截
```

## 一、随机行动表（概率动态调整）

```json
// enemies.json actions 数组
{
  "action": "claw",
  "weight": 50,              // 基准权重（归一化后=概率）
  "condition": null,         // 条件权重修正（如 pv_broken 时 ×2）
  "cooldown": 0,             // 行动冷却
  "hungry": 3,               // 饥饿保底：连续 N 回合没选则强制选（示例值；默认建议 0=关闭饥饿保底，可配 settings/enemies.json 覆盖）
  "probability": 0           // 锚点开关：0=锚点（只被链/条件/状态机触发）；1=参与随机池（数值不参与概率计算）
}
```

**规则**：
```
- 概率 = weight × 条件修正 × 状态修正（归一化）
- probability=0 = 锚点行动（不参与随机，仅被链/条件/状态机触发）；=1 = 参与随机池（开关语义，写其他正值等价 1）
- 概率=0 全表 = 纯脚本 BOSS（只走链/条件）
- hungry 防"永远不放大招"（随机偏差保护）
- 优先级建议：核心机制 100+ / 阶段 50-99 / 常规条件 10-49 / 连招锚点 0-9
```

## 二、条件行动（触发扩展 13 类）

### 触发类型（原 5 类扩展至 13 类）
```
① hp_below          血量低于 xx%（当前回合）
② pv_broken         防护崩溃后（下一回合）
③ get_up            起身后（下一回合）
④ battle_start      进入战斗/换区后第一回合
⑤ after_action      xx 行动后（下一回合，随机+锚点）
⑥ player_status     玩家带某状态/印记时（BOSS 叠印→消除博弈）
⑦ player_hp_below   玩家血量低于 xx%
⑧ turn_count        回合数达到 N
⑨ phase_changed     阶段切换后
⑩ zone_changed      换区后
⑪ ally_dead         召唤物死亡时
⑫ combo_broken      玩家连段被断时
⑬ script            剧情脚本（自定义）
```

```json
{
  "id": "magma_eruption",
  "trigger": { "type": "hp_below", "value": 30, "once": true },
  "action": "magma_eruption",
  "priority": 50,
  "trigger_cooldown": 5,
  "max_triggers": 1,
  "post_state": { "state": "exhausted", "turns": 1 },   // 触发后状态
  "chain_ref": "magma_combo_1"    // 连招引用 → 顶层 chains 表条目（连招唯一载体，见 §八【连招载体唯一化】；旧内嵌 chain=历史写法）
}
```

> 旧写法（兼容解析旧配置，新配置一律不用）：special_actions 内嵌 `chain` 数组与 action.json `action.chain` 字段 = 历史写法——解析器兼容旧配置（自动迁移为顶层 chains 表引用）；after_action 触发保留"单次锚点行动"语义，连招一律进顶层 chains 表（见 §八【连招载体唯一化】）

## 三、AI 状态机

> 边界声明（2026-08-16，全量重叠检查组5 F3）：**phases 阶段表 = 配置载体**（HP 阈值/每阶段行动表/转换演出，enemies.json phases），**ai.states 状态机 = 运行时行为状态**（巡逻/战斗/狂暴/濒死 + enter_action/权重修正）；两者分工——阶段表管"血量进度→行动表切换"，状态机管"行为模式→权重与专属行动"；阶段切换（phase_changed 触发）可联动状态机转换，但阈值声明只写一处（阶段表），状态机不重复声明血量阈值。**60/30 双阈值声明已收敛到 phases 单处**。

```
状态：巡逻 → 战斗 → 狂暴 → 濒死（可配自定义）
- 状态切换 = 条件表达式（与条件行动同一套）
- 切换时机 = 套间（打完一套再切）
- enter_action：进状态强制行动（入强制队列）
- exclusive_actions：状态专属行动表
- 状态修正：权重修正（如 狂暴=攻击行动权重×1.5，防御×0.5）
```

```json
"ai": {
  "states": {
    "normal":  { "weight_mod": {} },
    "enraged": { "weight_mod": { "attack": 1.5, "defense": 0.5 },
                 "enter_action": "roar",
                 "exclusive_actions": ["fire_burst"] },
    "dying":   { "weight_mod": { "attack": 2.0 },
                 "enter_action": "death_rattle",
                 "exclusive_actions": ["final_strike"] }
  },
  "transitions": [
    { "from": "normal", "to": "enraged", "condition": { "hp_below": 50 } },
    { "from": "enraged", "to": "dying", "condition": { "hp_below": 15 } }
  ]
}
```

## 四、决策管线（套内门 + 套间评估）

```
┌─────────────────────────────────────────────┐
│ 【套内门】套进行中？（在途链/蓄力中）            │
│   · 是 → 只走链推进/蓄力结算，跳过 0-5，结束    │
│   · 否 → 套间评估（0-5）                      │
│ 0. 状态机切换（套间先切）                      │
│ 1. 强制队列（开场技/脚本/enter_action）        │
│ 2. 条件行动（priority 降序，同级随机）          │
│ 3. 连锁队列（chain_queue，只由顶层 chains 表驱动）│
│ 4. 状态专属行动                                │
│ 5. 随机行动表（动态权重）                      │
│ 6. 兜底：默认普攻                              │
└─────────────────────────────────────────────┘
```

## 六、BOSS 战编排（阶段 × 连招 × 换区 × 教学 × 压迫感）

### 6.1 阶段机制（默认三阶段，可配）
```
阶段 1 常规期（100%→60%）：基础行动表，教学节奏（读全招式）
阶段 2 狂暴期（60%→30%）：行动表切换/新招解锁/权重变化/转换演出
阶段 3 绝境期（30%→0%）：濒死状态/处决技/印记反制加码
- 转换 = 剧情时刻（转换演出回合 + 开场技）
- 阶段内部小弧线：升压→峰值→喘息（每阶段有明确喘息点）
```

### 6.2 连招循环（固定骨架 + 随机血肉）
```
起手（50-70%）→ 锚点（25-40%）→ 收尾（≥70%）
- 锚点 = 可读性核心（看到火球 → 预判尾扫）
- 固定骨架：锚点→收尾必接（chance 建议默认 ≥80%，可配 settings/enemies.json 覆盖，未达仅黄提示）
- 随机血肉：起手选择/中间穿插（每次不同）
- BOSS 连招 vs 玩家连段 = 对称博弈（打断/霸体/防御三选一）
```

### 6.3 换区（BOSS 战斗体验的一部分）
```
- 换区条件：每 BOSS 独立配置（血量阈值/阶段/自定义）
- 换区目标：策划配候选区域列表（随机选一，网状地图）
- 未配置 = 不换区
- 流程：残血换区 → 提示"逃向 XX 区域" → 玩家走通道追击 → 决战
- 换区后：血量保持残血 + PV 恢复（比例=配置键 zone_change.pv_recover，默认 0.5，0=不恢复，1=全恢复，可配，见 §八）+ 开场技
- 退出规则：战斗中断=快照续玩（套内可续）；离开副本区域=重置
```

### 6.4 机制教学（精英怪 = BOSS 弱化版）
```
教学金字塔：普通怪（基础）→ 精英怪（BOSS 机制镜像）→ BOSS（组合考试）
弱化四法则：伤害降 / 频率降 / 无组合 / 无惩罚
- 精英怪 = BOSS 单个机制（残缺版），先教后考
- 教学顺序：先保命机制 → 再输出机制 → 最后反制机制
```

### 6.5 压迫感（高难 40-60 回合——建议目标带，非硬规则；压迫周期参数=pressure.breath_rounds，见 §八）
```
压迫-喘息循环：压迫感来自"压迫-喘息"交替
- 压迫：连招/多行动/印记反制/读招窗口
- 喘息：破防奖励/换区 PV 恢复/收尾硬直/虚弱窗口
- 每阶段必须有明确喘息点（长盘才能规划/恢复/续玩）
```

## 七、博弈体验（可读 × 差异 × 应对）

```
博弈体验 = 可读性（信息供给）× 差异性（行动变化）× 应对面（玩家选项）
- 可读性不足 → 挫败（"它凭什么这样打我"）
- 差异性不足 → 无聊（"背板就能赢"）
- 应对面不足 → 无力（"读懂了也没办法"）

读招四步法：宣告（预告）→ 预判（学规则）→ 应对（选行动）→ 反制（兑现收益）
读招窗口四选一：防御 / 打断 / 霸体硬吃 / 硬吃（资源交换）
锚点心理四阶段：见锚点（这是啥）→ 学规则（火球后尾扫）→ 预判（尾扫要来了）→ 反制（打断它！）
```

## 八、数据结构与登记（4.2/4.5/3.18）

### enemies.json 顶层扩展
```json
{

  "pv": 300,
  "actions": [ ... ],           // 行动表（一）

  "phases": [ ... ],            // 阶段（六.1）

```

### 连招载体唯一化（修复批4B 声明，重叠检查组5 F2/F4 仲裁落点）
```json
"chains": [                                    // 连招唯一载体（enemies.json 顶层表）
  {
    "id": "magma_combo_1",                     // 链 ID：供 special_actions.chain_ref / pressure 引用
    "actions": [                               // 链节点 schema：{action, chance, role, armor}
      { "action": "tail_sweep", "chance": 0.8, "role": "chain", "armor": false },
      { "action": "roar",       "chance": 1.0, "role": "finisher", "armor": true }
    ]
  }
]
```
- **顶层 chains 表 = 连招唯一载体**：链节点 schema `{action, chance, role, armor}`——action=行动 ID 引用（action.json）；chance=触发 roll（建议 ≥80%）；role=chain/finisher；armor=霸体免疫打断
- **历史写法（兼容解析旧配置，新配置一律不用）**：
  · action.json `action.chain` 字段（行动 ID 列表）——废弃，迁移路径：→ 顶层 chains 表条目引用
  · special_actions 内嵌 `chain` 数组——废弃（after_action 触发保留"单次锚点行动"语义，连招一律进顶层 chains 表）；需连招的用 `chain_ref` 引用链 ID
- 决策管线（§四 步骤 3）：连锁队列 chain_queue **只由顶层 chains 表驱动**——删除"条件行动内嵌链"入队路径
- 校验器：接受旧形状（裸节点列表 / 对象映射 / 内嵌 chain）并提示迁移（黄提示，只建议不限制）
- 框架侧：附 C 登记段（C.8 仲裁）由批内另一 agent 同步登记——本文档只声明载体归口，不另立存储/解析实现

## 九、示例：熔岩霸王龙（要点）

```
熔岩霸王龙（BOSS，PV 300，3 阶段）

  读招：看到火球 → 预判尾扫 → 打断技拆套（BOSS 随机化）或防御硬吃
  喘息：破防奖励 / 换区 PV 恢复 / 灭世龙息被打断后的虚弱窗口
```

## 十、验收标准（读招博弈成功判据）
