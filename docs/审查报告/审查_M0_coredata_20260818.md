## 四、P1（应改）明细

### P1-1 条件加成规则无内容包配置源 + 校验器零接线（TC-05「红色拦截不加载」不可达）
- **文件:行号**：`core/player_attributes.py:80-122`（validate_conditional_rules）、`:240-246`（唯一调用方 = calc_all_final_attributes）；`content/field_meta.py:177-195`（无 conditional 模块）；`content/loader.py:143-157`（_KIND_FOR_MODULE 无 conditional）；`content/models.py:267-280`（DEF_CLASSES 无 conditional）
- **实际**：`validate_conditional_rules` 仅在运行时 `calc_all_final_attributes` 内被调；内容包系统（field_meta / loader / DEF_CLASSES）不存在任何 `conditional`（join.json / 属性联动配置）模块，内容包根本无法声明条件加成规则；TC-05「依赖图检测 → 红色拦截，该内容包不加载（ADR-05 + L220）」只可能以结算期运行时 `ConditionalRuleCycleError` 形式发生，无法走"加载期红拦-拒绝挂载"路径。
- **应有**：细化_3b §3.2（规则配置 join.json/属性联动 · 每点 X→Y · source/target 校验）、TC-05/ADR-05：validator C 阶段解析 `conditional` 模块 → 调用 `validate_conditional_rules` → 命中环 → red block 拒绝加载。
- **修复建议**：注册 conditional 模块元数据（field_meta STAT_DEF 同款 map 形态 + loader kind + DEF_CLASSES），在 `content/validator.py` 增加依赖图环红拦（R-5）与 source/target ∈ 注册表校验。这与审查角色历史教训第 1 条「效果拦截链 8 阶段零接线——审查时查每个引擎函数的调用方」同类，Must-fix。

### P1-2 prefix_render 空称号分支只认「两侧对称装饰」，作者自定义 format 漏渲染 `[称号]` 占位符
- **文件:行号**：`core/message_format/prefix_render.py:73-87`（hide_when_empty 与 empty_title_text∈("-","") 两分支的正则）
- **实际**：`hide_when_empty` 仅执行 `re.sub(r"\s*[-=/~]+\[称号\]\s*[-=/~]+\s*", "", fmt)`，无 fallback；`empty_title_text` 在 ("-","") 时仅执行对称装饰替换。若作者自定义 `format`（3d §1.5 / TPL-05/06，占位符任意顺序任意组合 L74）为 `[职业] Lv[等级].[玩家名] -[称号]`（仅左装饰）或 `【[群名]】[玩家名] [称号]`（无装饰），正则不匹配 → **`[称号]` 原样泄漏到玩家可见前缀**（如 `【[群名]】阿伟 [称号]`），三态字段完全失效。TC-03/TC-04 仅默认格式（`- [称号]-` 对称）通过。
- **应有**：细化_3d §1.4（隐藏 [称号] 及相邻装饰符/仅隐本体），任意作者 format 下 [称号] 都必须被正确替换或删除。
- **修复建议**：正则替换后残留 `[称号]` 时补 fallback——hide 分支 `fmt.replace("[称号]","")` 再折叠多空格/清理行尾；非 hide 分支 `fmt.replace("[称号]", empty_title_text)`。

### P1-3 前缀超长截断无「已截断」信号 → TC-13 黄色提示「前缀过长已截断」不可达
- **文件:行号**：`core/message_format/prefix_render.py:98-100`；唯一调用方 `panel_render.py:67`
- **实际**：`render_prefix` 只返回纯 `str`，内部 `fmt = fmt[:prefix_max_len]` 静默截断；调用方无从得知"发生了截断"，3d §3.3/TC-13 要求的黄提示（归属发起指令所在群、不阻断正文）在现有 API 下**不可产生**。截断是"做了半截、事件被吞"的半接线。
- **应有**：3d §3.3 `截断 + 黄色提示`；前缀不等于正文长度预算（§3.3 末行）。
- **修复建议**：返回 `(prefix: str, truncated: bool)` 或 `PrefixResult` dataclass；或把截断职责整体移交壳层（壳层可自行测量并提示），二选一，但截断必须成为可观察事件。

### P1-4 stats.json 负数 base/growth 被红拦，违反 3b §4.2/TC-17「负数 → 黄（运行期按 0）」
- **文件:行号**：`content/field_meta.py:64-65`（STAT_CHILDREN base/growth，`FieldMeta(type="number", range_min=0,...)` 未设 `allow_negative=True`）；`content/validator.py:464-467`（allow_negative 默认 False → 数值 <0 → R-2 红拦）；`core/player_attributes.py:182`（calc_final_attr 对负 base 无「按 0」兜底）
- **实际**：stats.json 中 `"base": -5` 经 `_check_number` 判定 R-2 → **整包红色拦截**；而 3b §4.2 字段表与 TC-17 明示 `base=-5（黄）`、`growth 负数 → 黄`，「运行期按 0」语义也未在 calc 中落地（负 base 会被直接带入白值计算）。
- **应有**：3b §4.2 `base/growth | number ≥0 | 负数 → 黄（运行期按 0）`；TC-17 `base=-5（黄）`。
- **修复建议**：STAT_CHILDREN base/growth 加 `allow_negative=True`（走 Y-1 黄提示不红拦）；并在 calc_final_attr / calc_all_final_attributes 入口对 base<0 按 0 兜底（不影响 ADR-04 出口唯一取整）。

## 六、🟢 通过项（13 项）

1. **五步管线逐字落地**：`calc_final_attr`/`_pipestep`（player_attributes.py:125-150,153-194）与 3b §2.1 伪代码 step0~4 完全一致：白值=base+growth×(lv-1)+加点 → 基础合计 → ×(1+加成pct) → ×(1+临时pct) → +条件+临时flat；管线顺序写死不可配（L144/L221）。
2. **百分比只乘一次两含义**：加成 pct 仅乘基础合计、临时 pct 仅乘加成后属性，无递归（TC-02/TC-08）；单步乘算物理杜绝叠乘。
3. **条件加成三重锁**：基准锁（base_total=白+flat 触发，TC-04）、终值锁（最后一步纯加法不入乘算，TC-09）、自引用锁（DFS 三色找环，TC-05；含 X→X 自环）全部成立；元素管线 flat→×临时%（TC-11）由共享管线正确覆盖。
4. **resource 默认不吃百分比**：`apply_pct=(attr_type!="resource") or resource_pct`（player_attributes.py:251）→ ADR-02/TC-18。
5. **取整时机唯一**：仅出口 `int(math.floor(raw))`（ADR-04，TC-01/TC-17）；管线内保留浮点。
6. **派生属性五公式逐条一致**：crit_rate（√幸运×0.5%+crit_bonus，cap95/0=不限，TC-12）、crit_roll 三档+超会心（r≤P→2.2、r≤3P→1.7、其余1.3，+0.05×Lv，TC-13）、hit_rate（敌敏≤0→100%、双方0→100%、clamp(10,95)、K 可配，TC-14）、block_rate（min(40%, 专注/(专注+150))，TC-15）、phys/mag/elem_reduce（TC-16）；派生只读不回写（ADR-03）。

## 七、结论

**可合入（无 P0 拦截）**。M0 core 属性管线 + message_format + data 领域类型核心语义（三层五步管线、百分比只乘一次、条件加成三重锁、派生五公式、前缀三态默认逐字、5 条页分页、键空间、零 NoneBot/纯 str/统一错误文案）全部正确落地并有单测覆盖。
**须在 M0 合入前/紧随修复的 P1（4 项）**：P1-1 条件加成配置源+校验红拦接线、P1-2 自定义 format 空称号占位符泄漏、P1-3 截断无信号致黄提示不可达、P1-4 stats 负数 base/growth 红/黄口径偏差。P1-1/P1-2 直接触及本里程碑声明的「条件加成防叠乘 TC-05」与「作者可配 format TPL-05/06」，强烈建议 M0 内修。P2-3/D-05 模板注册表务必在 M1 前补全（避免各系统自造页脚/文案）。细化文档内部冲突 2 处（P2-2：3b §3.2 vs TC-05 自环口径；P2-9：3b ADR-05/TC-17 vs 3e Y-7 未注册键口径）按铁律**上报不裁决**，交用户/仲裁拍板。
