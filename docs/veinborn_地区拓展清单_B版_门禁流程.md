# 后续地区拓展清单·B版（门禁流程版）

> 适用范围：veinborn（蚀脉猎师·群脊荒原）阶段二及以后，每新增一个地区必须逐门照做。
> 门禁语义：每道门 = 一个可验收的阶段出口；本门通过才进下一门；六门全过 = 一个新区落地。
> 编号体系：[新区代号首字母+序号] 检查门。新区用区名缩写（例：新区代号 E 区 → E1 勘察门 / E2 设计门 / E3 数值门 / E4 内容门 / E5 实测门 / E6 回归门）；
> 既有区代号沿用 A-D（A1 区即 L1-A1 约定延续），写在门后括号里作为落盘文件名与验收命名（如 E1-勘察门：A1-衔接_L1-A1 对照）。
> 参照基线（阶段一已落地事实，勘察门 E1 的输入）：docs/veinborn_阶段一_区域风味设计_v1.md（区域风味设计 v1，含 A-D 区表）；docs/veinborn_阶段一_数值模型_1-35_v2.md（数值模型 v2）；docs/veinborn_阶段一_进度存档_20260903.md；docs/veinborn_装备体系规划_v1.md；content/veinborn/ 全部 JSON；docs/qa_report_20260907.md（P1/P2 修复基线 59ad1b4）。
> 新文件守则：纯文本中文、无 emoji、表格排版，可直接当仓库 docs 使用（落 docs/ 后同目录其他文档同守则）。

## E0 预备门（新区启动前置）

入口条件：用户拍板「做新区 X」，给出区名代号（X 首字母）、设定方向与阶段二接入点（接在 D 区隐藏 Boss 后）。

门内步骤：
1. 在 docs/veinborn 下建新区工作区，写《X区_开工页》：区代号、地图代号前缀（x1/x2…）、接续区（前一区尾图/隐藏图）、推荐等级带、Boss 位规划草稿。
2. 确认新区不新增框架模块时的落地方式；若需新区专属 JSON 模块（新模块文件），立即登记到「框架模块缺口清单」并先走框架流程，不混进内容包验收。
3. 确认数值衔接点：新区首图怪物等级与旧区尾 Boss 的衔接口径（小怪等级 ≤ 旧区主 Boss 等级，参照 v2「小怪 ≤ 上区 Boss」铁律）。
4. 确认要不要动既有区内容：要动（改旧怪数值/旧图通道）则 E1 前先出「旧区改动单」单独评审，禁止与新区内容同批提交。

出口验收清单：
- [ ] 《X区_开工页》存在，有区代号/图代号前缀/接续区/推荐等级带四要素。
- [ ] 新区不动框架代码（若必须动，已登记框架缺口并附需求单据）。
- [ ] 旧区改动（如有）已拆出独立改动单。

典型翻车点：新区未分配图代号前缀就开写 JSON，id 撞车（a1/x1 前缀必须唯一）；新区混改旧图数值导致回归无处归因。

## E1 勘察门（旧区做法全量对照）

入口条件：E0 通过；能读到 docs 锚点 + content/veinborn 全量 JSON（maps/enemies/quest/npc/shop/equipment/items/forge/effects/action/skills/jobs/settings/manifest）。

门内步骤：
1. 读旧区全量资料：docs/veinborn_阶段一_区域风味设计_v1.md、docs/veinborn_阶段一_数值模型_1-35_v2.md、docs/veinborn_装备体系规划_v1.md、docs/veinborn_阶段一_进度存档_20260903.md、docs/qa_report_20260907.md；读 content/veinborn 全部 JSON（留意字段形状，非只读文档）。
2. 产出《旧区做法对照表·A-D 区》：逐区列出 图数/每图怪组数/小怪数/精英数/Boss 数/主任务链长度/区域装备线/营地位置/隐藏图机制。
3. 产出《新区必须对齐的惯例清单》（逐条可勾选）。

出口验收清单（以 A-D 区实际落地事实为准绳，不是以风感想象为准）：
- [ ] 《旧区做法对照表》四区齐全，行列为：区|图数(主+隐藏)|每图主怪组|精英|Boss(主/隐)|怪风味表行数|任务链(主线链数/支线)|装备线(系+区段档)|营地(图|名|功能)|隐藏要素机制。
- [ ] 《惯例清单》至少覆盖下列已验证条目：
  - 图数规模：A 4 图/B 4 图/C 5+1 图/D 7 图；新区图数应与等级带宽度匹配（约 1 大级/图，隐藏图单列）。
  - 生态混居：主怪 + 混居怪；跨度 ≤1 区段；下区怪提前露脸（放在上新图尾）、上区怪残留（放新下靠前图）。
  - 每图怪物 1-3 种，respawn_minutes 3-8（小怪）/15-25（精英）/30-60（Boss）。
  - 精英怪每区 1-2 只（B 区双精英同图是特例），放区中后段图。
  - Boss 位：每区 主 Boss 1+(隐藏/双主视设定)，Boss 图怪物带 intro/signal 文案，hidden_boss=true。
  - Boss 召唤行动限制：单场 1-3 次、召唤间隔冷却 ≥3 回合、绑定姿态/血线、召唤物偏弱。
  - 任务链：主线按图递进（slay 型 + 链式 unlock_chain，先例 q_tut0→q_tut4 5 链 + q_b1-q_d3 区链）；引导/新手任务只在 A 区有。
  - 营地：每区 1 图（区中段），camp_name/safe/补血 NPC，解锁后是传送目标+安全区；驿站=唯一主城。
  - NPC：驻地发牌员（老猎人型 1 个接全区主线）+ 营地药婆型（疗伤收费随区递增 50/80/120）+ 商店 NPC 引 shop_refs。
  - 装备线：商店白板 ~80% 档 + 打造线随怪物素材；装备数值对齐 v2 上拉口径。
  - 地图列表不泄露未发现图：新区只把「已发现图」登记进玩家可见列表，隐藏图/未解锁图不进列表（对照 c6 沉渊回廊先例）。
- [ ] 惯例清单每一条都有 A-D 区对应出处（区名/图名/JSON 文件）。

典型翻车点：只看文档不看 JSON 字段形状（照文档字段名写 JSON 对不上 loader）；照搬 A 区新手图节奏做后期区（引导任务/白给装备只属于 A）；新区怪名/图名与旧区同词根导致检索混淆；漏登记「新区怪物 skill/action 服务端 _derived 派生链」（见 E4）。

## E2 设计门（世界观续接 + 生态 + 地区三表）

入口条件：E1 通过；《惯例清单》全勾；新区代号/等级带/接续点已定稿。

门内步骤：
1. 世界观续接：写新区与群脊荒原/苍穹界的承接关系（蚀脉生态延续或反差）、为何存在（D 区预留在 D2 西缘的出口如何落到新区）——D 区设计预留「D2 夜嚎森林西缘 → ?（阶段二预留）」，新区入口须解释并落这条通道。
2. 玩家数值门：明确新区「进区/毕业」两级玩家门槛（进区：等级+装备线档位+主线完成度；毕业：下一区会用什么打你），对照 v2 玩家成长表（35 级毕业中值 atk 900/dfn 537/hp 1939）外推。
3. 生态设计：主怪/混居怪分配表（含下区怪提前露脸与上区怪残留的位置），跨度 ≤1 区段。
4. 地区三表（图/怪/Boss 风味行为表）——必须对齐 docs/veinborn_阶段一_区域风味设计_v1.md 的表格格式：
   - 图表：| # | 图名 | 风味 | 主怪 | 混居怪 |（行内标注混居怪来历：B 残留/A 提前）
   - 怪风味表：| 怪 | 类 | 风味 | 行为特征 |（小怪/精英/Boss 分列）
   - Boss 行为表：每个 Boss 三姿态设计 + 专属行动清单（对齐「三姿态（专属行动见下）」格式）。
5. Boss 召唤限制：逐 Boss 写明 召唤行动名/单场上限次数(1-3)/召唤间隔冷却(≥3 回合)/绑定血线或姿态/召唤物数值档（偏弱、玩家 1-2 刀清）。
6. 营地与通道表：每区 1 营地（区中段）+ 跨区通道（非一本道，含提前探路通道与主线隘口）。

出口验收清单：
- [ ] 世界观续接段有「接哪张旧图/为什么长这样/给旧区留了什么回望点」三问答。
- [ ] 玩家数值门有进区/毕业两行对照（等级/白值/装备线档/预期单发被击%）。
- [ ] 生态混居表每行注明混居跨度 ≤1 区段，提前露脸/残留怪标了方向。
- [ ] 图/怪/Boss 三表格式完全对齐区域风味设计 v1 的表头（评审逐列比对）。
- [ ] Boss 召唤限制每 Boss 一条，字段齐全（次数/冷却/血线/召唤物强档）。
- [ ] 通道表含营地（camp_name）与隐藏图解锁条件（对照 C6/D7 先例）。

典型翻车点：三表格式走样（评审要按 v1 表头逐格比对，多了自定义列必被挑）；召唤行动不写冷却与次数上限——引擎语义是「召唤做节奏点缀，不让玩家陷入清-再清重复劳动」（风味 v1 Boss 召唤总规则）；入口接旧图却不改旧图 exits（新区出现在地图上但旧区过不去）；隐藏图未写解锁条件导致「永不可达」（内容校验黄基线的来源，见 E4）。

## E3 数值门（怪三档数值表 + 装备素材线 + 蒙特卡洛自证）

入口条件：E2 通过；三表定稿；玩家数值门定了进区/毕业门槛。

门内步骤：
1. 怪三档数值表：新区全部小怪/精英/Boss，格式对齐 veinborn_阶段一_数值模型_1-35_v2 区域数值总表：| 怪 | 类 | Lv | HP | atk | con | 斩回 | 单发% | 评 |。
   - 对照 v2 数值模型口径：HP/atk/con 与前后区衔接（小怪等级 ≤ 旧区 Boss 等级）；斩回=玩家几回合击杀；单发%=怪物单发打中值玩家 HP 百分比。
   - 各区经验档参考：A 小怪 100-400 / B 1000-2500 / C 4000-9000 / D 1.5万-4万；新区照曲线外推并落 express。
2. 装备素材线：新区材料（新怪掉落素材、沿用通用素材脉晶碎片 vein_shard）+ 武器系档（对照装备规划 v1 六系武器表：A前/A后/B/C/C隐D前/D 档位）+ 防具套装来源（商店套/精英素材套/Boss 素材套）与数值衔接。
3. 经验奖励曲线对齐：settings.json exp_curve 前缀不断裂；新区怪 rewards.exp 落在同区间曲线 ± 档内，与旧区无断崖。
4. 副本/复战数值位：Boss 战（首杀/复战）数值沿用 v2「Boss 7 只」表结构与挑战状态标注（如 D 隐超模毕业战）。
5. 蒙特卡洛自证（斩回/胜率/药水）：用子 agent 派模拟器（scripts/qq_group_sim.py 或 scripts/veinborn_battle_probe.py 系）跑：
   - 各档怪对中值玩家：命中/会心/格挡按 v2 公式口径，斩回分布（均值+5-95 分位）、胜率、药水消耗中位数；
   - Boss 战对毕业玩家：胜率 ≥ 阈值（对照「药紧/超模毕业」语义），召唤行动出现次数不超过设计上限；
   - 药水线：新区 Boss 战药水消耗进入 v2 注释的「药水管理刚需」档还是「碾压」档，偏差超 ±20% 要回炉。

出口验收清单：
- [ ] 怪三档数值表逐行填完，Lv/HP/atk/con/斩回/单发% 六列无空；与前后区（上一区尾图/下一区首图）怪物数值无断崖（Δ ≤ 模型允许带）。
- [ ] 装备素材线表：素材→来源怪→用途（武器系/防具套）三列闭环；[旧] 区 Boss 素材不被新区复用。
- [ ] 经验曲线对照：新怪 exp 落在曲线表内，无 < 旧区尾 BOSS 奖励的反直觉倒挂。
- [ ] 蒙特卡洛自证报告归档：斩回/胜率/药水三指标 + 子 agent 跑的分区记录（哪个 agent/哪条命令/哪个 --file）。
- [ ] 数值评审意见/拍板记录进 E3 出口材料（参照 v2「数值骨架 v2（待审）」先审后落的惯例）。

典型翻车点：斩回/单发% 只填了理论值没跑模拟器（v2 是实跑模型，评审以实跑为准）；胜率卡在 50% 边缘却说「药紧=设计如此」（D 隐超模是有意锚定，普怪不能借超模名义）；boss 召唤物数值做太强把 Boss 战变成先清小怪（风味 v1 Boss 召唤总规则第 4 条）；
装备线只给了「一件武器」没给全套套装（对照装备规划拆分版：武器独立/五件防具/饰品选配）。经验曲线改了但 settings.json exp_curve 没跟（exp 入账与曲线表「前缀不断裂」检验失败，见 E5）。

## E4 内容门（全模块 JSON 落地 + manifest + 校验基线）

入口条件：E3 通过；数值表/素材线/自证报告定稿。

门内步骤：
1. 全量 JSON 落地（新区内容写进 content/veinborn 对应文件，不是新建 demo 包）：maps/enemies/quest/npc/items/equipment/shop/forge/effects/action/skill_chains（列表齐全；新区不开新模块文件则落既有文件对应区段）。
2. 新区若新开 JSON 模块文件：modify manifest.json modules（登记模块）+ stats/formula/settings 键符合 loader/field_meta 预期；同时检查编辑器自动页表测试（E6 回归门）。
3. 引用健壮性复查：enemies.actions/special_actions 引用 action.json 存在的 id；skills.effects 引用 effects/statuses/marks 存在的 id；maps.exits.to 指向存在的 map id；npc.interactions.shop_refs 指向 shop.json 存在的 id；quest.reward/conditions.param 指向 items/enemies 存在的 id。
4. 文案零 emoji：新区所有 desc/name/broadcast/templates 文案零 emoji（先例基线：tests/unit/test_emoji_discipline.py 抓渲染串级 emoji；仓库现有内容包/框架串含历史 emoji 属遗留，新区新增文案不受影响但不可新增）。
5. 跑内容包校验：python scripts/check_m7_content.py --path content/veinborn——基线 0 红（RED 0），黄（YELLOW）只允许既有 249 基线水平，新区带入的黄=新增黄要逐条说明。
6. 新区专属 loader/装配检查：新区不复用旧区 templates 覆盖（templates.json 覆盖需要 ctx 装配注入——先例：注册成功引导模板 register_success_next 被 P1-2 修复为可覆盖，复制粘贴旧模板会丢 ctx 占位符）；怪物 skill 派生链检查（见翻车点）。

出口验收清单：
- [ ] 上述 11 类 JSON 文件全部含新区条目（无新区内容遗漏文件）；与新区 map id 前缀（x1/x2…）一致。
- [ ] manifest.json modules 与新模块数一致（新区没有该加未加的声明）。
- [ ] 引用复查全绿（新区 id 全部可解析，无悬空引用）。
- [ ] 新区文案零 emoji（grep 新区段新写的中文文案无 emoji 字符）。
- [ ] 内容包校验摘要：RED 0；YELLOW 相对既有基线无净增（或净增逐条有解释落盘）。
- [ ] 新 Boss/新怪物的 action 带 _derived 派生标记检查通过（服务端派生链可解析，见翻车点）。

典型翻车点：
- 内容校验 0 红基线语义：check_m7_content 的 RED=不可达要素（隐藏图/无发现路径=可能永不可发现）；黄=条件键未注册等提示（契约级「黄提示不阻断」）；新区漏掉 entrance/unlock 声明 → 隐藏图变 RED，新区每新增一条黄=要解释。
- 怪物 action 无覆盖标记/服务端派生链缺失：技能派生（skill_chains steps variant_override/derived 结算）若服务端没收到派生态标记会直接打不出派生大招（先例：G1 派生结算修复/qa P1-1 derived cap 误砍）。新区专属行动先查 action.json kinds 表（现状 68 条 active，新区动作要落 action 再被 enemies.actions 引用）。
- utility power=0 零伤害：新区别把「纯 utility/无伤害动作」写成带伤害期望——utility skill/power=0 动作打出去期望零伤（QA P2 已修框架级渲染，但内容侧别再造此类怪动作）。
- templates 覆盖需 ctx 装配注入：新区照抄 register_success_next/job_switch_success 会丢 {job}/{rec} 占位符的 ctx 注入（注册引导/转职提示是内容包可覆盖模板，覆盖值缺 ctx = 渲染崩或空提示）。
- 地图列表不泄露未发现图：新区地图登记时，检查新区隐藏图/未解锁图是否被提前登记进玩家可见列表（对照主城/营地只登记已发现图先例）——泄露 = 玩家「看见去不了」。

## E5 实测门（模拟器黑盒逐流程 + 数值抽查）

入口条件：E4 通过；JSON 全落地且校验基线达标。

门内步骤：
1. 模拟器黑盒逐流程（scripts/qq_group_sim.py，单 --file 长序列）：单文件命令序列覆盖：注册（新玩家，验证注册引导可覆盖文案含新区正确引导）→ 引导推图 → 任务链（领取任务/杀怪计数/交任务/奖励入账）→ 推进跨区（旧区进新区通道可达；新区首图可进；提前探路通道/主线隘口行为）→ Boss（战前信号/姿态切换/召唤行动次数上限）→ 复战（首杀成就/NPC 传送副本）→ 死亡惩罚（虚弱期开战拦截、经验掉落、疗伤）→ 营地休息（camp 图休息恢复）。
   - qq_group_sim.py --file 长序列单文件跑完，输出逐条存档；新区专属长序列文件放 scripts/ 或记录到实测门产出。

   - 经验入账：击杀经验=rewards.exp 且与 settings exp_curve 对应档位一致（「经验曲线前缀不断裂」检验）。
3. 边界抽查：新区首图 1 级角色能不能进（要能拦则拦得有理）；隐藏 Boss 图在未达解锁条件前不可进；死亡回营地后新区图 respawn 正常；复战 Boss 数值与首战一致（纯配置副本）。

出口验收清单：

## E6 回归门（全仓回归 + 记录 + 手册 + 提交）

入口条件：E5 通过；黑盒与数值抽查全绿。

门内步骤：
1. 全仓 pytest 回归：python -m pytest tests -q——基线 12 failed 零新增（当前基线：test_g0_architecture/test_battle_render_skill×2/test_codex_commands/test_contest/test_e2e_m4_smoke×4/test_emoji_discipline/test_investigate_commands/test_m125_formula_assembly）；逐个核对失败集合与基线完全同集合，多一个 = 回归失败。
2. ruff 新文件干净：ruff check 只检查新区改动/新增文件，零告警（仓库 ruff E501 零豁免纪律）。
3. 编辑器 auto 页断言同步：若新区内容改动 veinborn 模块数（manifest modules 增减）→ 同步 tests/unit/test_editor_registry.py 的 test_auto_pages_veinborn_all_modules 断言（当前断言 veinborn 17 模块 → len(ids)==20，实际模块数 22 但 auto 页只由 list 模块生成，改动时按实际模块数重算并同步注释）；模块数未变则本项跳过但要在记录里写明「模块数未变，页表断言不需动」。
4. 记录.md：
   - 新区开发记录（参照 docs/m125_记录.md 格式：批计划→提交→验收门禁→已知基线）；
   - 如果新区触发了引擎修改，同步登记 docs/veinborn_引擎缺口登记与修复.md（G1/G2/G3 模式）。
5. 玩家手册：docs/玩家指令手册.md 新区可用内容更新（新区指令/功能按「实际可用」标注；手册铁律：标 ✅=veinborn 有数据实机可用，⚠️=框架已实现但 veinborn 未配数据）。
6. 隐私扫描 + git 提交：提交前跑项目隐私扫描（docs 提示词链有隐私扫描先例）；git 提交遵循仓库提交信息规范（scope 如 veinborn 新区），提交信息含新区代号。

出口验收清单：
- [ ] 全仓 pytest 12 failed 零新增（失败集合逐条与基线比对一致）。
- [ ] ruff 对新文件/改动文件零告警。
- [ ] 编辑器 auto 页断言与 veinborn 实际模块数一致（模块数变化才改动；变化前后都跑 test_editor_registry）。
- [ ] 新区记录.md 落盘（含批次/提交/验收/回归基线四节）。
- [ ] 玩家指令手册新区节更新（✅/⚠️ 标注纪律）。
- [ ] 隐私扫描通过，git 提交完成（新区 = 至少 1 commit，内容与 docs 分离亦可拆批）。

典型翻车点：
- 编辑器页表测试断言模块数：veinborn 模块数一动，test_auto_pages_veinborn_all_modules 的 len(ids)==20 断言就红——回归失败集合会多出这一条，必须明确它是「同步断言」不是「实现倒退回」；反之若断言没同步，编辑器 auto 页会静默缺新区新模块页。
- templates 覆盖需 ctx 装配注入（提交前复检一次，E4 查过提交又改过 templates.json 时必复发）；
- 转职不重算属性=定稿：转职后已有属性保留、只换成长曲线（用户拍板设计行为），回归脚本把「转职重算属性」当 bug 报是误报；若新区任务链诱导频繁转职刷成长，要按「已知限制（勿报）」标注，不改引擎。
- utility power=0 零伤害：若新区普通攻击/技能被写成 utility 型吃 0 伤害，QA 会以 P2「被我方工具技 0 伤」复发——内容侧避免，引擎修复只看渲染层；
- 怪物 action 少 _derived 标记：新区怪行动派生链不全时，模拟器打 Boss 到血线但派生大招没触发，测试会误判「Boss 卡死」——先查 _derived 派生标记再查血线。
- 地图列表不泄露未发现图：提交后浏览器/编辑器抽查——新区图（尤其隐藏图）在玩家地图列表可见性，做对是「未发现不可见」。
- 提交把 JSON 改了但 docs/记录 没改（新区别名/数值/图名改了文档没同步，下个新人 E1 勘察时对照表失真）。
