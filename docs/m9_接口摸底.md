## 一、combine 执行器（缺口1）✅ 已实装

**结论：3:1 合成 = recipe.json 配 `kind=combine` 实例，直接复用 `SynthesisEngine.synthesize`，零新引擎。**

实测证据：
- `content/test_demo/recipe.json` 已有真实 combine 实例 `rcp_combine_3to1`（kind=combine, 3 moon_grass → 1 ghost_moss）
- `core/synthesis.py`：
  - `SynthesisEngine.__init__(ctx, prof, settings, qs, mode, ...)`（L269+）
  - `check_eligible(ctx, recipe_id)` → {ok, recipe, recipe_level, job_id, synth_allowed, hint?}
  - `_material_shortfall`（GU-04 原子校验，材料+金币全量差额）
  - `synthesize(ctx, recipe_id, count, *, on_codex)`（L516）——快照-回滚原子、count 批量、熟练经验 source='craft'、on_codex 图鉴点亮回调、message 模板
- `field_meta.py` recipe_fields 已登记 kind ∈ {craft, combine, upgrade}

**M9 用法**：3:1 合成直接配置 recipe.json combine 实例（CMB-02 映射表 `comb_synth_map` 作者登记），铸造 SP-F2 解锁开关控制入口；synth_ratio_3to1=false 时实例禁用（指令侧拦截或隐藏）。

## 二、装备实例快照管线（缺口2）⚠️ 需新写

**结论：ItemInstance 无 slots_state/aug_list/set_tag 字段，锻造节点×items 双源仲裁合并 + 快照入档需要新写（T2/T12 核心）。**

实测证据：
- `data/item.py` ItemInstance(frozen=True)：item_id/name/count/quality/bound/stack_max/slot/stats_bonus/traits/cooldown_until —— **无 slots/aug 字段**
- `core/equipment.py` L47-49（P1-2 登记）：unequip/后装覆盖会丢弃原 EquipmentSlot 的 slot_level/locked/gems，**当前强化/镶嵌未接线为潜伏；M9 锻造强化接线前必须在数据模型层解决（ItemInstance 补强化字段或引擎侧暂存恢复）**
- `core/equipment.py` P1-1（L43-46）：同 item_id 多件实例行并存时「穿戴行身份」精确区分需数据模型改进，登记 M9 强化接线前置项

**M9 处理**：
- 双源仲裁（2c2a AR-1~5）：/锻造 完成时按「items 基础 + 节点改造」合并实例化 → 属性快照入玩家存档

- **注意**：P1-2 提醒「ItemInstance 补强化字段或引擎侧暂存恢复」——M9 锻造产物快照与强化字段（+N）的共存是接线前置，需在批0/批1 数据模型层决策（见 m9 派工单）
