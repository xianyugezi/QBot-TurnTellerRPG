# 全局图标登记表（M5-11）

> 状态：✅ 生效（2026-08-27）｜依据：docs/m5_shared_contract.md §4.1（M5 裁决：不用 emoji）
> 权威性：**本表为全仓渲染输出 emoji/符号的唯一允许集合**，无其他出口。
> 配套门禁：tests/unit/test_emoji_discipline.py（已接入 pytest，L1 unit 层）。

## 一、唯一允许集合

### 1. 功能性标记（全仓唯二允许出现的 emoji 字符）

| 标记 | 码位 | 语义 | 位置约束 |
|---|---|---|---|
| ✅ | U+2705 | 成功 | 仅结果行行首，一行至多一个，其后必须纯文本描述 |
| ❌ | U+274C | 失败 | 仅结果行行首，一行至多一个，其后必须纯文本描述 |

### 2. 排版符号豁免（非 emoji，不计入 emoji 白名单，天然豁免扫描）

| 符号 | 码位 | 说明 |
|---|---|---|
| `|` | U+007C | 竖线分隔 |
| `→` | U+2192 | 箭头 |
| `×` | U+00D7 | 乘号 |
| `/` | U+002F | 斜杠 |
| `「」` | U+300C / U+300D | 引号 |
| `【】` | U+3010 / U+3011 | 方头括号 |

> 上述符号全部落在 emoji 扫描正则范围（U+2600+ / U+1F000+ / VS16 / ZWJ）之外，
> 无需登记白名单即天然通过扫描。

### 3. 明确禁用（示例，非穷举）

🔥 🟢 💥 ⚔️ 🛡️ ✨ ⭐ 🌟 🎉 🎊 💎 🏆 ❤️ 💖 ⚠️ 🚫 📜 🗡️ 🛒 🧪 ⏰ 📅 ➡️ 🔹 🔸 ▸ ⛩️ ☀️ ☁️ 🌧 ⛈ 🌫 💰
……以及其余一切非 ✅❌ 的 emoji 字符（含数据型功能图标一律降级纯文本）。

## 二、数据 icon 字段渲染剥离规则

内容包 schema 的 `icon` 字段（items.json / npc.json / shop.json / weather_pool / marks.json）
**字段保留**（数据层不动），但渲染出口一律经 `qbot_rpg/data/emoji_sanitize.py::strip_icon_emoji`
剥离 emoji 字符；保留 ✅/❌ 功能性标记、排版符号、CJK 汉字与 ASCII 文本符号——
作者可配「剑」「火」「+」等纯文本图标。

- 剥离范围与保留集合与 §一 完全一致（实现见 `emoji_sanitize.py` 的 `_EMOJI_CLASS`）。
- 该函数为全仓统一剥离出口：engine / core / world / storage / content / commands 各层
  渲染 icon 必过此函数（依赖矩阵 §1.4 允许各层依赖 data，避免 engine→core 反向依赖）。

## 四、全仓扫描覆盖点

扫描测试路径：`tests/unit/test_emoji_discipline.py`（M5-10 落地，已接入 pytest 全绿）。
经 `scripts/run_all_tests.py` 的 `LAYER_PATHS["unit"] = ["tests/unit"]` 纳入门禁——
全量回归与 `--only unit` 均执行；`--only m5`（verify_m5，M5-12）接入后仍保留该测试。

| 覆盖点 | 测试 | 说明 |
|---|---|---|
| 渲染字符串 emoji 扫描 | `test_no_emoji_in_render_strings` | ast 解析 `qbot_rpg/` 全仓 `.py` 字符串字面量（跳过 docstring/注释），断言无非白名单 emoji；白名单 `_ALLOWED = {✅, ❌}`，`WHITELIST` 仅登记 emoji_sanitize 字符类定义字符串（检测代码本身，非渲染输出） |
| fixture icon 扫描 | `test_fixtures_no_emoji_icon` | `tests/fixtures/packs/legal` 全量 JSON 无 emoji icon 数据 |
| 登记表-实现一致性 | `test_registry_allowed_markers` | 断言扫描白名单恒等于 `{✅, ❌}`（防白名单意外扩宽） |
| 剥离函数行为 | `test_strip_icon_emoji_registry_contract` | 断言 `strip_icon_emoji` 保留 ✅❌ + 排版符号、剥离禁用 emoji、非字符串容错 |

## 五、变更流程

1. 新符号须先在本表登记（含码位与用途），再投入使用。
2. 新增 emoji 出口 = 修改扫描白名单 = 必须同步本表；`test_registry_allowed_markers`
   断言白名单 == {✅, ❌}，两者必须一致。
3. 排版符号豁免的增删同样须回写本表 §一.2（新豁免符号须确认落在 emoji 扫描范围外，
   否则需调整扫描实现并同步本表）。
