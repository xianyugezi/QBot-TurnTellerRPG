## 一、R-01 触发枚举双源冲突（新裁决 · P1）

- **争议**：特殊行动触发 13 类枚举存在**双源冲突**，对同一字段给出互斥的合法值集合：
  - 源 A（旧枚举）：细化_1e A05（L89）/ R2（L201）/ TC-08（L233）以定稿① L296 旧枚举为权威：`hp_below / phase_below / cooldown_ready / turn_elapsed / after_action / chain_complete / broken / revive / ally_dead / script / tag_trigger / enter_phase / delayed`。
  - 源 B（权威枚举）：细化_1f ②（L63-76）与 实现层规划 L317 采用 **怪物行动AI定稿 §二**（L59-91）权威 13 类：`hp_below / pv_broken / get_up / battle_start / after_action / player_status / player_hp_below / turn_count / phase_changed / zone_changed / ally_dead / combo_broken / script`。
  - 两表**交集仅 4 类**（hp_below / after_action / ally_dead / script）；按 1e R2 硬拦，AI 定稿的 `player_status / turn_count / phase_changed / zone_changed / combo_broken` 会被拒绝入库（覆盖审计_C M-01，L89-92）。
- **裁决**：**以 AI 定稿 §二 权威枚举为唯一合法值集合**——定稿① L296 自指「枚举以怪物行动AI定稿为准」，权威层级明确无歧义。
  - 细化_1e A05 / R2 / R12 / TC-08 全部改引权威枚举；
  - 旧枚举降级为**兼容别名**（校验器接受 + 黄提示迁移，不拦截），与 1e S4（L15）既有别名归一逻辑合并为**一张归一表**（broken↔pv_broken、revive↔get_up、enter_phase↔battle_start、phase_below↔phase_changed 等按 S4 既有别名语义收敛，`x_` 前缀扩展保留）；
  - 校验器红拦基线同步为权威枚举（1e R2），别名归一不拦截。
- **需改既有文档**：**细化_1e**（A05 L89 / R2 L201 / R12 / TC-08 L233 更新）✅必改；细化_1f（② L63-76 引用索引同步确认）；覆盖审计_C M-01（关闭回执：结论 = 已按建议修订）。
- **影响文档**：细化_1e、细化_1f、覆盖审计_C、实现层规划 L317（确认已对齐，无需改）。

## 二、R-02 GM 日志默认条数冲突（新裁决）

- **争议**：同一 `/日志` GM 系统日志的默认条数两稿不一致：
  - 细化_3f §1.7 D-03（L51）与 R-06（L159）：「默认展示最近 **50** 条（可配），分页 20 条/页」；
  - 细化_5b GM 指令表 G8（L96）：「可选 `条数=N` 键值，**默认 20**，上限 50【细化】」。
- **裁决**：**默认展示条数统一为 20**（一次展示一页，与「分页 20 条/页」语义自洽；5b 为指令层契约，更贴近玩家可见行为），**保留窗口 50 条**（3f 环形窗口/资源上限语义）；全部经配置项收敛：
  - `sys_log.default_show = 20`（每次展示条数，`/日志 条数=N` 可覆盖，上限 50）；
  - `sys_log.page_size = 20`；`sys_log.max_entries = 50`（环形保留窗口，超出覆盖最旧）。
- **需改既有文档**：**细化_3f**（§1.7 L159 默认值 50 → 20，补配置键引用）✅；**细化_5b**（G8 L96 补配置键与「上限=保留窗口 50」口径）✅。
- **影响文档**：细化_3f、细化_5b。

## 三、R-03 魔法穿透语义（登记引用 · ADR-6a-01）

- **争议**：覆盖审计_B P1 #4——细化_1b 将 pierce 三修正器合并为单一「无视目标防御 X%」（1b §7.1 L77-80：`pierce：无 target · value=无视防御百分比`），**未承接「无视对方一定百分比精神」**（效果定稿 [效 L121]）。
- **裁决（既有，登记引用）**：采 **细化_6a §5 ADR-6a-01**（L228-274）：
  - 修正器参数化：`pierce := { target: "def" | "spr", pct: 0-100 }`；缺省 `target = "def"`（兼容 [效 L325] 既有登记值）；
  - `target=def` = 物理穿透（物理通道、防御系数/有效体质段）；`target=spr` = 魔法穿透（元素通道、元素减伤/精神抵抗段）；
  - 穿透/减抗/减防三语义严格区分（是否写目标状态），禁止用 pierce 负数模拟减抗（6a V-12 黄提示对位）；
  - 魔法穿透 × 魔攻击无视格挡 = 不同判定段、独立维度、可叠加（6a §5.4）。
- **需改既有文档**：**细化_1b**（§7.1 三模板参数结构 L77-80 对齐 `{target, pct}` 并补 `magic_pierce` 别名条目，或直接以参数化 pierce 收敛——按 ADR 选参数化单键）✅；6a 已含 V-12 校验语义，无需改。
- **影响文档**：细化_1b、细化_6a（权威落点）、覆盖审计_B（#4 关闭回执，随 1b 修订后）。

## 四、R-04 强化曲线 +11/+12 覆盖率（新裁决 · 关闭「待人工确认」）

- **争议**：强化定稿内部一致性缺口——默认消耗/成功率曲线与石档位**止于 +10**（定稿 L80-81 默认率、L179-181 `high=[7,8,9,10]`），但**传说品质上限为 +12**（L114/L154），而校验器要求曲线覆盖 0→最大上限（V2，L199）且档位区间连续（V4，L201）——**默认配置自身不满足校验器**（2c3a §7-S1/S2，L328-335；覆盖审计_F L129 备查注记，「待人工确认」）。
- **裁决**：采纳 2c3a §7-S1/S2 建议并**定案默认值**（消除「落地前需人工确认」）：
  - 默认 `success_curve` 补 **+11：20%、+12：15%**（延续成功率递减趋势；L105 表注落定）；
  - 默认 `stone_tiers.high` 延至 **[7,8,9,10,11,12]**（不新增 ultra 档，保持简单优先）；
  - 传说上限保持 **+12**（品质四档 `max_by_rarity` 不变）；
  - 内容包若配置更高上限，**必须自配齐档位曲线**（V2 校验器硬拦 + TC-12 拒绝加载并提示补档）。
- **需改既有文档**：**细化_2c3a**（§1.3 表注 L67、§2.1 L105 注记、§7-S1/S2 结论落定、TC-12 同步）✅；覆盖审计_F（L129 备查注记改为「已由细化_0 R-04 裁决」）回执。
- **影响文档**：细化_2c3a、覆盖审计_F、2c3b（强化流程契约引用曲线时以 R-04 为准）。

## 五、R-05 副本地图 BOSS 不恢复（登记引用 · 1g4 J-01）

- **争议**：框架 3.15「BOSS 脱战回血」（L312-317）字面未排除副本；副本换区=离开当前区域，若照搬回血会击穿副本追击续战机制。
- **裁决（既有，登记引用）**：采 **细化_1g4 J-01**（L269）：**副本内 BOSS 不恢复（残血保留）**——3.15 的「脱离战斗」特指世界层战斗三事件（解除锁定/离开地图/战斗失败）；副本 BOSS 的换区/中断/死亡由副本定稿 §2.2 接管：换区=阶段切换残血保留（L25/L105-106）、BOSS 状态 keep/reset 可配（L123-126）、副本内 HP/MP 不恢复（L249）。裁决依据：副本定稿后发布且明确声明换区=阶段切换，权威层级更高。
- **需改既有文档**：**无**（1g4 J-01 已含完整裁决与 TC-05~07）；建议 2a3（副本两型流程）/2a1c（地图副本衔接）在 BOSS 战斗边界处**加交叉引用** J-01 防误读。
- **影响文档**：细化_1g4（权威落点）、细化_2a3、细化_2a1c。

## 八、R-08 能量条默认关（新裁决）

- **争议**：炼金定稿 §2.4 调合能量条（L91-98）要求「上限随级/30 分钟回 1/安全区加速」，但**未明示默认开关**；覆盖审计_F J-08（L144）已确认覆盖落点，默认口径待定案。
- **裁决**：**能量条默认关**：`settings alchemy.energy_enabled = false`（可配）——依据实现层规划 L286「能量条（可选默认关）」/ L560「能量条（默认关）」与设计总纲 L56「所有默认关口径统一（默认不干预，作者显式开启）」。关闭时：/炼金 /深度炼金 /即时调合 不扣能量、不显示能量上限、无「能量不足」模板（不干预炼金节奏）；`mode: "simple"` 本就无炼金层/能量条（L410）。
- **需改既有文档**：**无**——细化_2c4f ENG-01（L81）已落点 `energy_enabled: false`，本决议正式确认；可选核对：5a 编辑器能量条开关项登记（关联覆盖审计_F F-23 生活系统卡片开关，跨系统页面级登记）。
- **影响文档**：细化_2c4f（ENG-01 为权威落点）、细化_5a（编辑器开关登记核对）。
