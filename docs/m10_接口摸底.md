## 一、farming.harvest_sec（缺口 1）

**文件**：`qbot_rpg/core/alchemy_harvest.py`（HarvestEngine，第 2 层种植引擎，915 行）

- 构造器 `__init__(settings=None, quality=None)` 配置注入单源；`_harvest_sec(seed_info=None)` 读 `settings.alchemy.farming.harvest_sec`（默认 14400=4h），seed_info 逐种子覆盖优先。
- 种植落盘 `harvest_at = now_ts + harvest_sec`（F-21 数据落点）；到期判定 = `now >= harvest_at`（纯时间戳懒判，无实时计时器）。
- **M10 用法**：钓鱼等待同构——抛竿时算 `cast_at = now + wait_sec`（wait_sec 从 `settings.fishing.wait_sec {min,max}` 区间取，0=即收）；到期判定 `now >= cast_at`。**不构造 HarvestEngine**（其字段绑定种植语义 farm_plots/seed_info/quality）。等待状态落 player.persistent_state（跨会话懒计算，无实时计时器）。

## 二、monster_intent（缺口 2）

**文件**：`qbot_rpg/core/monster_intent.py`（build_intent 59 行）+ `qbot_rpg/core/monster_ai.py`（MonsterAI.intent_for 256 行委托）

- `build_intent(action_id, action_def, ai, codex)`——入参绑定战斗三件套（action_def 行动定义 / ai 战斗 ai_state / codex 图鉴 reveal 条件），返回 {level, category, action_id, name_revealed, chain_preview, progress}。
- **M10 鱼讯三类（微动/拉扯/猛烈）不复用其实现**（钓鱼无 action/ai_state/codex 形态），复用「意图预告语义」：鱼讯真实预告本局出鱼档位（normal→微动 / rare→拉扯 / gold→猛烈，2c1b §3.1 已写死映射）。实现为轻量纯函数 `fish_intent_of(rarity, king_hit) -> {kind, golden}`，king_hit 时覆盖为 violent+golden。

## 三、codex type=fish（缺口 3）

**文件**：`qbot_rpg/core/codex.py`（331 行）

- `CATEGORIES = {monster:(enemy,), weapon:(equipment,), item:(item,), alchemy:(recipe,item)}`（42-50 行）→ 加 `"fish": ("fish",)`。
- `CATEGORY_ORDER = ("monster","weapon","item","alchemy")`（53 行）→ 加 `"fish"`（末尾，M8 收口裁决炼金在末尾）。
- `_CATEGORY_LABELS`（55-60 行）→ 加 `"fish": "鱼图鉴"`。
- **mark_seen 覆盖陷阱**：`mark_seen` 写 `cat[rid] = {"name", "seen", "killed", "lore_unlocked"}` 整条目覆盖（209-217 行）——鱼册扩展字段（caught_count/best_crown 等）会被冲掉。**必须建专用入册函数 `fish_codex_update(ctx, species_id, catch)`**：读 codex_state["fish"][id] → 更新七键（2c1a G-01~G-07）+ 首获时同步 mark_seen（点亮+日志+事件，first_seen 判定）。未捕获无条目（2c1a §4.2）。
- **图鉴展示**：codex_view 返回通用条目（ref_id/name/seen/killed/lore_unlocked，294-331 行）——鱼册展示需**特判**（M8 alchemy 分册先例：codex_commands 对 alchemy 特判调 render_alchemy_codex）。M10 鱼册展示在 codex_commands 对 fish 特判调 render_fish_codex（冠级标注，不写判定公式）。
- **鱼综述**：codex 鱼册聚合段追加 `king_victory_count`（2c1c E-01），供图鉴补全判定（R-07）读取。

## 四、reward（缺口 4）

**文件**：`qbot_rpg/core/reward.py`（dispatch_reward 346 行）

- `dispatch_reward(entries, ctx)`：entries 结构化数组/单条目/内联键值串；ctx 契约 = currencies / settings（货币键空间）/ items|resolve_item（物品存在性）/ add_item（入包 hook）/ tx_id + ledger（幂等）/ rep_board。
- 返回 {ok, granted, skipped, idempotent}；单条目失败 skip 不中断整批；item_add_failed 不封口幂等。
- **M10 用法**：出鱼结算 = 一条 dispatch_reward（金币/物品/经验 + 熟练经验走 prof 桶或单独 grant）+ fish_codex_update（图鉴点亮）。幂等：抛竿/收杆原子指令在 processing 的 repo.tx 内（F3 单指令单事务，内部不再自开 repo.tx）。

## 五、鱼王 BOSS 战（缺口 5）

- **数据接线**：fishing.json `king[]`（2c1a K-01~K-07：id/species_id/enemy_id/hint/window_daily/chance/enabled）；profession.json fishing 段 `king_event {enabled, window_daily=2, chance=0.3}`（T01 骨架）；行级覆写 > 段级（2c1a §3.1）。
- **触发链路**：出鱼轮命中某鱼种 king 行 ∧ chance 命中 ∧ 当日未满 window_daily → 鱼讯升级「猛烈+金闪」→ 进 enemies BOSS 战（TR-10，复用怪物/BOSS 引擎，M2 battle / M3 BossFlow 入口）。讨伐胜利计 1 次 → 参与图鉴补全（钓鱼王称号条件）。
- **窗口计数**：`king_trigger_count`（当日触发尝试，门控用，无论胜负）/ `king_victory_count`（胜利计，补全用）——2c1c R-02。跨日重置（dayroll 懒计算同源）。落 player.persistent_state。
- 接线细节：批4 路4B 派工前再查 battle/BOSS 引擎入口（参考 M9 锻造与战斗联动 + M2 C1 battle 集成）。

## 九、其他坑（M9 实测教训速记）

- **F3 嵌套事务**：抛竿/收杆原子指令在 processing 的 repo.tx 内运行，内部不得再自开 repo.tx。
- **Def→dict 表注入**：ctx["fishing"] 走 modules_raw 必须转 raw dict + resolve 单参包装；fishing 顶层 obj 不能走 _table_from_registry。
- **qid 键注入**：ctx["qid"] 必须注入（仅 qq_id 时 _qid_of 读不到 → 会话/存档主键错）——make_context 已注入（L922），新指令壳必须消费 ctx["qid"] 勿再造键。
- **单测掩盖部署 bug**：直测引擎不暴露装配层问题——每批须 run_command + 真实 DB 全链路实测（verify_m10 脚本）。
- **用户拍板不可擅改**：冠级纯收藏（不碰数值）、收杆无小游戏、判定顺序写死、说明不教攻略——都是定稿铁律。
- **随机可复现**：冠级/收杆概率必须种子化（种子 42/2026 可复现），实现不得用裸 random（无固定种子）——rng 注入（ctx["rng"] 已装配，rng_factory 确定性源）。
- **来源纯度**：冠级体系是用户原创，借他版机制（鱼讯=怪猎意图预告）需显式标注来源。
- **emoji 纪律**：仅 ✅/❌ 功能性标记 + 排版符号 | → × / 「」【】（M5 拍板升级）；列表类 5 条/页。
- **M43 探针**：零定时器/确定性/快照完整性——钓鱼等待用时间戳懒判（零实时计时器），docstring 勿写字面「time.sleep」。测试文件头注同样避开。
