## 二、问题清单

### P0（0 项）

未发现直接捏造定稿内容、引用定稿不存在章节或原则性矛盾的问题。所有被引用的定稿段落均真实存在且内容大体一致。

### P1（8 项）— 重要瑕疵：结构偏离/引文不存在/默认值无依据且未标注补白

- **P1-1（§7.3 modules 包装对象与定稿文件结构冲突，未标注补白）**：细化将 `alchemy`/`fishing` 的 mode 三态包进 settings.json 的新顶层键 `modules`（§7.3「modules: {alchemy, fishing}」）。但定稿【框架】L374 明确 alchemy 为 settings.json 顶层段（平铺）；L400 明确 fishing 段（含 mode 三态）属 **profession.json**；实现层规划 L182 亦为「settings.json 各模块段 mode 字段（炼金 alchemy.mode、钓鱼 fishing.mode）」内嵌式。细化把 fishing.mode 从 profession.json 移入 settings.json、并把 alchemy 从顶层移入包装键——文件归属与定稿 4.1 树冲突；且与自身 D-02「顶层键平铺、不引入包装层」精神自洽性存疑（D-02 只豁免了六大分段）。此结构变更未写入 §0.3 ADR、未标【补白】。

- **P1-2（§1.1 / 0.3 D-01 引用不存在的依据「3e §1.2『空 modules 合法』」）**：D-01（settings 常驻加载）论证依赖引文「3e §1.2『空 modules 合法』」，但细化_3e 全文中无此表述；3e §1.2 反而规定 modules 必填字段缺失→红拦。同时 D-01 的常驻加载语义与定稿【框架】L443「不声明 = 对应系统不加载（向后兼容）」、规划_路3 A5「不声明=系统不加载」直接相悖——虽已按 ADR 纪律显式标注并附理由（合规），但**引用的支撑条款不存在**。

- **P1-3（§4.2 post_battle_recovery 默认值 0.2/0.1 无依据、未标注补白）**：定稿 L298-300 仅给「战后治疗比例/安全区停留回复」两个可配项，**未给任何数值**；细化擅自定 heal_ratio=0.2、safe_zone_heal=0.1 并作为 schema 默认值，未标【补白】。同时「ratio>0.5→黄提示」阈值亦无依据。

- **P1-4（§2.2 death_penalty 默认值无依据、未标注补白）**：定稿 L282-292 未给比率数值；细化定 currency_loss.ratio=0.05、exp_loss.ratio=0.1、item_loss.count=1 并作默认值，未标【补白】。（weak_time=60 有 L285「默认 1 分钟」依据 ✅。）

- **P1-5（§2.1 level_cap.value 默认 1 无依据、未标注补白）**：定稿 L296 仅举例「如 45 级」，未定缺省；细化断言「默认 1（不配=仅 1 级，作者必配）」，未标【补白】。（「经验不再增长/经验转货币可选」有依据 ✅。）

- **P1-6（§7.1/§8 leaderboard 大量补白字段未标注）**：定稿 L1100 仅定「榜单类型（三枚举）+ 刷新秒数（默认 86400）」。细化新增 top_n=10（1~50 校验阈值）、types 缺省值、currency_id 缺省取第一货币、refresh_sec≥60 下限、stale 快照与并发重建语义——均为实现层决定，未逐项标【补白】。（默认关有开发规则 L502「定时推送（公告/排行榜）默认关闭」支撑 ✅。）

- **P1-7（§10.2-B GM/机主指令放行，扩张定稿「任何指令」语义未标注补白）**：定稿 L1194 原文「编辑期间玩家发送**任何指令** → 返回『作者更新中，请稍后再试...』」；细化 §10.2-B 增加「GM/机主指令放行（可继续 /重载 /调试）」——属于对定稿语句的重大语义豁免，ADR D-06 亦未提及 GM 放行，未标【补白】。若实现按细化执行，与定稿「任何指令」字面冲突。

- **P1-8（§6.2/§9.1 player_join 触发点新增「/注册 成功」未标注补白）**：定稿 L1126 仅「新人入群自动推送欢迎语」；细化把 player_join 触发点扩为「新玩家完成注册（/注册 成功 @ 所在群）/ 新人入群」双触发，其中注册完成触发为定稿外新增，未标【补白】。
