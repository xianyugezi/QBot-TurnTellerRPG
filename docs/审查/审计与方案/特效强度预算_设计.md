## 〇、一页结论

1. **概念上已绕开，工程上尚未绕开（重要澄清）。** `PANEL_AXIS_KEYS = ("atk","dfn","hp")`
   （`qbot_rpg/core/panel_budget.py:52`）只覆盖三轴，`scale_panel_bonus`（`:125-149`）也只缩放这三轴；
   但**目前全仓内容包对特效键的使用量为 0**（`immune_dmg / absorb_hp / heal_amp_pct / cooldown_reduction_pct`
   在 `content/` 与 `qbot_rpg/content/` 下 grep 无命中）→ **批45 的 60% 校准此刻并没有被实际绕开**。
   风险是**潜伏的**：批50/51 接线 + 内容开始使用特效词条之后，立刻成为现实。
2. **量化（典型 build = 减伤 25% + 吸疗 15% + 冷却 ×0.8）**：
   - 输出等效 **+6.8%**（冷却 ×0.8，轮转模型 C=4 / 普攻=技能 40%）；
   - 生存等效 **×1.33–1.48**（减伤 25% 单用恰为 ×1.333；叠加吸血 15% 后中/高怪 ×1.43–1.48）；
   - 综合 **+19%～+26%（几何口径）／+42%～+58%（乘积口径）**。
3. **折算进 7:18:5 预算池（30 份）**→ 特效等效 **+5.8～+17.4 份** →
   **真实装备占比 38%～50%，偏离 60% 目标 10～22 个百分点**（仅算输出侧则只掉到 56%）。
4. **斩回偏差（batch45 确定性口径 · 种子 20260919 · 中值档）**：
   普通 7→7（**0**）、精英 20→19（**−1**）、Boss 24→22（**−2**）。
   翻转阈值（面板输出等效）：**普通 +9.74%／精英 +2.82%／Boss +0.87%** → **Boss 最敏感（约 1% 就掉一回合）**。
5. **实机口径更危险**：生存轴把「防御回合」换成「攻击回合」（ρ 机制），
   Boss 实机回合 ≈48 → **≈39–41**，**贴死 40 下沿**→ 越档风险成立；且这部分压缩**几乎全部来自生存轴**，
   冷却只贡献 −1.5 回合。
6. **口径分裂（必须先说清）**：batch45 工具口径（单发普攻 7/20/24）**≠** 定稿档位口径（3-8／10-15／40-60）。
   工具是**相对仪器**，档位是**绝对红线**；终校批必须两把尺子都跑（§4）。
7. **推荐**：**方案 B（另立特效强度上限，主）+ 方案 A1（`equip_share` 度量式，只报不改）+ 方案 C（`monster_scaling` 备用杠杆，缺省 1.0）**。
   默认 `effect_budget.cap_equiv_pct = 8`（≈2.4 份）、`tier_mult = 12%/8%/5%`（普通/精英/Boss）、`gate_mode = "warn"`。
   该缺省把确定性口径最坏偏移锁在**全档 ≤±1 回合**；但它同时会把 §1 的典型 build（综合 19%–26%）判超限
   ——「特效是点缀还是支柱」由 §5-2 拍板。
8. **缺省零变化**：`effect_budget` 缺省 `enabled=false`；`monster_scaling` 新键缺省 1.0；`PANEL_AXIS_KEYS` 冻结不动。
9. **最大待裁决**：特效强度**该不该计入「60%」**——这决定 60% 是**面板口径**还是**总战力口径**（§5-1）。

### 1.2 输出侧等效：冷却 ×0.8

**轮转模型（显式、可手算）**：技能伤害 `D`，每 `C` 回合放一次；其余回合普攻伤害 `k·D`。
则每回合期望伤害

```
E = D · [1 + (C−1)·k] / C
冷却 ×0.8（使用间隔 C → 0.8C）后的增益：
    Δ = [1 + (0.8C − 1)·k] / [0.8 · (1 + (C−1)·k)] − 1
```

| C \ k | 0.2 | 0.4 | 0.5 | 0.6 | 0.8 |
|---|---|---|---|---|---|
| 3 | +14.29% | +8.33% | +6.25% | +4.55% | +1.92% |
| 4 | +12.50% | **+6.82%** | +5.00% | +3.57% | +1.47% |
| 5 | +11.11% | +5.77% | +4.17% | +2.94% | +1.19% |
| 6 | +10.00% | +5.00% | +3.57% | +2.50% | +1.00% |

- **典型取值：C=4、k=0.4 → +6.82%**（技能 4 回合一轮、普攻约为技能伤害的 40%）。
- **区间**：保守 +2.9%～+5.0%（技能占比低）／典型 **+6.8%**／激进 +11%～+14%（技能占主导）／
  **理论上限 +25%**（纯冷却门控 `k=0`，即技能完全替代 0 伤害填充）。
- 吸血、减伤、受疗**不改变输出** → 不进斩回（但见 §1.6，它们**间接**压缩实机回合）。
- 结论：输出侧等效 = **×1.068**（区间 ×1.03～×1.25）。

### 1.3 生存侧等效：减伤 25% + 吸疗 15%

**(a) 减伤 25%（精确）**

```
有效血量 EHP 倍率 = 1 / (1 − 0.25) = 1.3333        （+33.3%）
```
该轴与「HP 面板轴 +33.3%」在生存上是**严格等效**的。

**(b) 吸血 15%（净损血率模型）**

每回合回血 `0.15 × D`（D = 我对该怪的每回合伤害），每回合挨打
`inc = max(1, floor(怪atk × defense_factor(玩家dfn)))`（同一 `core.damage.defense_factor`，
与工具对怪物的算法**对称同源**；乱数 1.0、不格挡 → 乐观假设，见下方注）。

存活回合 = `HP / (inc − 0.15·D)`；**减伤 25% 后** `inc' = 0.75·inc`。

| 怪物 | 怪HP | 怪atk | inc | 我每回 D | 吸血 15%/回 | 净损血 | 基线存活回 | 减伤后 inc' | 减伤后净损 | 存活回 | 生存倍率 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 黑脉熊（普通） | 3786 | 1659 | 170 | 575 | 86 | 84 | 9.62 | 128 | 42 | 19.24 | **×2.00** |
| 黑晶巨魔（精英） | 6428 | 2168 | 222 | 329 | 49 | 173 | 4.67 | 166 | 117 | 6.91 | **×1.48** |
| 群山嚎主（Boss） | 7100 | 2602 | 267 | 306 | 46 | 221 | 3.66 | 200 | 154 | 5.25 | **×1.43** |

- **减伤单用 = ×1.3333（精确，可信度最高）。**
- **叠加吸血后 ×1.43–1.48**（中/高怪）；普通怪的 ×2.00 是**上限**，因吸血受 `overheal`（过量治疗）封顶约束，
  实际会被削掉一截，**不采信**。
- 取区间 **生存等效 ×1.33–1.48**。
- **注（口径分歧，登记 §5-6）**：若「吸疗 15%」读作**受疗 +15%**（X17），则它只放大「治疗来源那部分」的回复量，
  等效生存约 ×1.05–1.20（取决于治疗在生存中的占比），比吸血弱一档。本文主口径按吸血。

### 1.4 综合等效与「真实装备占比」

两种聚合口径（都显式，取哪个是玩法取向）：

| 口径 | 算式 | 结果 |
|---|---|---|
| 仅输出侧 | ×1.068 | **+6.8%** |
| 几何（√输出×生存） | √(1.068×1.333) ～ √(1.068×1.48) | **+19.3% ～ +25.7%** |
| 乘积（输出×生存） | 1.068×1.333 ～ 1.068×1.48 | **+42.4% ～ +58.1%** |

把综合倍率折回 7:18:5 的预算池（面板总功率 = 30 份，`18/(7+18+5)=60%`）：

```
特效等效份 u = (综合倍率 − 1) × 30
真实装备占比 = 18 / (30 + u)
```

| 口径 | 综合倍率 | 特效等效份 u | **真实装备占比** | 相对 60% 的偏差 |
|---|---|---|---|---|
| 仅输出侧 | ×1.068 | +2.04 | **56.2%** | −3.8pp |
| 几何 | ×1.193～×1.257 | +5.8～+7.7 | **47.7%～50.3%** | −9.7～−12.3pp |
| 乘积 | ×1.424～×1.581 | +12.7～+17.4 | **37.9%～42.2%** | −17.8～−22.1pp |

> **一句话**：装备占比 60% 是**面板口径**；把特效轴算进真实战力后，同一个 build 的
> **真实装备占比只有 38%～56%**，偏离校准目标 **4～22 个百分点**。

### 1.6 实机口径的额外放大：防御回合 → 攻击回合的转换

斩回口径只看到输出侧 +6.8%；但**承伤/治疗轴真正压缩的是实机回合**，机制是：

```
实机回合 R = 攻击回合 T / ρ           ρ = 攻击回合占比（其余 = 防御/换循环/嗑药/躲机制）
```

基线 Boss：`T = 24`、`ρ = 0.5` → `R = 48`，**正好落在定稿 40–60 档内**（与 `战斗数值层设计定稿.md:141/147` 自洽）。
加入典型 build 后：

- `T = 24 / 1.068 = 22.5`（冷却贡献）
- 生存 ×1.33–1.48 → 防御回合需求 ∝ 1/生存 → 防御回合 `24/1.33 = 18.0` ～ `24/1.48 = 16.2`（基线防御回合 = 24，因 ρ=0.5）
- `R = 22.5 + 18.0 = 40.5` ～ `22.5 + 16.2 = 38.7`

→ **Boss 实机回合 ≈48 → ≈39–41，贴死 40 下沿（越档风险成立）**。
**关键结论**：这个压缩里冷却只贡献 −1.5 回合，**其余全部来自减伤/吸血**。
即——「特效绕开 60% 校准」的主要危害**不是面板 DPS，而是把防御回合转换成攻击回合**。
这是一条只能靠实机口径发现的风险，也是 §4 检查清单必须两把尺子都跑的原因。

> 假设声明：ρ=0.5 是**从档位反推的标定值**（24 × 2 = 48 ∈ 40–60），不是实测值；
> 防御回合 ∝ 1/生存 是**线性假设**。两者都需在批53 用实机整场战斗校准（§5-3）。

|---|---|---|
| 定义 | 单发普攻、无技能、不暴击、乱数 1.0 | 实机整场回合（技能 250–400% 倍率 + 防御/嗑药/阶段机制） |
| 普通 | 7 | 3–8 |

## 二、预算方案（候选）

### 2.0 三方案的共同约束

1. **`PANEL_AXIS_KEYS` 冻结**：特效键**永不**加入（`panel_budget.py:52`），
   因此 `scale_panel_bonus`（`:125-149`）永不缩放特效轴 → C-02（倍率误乘特效键）风险 = 0。
2. **缺省零变化**：未配置新段/新键 → 与本方案引入前逐字段一致（F-1）。
3. **可回滚形状**沿用批45：读时参数化，改回缺省值即回滚（`panel_budget.py:26`）。
4. **不触碰暴击/命中/格挡参数**（F-4）。
5. **必须可被 `scripts/batch45_measure.py` 度量**——不可验证的方案不采纳。

### 2.1 方案 A · 特效强度折算进 `equip_share`

#### A1 · 度量式（report-only）

- **机制形状**：新增「特效等效份」`u_eff`，与 `equip_share` **并列**计算：
  `effective_equip_share = 18 / (7 + 18 + 5 + u_eff)`。只读、只报，**不改任何战斗数值**。
- **参数**：`effect_budget.report_effective_share = true`（§3.2 缺省）。
  注意：整段 `effect_budget` **缺省不存在** → 不配置即不计算、零行为；只有启用该段才走 A1。
- **对斩回影响**：**零**（纯观测）。典型 build 下它把 §1.4 的 38%–56% 变成**可见数字**。
- **优点**：零风险、零战斗改动、可立即落地；让「60% 是不是真的 60%」永远可查（对账工具）。
- **代价**：单独使用**不能阻止**绕开，只是把问题登记出来。
- **适用条件**：所有内容包常驻；作为方案 B 的**度量后端**。

#### A2 · 预算池式（特效从装备预算里扣）

- **机制形状**：总预算恒为 30 份，特效吃掉装备那份：
  `equip_stat_mult_eff = 2.25 × (1 − u_eff / 30)`；`equip_share` 因此恒 = 60%（总战力口径）。
- **参数**：`effect_budget.mode = "report"`（缺省，=A1）| `"pool"`；
  `pool_scope = "output"`（缺省，**推荐**）| `"combined"`（折算综合等效，实测每档都过度补偿，不建议）。
- **对斩回影响（实测推演，中值档，用同一 `defense_factor` 口径）**：

  | 折算的 `u_eff` | `equip_stat_mult_eff` | 中值 atk | 普通 | 精英 | Boss |
  |---|---|---|---|---|---|
  | 0（基线） | 2.250 | 1582 | 7 | 20 | 24 |
  | 仅输出 u=2.04 | 2.097 | 1507 | 7 | 21 | 25 |
  | 几何综合 u=5.8–7.7 | 1.815–1.673 | 1370–1301 | 8–9 | 23–24 | 27–29 |
  | 乘积综合 u=12.6–17.4 | 1.305–0.945 | 1122–947 | 10–12 | 28–33 | 33–39 |

- **优点**：单一口径（"60% = 总战力 60%"）成立；数值上闭环；不需要 cap 表。
- **代价（三条，都很硬）**：
  1. **等价映射不唯一**：25% 减伤 ≈ +33% EHP，但"33% 面板"在几何/乘积口径下差 2 倍（§1.4）→ 扣多扣少没有客观答案。
  2. **过度补偿**：上表**每一行都冲过了头**（Boss +1～+15 回合）。根因 = 特效的力量多在**生存侧**，
     而扣减全落在**输出侧面板**上 → 生存等效被当成输出等效扣掉，把一个平衡 build 打成残废。
  3. **动摇了 60% 本身**：`equip_stat_mult` 从常数变成随内容变化的函数，与批45「白值/buff 冻结、只动倍率」口径打架。
- **适用条件**：**仅当用户明确表示"60% 指总战力占比"**时才成立；且需先把 `pool_scope="output"`（只扣输出等效）作为默认。

### 2.2 方案 B · 另立「特效强度上限」（独立于面板三轴）

- **机制形状（四件套）**：
  1. **特效等效权表** `EFFECT_AXIS_WEIGHTS`：轴 → `{output: %, survival: %}`，
     每条轴给一个**校准点 + 线性外推**（是坐标表，不是加法定律）。
  2. **读时聚合器** `effect_equiv(build)`：把该 build **实际生效**的特效轴按权表求和 →
     `equiv_output_pct` / `equiv_survival_pct`，再按 `aggregate`（`geometric` 缺省 / `product`）合成 `equiv_pct`。
  3. **按档位给总量上限**：`cap = cap_equiv_pct × tier_mult[tier]`。
  4. **gate**：**条目级**校验（每件/每套声明的特效等效 ≤ 条目配额，属内容校验）
     + **运行时**对玩家实际生效总量提示（`warn` / `red`，属叠加超限）。
  5. **每轴另有上下钳**：`settings.effect_axes`（`特效整理设计_3` §3.2 已给出缺省钳制表）。
- **缺省权表（可配；校准点 = 本文实测点）**：

  | 轴 | 校准点 | 输出等效 | 生存等效 | 依据 |
  |---|---|---|---|---|
  | X27 冷却 `cooldown_reduction_pct` | −20（×0.8） | **+6.8%**（区间 +2.9～+25%） | — | §1.2 轮转模型 C=4/k=0.4 |
  | X02 承伤 `dmg_taken_pct` | −25 | — | **+33.3%** | §1.3(a) 精确 `1/(1−0.25)` |
  | X12 吸血 `absorb_hp` | 15 | — | **+43%～+48%（中/高怪）** | §1.3(b)，overheal 封顶后取下沿 +43% |
  | X17 受疗 `healing_received_pct` | +15 | — | +5%～+20%（治疗占比相关） | §1.3 注 |
  | X01 造成 `dmg_dealt_pct` | +10 | **+10%** | — | 线性（终伤乘区） |
  | X16 施疗 / X03 会心倍率 / X18 定值修疗 / … | — | 由终校批补 | 由终校批补 | **未登记 → `unknown_axis` 行为** |

  外推规则固定为：`等效% = 轴值 / 校准点 × 校准等效%`（线性、单向可负）。

- **参数默认（缺省全部不生效）**：
  `cap_equiv_pct = 8.0`、`tier_mult = {normal: 1.5, elite: 1.0, boss: 0.625}` → 上限 **12% / 8% / 5%**、
  `aggregate = "geometric"`、`gate_mode = "warn"`、`unknown_axis = "warn"`。
- **对斩回影响推演**（把 §1.5 的精确翻转阈值当尺子）：

  | 档 | cap（综合等效） | 输出等效上界 | 该 cap 下确定性口径最坏偏移 | 守住 ±1？ |
  |---|---|---|---|---|
  | 普通 | 12% | ≤12% | 熊 7→6（−2 需 +31.7%） | ✓（仅 −1，且仍在 3–8 档内） |
  | 精英 | 8% | ≤8% | 巨魔 20→19（−2 需 +8.54%，8% 够不到） | ✓ |
  | Boss | 5% | ≤5% | 群山嚎主 24→23（−2 需 +5.46%，5% 够不到） | ✓ |

  → **8% 总 cap + Boss 收紧到 5%**，把确定性口径的最坏偏差锁死在 **全档 ≤ ±1 回合**。
  → **代价**：§1 的典型 build（综合 19%–26%）会被这条 cap **直接判超限**——这正是 §5-2 要用户拍的取向：
    若"减伤 25% + 吸血 15% + 冷却 ×0.8"应被视为**正常**毕业 build，则 cap 必须 ≥12%（几何）或 ≥20%（乘积），
    8% 只适用于"特效是点缀"的取向。
- **优点**：
  1. **完全不碰战斗数学**（纯 gate + 观测）→ 真·缺省零变化、零回归面；
  2. 与 `PANEL_AXIS_KEYS` 正交，不与 `equip_stat_mult` 打架（C-02 风险 = 0）；
  3. 分级（普通宽 / Boss 紧）与"通勤快刷 vs 高难博弈"的档位设计同向；
  4. 每轴钳制表（§3.2）已设计好，直接复用。
- **代价**：
  1. **权表要维护**：每新增一条轴都要补等效系数；权表本身是拍的，需终校批验。
  2. **未知轴默认行为要选**：`warn`（可能漏网）vs `red`（可能误杀旧内容）→ 建议 `warn` + 必补。
  3. gate 是**上限**不是自动平衡：不超限的 build 仍能把真实占比压到 ~50%（§1.4）。
- **适用条件**：**主方案**；对任意内容包通用，且不改变既有数值。

### 2.3 方案 C · 怪物侧按典型特效 build 上浮

- **机制形状**：给 `monster_scaling` 增两键（复用批45 读时参数化形状）：
  `effect_hp_mult`（补输出侧）、`effect_atk_mult`（补生存侧）；缺省 **1.0 = 现状**。
- **参数**：校准值 `effect_hp_mult = 1.068`（补典型冷却）、`effect_atk_mult = 1.33–1.48`（补减伤+吸血）。
- **对斩回影响推演**：
  - 只上 `effect_hp_mult = 1.068`：特效 build 中值斩回**回到** 7/20/24；
    但**无特效玩家**变成 普通 7→8、精英 20→22、Boss 24→26（**向无特效玩家收税**）。
  - 再上 `effect_atk_mult = 1.33–1.48`：无特效玩家的怪伤害 **+33%–48%**
    （Boss 每击 267→355–395）→ 对玻璃大炮口径是致命的（存活 3.7 回合 → ≈2.5 回合），
    直接威胁定稿 §4.4「BOSS 单回合伤害可控（防秒杀）」。
- **优点**：0 内容纪律、单旋钮、改回 1.0 即回滚；对"特效已全民化"的环境最省事。
- **代价（硬）**：
  1. **向无特效/新玩家收税**：刚起号、纯面板党、纯输出 build 全部变难；
  2. **无法区分轴**：冷却 build 与减伤 build 吃同一个 `hp_mult`，配比错杀；
  3. `atk_mult` 上调直接撞"防秒杀"红线；
  4. 与 `def_factor` 反解相互纠缠（C-08），每调一次都要重解。
- **适用条件**：**不单独作为主方案**；只保留为"特效渗透率接近 100% / 出现失控 build"时的**应急杠杆**（缺省 1.0，不配置即不存在）。

## 三、推荐方案与落地接口

### 3.1 推荐组合

> **方案 B（主）+ 方案 A1（观测）+ 方案 C（应急杠杆，缺省 1.0）**；A2 **不推荐**。
