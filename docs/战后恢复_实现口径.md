## 二、与既有机制的对照（哪些直接复用，不新开）

| 机制 | 既有实现（落点） | 本批 | 复用方式 |
|---|---|---|---|
| 玩家持久 HP/MP | `ctx["player"]`（`Player` frozen / dict 双形态）；战斗结束由 `_sync_battle_vitals`（`commands/battle_commands.py:1281`）从引擎快照写回 | 恢复同样**只写 `ctx["player"]`** | 复用 `_sync_battle_vitals` 的写回形态（`dataclasses.replace` / dict 就地），不新开存档链路 |
| 战斗结束分支 | `_dispatch_battle_end`（`commands/battle_commands.py:1175`；`dispatch_round:1147` 在 `report.ended` 时调用） | **在此分支内**追加恢复 | 与奖励/击杀/图鉴/升级同层，不新开一套结算 |
| 升级回满 HP/MP | `LevelUpEngine.gain_exp`（`core/levelup.py:186-199`，LVL-05 回满 + `hp_restored/mp_restored`） | 恢复**叠加在升级之后**、同样受 `max` 封顶 | 顺序：奖励结算（含升级回满）→ 战后恢复；只加不减 |
| 资源轴 / lifecycle | `core/resource_axis.py`、`core/resource_lifecycle.py`（战斗结束 `battle_end_reset` 按 `reset` 策略清零/保留**注册轴**） | **不接入** | HP/MP 是战斗基础属性（`attr_types` 的 combat 类），**不是** `resource_axes` 注册轴（剑气/怒气等）——恢复不能也不应用资源轴表达；`lifecycle` 的 `_settle` 清理在 HP/MP 之前，二者不冲突 |
| 恢复量的「比例」语义 | 无既有 helper | 新增**纯函数** `core/post_battle_recovery.py` | 引擎层纯函数（零 IO/零 NoneBot，可独立单测），落点与 `gathering.py` / `battle_reward.py` 同规矩 |
| 提示文案 | 全量模板表 `core/templates/template_table.json` + `tpl_of` | 新增 `battle_settle_recovery` 键 | 文案**零硬编码**，走模板表（内容包可覆盖） |
| 结算行渲染 | `_render_settlement`（`core/message_format/battle_render.py:1482`）已承载 `battle_settle_*` 行（exp/金币/掉落/升级） | 追加恢复行 | 复用既有结算块（win 分支）渲染位，不新增独立消息 |
| 设置段登记 | `SETTINGS_FIELDS`（`content/field_meta.py:332`）+ `_soft_display` | 新增 `post_battle_recovery` 段 | 与 `pvp`（`field_meta.py:2621`）同款登记口径 |
| 设置段校验 | `content/validator.py` `_check_settings_1g4`（death_penalty）/ `_check_message_prefix` | 新增 `_check_post_battle_recovery` | 专项钩子挂 `_check_module` settings 分支，泛型范围校验并行 |

**结论**：恢复 = 「战斗结束分支里对 `ctx["player"]` 的一次受 `max` 封顶的 HP/MP 加算」，
用既有结算分支 + 既有模板表 + 既有落档链路表达即可，**无需资源轴、无需新消息、无需新存档段**。

## 三、本批实现范围

**做：**
1. **字段与校验**：`settings.post_battle_recovery` 登记进 `SETTINGS_FIELDS`（`enabled` bool /
   `heal_ratio` number[0,1] / `safe_zone_heal` number[0,1]，中文名与 help 齐备）；
   `validator.py` 增补专项：段非对象红拦、`enabled` 非布尔红拦、ratio 越界红拦（泛型范围 +
   专项兜底）、`heal_ratio > 0.5` 黄提示（3h V9，标注补白）。
2. **引擎纯函数**：新增 `qbot_rpg/core/post_battle_recovery.py`（零 IO、零 NoneBot、纯函数）：
   - `parse_config(settings) -> RecoveryConfig`：段归一（缺省 = 关闭；非对象降级；ratio 缺失/非法 → None 不恢复）；
   - `compute_recovery(cur, max_value, ratio) -> (new, healed)`：`heal = int(max*ratio)`，
     `new = max(cur, min(max, cur + heal))`（**只增不减、封顶 max**）；
   - `recover_after_battle(player_like, snapshot, settings) -> Optional[dict]`：就地写回 HP/MP，
     返回 `{hp_before, hp, hp_max, hp_healed, mp_before, mp, mp_max, mp_healed}`（关闭/无变化 → None）。
3. **引擎消费**：`commands/battle_commands.py::_dispatch_battle_end` 的 `winner == "win"` 分支内
   调用恢复（**只在战斗结束时、且只在 ctx player 上生效**——不触碰引擎快照，战斗内数值零影响）；
   恢复行随 `send_end` → `render_battle_end` → `_render_settlement` 的结算块输出（模板
   `battle_settle_recovery`）。
4. **编辑器**：字段中文名/说明齐备（字段元数据登记即编辑器可见，settings「基础」卡片）；
   页脚批次串更新为「批37 · 战后恢复」。
5. **模板**：`battle_settle_recovery` 键入全量模板表；占位符白名单同步。

**不做（明确排除）：**
- 不实现**安全区停留回复**（`safe_zone_heal` 的消费挂 2a1b 安全区判定，属另一机制）——
  字段照定稿登记（编辑器可见），消费见 §四 D5。
- 不改**内容数据**（含 `veinborn` 的 settings.json，内容侧不配该段）；E2E 用**临时内容根**造样本。
- 不给恢复加 Boss/地图/职业条件（定稿未写，见 §四 D2/D3）。
- 不新增战斗结束消息条数（恢复行并入既有结束消息，铁律 2）。
- 不改资源轴 / lifecycle（HP/MP 非资源轴，见 §二）。
