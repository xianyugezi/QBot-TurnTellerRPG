## 〇、总览与一页结论

### 0.1 落点三分（本文的判定标准）

| 落点 | 判定 | 合格线 |
|---|---|---|
| **P · 纯配置** | 键已在 `qbot_rpg/data/gear_stats.py` 且**已有消费点**；或机制已在（资源轴/套装档位/触发容器/叠层/相性池），只需写内容包 | 引擎 0 行改动；新内容包不改引擎即可生效 |
| **K · 引擎 knob** | 已有消费点/管线，只差"读轴 + 钳制"1~2 处插入；改动量 ≤ 约 50 行/轴；可对拍零影响 | 不配置时**逐字段零变化**；单测可对拍 |
| **M · 新机制** | 需新增**收口函数 / 新事件点 / 新聚合层 / 新数据段**；或既有消费点分散≥3 处需先收口 | 必须先设计评审；不得以"顺手改"名义落地 |

### 0.2 一页结论

1. **轴的数量不是重点，收口才是。** 归并后 **约 40 条轴**（§1.2），其中 **P 纯配置 6 条 / K 引擎 knob 27 条 / M 新机制 7 条**；
   真正的 M 只有 7 条，且 4 条属可延后的 P2。
2. **两条 P0 缺口先于一切轴**：`event_dispatcher` 的 **owner 归属过滤**（`event_dispatcher.py:80`/`:223`）
   与 **`on_kill` 等事件补点**（`event_dispatcher.py:58`）。不修，所有**触发型**装备特效会全局误触发或永久落空
   （与 `被动#N-5`、`搜5#接缝`、`搜3#3.4` 同一发现）。
3. **表示口径统一为「百分点增量轴」**（`_pct`、允许负值，`有效 = 基准 × clamp(1 + 轴值/100)`）。
   用户给的 `_mult` 语义**等价覆盖**（`mult = 1 + pct/100`），且负半轴更完整（`−200` 可表达"治疗反转"）——
   详见 §1.0，这是一条**需用户点头的工程裁定**。
4. **新轴一律走"特效键族"（`GEAR_EFFECT_KEYS`），不进属性 pct 层**（理由与 `pierce_pct` 同，`gear_stats.py:192-218`）。
5. **最大数值风险不是膨胀，是"60% 装备占比 + 三档推演"被特效轴绕开**：`panel_budget` 只覆盖 `atk/dfn/hp`
   （`panel_budget.py:52`），特效轴会抬高**实际战力**却不进 `equip_share`。必须另立"特效强度预算"，
   并把 **斩杀回合档位（普通 3-8 / 精英 10-15 / Boss 40-60 回合，`战斗数值层设计定稿.md:139-141`）** 定为硬红线（§3）。

### 0.3 明确不做（汇总 §1.4）

队友/光环指向、仇恨嘲讽、D2 帧数断点表、D3 触发系数矩阵、第三镶嵌层、
把无连续量的布尔/枚举硬做成 `_pct`、`action_speed` 与 `action_recovery` 并存 —— 逐条给**为什么**，不写"暂不支持"。

## 一、轴注册表与逐轴落点

### 1.0 表示口径裁定：百分点增量轴（`_pct`），而非裸乘法系数

**裁定**：所有双向修正轴在**数据与引擎内部**统一采用

```
有效值 = 基准值 × clamp(1 + 轴值 / 100, lo, hi)     # 轴值单位 = 百分点，可为负
```

包声明可写 `display: "mult"`，编辑器按乘数显示（`×0.5 / ×1.0 / ×1.5`）。
换算：`mult = 1 + pct/100` ⟺ `pct = (mult − 1) × 100`。用户例 `healing_received_mult` 的 `0.5 / 1.0 / 1.5`
⇔ **`−50 / 0 / +50`**。

**为什么不是裸 `_mult`（三条硬理由，均 file:line）**

1. **零改路由层**：`route_bonus_into`（`gear_stats.py:192`）按 `_pct` 后缀拆层，`combatant_updates`（`:221`）
   按桥接表进战斗；新键走既有族 = 只加"一行键 + 一行桥"。而 `pierce_pct` / `mag_pierce_pct`（`gear_stats.py:102-106`）
   已是**"以 `_pct` 结尾但留在 flat、不进属性层"的现成先例**（`:192-218` 注释明写此例外）。裸 `_mult` 需要第五套键族 +
   新聚合层 + 新桥 + 新编辑器字段表，成本高且与既有分层打架。
2. **与既有乘法轴同口径**：α3 技能增幅已是 `1 + 总计/100`（`equip_mods.py:12`；伤害 `battle.py:3032`、冷却 `battle.py:3254`），
   `_aggregate_boost`（`battle.py:952`）的 S6/S7 封顶也在百分点域。同域才谈得上归并与封顶共用。
3. **负半轴更完整**：`−100` = 禁疗/免疫、`−200` = **治疗反转成伤害**；裸 mult 在 0 以下无自然语义
   （"×0"与"负数倍"分不清"禁疗"与"反转"）。这是百分点口径**严格优于**乘数口径的唯一但关键之处（搜3 已论证）。

**唯一例外**：确需"多来源**相乘**叠加"的玩法，用独立的 `stack_mode`
（`add | mult | diminishing | max_only`，对应 `搜5#轴-7`），默认 `add`（= 现有 `_aggregate_boost` 口径）。
`stack_mode` 是**聚合规则、不是轴**，故单列、不混入轴表。

**钳制落点**：新增包声明段 `settings.effect_axes`
（`{axis_id: {min, max, default, display, stack, legacy_alias?}}`，**缺省 = 不钳/身份**），由消费点读取，
**不得写死在消费点**（对齐 `panel_budget.py` 的"包声明驱动 + 缺省恒等"风格）。效果级封顶仍走
`effects._DEFAULT_CONFIG`（`effects.py:111-124`：链深 3 / 每回合 10 / 每场 99 / S6 ±100% / S7 100%）那一族。

**键族落点**：新增 `GEAR_EFFECT_KEYS`（**特效轴键族**，登记于 `gear_stats.py`，与 COMBAT 键同路由：留 flat → `combatant_updates` 桥进战斗），
**不进 `GEAR_PCT_KEYS` 属性 pct 层**。理由：否则 `healing_received_pct` 会被属性管线当成 `pct["healing_received"]`
误算（详见 §3 · C-06）。
> 复核依据：`aggregate_bonus`（`equipment.py:872-955`）把 `flat`/`pct` 两桶整体写入 `attributes.bonus["flat"]`/`["pct"]`；
> 属性管线只消费已知属性 stem，未知键（如既有 `pierce_val`/`immune_dmg`）留在桶里由战斗桥读取——**这正是 EFFECT 键该复制的既有形状**。

### 1.3 确需单向的轴（为什么不能双向）

| 轴 | 单向范围 | 为什么不能双向 |
|---|---|---|
| `lifesteal_pct` / `drain_to_resource` | `0..100` | 负值（造成伤害反而掉血）无自然语义；`>100` 回血超过伤害 → 经济失衡。反吸血需求由 **H-1** 表达，不重复造轴 |
| `reflect_pct` | `0..100` | `<0` 无意义；`>100` 反弹超过所受伤害 = 免费反杀（当前实现未封顶，必须在轴层钳） |
| `damage_reduction_flat` | `0..N` | "负值加伤"已由 **D-1** 覆盖；固定值减伤与百分比减伤是**两个不同乘区**，各自单向即可 |
| `damage_taken_cap` / `damage_floor` | `0..∞` / `0..N` | 是上/下界钳制，没有"反向的下界"同义语义；强行合一 → `<1` 语义含糊（搜4 已论证） |
| `immune_charges` | `0..99` | 计数语义（消耗"免疫次数"，非状态层数），负数无意义；与 S-5/S-6 不是一件事 |
| `stat_floor` | 布尔 | `"<1"` 无对应玩法；布尔式"锁定/不锁定" |
| `execute_chance_pct` | `0..N` | 负值"永不处决"= 不填即可；加 `−100` 只为表达"关掉"，不值一条轴 |

### 1.4 明确不做（含理由，不用"暂不支持"敷衍）

| 项 | 理由 |
|---|---|
| **队友 / 光环指向**（搜2#AX-9、搜5#轴-6） | 战斗模型是 **player side ↔ enemy side 的 1v1**（`core/battle.py` 的 `side` 二值），无"12 米内 5 名队友"的选目标概念。搜5 提的 `field_aura` 与搜2 的"不适用"结论**冲突**，本文**采信搜2**：要做团队内容，先做"同侧全体状态"（`_aggregate_boost` 已读同侧状态，`battle.py:952`），**不做距离筛选** |
| **仇恨 / 嘲讽**（搜2#AX-10） | 无仇恨表、无多敌人，嘲讽无对象。替代：操作敌方隐性轴（受击怒气/耐力） |
| **D2 帧数 / 断点表**（搜1#3.3） | 我们是回合/行动制，无实时帧。只保留"动作时间修正"（= A-2），不引入 framebreak 表 |
| **D3 触发系数（Proc Coefficient）矩阵**（搜1#3.3） | 为每个技能维护一套系数表 = 数值债。用 S-3 概率轴 + proc 的 `chance`（`effects.py:2122`）表达 |
| **第三镶嵌层（组件+增幅）**（搜1#3.3） | 已有符文孔位（`jewel.py:442/885/986`）+ 词缀（`enhance_affix.py:232`）+ 客制；再加第三层只会让作者迷惑 |
| **把布尔/枚举硬做成 `_pct`** | `crit_immune` / `weakness_immune` / `overheal` / `immune_controls` 没有连续"量"；做成 `_pct` 会迫使作者用 0/100 模拟布尔，且会被 S6/S7 与后续增益拉回（搜3 §3.4） |
| **`action_speed_pct` 与 `action_recovery_pct` 并存** | 数学互为倒数，并存 → 指数级速度（搜3 §3.5）。**只留 A-2** |
| **`status_chance_pct` 与 `status_resist_pct` 合并** | 一个"我挂别人"、一个"别人挂我"，合并后无法表达"高命中 + 高抗性"双向 build |
| **`healing_done_pct` 与 `healing_received_pct` 合并** | 施疗方与受疗方是**两个不同实体上的字段**，合并会让"减疗"在治疗者与受疗者之间产生歧义 |
| **Headhunter"复制稀有怪全套词缀"**（搜1#3.3） | 我们**没有怪物词缀对象**可逐条搬运；要做只能是"从预设池随机授予 status"，走 T-6 + 相性池（`affinity.py:293`），不引入"任意词缀运行时搬运" |

### 1.5 预设体系的形状（"预设"到底是什么、落哪）

**预设 = 包声明的具名参数包**，由四层声明组成，**各归其位、不新建库**（与 `被动#2.1` 完全同构）：

| 层 | 落点 | 承载什么 | 是否新增 |
|---|---|---|---|
| **身份 / 命名 / 相性变更** | `traits.json`（`field_meta.py:2388-2400`）+ 装备模板字段 `passives`（**已在** `item.py:73`） | 叫什么、可否相性变更（`affinity_variants`）、变体目标 | **否**（复用） |
| **行为** | `effects.json`（`execute_action:1770` / `execute_proc_action:2122`） | 触发时点 / 概率 / 内置 CD / 次数上限 / 原子动作 | **否**（复用） |
| **数值轴** | `ItemInstance.stats_bonus`（`item.py:60`）→ `route_bonus_into`（`gear_stats.py:192`） | `{axis_id: 百分点}`，双向 | **否**（容器已在） |
| **轴范围 / 显示 / 聚合方式** | `settings.effect_axes`（**新段**，字段元数据 + 校验器 + 编辑器） | `min / max / default / display / stack / legacy_alias` | **是**（唯一新增数据段） |

**三条推论**
1. **"预设库"不新增模块**：词条型预设复用 `enhance_affix`（`enhance_affix.py:232`）与 `runes`（`runes.py:194`）的键引用；
   相性池预设复用 `affinity_pools`（`affinity.py:293`）。所谓"预设体系"是**一堆包声明条目**，不是一套新引擎。
2. **预设的强度 = 轴取值的组合**，因此**强度管理就是 `effect_axes` 的钳制 + 每档的强度预算**（§3 C-01）。
3. **预设的"双向"是同一个条目的两个填法**，不是两个条目：`重伤` = `healing_received_pct: −50`；
   `强化治疗` = `healing_received_pct: +50`。**内容侧不得为两个方向各建一条 trait**（否则相性池与图鉴会重复计数）。

## 四、与相性层 / 符文 / 强化词条的关系（唯一源原则）

### 4.1 一张表：一条轴如何被四个系统共用

```
data/gear_stats.py   GEAR_EFFECT_KEYS（新）→ GEAR_NUMERIC_KEYS
   │  同一份键、同一层路由（route_bonus_into:192）
   ├─► 装备本体      stats_bonus（item.py:60）
   ├─► 强化特殊词条  merge_affix_bonus（enhance_affix.py:232）
   ├─► 符文 1-3 阶   rune_stats_of（runes.py:194）
   └─► 相性池条目    affinity.py:293（stat 或 effect_ref）
   ▼
AggregateBonus（唯一聚合入口 equipment.py:872）
   ▼
战斗桥 combatant_updates:221 → 战斗
```

**产物**：同一条 `healing_received_pct`，可以由装备本体、强化词条、符文、相性池**任一或组合**提供，
但**只有一份键定义、一个聚合入口、一个消费点**。

### 4.2 四个系统的接入口径（逐条）

### 4.3 唯一源原则：三条禁止（建议由校验器红拦）

1. **禁止各玩法自造键**：轴键只在 `data/gear_stats.py` 出现一次。符文侧已有 **RUNE-05** 红拦（`gear_stats.py:33`、`符文#§三.2`）；
   强化词条与相性池需**同规则**（当前缺）。
2. **禁止内联执行语义**：行为必须 `ref` 到 `effects.json` 条目，不得在符文/被动/相性里内联动作（`符文#§三.2`）。
3. **禁止第二套基础设施**：不得新建第二个相性池、第二条孔位数组、第三层镶嵌、第二个聚合入口。
   `aggregate_bonus`（`equipment.py:872`）是**唯一聚合入口**（批45/47 均以此为收口，`批45报告:16`）。

### 4.4 与相性层的双向关系（一处易被忽略）

相性既是**轴值的来源**（池条目 `stat`），也可以是**轴的消费者**（相性影响被动变更 `affinity_variants`）。
两者都走 `resolve_*` 两个 API（`affinity.py:293` / `:351`），**不得**在打造/炼金/装备三处各写一套匹配
（决策记录 §三 补充 2：相性是通用机制，打造与深度炼金共用同一套定义/池/互动规则，`深度打造_决策记录.md:49-54`）。
**注意**：`resolve_affinity_effect` 目前只支持 `"<main>"` / `"<main>|<sub>"`，**不支持"只副相性"**
（`被动#Q-5`）→ 若特效需要"仅副相性触发"，须走池形态 `requires_affinity=["<sub>"]`（`affinity.py:293` 已支持子集匹配），
**不要**改公共 API（深炼金共用，改动需评审）。

## 五、风险清单与规避

### R-01 · 数值膨胀（终伤乘区无天然上限）

| 项 | 内容 |
|---|---|
| **现象** | 新轴（造成/承伤/时长/冷却）是**乘区**而非加算值，且**不进 S6/S7 属性封顶**（C-10）→ 多轴叠加呈乘法增长 |
| **触发条件** | 同一条 build 同时拿多轴正值；或特效轴与 `equip_stat_mult`（×2.25，`panel_budget.py:95`）叠加 |
| **规避** | ① 每轴上下钳落 `settings.effect_axes`（§3.2 表），默认值保守；② **每档预设给"特效强度预算"**（C-01 的 `effect_share`）；③ 同族轴之间用 `stack_mode: diminishing`（`1−∏(1−x)`）作可选项；④ 批53 统一复算，越档位即回滚 |
| **验收** | 三档斩回不越档位（F-5）；木桩"全特效满配"与"零特效"的战力比在预设预算内 |

### R-02 · 单一最优解（"无敌 loop"）

| 项 | 内容 |
|---|---|
| **现象** | `承伤 −100`（免疫）+ `受疗 +300` + `吸血` → 打不死、越打越满；或 `冷却 −80` + `资源消耗 −100` → 无限循环 |
| **触发条件** | 轴之间缺少互斥/边际递减；上钳过松；同一件装备同时给正反两向同族轴 |
| **规避** | ① **组合递减**：`承伤` 与 `受疗` 同时高值时对后者作边际衰减（`stack_mode: diminishing`）；② **互斥声明**：`immune_dmg` 满值时受疗轴衰减（写进 `effect_axes` 的 `stack` 规则）；③ **单件装备不得同时给同族正反两向轴**（校验器黄/红提示）；④ 冷却/资源轴上钳收紧（`−80% / −100%` 已足够强，不再放宽） |
| **验收** | 每条样板 build 在木桩打不死的循环可被检出（存活回合 > 设定上限即告警） |

### R-03 · 与既有机制的职责重叠

| 项 | 内容 |
|---|---|
| **现象** | 同一语义存在多条消费路径，改一处漏一处，且作者不知填哪个键 |
| **具体重叠（本设计已归并的）** | `damage_taken_pct` ↔ `immune_dmg` ↔ `mitigation` ↔ `_status_damage_mult`（`battle.py:4606/3998`、`effects.py:1080`）｜`healing_done_pct` ↔ `heal_amp_pct`（零消费）｜`cooldown_pct` ↔ 占位键 ↔ α3（`battle.py:3254`）｜`stack_potency_pct` ↔ `_aggregate_boost` 不乘层数（`battle.py:963-977`）｜`status_chance_pct` ↔ `debuff/buff_chance_pct`（零消费）｜`action_bar_shift` ↔ `counter_refund`（`ctb_rules.py:190`）｜`action_recovery_pct` ↔ `enrage/fatigue_recovery_mult`（`battle.py:281`） |
| **规避** | ① 每个语义**唯一消费点**（§1.2 的"收口点"列即该唯一处）；② 旧键保留为**别名 + 换算**，不双消费（C-03、C-06）；③ 文档维护一张"**旧键 → 新轴**"对照表；④ 校验器红拦"同名跨族键"与"同一语义双键" |
| **验收** | 全仓 grep 每个语义只在一处消费；旧键对拍逐字段一致 |

### R-04 · 兼容旧内容包（**最容易被低估**）

| 项 | 内容 |
|---|---|
| **现象** | 旧包声明的"占位键/零消费键"在接线后**突然生效** → 旧装备数值漂移；或旧存档的装备聚合层未重算 |
| **触发条件** | ① `cooldown_reduction_pct`（`gear_stats.py:114`，`route_bonus_into:192` 显式跳过）被接线（C-05）；② `heal_amp_pct` 从属性层迁到战斗层（C-06）；③ `immune_dmg` 换算（C-03）；④ **读时聚合**导致已穿戴玩家需重算（批45 同坑：`批45报告:217`） |
| **规避** | ① 占位键激活**必须显式 opt-in**（`legacy_alias`），缺省保持不生效；② 旧键迁移器 + 校验器提示；③ 装备聚合层重建口径（穿脱一件或显式重算）；④ 每批附**"旧包行为不变"**对拍测试 |
| **验收** | 取一个既有内容包（如 `content/veinborn`、`content/test_demo`），接线前后 `check_pack` 与战斗数值逐字段一致 |

### R-05 · 工程风险（收口不完整 = 沉默失败）

| 项 | 内容 |
|---|---|
| **现象** | heal 有 4 个来源（`effects.py:1880/1290/1333`、`battle.py:4709`）、事件候选是全局扫描（`event_dispatcher.py:80`）、相性池 `effect_ref` 无校验（`被动#P-5⑩`）——漏一处**不报错**，只是数值悄悄不对 |
| **规避** | ① 收口类改动配"**源枚举测试**"（像批46 的"6 处构造点静态审计"那样，把来源数量钉死）；② `on_kill`/owner 过滤保留旧行为路径并有单测；③ 相性池 `effect_ref` 补引用校验（批52） |
| **验收** | 每个收口函数有"来源枚举"断言；新增来源若未接轴则测试红 |

### R-06 · 档位/边界回归（批45 已登记的两处）

| 项 | 内容 |
|---|---|
| **现象** | ① 无 buff / 满 buff 两档斩回各 ±1（`批45报告:216`），单一全怪倍率无法同时锁定三档；② `def_factor` 与内容强相关，改毕业装/白值/buff 即需重解（`:218`） |
| **规避** | ① 接受三档 ±1 为**既有已登记偏差**，不因新轴而扩大；② 特效轴按"三档等比"设计（C-07）；③ **不同时改白值/buff**；④ `def_factor` 重解只在批53 |
| **验收** | 批53 对照表与批45 基线并排，逐格可解释 |
