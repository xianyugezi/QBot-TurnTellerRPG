### 1.1 材料条目字段（`items[]`，`type=material`）

|---|---|---|---|---|

### 1.2 相性定义 / 池 / 联动 / 互动（`settings.*`，批 38 已建的形状）

**相性定义 `settings.affinities[]`**（`field_meta.py:393-402`）：

| 中文名 | key | 类型 | 说明 |
|---|---|---|---|
| 相性 ID | `id` | str（required） | 内容包自定义 |
| 中文名 | `name` | str | — |
| 说明 | `desc` | str | — |
| 专属池 | `exclusive_pool` | str | → `affinity_pools[].id` |

**词条池 `settings.affinity_pools[]`**（`field_meta.py:403-421`）：`{id, kind ∈ common/exclusive/linkage, desc, entries[]}`；`entries[]` 行 `{stat | effect_ref, weight, min_level, requires_affinity, value_rule}`。查询语义 = **通用池 ∪ 主相性专属池（联动命中则被覆盖）**，再按 `requires_affinity` 过滤（`core/affinity.py:resolve_available_entries`）。

**联动 `settings.affinity_linkage[]`**：`{main, sub, override_pool}`。

**材料互动 `settings.affinity_reactions[]`**（`field_meta.py:430-442`）：`{kind, from, to, pair, value}`。

> **本草案新增 1 个可选字段 `exp_mult`**（number，品质经验乘子，分数）。理由：批 38 的 `value` 语义是**相性值增减**（`core/affinity.py` 单测用 `value=3` 作绝对增减），而决策 N1 的公式要求一个**品质经验乘子**。同一规则行同时携带两套数值，避免"互动规则写两处"（唯一源）。`exp_mult` 需在消费它的批次里登记进 `field_meta`（本草案只声明形状）。默认：`conflict=-0.25 / amplify=+0.15 / reverse=0.0`。

**相性 + 互动 JSON 示例**：

```json
{
"affinities": [
  { "id": "lunar", "name": "月华", "desc": "月照之华，柔和绵长", "exclusive_pool": "pool_lunar" },
  { "id": "frost", "name": "霜晶", "desc": "凝寒之晶，锐而脆", "exclusive_pool": "pool_frost" },
  { "id": "ember", "name": "炎火", "desc": "不熄之烬，烈而短", "exclusive_pool": "pool_ember" }
],
"affinity_pools": [
  { "id": "pool_common", "kind": "common",
    "entries": [ { "stat": "hp", "weight": 10 } ] },
  { "id": "pool_lunar", "kind": "exclusive",
    "entries": [ { "stat": "foc", "weight": 8, "requires_affinity": "lunar" } ] },
  { "id": "pool_frost", "kind": "exclusive",
    "entries": [ { "stat": "dfn", "weight": 8, "requires_affinity": "frost" } ] },
  { "id": "pool_ember", "kind": "exclusive",
    "entries": [ { "stat": "atk", "weight": 8, "requires_affinity": "ember" } ] },
  { "id": "pool_link_lunar_frost", "kind": "linkage",
    "entries": [ { "stat": "foc", "weight": 12, "requires_affinity": "lunar" } ] }
],
"affinity_linkage": [
  { "main": "lunar", "sub": "frost", "override_pool": "pool_link_lunar_frost" }
],
"affinity_reactions": [
  { "kind": "conflict", "pair": ["ember", "frost"], "value": 4,   "exp_mult": -0.25 },
  { "kind": "amplify",  "pair": ["lunar", "frost"], "value": 3,   "exp_mult": 0.15 },
  { "kind": "reverse",  "from": "frost", "to": "lunar", "value": 1.0, "exp_mult": 0.0 }
]
}
```

> **结算顺序 = 材料投入顺序**（原案 §12；`reaction_order: "input"`），引擎已实现（`core/affinity.py:accumulate_affinity`，docstring 注明"顺序敏感；同一次材料内不自我触发"）。**反转**口径：本次材料携带 `from` 时，把池中已有 `from` 按 `value` 比例转入 `to`。

### 1.4 打造参数段（`forge.craft_rules`，全可调）

### 2.4 自洽性检查（手算 + 脚本复核）

**通用算式**（决策 N1 的落地）：

```
装备等级 Lv = floor( 0.60 × Lv_main + 0.40 × Σ(free件数_j × Lv_j) / Σ free件数_j )
品质经验 QE = Σ_i [ Q(quality_rank_i) × A(i) × S(n_i) ] × (1+type_bonus)^(种数−1) × Π(互动 exp_mult)
   A(i)  = 1.5 若材料相性含图纸相性，否则 1.0
   S(n)  = Σ_{j=0}^{n-1} max(0, 1 − 0.25j)     → n=1:1.0 / 2:1.75 / 3:2.25 / 4:2.5 / 5:2.5
   互动  = conflict ×0.75、amplify ×1.15、reverse ×1.0（每条规则每件最多触发一次）
品质等级 = max{ l : QE ≥ 阈值[l] }，阈值 = [0,25,60,110,180,275,400,560,780,1080]
cost     = 60 + 20×种数 + Σ(craft_cost_i × 件数_i)
有效      ⟺ 等级带下限 ≤ Lv ≤ 上限 且 cost ≤ 该档 cap
```

> **两处上游数字修正（必须显式说明）**：
> **(a) 件数边际**：B §1.2 写"`S(n)=Σ max(0,1−0.25j)`；n=5 → **3.75** 有效件"，但按该式代入 j=0..4 实得 `1+0.75+0.5+0.25+0 = 2.5`，**B 的 3.75 算不通**。本草案取公式本身（n≥4 后边际为 0，有效上限 2.5），并把"第 5 件 0 收益"作为刻意的防堆料设计。若用户要 3.75，应改为 `step=0.15`（1+0.85+0.7+0.55+0.4=3.5）或明确另一形状——**见 §5-T6**。
> **(b) 品阶基数标度**：B §1.2 给出 `Q=[1.0,1.6,2.6,4.2,7.0,11.0]`，但 A8 阈值满值 1080；以 Q≈1–11 且最多 10 种×5 件，**满投 QE 仅约 538**，永远到不了 10 级 → 两者不同标度。本草案加一个标度旋钮 `quality_exp_scale`（默认 **10**），即 `Q_effective = 相对表 × 10 = [10,16,26,42,70,110]`，与 A8 阈值同量级后闭合（10 种满投红料理论 QE ≈ 5382 ≥ 1080）。**见 §5-T7**。

**例 1 · 铜 OPT（图纸 1，图纸相性 `frost`，band 2–8，cap 1000）**

投入（按投入顺序）：`ridge_ore ×4`（主）、`vein_shard ×4`、`mossvein_herb ×4`、`pulse_candy ×4`。

- 等级：主 `Lv=6`；自由件数 12，加权均 = `(4×4 + 4×3 + 4×2)/12 = 3.0`；`Lv = floor(0.6×6 + 0.4×3.0) = floor(4.8) = 4` ✅ 在 2–8。
- QE：
  - `ridge_ore`：Q16 × A1.0（ember≠frost）× S(4)=2.5 = **40.000**
  - `vein_shard`：Q10 × A1.5（frost）× S(4)=2.5 = **37.500**
  - `mossvein_herb`：Q16 × A1.0 × S(4)=2.5 = **40.000**
  - `pulse_candy`：Q10 × A1.0 × S(4)=2.5 = **25.000**
  - ΣQAS = **142.500**
- 种类奖励：`1.03^(4−1) = 1.092727`
- 互动（顺序：ridge_ore→vein_shard→mossvein_herb→pulse_candy）：投入 vein_shard 时 frost 新入、池有 ember → **conflict ×0.75**；投入 mossvein_herb 时 lunar 新入、池有 frost → **amplify ×1.15** → 净 **0.8625**
- `QE = 142.500 × 1.092727 × 0.8625 = 134.303` → 品质等级 **4**（≥110）
- `cost = 60 + 20×4 + (40×4 + 50×4 + 25×4 + 15×4) = 140 + 520 = 660` ≤ cap 1000（余额 340，**未触达 cap**）
- 结论：**有效**。铜档天花板由"带内材料品阶"决定（cap 不绑定）。

**例 2 · 银 OPT（图纸 3，图纸相性 `lunar`，band 9–16，cap 2100）**

投入：`lunar_eclipse_stone ×4`（主）、`wind_ridge_shell ×3`、`crystal_mane ×3`。

- 等级：主 `Lv=12`；自由件数 6，加权均 = `(3×10 + 3×14)/6 = 12.0`；`Lv = floor(0.6×12 + 0.4×12.0) = 12` ✅ 在 9–16。
- QE：
  - `lunar_eclipse_stone`：Q42 × A1.5（lunar）× S(4)=2.5 = **157.500**
  - `wind_ridge_shell`：Q26 × A1.0（frost）× S(3)=2.25 = **58.500**
  - `crystal_mane`：Q26 × A1.5（lunar）× S(3)=2.25 = **87.750**
  - ΣQAS = **303.750**
- 种类奖励：`1.03^2 = 1.0609`
- 互动：amplify（lunar × frost）触发一次 → **×1.15**
- `QE = 303.750 × 1.0609 × 1.15 = 370.586` → 品质等级 **6**（≥275）
- `cost = 60 + 20×3 + (200×4 + 130×3 + 260×3) = 120 + 1970 = 2090` ≤ cap 2100（余额 10，**触达银档 cap 99.5%**）

**例 3 · 银 SUB（同图纸，省料流）**

## 三、cost 平衡建议

### 3.1 cap 阶梯：三种口径的冲突必须裁决

| 口径 | 来源 | cap 阶梯（铜/银/金/彩） | 语义 |
|---|---|---|---|
| **N3（权威决策）** | 决策记录 `:30` | 顶部 ≈ **4200**，按档缩放 | cap = "刚好到品质 10 级 + 少量冗余"的**单次品质预算** |
| **B §2.3** | B `:199-206` | **600 / 3900 / 18000 / 86000** | cap = 该档**固定材料价值 × 1.5**（随材料价格走） |
| **本草案 provisional** | 本文 §2.4 实测 | **1000 / 2100 / 4200 / 8600** | 铜/银由实测最优解 ×1.15–1.5 反推；金/彩为形状（材料表待 T-1） |

**冲突的本质**：N3 把 cap 当成**品质预算**（与材料价格无关），B 把 cap 当成**材料价值比例**（与材料价格强相关）。两者在铜/银档接近（数量级内），在彩档相差 **20 倍**。

**本草案建议（供裁决）**：采用 **`cap = 等级承载成本(档) + 品质预算(档)`** 的合成式：

- `等级承载成本` = 该档等级带下限对应的主材料槽最低可用材料单价 × 少量件数（本样例：铜 ≈40–50、银 ≈130、金 ≈280、彩 ≈1100）；
- `品质预算` = 该档目标品质等级的"省料流成本"（N3 口径；本样例银档 q6 ≈2100、彩档若要求 q10 则需 ≈4040 起）；
- 则 provisional cap ≈ **铜 900 / 银 2000 / 金 3600 / 彩 5400**（与 §2.3 的 1000/2100/4200/8600 同量级，差异来自"是否含等级承载"）。

> **必须裁决**：彩档是否**要求品质 10 可达**？若要求，本样例 12 材料下需约 **19500 cost**（q8）甚至更高，或**扩充彩档材料种类**；若接受"高品质靠金/彩档材料表自然形成"，则 cap 取 5400–8600 即可。**这一项直接决定全系统经济规模，不能由实现者默认。**

### 3.2 示例最优解 vs 次优解（银图纸 3）

| | 最优解 OPT | 次优解 SUB | 差异 |
|---|---|---|---|
| 投入 | `lunar_eclipse_stone ×4`（主）+ `wind_ridge_shell ×3` + `crystal_mane ×3` | `lunar_eclipse_stone ×5`（主）+ `crystal_mane ×2` | OPT 多 1 种、多 3 件 |
| 种数 / 件数 | 3 / 10 | 2 / 7 | — |
| 结果等级 | **12** | **12** | 持平 |
| 品质经验 | **370.586** | 267.401 | OPT **+103.185（+38.6%）** |
| 品质等级 | **6** | 5 | OPT **+1 级** |
| cost | **2090**（cap 2100，99.5%） | 1620（cap 2100，77%） | OPT **+470（+29%）** |
| 互动 | amplify ×1.15 | amplify ×1.15 | 同 |
| 取舍 | 花满预算，换 +1 品质级 | 省 470 cost，接受 −1 品质级 | **cost ↔ 品质 的连续取舍** |

**这条取舍正是用户要的"满足 cost 前提下堆高经验"**：OPT 把预算用满（触达 99.5%），SUB 留 22% 预算不用。**两者均满足 cap 与等级带，不存在"单一最优"**——因为玩家的目标函数里同时有"品质"和"省下的 cost（可换其它件打造）"。且**同 QE 的最优解不唯一**：脚本对铜档穷举的 top5 全部 `QE=134.30`，但件数分布各不相同（4×4×4×4 / 5-4-4-4 / 4-5-4-4 …），说明"最优"是一个**解集**而非一个点。

**为什么不退回"低阶料刷品质"的单一解**（N2-② 的作用）：若 cap 改成**全局 4200**（不随档缩放），银档可把 3 种材料各加到 4 件（cost 2480），QE 从 370.6 升到 390.4（仍 q6，因本样例银档只有 3 种材料）；但**铜档在等级带约束下天花板不变**（仍 q4）。→ 在"等级带约束已存在"时，② 对**低档**不绑定；它真正的作用域是**自由槽放宽为带外**或**等级权重调低**的场景（此时 ② + 结果等级带共同兜底）。**结论：① 必做且是主力，② 保留为兜底与调参旋钮**（与决策 N2"两条都必做"一致）。

### 3.3 cap 与"10 级 cost 上限"的对照

- N3 的"品质 10 级"参考量级 = **≈4040 cost**（B §2.6 省料流；B §1.2 阈值 1080）。
- 本样例银 OPT cost 2090 **未触达 4040**，故在银档 cap 内**到不了品质 10**（银档天花板 q6）；要 q10 必须扩材料（§2.4 天花板不单调的根因）。
- **单旋钮 `quality_exp_scale` 能整体平移天花板，但修不了"不单调"**：本样例彩档在 cap 8600 内 QE=382.0（q6，scale=10）。若调到 scale≈**28**，彩档 QE ≈ 382.0×2.83 ≈ **1081**（≥1080，可达 q10）；但同一旋钮把铜档抬到 ≈380（→q6）、银档 ≈1049（→q9），**低档一并膨胀**；scale=16 时彩档仅 ≈611（q7），仍到不了 q10。→ **真正的修复是扩充每档材料密度（§5-T1），`quality_exp_scale` 只作整体微调（§5-T7）。**

### 4.1 加一种材料

1. 在对应内容包 `items.json` 增加一行 `type="material"`，**必填** `id`/`name`/`price`；**打造向必填** `material_level`（1..level_cap）、`quality_rank`（六档之一）、`craft_cost`（默认随 `price`）。
2. `affinities` 填 `{相性id: 正数}`；**相性 id 必须先出现在 `settings.affinities[]`**，否则校验器红拦（`field_meta.py:2349-2352` 注释）。
3. `material_tags` 至少 1 个，且**必须与目标图纸 `material_slots[].filter.material_tags` 有交集**，否则该材料进不了任何槽。
4. 若该材料参与互动：互动规则写在 `settings.affinity_reactions[]`（**不是材料条目上**），用相性 id 配对；**冲突/增幅的 `value` 是相性值增量，`exp_mult` 是品质经验乘子**，两套语义不要混。
5. **同级同价同相性三同**（原案 §12）：同 `material_level` + 同 `quality_rank` + 同 `affinities` 的材料视为等价，作者扩写时按此对齐，避免"同档材料效率漂移"。

### 4.2 加一张图纸

1. 在 `forge.blueprints[]` 增加一行；**先定 `grade` 与 `level_band`**，再定槽。
2. `material_slots`：`role="main"` 至少 1 个（`count` 通常 1），自由槽 1–3 个；`filter.material_tags` 决定"对应类型"，`level_min/level_max` 建议与 `level_band` 同步。
3. 固定属性 1–3 条（`fixed_stats`）、随机属性 0–2（`random_stat_count`）；套装词条 **恰好 1 条固定** + 0–2 随机；固定被动 1 条；图纸相性 1 条（可加副相性值）。
4. 图纸作为物品：另建 `items[]` 一行 `type="图纸"`（部分唯一图纸 `tradable=false`，原案 §12）。
5. 校验自检：`等级带 ∩ 材料等级范围 ≠ ∅`；`cap ≥ 该档省料流最优 cost`；`固定属性条数 ∈ [1,3]`；`随机位 ∈ [0,2]`。

### 4.3 常见坑

| 坑 | 后果 | 规避 |
|---|---|---|
| 材料带外自由料 | 结果等级被拉低到带外 → 打造无效 | 图纸 `level_min/max` 与 `level_band` 同步；引擎按结果等级判定 |
| 相性 id 未声明 | 校验红拦 / 池抽不出词条 | 先写 `settings.affinities` |
| 互动写在材料上 | 与 `affinity_reactions` 唯一源冲突 | 只在 `settings.affinity_reactions` 声明 |
| 每档材料过少 | 品质天花板不单调（本样例金档 q5 < 银档 q6） | 每档建议 ≥6 种、价格跨度覆盖该档 cost |
| cap 全局常量 | 低档图纸能刷高品质 | cap 随档缩放（N2-②） |
| 同一材料件数堆到 10 | `S(n)` 第 5 件起 0 收益，纯浪费 | UI 提示"4 件已饱和" |
| 相性倍率调 ≥2.5 | 策略退化成"只找同相性"单一解 | 钉在 1.4–1.8（B §2.5） |
| 随机属性池过大 | "毕业一件"期望次数乘积级膨胀 | 池控 6–8 条（B §4.2） |
