## 二、🔴 P0 必改

### P0-01：回合开始 dot 致死 → `ACT→DTH` 非法迁移抛 `BattleStateError`（回合开始即死通道整体断裂）

- **文件:行号**：`qbot_rpg/core/battle.py` L849（`start_turn` 首行 `_to_state(STATE_ACT)`）→ L857-875（① dot 循环）→ L869（`_death_check_side(side,"turn_start_dot")`）→ L585（`_to_state(STATE_DTH,...)`）；`_LEGAL_EDGES` 定义 L137-151 **缺 `(ACT, DTH)`**；`_to_state` 非法迁移拦截 L353-356。
- **实际**：`start_turn` 进入时 `self._state == STATE_ACT`。当某侧 carry `tick=="turn_start"` 的 dot 且被 dot 扣死时，`_death_check_side` 从 ACT 态发起 `ACT→DTH`，不在合法迁移集 → `raise BattleStateError("非法状态迁移 act→dth")`。
- **应有**：1g1b 不变量2「死亡判定唯一两触发点：回合开始 ②（L46）与行动结算 ④（L50）」；1g1a §4「① 回合开始 dot 结算后即查」；1g1c TC-02 / TC-13「回合开始 dot 结算后即查死亡；死则跳过其本回合行动 / 玩家死→失败标记」（1g1c L182-L186、L203-L205）。即死路径应**正常工作**，死方直接打胜负标记（1g1b A1 直出），而非抛异常。
- **证据**：`start_turn` L849 设置 ACT 后、L869 才检查死亡；`_LEGAL_EDGES`（L137-151）中 (`RES,DTH`)、(`DTH,RES`)、(`DTH,WIN`)、(`DTH,LOSE`) 存在，唯独无 (`ACT,DTH`)；`_death_check_side` docstring（L579-582）假设"state 经 RES→DTH→RES 走一圈"，与 start_turn 内 state==ACT 的调用环境不符。
- **修复建议**：① 在 `_LEGAL_EDGES` 增补 (`STATE_ACT, STATE_DTH`)（配合既有 `DTH→RES` 回程），或 ② 将 start_turn ① 段包进 RES 相位后再挂 DTH，或 ③ 按 1g1b A1「即死直出」重构：回合开始即死不走 DTH 回程，直接 `_mark_dead` + `_settle` 直出 LOSE/WIN。三选一，均需补 `start_turn` 即死用例（现 8 用例零覆盖）。
- **SQL 静态推导**：仅代码路径推得，未运行验证。

### P0-02：回合结束 tick 内 dot（tick=turn_end）扣血致死 无死亡判定/无终局 → HP=0 不死单位，战斗永不终止

- **文件:行号**：`qbot_rpg/core/effects.py` `tick_turn_end` ② dot 分块 L1275-1287（`c["hp"] = max(0, hp - value)` **直接改 HP**，且此时倒扣 `dot["turns"]`）；`battle.py::end_turn` L1313-1326：先 `tick_turn_end` → `_resolve_battle_end(force=False)` → `if self._dead(...): _resolve_battle_end(force=True)`；`_resolve_battle_end` L602-650 全程只读 `result.mark_lose/mark_win`（L612-613），**不读 HP**。
- **实际**：tick 内 dot 把一侧 HP 打到 0 后，`dead_mark`/`result` 均未置位 → `_resolve_battle_end` 两次调用都返回 `None` → `end_turn` 落入 `start_turn()` → start_turn ① 对死侧 skip（L858 `if not self._alive(side)`）、② 块（L885-890）`_resolve_battle_end(force=True)` 仍读空 marks → 不终局。结果：
  - 怪物被 tick dot 打死：**0HP 不死单位**，无 mark_win，胜利被无限推迟至玩家下一次攻击才补挂 mark（此时才终局）；
  - 玩家被 tick dot 打死：mark_lose 永不上，`do_action("player")` 触发 L941-942「已死亡/退场」异常，玩家永远无法行动，`end_turn` 恒 tick→start_turn 空转（回合无限自增）→ **死锁**。
- **应有**：1g1c §1.4「dead_mark 与 result 写入先后：死亡判定先于当轮末结算」，明确「不允许『死而未结算』**穿透回合边界**」；1g1b 不变量2（每处扣血后即查）；1g1c TC-03（回合结束 tick 副作用正常结算后死亡必被处理）；1g2 §1.3 tick#6「dot（如配 tick=turn_end）」在契约射程内。`dot` 动作默认 `tick="turn_end"`（effects.py L1538）→ 该通道**必然可达**。
- **证据**：`end_turn` L1315-1326 无任何 `_death_check_side`/`_mark_dead` 调用；`_resolve_battle_end` 判定完全依赖 `result` marks（L612-613），`force` 只豁免"非 BOSS 普通击杀的排期"（L644-646），不补 HP 检查；start_turn ② 块（L884-890）同样只 `_resolve_battle_end` 不补 mark。
- **修复建议**：① 回合结束 tick 后对两侧补一次死亡判定挂点（`_death_check_side(side,"turn_end_dot")`），或 ② 将 `tick_turn_end` 的 dot 改走拦截链扣血（与回合开始 dot 同构，1g2 §2.1 B 复用链），或在 ⑧ 结算判定中把"HP≤0 且无 mark"兜底补登 marks。+ 补 TC-03 方向的死亡用例。
- **SQL 静态推导**：仅代码路径推得。

## 四、🟢 P2 建议（9 项）

1. **STATE_SNP 死状态 / 死边**：`_LEGAL_EDGES` 含 (`PREP,SNP`)、(`ACT,SNP`)、(`SNP,PREP`)（battle.py L140/143/149），但全文件**无任何 `_to_state(STATE_SNP,...)` 调用**（grep 证实）→ 快照中断以"外部序列化"实现，SNP 态与其 3 条迁移边是声明未落地的死代码；1g1b T7 的"状态迁移"语义未真实现。建议：要么真实进入/离开 SNP，要么删边并登记实现偏移。
2. **end_turn 传入 ACT 态会崩**：`end_turn` 允许 `state in (ACT,RES)`（L1311），但若玩家已行动（state 回 ACT）而怪物未行动时直接 `end_turn` → `start_turn` 内 `ACT→ACT` 不在迁移集 → 抛错。player_act 正常路径先 enemy_act 故不触发；低层 API 误用可达。建议：end_turn 加 `if self._state != STATE_RES` 前置或补 (`ACT,ACT`) 幂等。
3. **玩家死亡结算标记 resolve_at="immediate"**：`_resolve_battle_end` L649 与反射死亡 L1213-1218 对"玩家死"直接 `_settle(..., resolve_at="immediate")`；1g1b T4 / 1g1c TC-12 措辞为「当轮事件末尾统一结算一次」。行为可接受但标记语义不一致，建议统一为 turn_end（或补设计裁决）。
4. **快照随机种子回卷而非续接**：`to_snapshot` 只存初始 `_rng_seed`（L1414），`from_snapshot` 以同一 seed 重新播种（L1443-1444）→ 恢复后 PRNG **重放**（下一回合 roll 序列 = 第一回合的 roll 序列），docstring L49「恢复后随机序列一致」仅"确定性"成立、非"续接"。若要续玩流一致需在快照中保存 PRNG 状态位点。
5. **快照 boundary 标注与真实落点错位**：`end_turn` 已自动 start_turn（①/② 已跑，turn+1），非终局快照恒标 turn_start（L1401-1402），与 1g1a §8「回合开始前」语义有差；`from_snapshot` 的 "turn_end" 分支（L1463-1466）对非终局快照不可达（除非显式传 boundary），且其"回 PREP→再 start_turn"路径会对已跑过的 ①/② 重复结算。
6. **F-23 只聚合 attacker 单属性 atk**：`_apply_boost_to_mult(attacker, base_mult, "atk")` 硬编码 atk（L1143），魔法攻击（走 int/mag，L1148-1149）不获 stat_modifier 加成；S7 `cap_combined` 只截正上限不截负下限（effects L827-832）。建议按 attack_type 选 stat 聚合。
7. **战斗结束无公开"回 PREP 再战"入口**：1g1a §1 PREP「战后亦可作为再战入口」未实现——战后 `_state` 为终态，`start()` 被 L776-777 拒绝；需新建引擎实例。建议补 `reset()`/`start()` 对终态重置支持（木桩连打场景）。
8. **action_record / 快照字段未全落 1g1c schema**：缺 `combo_seg`/`combo_delta`/`hp_delta_src`（1g1c §1.2 四）；`_engine_state`（L1411）存了但 from_snapshot 未用（死字段）；`timestamps.updated_at`（L794-813）从不刷新。
9. **杂项收敛**：stats_collector 判 `damage.get("final",0) >= 0`（battle L539）恒真（含 miss 的 0 伤害入册，语义疑似应 >0）；`effects._resolve_value` 对纯数字字符串（非 %/非公式，L1400-1401）回 0 兜底——内容包若用字符串写数字 value 会静默归零；EffectRuntime 在 battle 内恒 `config=None`（battle L370）→ S6/S7 上限不可经战斗 config 注入；formula 快路径对大整数（>2^53）算术与 Node 浮点结果理论可差（域外，游戏数值不达）。
