## 一、热重载四项接线（WIR-xx）

### 1.1 接线总览（四项清单）

HotReloadWatcher 由「content 层自测完备的独立组件」升级为「壳层接线对象」。M6 接线清单显式含四项（承接【组B】P2-6 点名，防漏掉 F5 验收①「人话提示」）：

| 项 | 接线点 | 落点规则 |
|---|---|---|
| ① 启动装载 | watcher.start() 首次装载 + content 包发现 + 首轮失败策略 | WIR-02 / WIR-03 |
| ② 调度驱动 | apscheduler 定时任务驱动 poll_once，poll_interval_ms 可配 | WIR-04 / WIR-05 |
| ③ /重载 真实后端 | GmBackend.reload_content 实装 = watcher.reload（同一条管线），权限分级 | WIR-06 / WIR-07 / WIR-08 |
| ④ ReloadResult 人话翻译 | 成功/失败回退/连续失败暂停/无变更 四模板进 3d 消息模板注册表 | WIR-09 / WIR-10 |

## 二、P0-1 续战旧配置修复（RSM-xx）

### 2.1 缺陷根因与修复方案

【组B】P0-1：F5 承诺的「旧局旧配置」只对**内存中在途战斗**成立（引擎持旧 registry 对象引用）；对局被打断/存档后**热重载再续战**：敌方战斗数值从 `_snap` 还原（start 时已快照，旧值），但效果/状态/印记解析依赖 from_snapshot 注入的 pipeline/defs——调用方若传当前（新）registry，续战对局 = **旧 combatant 数值 + 新 effects/status/marks 解析混跑（半套配置）**。「ID+名称冗余」只够显示层防悬空（resolve_name），还原解析用配置仍需旧 registry 对象或世代绑定；快照无世代、_backup_snapshot 无调用方。

修复方案（三路组合，对应组B 修复建议 1/2/3）：
1. 快照 dict 增 `registry_generation` 字段（RSM-02）；
2. `from_snapshot` 增 `registry` 参数并在 `BattleEngine.__init__` 透传（RSM-03）；
3. 续战入口按世代从 `HotReloadWatcher._snapshots`（N=2 滚动）取对应 registry 快照重建 `Registry` 注入（RSM-04）；会话层按「会话创建时刻世代」持久化绑定（RSM-08）。

## 四、边界与遗留（决策记录）

**ADR-D3-01（首轮装载失败 = 启动失败）**：watcher.start() 红拦/异常 → 装配层按启动失败处理，不对外服务带病空 registry。理由：空 registry 对外服务即半套配置风险（【规则】L178），宁可启动失败。影响用例：TC-WIR-02。【细化定型】

**ADR-D3-02（批语义取「节拍内 Δ 为一批」）**：攒批完成机制二选一取「轮询节拍内检测到的全部变更集 Δ 为一批、一次管线全包构建」（当前实现口径），不取 manifest 最后写标记方案。理由：零新增完成信号、与现有 _detect_changes 一致。影响用例：TC-WIR-12。【组A】G2。

**ADR-D3-03（世代缺失降级 = 取最近 ≤ 世代档 + 告警）**：快照 registry_generation 超出 N=2 档范围时，取最近一份世代 ≤ 快照世代的档并日志告警，不拒绝恢复（除非引用 ID 已删 → 运行期降级）。影响用例：TC-RSM-04。【细化定型】

**ADR-D3-04（SessionManager 实装归 D5）**：世代绑定契约由本档定义（RSM-08），实装（acquire/release/restore 非桩）归 D5（总纲 批序表 批5，掉线重连批）。影响用例：TC-RSM-07。
