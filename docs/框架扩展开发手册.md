## 三、最小上手（外部开发者最快的路）

1. **新建内容包**：`content/<包>/manifest.json` 声明模块 → 编辑器「**推荐组合**」一键勾（基础 RPG / 生活冒险 / 故事探索）→ 写各模块 JSON；
2. **要加玩法**：先在《手册·2》§7 找**有没有现成声明段**（93 条里有就写声明，不写代码）；
3. **要加代码**：走 **E1 指令 / E2 渲染 / E3 测试脚本**（**双闸默认关**，重名拒）；**只 import `qbot_rpg.ext_api`**（其余 `qbot_rpg.*` 为内部实现，**不承诺兼容**）；
4. **校验**：起编辑器 → 点「校验」→ 红拦必改、黄提示按需；
5. **交付**：导出 `.ttrpack`。

## 四、★ 给维护者：「勿当 bug 修」速览（完整版见《手册·3》§3）

| 现象（看着像 bug） | 真实设计 | 判据 |
|---|---|---|
| **锻造没有随机/成功率/失败分支** | 失败与随机**刻意隔离**到炼金与强化；锻造是确定性派生树、零会话原子 | `docs/m9_启动包.md:75/95`、`docs/细化/细化_2c2b_锻造流程契约.md:14/250` 等 8 处 |
| **同一效果旧键/新键都能写，且旧键符号常相反** | **键族别名归并**（`EFFECT_LEGACY_ALIASES` 等），为兼容既有内容 | `data/gear_stats.py`（批50/53 归并不双计） |
| **某表/常量还在，但已不生效** | **legacy 兜底 + 声明优先双轨**（包声明驱动新路径，旧常量兜底不砸包） | 批71 模式（`stance` / `role` / `sp_effects` / `schema_ext`） |
| **`mitigation` 阶段没并进承伤乘区** | 与**护盾/保底伤害交织**，混入易伤会算错（有意接受收敛度更低） | 批52 决策记录 + 批50 `consumer_note` |
| **`EVENT_POINTS` 里有 17 点，但只有 11 点会派发** | 其余属**二期预留**（声明 ≠ 可用；**用前先查手册**） | 《手册·2》§2 |
| **`ctx` 有约 170 个键却没有单一源** | 历史演进所致，**已知缺口**（不是设计，属待收敛） | 《手册·1》§6 |

> **判定原则（《手册·3》§3.7.2）**：能给出**文档铁律 / 代码注释 / CHANGELOG 裁决**判据的 → **不要动**；只能给出"看起来不合理"的 → **按 bug 处理并登记**。**置信度"待查"的，先查清再动手。**

## 五、维护规则（**重要**）

1. **本手册与其三章随框架版本更新**：凡改动 **[稳定契约]**（《手册·1》§5 / 《手册·2》§6 等）→ **必须同步更新手册并评审**；
2. **新增常量/字段/事件/声明段** → 同步进对应章节的表格（**表格是本手册的价值所在**）；
3. **发现"故意设计"被误改** → 立即回滚并在《手册·3》§3 补一条判据；
4. **手册与实现冲突时**：以**代码 + 门禁脚本**为准，并在文档登记偏差（不得只改文档不改代码）。

## 七、附：技能等级变量（批80 新增 · 2026-09-23）

**用途**：技能等级**不内置任何数值映射**；框架只把它作为**变量**交给作者，**由作者在技能公式里自行使用**。

| 项 | 说明 |
|---|---|
| **写法** | 技能公式中的占位符 **`[技能等级:<技能ID>]`** → 求值时取 `attacker.skill_level[<技能ID>]` |
| **值从哪来** | **三源并集**（**装备赋予** / **套装档位** / **`skill_slots` 行 level**），**同技能多源取最大**；纯读、不写存档（`core/skill_slots_battle.py`） |
| **何时可得** | **施放该技能时**（由装配层进战注入 `self._config["skill_levels"]`，`core/battle.py`） |
| **缺省行为** | 该技能**无等级来源** → 等级 **1**；公式**不引用该变量** → 结果**逐字节与改动前一致** |
| **声明侧（F18）** | `skills[].level = {max, growth[]}`：**`max ≥ 2` 才进等级线**；`growth` 长度须 = `max`、`growth[0]` 须 = 1.0（**非法红拦**）；既有标量 `level: 1` **兼容**（不报错、不进线） |
| **示例** | `[技能等级:fireball] * 8 + 100`（等级越高倍率越大——**用什么曲线由作者定**） |

> **【稳定契约】**：变量名 `[技能等级:<技能ID>]` 与三源合并规则（多源取最大）为稳定面，改动需评审。
> **勿当 bug 修**：框架**故意不内置**"等级→伤害/冷却"的映射——那是**作者的公式自由**，不是缺失功能。
