## 〇、契约总则

### 0.1 术语表

| 术语 | 定义 | 依据 |
|---|---|---|
| 印记 | 战斗中的**资源标记**，独立"标记类"效果，不算正面/负面效果；可挂自己也可挂敌人，统一系统记录管理 | 【印记】§1.1 |
| 极性 polarity | 印记定义标注"对本方是正/负"：positive=对自己有利的资源印（火印）；negative=对自己有害的威胁印（诅咒印） | 【印记】§2.1 |
| 双向管理 | marks_state 按战斗侧分表（player/enemy 各一张），实例记录施加方 applier | 【印记】§三 |
| 寻址 | 消除动作以 marks_on（self/enemy）+ polarity 过滤（+可选 mark 指定）定位目标实例 | 【印记】§2.1 / §4.2 |
| 叠消用 | 核心循环：叠印→攒印→印记达标→技能派生/强化；消除技清对方印记；消耗技变现 | 【印记】§1.3 |
| 施放前快照 | 指令确认瞬间的战斗状态快照；条件评估与 consume 不足判定均基于该快照，施放后不重评 | 【印记】§5.1 / §5.2 |
| 被拒规则 | 指令因条件不满足被拒：不耗回合、不改连段、不清印记、可反复尝试（复用技能库被拒语义） | 【印记】§5.2；路1 T27 |

### 0.2 一句话契约

> 印记 = 战斗内独立"标记类"资源（非增益/减益/控制），配置于 marks.json，运行期状态存 marks_state 双向表，
> 只能通过 mark_add / mark_remove / clear_marks 三个框架级原子动作与 consume_marks 消耗原语操作；
> 不吃驱散/免疫/反射/解除，唯一移除通道 = 显式消除动作 + 生命周期（tick 扣减 / 逃跑清空 / 战斗结束清零）。

### 0.3 契约决策记录（ADR，均为对定稿空白的显式收敛）

| 编号 | 决策 | 理由 | 影响用例 |
|---|---|---|---|
| D-01 | consume 不足判定的口径 = **施放前快照、指令处理时（先于结算）**。【印记】§5.2 的"执行次序：条件评估→结算→扣除"与"印记不足=指令被拒（不耗回合不改连段不清印记）"并读，被拒语义要求整条指令未执行；故不足判定与条件评估同属指令门禁，用同一快照。同技能含 mark_add 时仍按施放前快照判定，防"自产自销"绕过不足检查（与 §5.1 死配置规则同精神） | 消除定稿两条款的表观矛盾 | AT-17 |
| D-02 | mark_remove 支持可选 `mark` 精确指定（与 clear_marks 同寻址语法）；寻址规则"marks_on + polarity 过滤（+可选 mark 指定）"【印记】§4.2 覆盖消除动作族整体 | 定稿示例未列 mark_remove 的 mark 参数，但寻址描述通用 | AT-11 |
| D-03 | 消除按**饱和减法**：mark_remove 的 count 超过现有层数时消至 0，不报错；与 mark_add"到顶不再涨"【印记】§4.1 的钳制语义对称 | 消除是反制手段，超量不应使指令失败 | AT-11 |
| D-04 | marks_state 实例冗余存储 polarity（定义快照化），与 mark_id+name 冗余同因：防热重载失效，显示与寻址不依赖定义表 | 【印记】§三 实例示例即含 polarity；§九 热重载降级原则 | AT-04 / AT-08 |
| D-05 | applier 取值 = 战斗侧枚举 `"player" | "enemy"`（非全局 actor id）；v1 固定两侧，PVP 双方各存各表 | 【印记】§三 示例 applier 值即 "player"/"enemy" | AT-07 |

## 一、数据模型 A：marks.json（字段级 schema）

### 1.1 字段表（**10 字段**，框架 4.1 新增文件）

| # | 字段 | 类型 | 必选 | 默认 | 枚举/取值 | 约束与语义 | 依据 |
|---|---|---|---|---|---|---|---|
| 1 | id | string | ✅ | 无 | 全局唯一 | 引用键（技能效果/条件/消除寻址均按 id 引用） | 【印记】§二 |
| 2 | name | string | ✅ | 无 | 非空 | 显示名；冗余写入 marks_state 实例（防热重载失效，对齐 combo_state） | 【印记】§二/§三 |
| 3 | icon | string | ✅ | 无 | emoji | 显示用；资源印 🔥 / 威胁印 🩸 由 polarity 派生图标区分 | 【印记】§二/§2.1 |
| 4 | type | string | ✅ | 无 | 仅 `"mark"` | 标记类第四类型标识；枚举外取值→校验拒绝 | 【印记】§二/§1.2 |
| 5 | max_stack | int | ✅ | 2–3 | ≥1；`0`=不限 | 叠加上限；重复施加=+count 至上限，到顶不再涨 | 【印记】§二/§4.1/§6.2 |
| 6 | appliable_to | string[] | ✅ | 无 | 非空子集 ⊆ {`"self"`,`"enemy"`} | 可挂自身/敌人；空数组→校验拒绝 | 【印记】§二 |
| 7 | polarity | string | ✅ | 无 | `"positive"` \| `"negative"` | 对本方是正/负；实例冗余存储 | 【印记】§二/§2.1 |
| 8 | element | string | 可选 | 无 | ∈ formula.json 元素注册表 | 可选元素引用；**v1 不参与克制**；未注册 id→校验拦截 | 【印记】§二 |
| 9 | duration | string | ✅ | `"battle"` | `"battle"` \| `"turns:N"`（N≥1） | battle=战斗内永续；turns:N=限时，剩余回合记入 marks_state.remaining_turns | 【印记】§二/§三 |
| 10 | desc | string | ✅ | 无 | 非空 | 描述 | 【印记】§二 |

### 1.2 示例（对齐【印记】§二）

```json
{
  "id": "fire_mark",
  "name": "火印",
  "icon": "🔥",
  "type": "mark",
  "max_stack": 3,
  "appliable_to": ["self", "enemy"],
  "polarity": "positive",
  "element": "fire",
  "duration": "battle",
  "desc": "元素之力凝聚的火焰印记"
}
```

## 二、数据模型 B：marks_state（快照结构）

### 2.1 结构（双向表，**实例 6 字段**；3.18 战斗快照扩展）

```json
{
  "marks_state": {
    "player": [
      {"mark_id": "fire_mark", "name": "火印", "count": 3, "applier": "player", "polarity": "positive"}
    ],
    "enemy": [
      {"mark_id": "curse_mark", "name": "诅咒印", "count": 2, "applier": "enemy", "polarity": "negative", "remaining_turns": 3}
    ]
  }
}
```

| # | 字段 | 类型 | 必选 | 语义 | 依据 |
|---|---|---|---|---|---|
| 1 | mark_id | string | ✅ | 印记定义引用键 | 【印记】§三 |
| 2 | name | string | ✅ | 冗余存储显示名（防热重载失效，删配置后仍可显示/降级） | 【印记】§三/§九 |
| 3 | count | int | ✅ | 当前层数（≥1；≤ 定义 max_stack，0=不限时不受限） | 【印记】§三 |
| 4 | applier | string | ✅ | 施加方战斗侧：`"player"` \| `"enemy"`（D-05） | 【印记】§三 |
| 5 | polarity | string | ✅ | 冗余自定义（D-04）：消除寻址 = marks_on + polarity 过滤的直接依据 | 【印记】§2.1/§三 |
| 6 | remaining_turns | int | 条件可选 | 仅限时印记（duration: turns:N）存在；battle 型**不占**该字段（省略） | 【印记】§三/§八 |

### 2.2 生命周期规则

| 时机 | 行为 | 依据 |
|---|---|---|
| 施加 | mark_add：必中、技能结算**末尾**施加；重复=+count 至上限（到顶不再涨） | 【印记】§4.1 |
| 每回合结束 | 限时印记 remaining_turns 统一 tick 扣减；值同步写入快照（中断恢复按 remaining_turns 还原，"marks_state 全保留"可兑现） | 【印记】§三 |
| 归零 | 被控保留；逃跑成功清空、失败保留；战斗结束一律清零 | 【印记】§5.3 |
| 施加方/目标死亡 | 战斗结束自然清零（不单独触发即时移除） | 【印记】§三 |
| 热重载删印记 | 已有实例按 name 冗余降级显示；技能效果按「无印记」降级不报错 | 【印记】§九 |

### 2.3 快照契约

- marks_state 入 3.18 战斗快照；中断恢复全量还原（含 remaining_turns），恢复后 10 秒内可继续战斗（路1 T52）。
- PVP：双方各存各表（player/enemy 都入快照）。
- 战斗内资源：随战斗结束清零，与连段（combo_state）一致。
- 双轴各自独立：combo_state 与 marks_state 生命周期各自管理，互不读写对方字段。

## 三、原语集（**9 项**：条件 5 + 动作 3 + 消耗 1）

### 3.1 条件原语（5 项，写进 9.3 条件 Schema + 编辑器下拉；键名避开 count）

| # | 原语 | 语法示例 | 语义 | 依据 |
|---|---|---|---|---|
| C-1 | `self_marks` | `{"self_marks": {"fire_mark": {"min": 3}}}` | 施放者身上指定印记层数满足 min/max（至少其一，V-2 校验） | 【印记】§5.1 |
| C-2 | `target_marks` | `{"target_marks": {"curse_mark": {"max": 1}}}` | 技能目标身上指定印记层数满足 min/max | 【印记】§5.1 |
| C-3 | `marks_total` | `{"marks_total": {"min": 5}}` | 施放者全部印记层数之和满足 min/max | 【印记】§5.1/§6.2 |
| C-4 | `marks_set` | `{"marks_set": {"all": ["地", "水", "火", "风"]}}` | 齐备：施放者同时持有列表内**全部**印记（每类 ≥1 层）；引用印记须有施加来源（V-6） | 【印记】§5.1/§6.2 |
| C-5 | `marks_any` | `{"marks_any": {"min": 3}}` | 施放者当前持有印记的**种类数**满足 min/max | 【印记】§5.1/§6.2 |

**公共语义**：
- 求值时机：基于**施放前快照**求值一次（指令处理时），施放后不重评；显示层印记变化后即时重算（置灰/点亮），结算层按确认瞬间快照求值一次（【印记】§5.1）。
- 复合：支持 and/or 复合引用（如 `and: 连段 count + self_marks`），复用派生条件引擎复合机制（【印记】§5.3）。
- 条件数量不设限（过多仅黄警告 V-5）；用阈值而非全组合配置派生（【印记】§6.2）。

### 3.2 原子动作（3 项，框架级，不走 x_ 前缀；3.4 词汇表新增）

| # | 动作 | 字段 | 语义 | 依据 |
|---|---|---|---|---|
| A-1 | `mark_add` | `target`: self\|enemy（独立于技能伤害 target）；`mark`: mark_id；`count`: int ≥1 | 施加必中（独立于伤害判定）；技能结算末尾施加；重复=+count 至上限；概率施加走 3.4 proc 包一层（动作语义不变） | 【印记】§4.1 |
| A-2 | `mark_remove` | `marks_on`: self\|enemy；`polarity`: positive\|negative；`count`: int ≥1（默认 1）；`mark`?: mark_id（可选精确指定，D-02） | 按**层数**消；寻址 = marks_on + polarity 过滤 + 可选 mark；超量=饱和减法至 0（D-03） | 【印记】§4.2 |
| A-3 | `clear_marks` | `marks_on`: self\|enemy；`polarity`: positive\|negative；`mark`?: mark_id | **整组清空**（全消，无 count）；寻址同 A-2 | 【印记】§4.2/§八 |

## 四、消除技平衡与 consume 不足即拒

### 4.1 消除技平衡（【印记】§4.2/§九 3）

| 维度 | 默认/规则 | 级别 | 依据 |
|---|---|---|---|
| 消除量 | 默认消 1 层（mark_remove count 默认 1） | 默认值 | §4.2 |
| 冷却 | 消 1 层默认冷却 2；作者改低（<2）→ 警告「消除技过强，注意 1:N 博弈」 | 软（黄警告） | §4.2 |
| 冷却硬下限 | cooldown ≥ 1 | 硬拦 | §九 3 |
| 全消/多消 | 全消（clear_marks）cooldown ≥ 3；多消/全消需更高成本（更长冷却/高 MP/无伤害/自身 debuff）为作者责任区 | 硬拦（全消冷却）/ 建议 | §4.2/§九 3 |
| MP | mp_cost > 0 | 硬拦 | §九 3 |
| combo 标签 | 消除技默认**无** combo 标签（=普通技能，断自己连段=自然代价） | 默认行为 | §4.2 |

### 4.2 consume_marks 不足即拒规则（【印记】§5.2；复用被拒规则）

1. **执行次序**（成功路径）：条件评估（施放前快照）→ 结算 → 扣除印记（结算后扣）。
2. **不足判定**：口径 = 施放前快照、指令处理时、**先于结算**（D-01）；所需层数不足 → 整条指令被拒。
3. **被拒副作用清单**（全无）：不耗回合、不改连段、不清印记；可反复尝试（对齐技能库指令被拒语义，路1 T27）。
4. 消耗印记的派生**默认 combo_preserve**（保留连段，双轴各管各的）。

## 五、边界契约：不吃驱散/免疫/反射（【印记】§1.2/§5.3）

### 5.1 唯一移除通道

```
印记移除 = 显式消除动作（mark_remove / clear_marks，仅消除类技能可配）
          + 生命周期（remaining_turns tick 扣减至 0 / 逃跑成功清空 / 战斗结束清零）
禁止任何其他路径移除印记。
```

### 5.2 不命中清单（对印记一律无效）

| 系统 | 规则 | 依据 |
|---|---|---|
| 驱散/净化（dispel FIFO 寻址） | 不命中印记（驱散=清增益、净化=清减益；印记不算增益/减益） | 【印记】§1.2；效果 T15 |
| 免疫矩阵（immune_vs 四维） | 不拦印记（印记非状态异常；status 维度仅挡负面状态） | 【印记】§1.2；效果 T18 |
| 反射 | 不反弹印记（反射只作用于伤害） | 【印记】§1.2 |
| 解除/控制 | 不解除印记；**被控保留**（归零规则对齐） | 【印记】§1.2/§5.3 |
| 状态异常 3.4 五维 | 不互通：印记不占 5 位状态显示（专属印记行）、不吃状态衰减、状态栈叠加规则不适用 | 【印记】§1.2/§七 |

### 5.3 系统边界表

| 相邻系统 | 边界约定 | 依据 |
|---|---|---|
| 显示（7.1 状态行扩展） | 印记行独立：「🔥火×3/3 💧水×2/5」；资源印🔥/威胁印🩸；不占 3.4 的 5 位状态位；PVP /查看目标 显示目标印记（模糊信息"目标身上有 N 个印记"可选） | 【印记】§七 |
