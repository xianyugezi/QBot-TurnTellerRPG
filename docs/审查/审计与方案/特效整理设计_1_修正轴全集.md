## 0. 口径、全局约定与归并前的事实纠正

### 0.1 本文要解决的问题

把 5 份搜集报告的「需新轴 / 轴候选」**去重、合并同义**，产出**唯一一份轴全集**：
一条轴覆盖双向玩法，而不是「加一套 / 减一套 / 再造一个 debuff」。
本文只给**设计口径与归并方案**，不含实现代码。

### 0.2 全局约定（每条轴都遵守，正文不再重复）

| 编号 | 约定 | 说明 |
|---|---|---|
| **R-1** | **数值口径 = 倍率（mult）** | 单值 `float`，**默认 `1.0` = 原样**；`<1` = 减弱方向，`>1` = 增强方向。与用户点名范例一致（`<1` 减疗 / `1.0` 原样 / `>1` 增疗），也是 R4/R5 的主口径。**否决**「正向 `_pct` 默认 0、反向另造一键」。 |
| **R-2** | **加算轴例外** | 层数上限 / 行动条 / 移动力 / 范围 / 属性上限这类**整数阈值语义**用差值 `int`，默认 `0`。双向 ≠ 必须百分比（R3 §3.1 已点明）。 |
| **R-3** | **`_pct` 是书写糖，不是第二套轴** | 存量 `xxx_pct`（百分点）→ `mult = 1 + pct/100`，反向 `pct = (mult-1)*100`。换算落在聚合入口 `route_bonus_into`（`qbot_rpg/data/gear_stats.py:192-210`），**存量内容零迁移**。 |
| **R-4** | **同一轴线的 `dealt` / `received` 是两个注册实例，不是两条轴** | 治疗、状态时长、状态概率、层数获取都有「我施加」与「我承受」两侧。共用**同一轴线定义/钳制/消费点**，但**保持两个键实例**——施疗方与受疗方是两个实体，合并会让「减疗装备」产生归属歧义（R3 §3.5）。层数上限/时长这类无需区分的轴则只用单键。 |
| **R-5** | **范围/上下限一律包声明** | 本表「建议范围」是**缺省值**，写进内容包 `axes` 段；消费点只读不写死。**禁止**在 `effects.py` / `battle.py` 里硬编码钳制（既有反例：`max_boost_pct` 虽在 `_DEFAULT_CONFIG`，但仍是引擎常量）。 |
| **R-6** | **落点三档** | ① `gear_stats` 键空间（装备词条，α 组接法）；② **通用修正层**（新注册表 `axes`，装备/状态/效果都能写）；③ 状态/效果层（status def 字段 / effect action 参数）。**本全集主体注册在②**，①只作别名，③是消费点。 |
| **R-7** | **归并等级四档** | `已有·直接复用` / `已有·接消费点`（键已注册、消费点为 0）/ `已有·升级或替换`（占位键、单向键）/ `新轴`。 |

### 1.1 伤害族（15 条）

#### X01 · `dmg_dealt_mult` ｜造成伤害修正
- **语义**：自己造成的最终伤害 ×mult，可按 `scope` 过滤；`scope ∈ {global, phys, magic, elem:<id>, dot, basic, skill:<tag>, channel, target_tag:<x>, target_state:<y>, weakness, content:<z>}`。
- **方向/范围/默认**：**双向**｜建议 `0.1–5.0`（负值不开放，见 §4）｜默认 `1.0`。
- **落点**：通用修正层（**终伤乘区**）＋ gear_stats 别名 `dmg_dealt_pct`。
- **归并**：把 `weakness_dmg_pct`（`gear_stats.py:99`，未接消费 `:170-171`）收编为 `scope=weakness` 的一个取值，**保留旧键作别名**；复用 α3 技能增幅乘区（`battle.py:3029-3034`）与 `_aggregate_boost` 的「加法叠乘 + S6/S7 封顶」口径（`battle.py:952-984`，封顶值 `effects.py:120-121`）。与 `atk_pct` **不重复**：`atk_pct` 走属性乘区且受 S6/S7 封顶，本轴是终伤乘区（是否受封顶可配）。
- **来源**：R1#2、R3§3.1 `outgoing_damage_pct`、R4-A3 `dmg_dealt_mult`、R2-AX-4 `damage_scope_pct`、R5（M 系列定向增伤）。

#### X02 · `dmg_taken_mult` ｜承受伤害修正（易伤 / 减伤同一轴）
- **语义**：自己受到的伤害 ×mult。`>1` 易伤，`<1` 减伤，`=0` 免疫。
- **方向/范围/默认**：**双向**｜建议 `0.0–3.0`（`0` = 免疫；不建议负值，反伤走 X14）｜默认 `1.0`。
- **落点**：通用修正层＋ gear_stats 别名 `dmg_taken_pct`；消费点 = 伤害管线 `_stage_mitigation`（`effects.py:1080-1110`）与状态侧 `_status_damage_mult`（`battle.py:3998-4020`，实际乘入 `:4601`）。
- **归并**：`immune_dmg`（`gear_stats.py:104`，真实消费 `battle.py:4603-4610`）是**本轴负半轴子集**，保留键并等价换算 `mult = 1 - immune_dmg/100`（**不删键**，存量内容不受影响）；R1#21 `dmg_taken_mult_by_state` 收编为 `scope=target_state:<id>`；R2-AX-2 的「易伤」不另造 `vulnerable` 状态类型。**乘区口径待裁决**（与 `mitigation` 阶段叠乘还是替换，见 §5-D3）。
- **来源**：R2-AX-2、R3§3.1 `incoming_damage_pct`、R4-A3 `dmg_taken_mult`、R5-轴2、R1#21。

#### X03 · `crit_dmg_mult` ｜会心伤害倍率修正
- **语义**：暴击时的伤害**倍率**×mult。
- **方向/范围/默认**：**双向**｜建议 `0.1–5.0`｜默认 `1.0`。
- **落点**：通用修正层（会心乘区）。
- **归并**：`super_crit_lv` / `elem_crit_lv`（`gear_stats.py:103`，封顶 3 档，`gear_stats.py:125-126`）**保持独立**——它们是离散档位，视作本轴的**离散取值**即可，不并入、不替换。
- **来源**：R4-A12 `crit_dmg_mult`、R3§3.1 `crit_damage_pct`、R1（E07/E40/E53 会心族）。

#### X04 · `crit_rate_add` ｜会心率修正
- **语义**：会心概率的百分点加算（可负）。
- **方向/范围/默认**：**双向**｜建议 `-100..+N`｜默认 `0`。**加算语义**（概率直线叠加，同 `crit` 现状）。
- **落点**：`gear_stats` 键空间（COMBAT 档，已有）。
- **归并**：**已有·直接复用** —— `crit`（`gear_stats.py:103`；桥接封顶 `None` = 可负，`gear_stats.py:123`；消费 `damage.py:342 crit_prob`）。本轴无需新键，只把它在轴全集里登记为一等公民。
- **来源**：R1#10、R3§3.1（会心族）。

#### X05 · `avoid_mult{kind}` ｜命中/闪避对抗
- **语义**：`kind ∈ {hit, evade, crit_avoid}`。`hit` = 自己命中率 ×mult；`evade` = 自己被命中前闪避判定；`crit_avoid` = 把敌方会心降级为普通命中。
- **方向/范围/默认**：`hit` **双向** `0.1–5.0` 默认 `1.0`；`evade`/`crit_avoid` **单向** `0..100%`（见 §4-E2，故同轴内以 `kind` 区分方向）。
- **落点**：通用修正层；消费点 `damage.py:422 hit_rate` / `:453 block_rate` / `:342 crit_prob`。
- **归并**：R3§3.3 `evasion_pct` 与 R1#11 `evade_pct{source}` 合并为同一轴的 `kind=evade`（`source ∈ melee/projectile/aoe` 作 scope）；R1#10 `crit_avoid_pct` 收编为 `kind=crit_avoid`（对抗项，与 `crit` 成对）。
- **来源**：R1#10、R1#11、R3§3.1 `hit_pct`、R3§3.3 `evasion_pct`。

#### X06 · `pierce{target}` ｜穿透参数化
- **语义**：`target ∈ {defense, elem_res:<id>}`；值分「点」与「比」两层。
- **方向/范围/默认**：**单向**（≥0）｜点：`0..N`；比：`0..100%`｜默认 `0`。**为什么不能双向**：负穿透 = 给目标加抗，语义上属于「对目标的属性修改」，应由 `effects.stat_modifier` 负向改 `dfn` 表达（`effects.py` 对 target 属性生效），不做进穿透轴。
- **落点**：`gear_stats` 键空间（COMBAT 档，已有）＋通用层扩展。
- **归并**：`pierce_val/pierce_pct/mag_pierce_val/mag_pierce_pct`（`gear_stats.py:104-105`，封顶 100 `:131/133`）**扩展**出 `elem_res:<id>` 目标参数；R2-AX-13 `target_resist_mult`（减抗/减防）**并入本轴**（减抗 = 提高穿透，不是新轴）；效果原子 `pierce`（`effects.py:1827-1832`）合并到同一封顶口径。
- **来源**：R1#14、R1（E04 按元素穿透）、R2-AX-13、R4（G09/F06 族）。

#### X07 · `dmg_reduction_flat` ｜固定值减伤
- **语义**：作用于单次伤害的**定值**减免（与百分比是不同乘区）。
- **方向/范围/默认**：**单向**（≥0）｜`0..N`｜默认 `0`。**为什么不能双向**：负值加伤已由 X02 覆盖，重复造轴违反归并原则（R3 §3.2 已判）。
- **落点**：状态/效果层＋通用层；消费点 = `_stage_mitigation`（`effects.py:1080-1110`，现读状态 `mitigation.value`）。
- **归并**：**已有·直接复用**（状态 def 的 `mitigation` 段），只是登记进轴全集并允许装备侧写入。
- **来源**：R3§3.2、R1（固定减伤族）。

#### X08 · `dmg_bounds{cap,floor}` ｜单次伤害上下界
- **语义**：`cap` = 单次受伤上限（「无形」把伤害钳到 1）；`floor` = 单次伤害保底。
- **方向/范围/默认**：**单向**（上界钳制/下界保底无「反向的下界」语义）｜`cap: 1..∞`（0=不限）；`floor: 0..∞`（0=关）｜默认全 `0`。
- **落点**：通用修正层＋效果层；消费点 = `_stage_mitigation`（`effects.py:1080-1110`）。
- **归并**：**`floor` 半边已有** —— `ctx.variables["min_damage"]` 保底伤害机制（`effects.py:1080-1110`，仅命中实例由 battle 注入，floor 而非 set，只抬不压）；`cap` 半边缺失（R4§3.2、R3§3.3）→ 新增。**`cap` 与 `floor` 不强行合成一条轴的非负/非正两端**，用同一 key 的两个字段。
- **来源**：R4§3.2 `damage_taken_cap`、R3§3.3 `damage_cap_add`、R1（八方旅人 Surpassing Power）。

#### X09 · `dmg_convert{from,to,pct}` ｜伤害转换
- **语义**：把一类伤害按 `pct` 转成另一类（元素/物理），一次性、不可链式。
- **方向/范围/默认**：**单向**（`from→to` 是方向而非正负）｜`0..100%`（合计封顶可配）｜默认 `0`。
- **落点**：通用层；消费点 = 伤害通道 `damage.py:524 channel_phys` / `:557 channel_elem` 之前（元素空间 `damage.py:73-81`）。
- **归并**：效果原子 `convert` 目前是**占位**（`effects.py:2014-2016`，只落 `side_effects` 不结算）→ 升级接线；R1#13 的 `dmg_gain_as_extra`（额外获得而非替换）作为同轴 `mode` 字段。
- **来源**：R1#13、R1（PoE 转换族）。

#### X12 · `drain_to_resource{resource_id,pct}` ｜伤害转资源（吸血泛化）
- **语义**：按造成伤害的 `pct%` 回充**任意资源**（HP/MP/自定义资源轴）。

1. **没有任何「同义但必须并存」的轴**——5 份报告共 60+ 个候选，归并后 **48 条轴**，其中 **9 组**是「多报告同义」（治疗受身 5 处、承伤 5 处、冷却 5 处、时长 4 处、层数 4 处、奖励 4 处、属性转化 2 处、击退/位移 2 处、伤害基准 2 处）。
