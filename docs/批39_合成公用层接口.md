# 批39 · 「合成」公用层：接口与调用边界（打造 / 炼金 / 合成）

> 拍板依据：`docs/深度打造_决策记录.md` §六（用户 2026-09-19 二次）——把「合成」作为**打造与
> 炼金的公用系统**；玩家可只启用合成，再加炼金或打造。
>
> 本批范围：**归位 + 接口就位**（不实现打造深度层；打造主流程见批40）。

---

## 一、三层 + 三条启用路径

```
合成（公用层：装备 / 药剂 / 材料 皆可走；极度简化的投料产出）
  ├─ 炼金  → 深度炼金   （职业专属 → 大师解锁；走 recipe + alchemy 三层漏斗）
  └─ 打造  → 深度打造   （走 recipe 公用合成 + 打造深度层）
```

| 启用路径 | 声明 | 合成 | 炼金 / 深度炼金 | 打造 |
|---|---|---|---|---|
| ① 只启用合成 | `settings.alchemy.mode = "simple"` | ✅ | ❌ | 关（`deep_craft.enabled` 默认 false） |
| ② 合成 + 炼金 | `settings.alchemy.mode = "full"` | ✅ | ✅ | 关 |
| ③ 合成 + 打造 | `mode = "simple"` 或 `"full"` + `settings.deep_craft.enabled = true` | ✅ | 由 mode 决定 | ✅ |
| 全开 | `mode = "full"` + `deep_craft.enabled = true` | ✅ | ✅ | ✅ |
| 关闭 | `settings.alchemy.mode = "off"` | ❌ | ❌ | ❌（打造依赖公用合成层） |

- **缺省 = 现状**：不配置 `mode` → `full`（合成 + 炼金）；不配置 `deep_craft` → 打造关。
- **不是硬编码三段 switch**：炼金 / 深度炼金 / 打造专属层是否可用，由同一声明（`alchemy.mode`
  三态 + 打造开关）经 `qbot_rpg/core/craft_paths.py` **推导**；新增路径只需在 `mode_matrix()`
  加一列。
- 同一口径的唯一权威实现 / 测试锚点：`core/craft_paths.py::mode_matrix()` / `path_matrix()`。

## 二、公用合成 API（qbot_rpg/core/synthesis.py）

| API | 入参 | 出参 | 用途 |
|---|---|---|---|
| `resolve_recipe(ctx, ref)` | ctx + 配方名/id/序号 | recipe \| None | 配方解析（名称优先 → 序号兜底） |
| `base_output(recipe, ctx=None)` | 配方（+可选 ctx） | 单份**标准版产出**定义（quality=标准 / traits=[] / …） | 深度层「基础产出」定义（LAY-04a） |
| `requirements_of(recipe, count=1)` | 配方 + 数量 | `{count, materials[], cost{coins,gem}}` | 投入需求总量（不读玩家状态） |
| `preview_base_output(ctx, recipe, count=1, *, settings=None)` | ctx + 配方 + 数量 | `{ok, reason, count, advisory, requirements, shortfall, base_output, …}` | **给定投入 → 基础产出**（只读预演，不改玩家状态） |
| `SynthesisEngine.synthesize(ctx, recipe, count=1, *, on_codex=None)` | ctx + 配方 + 数量 | `{ok, message, produced, exp_gained, …}` | 事务落地（原子扣料 + 熟练 + 图鉴；不耗能量） |
| `SynthesisEngine.check_eligible(ctx, recipe)` | ctx + 配方 | `{ok, reason, recipe_level, job_id, synth_allowed, hint?}` | 守卫链（mode/配方/职业区间/synth_allowed） |

`preview_base_output` 的 `ok` 仅表示**投入是否满足**（材料/货币差额见 `shortfall`）；即使
`ok=False`，`base_output` 仍给出基础产出（供深度层展示）。拒绝场景（配方不存在 / 等级不足 /
深度未解锁 / mode=off / 数量非法）→ `base_output` 与 `requirements` 为 `None`。

## 三、打造侧怎么调用（边界铁律）

**打造只做深度层，基础合成走公用层。** 打造深度层（批40+）按下列方式消费公用 API，**不得**
另造第二套「投料 → 基础产出」：

```
# 1) 预演：给定投入 → 基础产出（只读，不改玩家状态）
p = preview_base_output(ctx, recipe_ref, count)         # core/synthesis.py
p["base_output"]        # 单份标准版产出 × count（item_id / item_name / count / quality…）
p["requirements"]       # 材料 + 货币投入总量
p["shortfall"]          # 差额（None = 满足）；p["ok"] = 投入是否满足
p["hint"]               # 深度配方绕过提示（CASC-04），原样透传或按打造口径改写

# 2) 深度层：在基础产出之上追加（图纸 / 材料相性 / 随机属性与套装词条 /
#    品质经验 / 强化词条 / 符文 / 淬炼）——这些是打造**私有**的，不回流公用层。

# 3) 落地：扣料 + 入包仍走公用合成引擎（原子 + 熟练，LAY-04a/LAY-05/CASC-01）
res = SynthesisEngine(settings=settings).synthesize(ctx, recipe_ref, count)
```

边界清单：

- ✅ 打造**可以**：调用 `preview_base_output` / `base_output` / `requirements_of` /
  `SynthesisEngine.synthesize` / `SynthesisEngine.check_eligible`；消费 `craft_paths` 的
  `forge_path_enabled()` 判定自身入口是否可用。
- ❌ 打造**不得**：复制一份配方解析 / 材料差额 / 标准版产出 / 熟练入账逻辑；改写
  `SynthesisEngine` 的标准版语义（`quality="标准"`、`traits=[]`）；在公用层写入打造私有字段。
- 炼金侧同理：炼金层（`/炼金` `/深度炼金`）在 `mode=full` 时可用，其**合成层**同样走
  `SynthesisEngine`；`mode=simple` 时只保留公用合成层。

## 四、指令归属（提层前 → 提层后）

| 指令 | 提层前注册方 | 提层后注册方 | 说明 |
|---|---|---|---|
| `/合成`（`SYNTH_CMD`） | `commands/alchemy_commands.register_alchemy_commands` | `commands/synth_commands.register_synth_commands`（**公用层**） | 本批归位；名称/参数/文案/行为不变；`alchemy_commands` 仅再导出常量与处理器 |
| `/炼金` `/投料` `/继承` `/继承超` `/确认` `/放弃` `/调合续` `/分解` `/深度炼金` `/即时调合` 等 | `alchemy_commands` | **不变**（炼金专属层） | `/投料` 属炼金层（需 `/炼金` 会话，GU-09）；非合成族 |

装配顺序：`REGISTER_GROUPS` 中 `synth_commands` 先于 `alchemy_commands`（`/合成` 只注册一次，
防同名双注册）。白名单：`/合成` 仍在 `commands/parsers.DEFAULT_WHITELIST`。

## 五、编辑器可见项

- **模块**：`recipe`（配方；框架目录在册，`requires=items`）——启用后其段/字段可见；
  `settings_section` 指向 `settings.alchemy.mode`。
- **合成 / 炼金开关**：`settings.alchemy.mode`（枚举 `full` / `simple` / `off`；默认 `full`）。
- **打造开关**：`settings.deep_craft.enabled`（`obj` + `enabled`，**默认关闭**；对齐批38
  `settings.equipment_offhand`）。说明卡写明「只启用合成 / 加炼金 / 加打造」的区别与影响。
- **校验**：`settings.deep_craft` 段结构/类型非法 → 红拦；打造已开但 `alchemy.mode=off`
  → 黄提示（不硬拦）。
