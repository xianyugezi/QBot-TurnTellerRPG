## 一、细化_4c 契约摘要（核心口径，行号已验证）

### 1.1 字段 schema（11 叶子字段，§1.1-1.3，【4c】L81-110）

- 顶层 8 字段（L93-100）：`id`（必选）/ `name`（必选 ≤20 字）/ `desc`（可选 ≤50 字，90% 档软锚例外）/ `conditions`（必选 list，三原语 `{var,op,value,param}`，空=接取即达成，D-09）/ `trigger`（enum，仅 `"check"`，默认 check，其它值硬拦）/ `once`（bool 默认 true；false=可重复达成黄提示）/ `hidden`（bool|obj 默认 false）/ `reward`（str|list 默认 []，内联串=糖，别名 `rewards` 等价）。
- hidden 子对象 3 key（L108-110）：`mode`（`locked`|`hide`，默认 locked）/ `reveal_text`（hidden 时建议必填，达成瞬间一次性揭示）/ `clue_ref`（线索引用 list，每隐藏成就 ≥1 条硬提示软拦）。
- 校验器（L114-116）：硬拦=引用不存在（title 未注册/物品未注册/变量或事件未注册）/ trigger 非 check / 类型错误 / 负数；黄提示=条件永假/超基准/once=false 通胀/conditions 空/hidden 缺 reveal_text/别名重复冲突；默认兜底 D-09。

### 1.2 四类解锁条件映射（§2.2，L146-149）——**全部复用既有条件键，零新 var**

| 类别 | var | param | 读取来源（已实现） |
|---|---|---|---|
| 图鉴完成度 | `codex` | 缺省=总册；monster/fish/item/craft=分册 | ctx["codex"] 标量（codex.py 投影）或 codex_state |
| 事件计数 | `[事件:xxx]` | 事件目标（可空） | event_counts（bump_event 写入） |
| 物品收集 | `gain_count`（累计）/ `item_count`（当前背包） | 目标物品 ID | longline_counters / inventory 快照 |
| 等级 | `level` | 无 | ctx["level"] 快照 |

条件键全量（§2.3，L155-158）：level / item_count / gain_count / kill_count / codex / dungeon_clear / main_progress / prof_level / reputation / [事件:*] / season / period / weather —— 全部在 condition_engine.REGISTERED_VARS 注册（见 §二.1）。

### 1.3 reward 四型（§3.1，L176-190）与结算管线（§3.2，L198-211）

- ① 物品 `{item,count}` ② 货币键值 `{coins|gem|exp|rep:N}` ③ 组合数组 ④ **称号型 `{title:"称号ID"}`（仅成就使用）**。
- 入账顺序：exp → 货币 → 物品 → 称号；单事务（D-04）；条目级失败黄字跳过不吞整次（L229）；幂等 message_id 快照（D-04）。

### 1.4 称号联动（§3.3，L217-225）

- 三来源：职业王 / 品评冠军 / **成就称号**（本契约 reward ④）。
- 佩戴 1 槽替换式；`/称号 查看` `/称号 佩戴 <N>`（L222）；消息前缀 `[称号]` 占位（L223）；title_state = owned 集合 + 当前佩戴（L224）。

### 1.5 隐藏成就两模式（§五，L275-280）

- `locked`（默认）：/成就 列表显示「？？？」锁定行占序号，不渲染 name/desc/reveal_text；达成后翻转正常展示。
- `hide`：列表完全隐藏不占序号。
- **不注册 /秘密 类指令**（L279）；达成瞬间 ⛩️ 一次性揭示卡片输出 reveal_text（D-08，L313-317）；未达成任何路径不渲染 reveal_text。

### 1.6 指令表（§七 L404）与状态持久化（§四）

- 指令：`/成就 [页数]`（5 条/页）/ `/成就信息 <N>` / `/称号` / `/称号 佩戴 <N>`。
- achievement_state（L243-248）：`unlocked: {成就ID: ISO8601}` + `repeat_count: {成就ID: N}`；只增不减（ACH-08）；热重载删除配置保留存档字段（L261-262）。

## 二、既有接口盘点（真实代码核对）

### 2.1 条件引擎 condition_engine.py（759 行，唯一实现）

- **REGISTERED_VARS 实际内容**（L127-141 VAR_CATEGORIES 扁平化）：`has_quest, quest_completed, quest_state, has_item, not_has_item, item_count, job, job_level, prof_level, level, reputation, main_progress, codex, gain_count, kill_count, dungeon_clear, [事件:<事件名>], time, is_day, is_night, season, period, weather, affection, [签到:<表名>.<字段>], any, all, not, x_<自定义>`。
  - 4c 四类条件键 **codex / [事件:*] / gain_count / item_count / level 全部已注册**，成就零新增 var。
  - 前缀模式运行时识别：`[事件:xxx]` → 读 event_counts（L570-571）；`x_` 扩展 → ctx["ext_vars"]（L572-576）。
- **eval_condition(cond, ctx) -> bool**（L611-646）：fail-safe 不抛错；list/tuple=全与（2b4 D-02 同款，成就 D-02 直接复用）；`{all:[...]}` 嵌套也支持。
- **validate_condition(cond, report) -> None**（L701-759）：结构红拦（var 未注册/op 非法/缺键）+ 旧格式/事件未登记黄提示；report 鸭子类型兼容 validator._Checker。
- 求值口径（L52-56 补白 4）：longline_counters 缺表=计数 0；event_counts 表整体缺失=求值失败→False；事件名缺条目=0。
- **缺口**：`codex` 目前读 `_ctx_get(ctx, "codex")` 标量（L531-532）；4c §2.2 要求 `param:"monster"/"fish"/"item"/"craft"` 分册维度。当前 `codex` var 无 param 分册处理（param 直接丢弃）。→ 需扩展 `_resolve_var` codex 分支：param 非空时读分册 pct（codex.py `codex_progress(ctx, category)` 已支持 category 参数，M11 批2 2B 加权后可用）。**列为批1 1A 前置小改 + 批2 2B 落位**。

### 2.2 reward 解析器 core/reward.py（406 行，dispatch_reward 唯一实现）

- **dispatch_reward(entries, ctx) -> dict**（L346-406）：返回 `{ok, granted, skipped, [idempotent]}`。
- entries 形态：结构化数组 / 单 dict / **内联串**（`expand_inline_reward` L82-123，D-05 已实现）/ 混合。
- ctx 契约：`currencies`（货币表就地累加）/ `settings.currencies[].id` 键空间 / `exp` 标量槽 / `reputation_state` / `items`|`resolve_item` 物品存在性 / **`add_item` hook（签名 add_item(item_id, count, bound)，L27-30）** / `tx_id` + `ledger`（幂等，L374-404）/ `rep_board`。
- 条目级失败 skip 黄字不中断（P1-2）；`item_add_failed` 不封口幂等（P1-1）。
- **称号型 `{title:ID}` 缺口**：`_dispatch_one`（L261-280）识别 item/id/rep/prof/标量键，**无 title 键处理** → 目前 `{title:...}` 会走 `invalid_entry` skip。→ 需在 `_dispatch_one` 加 title 分支（校验 title 在 ctx["titles"] 注册表 + 写入 ctx["title_state"]["owned"] 可佩戴列表）。**列批1 1A**。
- 幂等：成就侧复用 `tx_id`（=结算点 message_id）+ `ledger`（成就模块持有，与 reward 共享）。

### 2.3 title_state（assembly/context.py + core/proficiency.py）

- **形态**（proficiency.py L198-217）：`title_state = {owned: [title_id...], equipped: title_id|None}`；`_title_state(player, create)` / `_owned_list(ts)`。
- **ctx 注入**（context.py L1103-1104）：`ctx["title_state"]` **就地引用 player.title_state**（M9 实机收口，写入即落档）——成就称号授予直接 `title_state["owned"].append(title_id)` 即可落档。
- **当前佩戴读取**（context.py L161-172 `_current_title`）：读 `title_state["current"]` → 兜底 `["title"]` → ctx["title"] → 前缀 [称号] 渲染（prefix_wiring.py L80-84 format 含 `[称号]`，status_commands L213 前缀行）。
  - ⚠️ **键名不一致**：proficiency 写 `equipped` 键，_current_title 读 `current`/`title` 键。成就侧称号写入与佩戴须用 **`equipped`**（与 ProficiencyEngine 一致），且 /称号 佩戴指令要写 `equipped`；`_current_title` 兼容三键可不动。
- **佩戴引擎现成**：`ProficiencyEngine.equip_title(player, title_id)`（L477-497，1 槽替换式，校验 owned）、`owned_titles(player)`（L462-475）、`grant_king_title`（L441-460）。成就模块可直接复用或薄委托。

### 2.4 event_bus.py（175 行，三表同写）

- **bump_event(ctx, key, *, instance=None) -> dict**（L109-175）：一次写三表——`event_counts`（nested {key:{target:count}} 或 flat）/ `longline_counters[key]+=1` / `persistent_state["event_log"]` 环形（容量可配缺省 300）。缺省兜底不抛。
- ctx["bump_event"] hook 装配级注入（context.py L1279）；dialog_commands._bump_events（L265-282）优先消费 hook、缺省调 event_bus.bump_event。
- **预置事件**（condition_engine EVENT_PRESETS L176-183）：`[事件:副本通关]/[事件:任务完成]/[事件:签到]/[事件:怪物击杀]/[事件:等级提升]/[事件:NPC对话]`。**4c 需要的 `[事件:神鱼支线完成]` 类自定义事件不在预置表** → 校验器黄提示「事件未登记」但可加载（NPC 4.3.2 口径，成就侧同口径：黄提示不拦，内容包自行 bump）。
- adventure_log.py 六类事件键已实装（L27-34）：`[事件:首杀]/[事件:首钓冠级]/[事件:任务完成]/[事件:隐藏发现]/[事件:里程碑]/[事件:图鉴新增]`——隐藏成就 `[事件:隐藏发现:ID]` 条件可直接消费。

### 2.5 longline_counters（已实现）

- player.py L94：`longline_counters: Dict[str, int]`（玩家存档字段）。
- ctx 注入（context.py L1090-1091）：`ctx["longline_counters"]` 就地 dict（写入即落档）。
- 条件引擎读 `gain_count/kill_count/dungeon_clear/main_progress`（condition_engine L530-544）。
- **写入侧**：bump_event 写 `longline_counters[key]+=1`；`gain_count` 维度的累计获得计数由物品获得结算点写（现由 bump_event 事件键写入，如 `[事件:图鉴新增]`——物品累计口径 `gain_count:物品ID` 若需精确由内容包结算点 bump 带 target）。4c ACH-09「只读不计数」天然满足。

### 2.6 指令注册白名单模式（commands/parsers.py + assembly/router_setup.py）

- **DEFAULT_WHITELIST**（parsers.py L107-151）：独立指令名须进白名单才能被 S5 前缀匹配触发（P-05 铁律；M9 锻造/M10 钓鱼先例）。**`成就`/`成就信息`/`称号` 均不在白名单** → 需新增。
  - ⚠️ 注意：`图鉴` 在 DEFAULT_PREFIX_REQUIRED（L156）且 `称号` 未注册——若 /称号 为纯查询+佩戴，建议 `称号` 进白名单（可快捷）还是前缀必须（/图鉴 先例）？建议对齐 /图鉴：**`成就`/`成就信息`/`称号` 三词全进 DEFAULT_WHITELIST；`成就`/`成就信息` 加 DEFAULT_PREFIX_REQUIRED**（查询面板类，对齐 /图鉴 /调查 接缝）。
- **REGISTER_GROUPS**（router_setup.py L78-100）：tuple 收集 register_*_commands(router, *, make_context=None) -> router（链式）。成就侧新增 `achievement_commands.register_achievement_commands` 加进 tuple（主 agent 装配收口，同 fishing 先例 L98-99）。
- CommandSpec 注册模式（forge_commands L1863-1947 先例）：`router.register(CommandSpec(CMD, handler=_fn, whitelisted=True))`。

### 2.7 模板分区（core/templates/__init__.py + forge_tpl 先例）

- `tpl_of(ctx, key, data)`（__init__.py L123-131）：ctx["templates"] → 内容包覆盖 → 内置默认。
- 分区模式（forge_tpl.py 先例）：模块 `DEFAULT_TEMPLATES: Dict[str, str]` + `PLACEHOLDER_WHITELIST: Dict[str, set]`，在 `__init__.py` `_ALL_TABLES`/`_ALL_WHITELISTS`（L65-74）登记。
- **成就侧需新建 `core/templates/achievement_tpl.py`**（key 命名 `ach_*`），并在 __init__.py 两清单登记（与 _FISHING 同款，L41-42 先例）。

### 2.8 loader / field_meta / 校验器接线（content/）

- **field_meta.py**：`default_field_meta_table()` 返回模块表（L699-745）；成就需新增 `"achievements": ModuleMeta(entry_type="list", fields=achievement_fields, kind="achievement", namespace="achievement_lib")`（对齐 recipe/proficiency L714-716 先例；fields={} 空表 + 专项校验器全权，对齐 quest/npc L735-738 口径）。
- **loader.py**：`_KIND_FOR_MODULE`（L150-183）登记 `"achievements": "achievement"`；`_register_def` 缺省 BaseDef 回退（顶层 obj 模块 forge/fishing 先例，L164-169）——achievements.json 为**顶层 list**（每条成就一个对象），走 list 分支 L109-116 自动注册。
- **validator.py**：`_check_module`（L465+）专项路由——新增 `if module_name == "achievements": from qbot_rpg.content.achievements_models import validate_achievements; validate_achievements(self._modules, self)`（对齐 maps/dungeon L511-524 先例）。
- **manifest**：achievements 模块声明即加载（4c L120「不声明=不加载」天然由 manifest 机制满足）；**热重载**（hot_reload.py）按 manifest 监控，零额外工作。
