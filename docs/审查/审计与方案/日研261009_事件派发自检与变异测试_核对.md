## 二、E-20261009-01 实测：AST ↔ 现有正则扫描器对拍（报告标「尚未实测」）

**脚本**：`日研261009_探针_ast对拍.py`（只读）

| 口径 | 结果 |
|---|---|
| AST 检出的派发调用点 | **20** 个（`core/battle.py` 18 + `core/effects.py` 2，另有 1 处注释行不计） |
| 其中首参**非**字符串字面量（变量 / f-string / 无参）= 正则天然盲区 | **0** |
| AST 事件名集合 | 12 个：`action_end / action_start / battle_end / battle_start / death / on_kill / revive / season_change / status_gain / status_lose / turn_end / turn_start` |
| 正则扫描集合（`test_batch84_event_dispatch_status.py:23`） | **与 AST 逐字相等** |
| 仅 AST 命中 / 仅正则命中 | **0 / 0** |
| `EVENT_POINT_TABLE.dispatched=True`（12）== 两侧 actual | **True**（两侧均 True） |
| 被调函数定义处 | `core/battle.py:2092 _dispatch_event`、`core/effects.py:2045 _dispatch_status_event` |

**结论**：在「派发一律字面量」这一既成约定下，**正则扫描器零漏检**——AST 的增量只有
**可解释性**（顺带产 `file:line`），不是正确性。据此判 `H-20261009-01`（AST 改造）**不做**，
判据正是报告自己的反例 R1。
