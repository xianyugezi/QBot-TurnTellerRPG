## 三、本批实现范围

**做：**
1. **字段与校验**：`maps.gather_points` 按 GP-01~GP-11 落地字段元数据（中文名/范围/枚举）+
   `validate_maps` 增补 V-1Z（id 唯一）/ V-2Z（item 引用存在）/ V-3Z（天气键注册）/
   V-4Z（季节/时段枚举）/ rate∈[0,1] / respawn_minutes≥1 + rate<0.01 黄提示。
2. **引擎**：新增 `qbot_rpg/core/gathering.py`（纯函数、零 IO、零 NoneBot）：
   - `resolve_gather_points(map_node, season, period)`：过滤季节/时段白名单 → 可用点列表（原序）；
   - `gather_one(point, *, weather, weather_mods, rng)`：天气修正（调 `apply_weather_mods`）→ 概率 roll → 产出；
   - `point_available(state, map_id, point_id, now)` / `mark_depleted(state, ...)`：`respawn_minutes` 冷却；
   - `is_unlimited_map(map_node)`：无限资源图判定（R-23/R-24，见 §五 P-1）；
   - 全部入参可注入（rng / now / weather / state），确定性、可测、不 flaky。
3. **指令**：`/采集` 独立入口（无参数，【总纲】L1280 形态）——接线到 `explore_commands` 同层
   （世界层指令）；产出走既有入包链路；边界（无采集点 / 次数耗尽·冷却中 / 时段季节不满足 /
   无限资源图）全部**人话提示**。
4. **挖掘通道**：按定稿规定——挖掘是**来源通道标签**（矿石系产物族），无独立指令、无独立 schema；
   本批让采集引擎对**任意** `gather_points` 点生效（矿石系与草药系同引擎），并在
   `forge_deadlock`/来源分类既有的 `gather = 采集/挖掘` 归口下继续成立。**不新造 `/挖掘` 指令**。
5. **编辑器**：`gathering` 目录条目 `implemented=False → True`（可启用）+ 字段中文名/说明齐备。
6. **模板**：`gather_*` 键入 `core/templates/template_table.json`（框架全量表）。

**不做（明确排除）：**
- 不改**内容数据**（`content/*/maps.json` 的采集点数量/产出/概率，属内容侧）；
  E2E 用**临时内容根**造样本。
- 不新增 `settings.gathering` 配置段（定稿未定义）。
- 不实现采集的**每日次数上限**（定稿未写，见 GA-2）。
- 不实现**职业熟练经验入账**（归属职业未定，见 GA-4）与**图鉴点亮**（见 GA-5）。
- 不实现 `/天气` 摘要中的采集点提示（属天气指令链路，另批）。
