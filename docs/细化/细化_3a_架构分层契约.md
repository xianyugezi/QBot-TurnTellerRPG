## 〇、契约总则

### 0.1 术语表

| 术语 | 定义 | 依据 |
|---|---|---|
| 平台无关层（零 NoneBot 层） | `qbot_rpg/{core,world,storage,content,data}` 五层——不 import nonebot、不接触 QQ 平台概念（CQ 码/at 段/群号语义），必须可脱离 NoneBot 单测 | 【规则】L52 |
| 壳层 commands | **唯一 NoneBot 适配器接触点**：指令注册（on_command）/权限/频率/解析/发送出口，翻译领域异常为人话 | 【规则】L52-53；【框架】L1604/L1622-1623 |

| CQ 码 | QQ 平台消息段语法（如 `[CQ:at,...]`），仅壳层可接触与转义 | 【框架】L1622；【规则】L510 |

### 0.2 一句话契约

> 框架 = **平台无关核心包 `qbot_rpg`**（core/world/storage/content/data 五层，零 NoneBot import）
> + **壳层 `commands`**（唯一适配器接触点）+ **`web`**（FastAPI 编辑器外壳，同样零 NoneBot）；
> 数据流单向：QQ 消息 → commands 解析 → 核心层纯逻辑（读 content 配置、读写 storage 存档、结算 core 引擎）→ 返回结构化结果 → message_format 渲染**纯字符串** → commands 统一发送出口；
> 引擎层不拼用户文案（抛领域异常由壳层翻译），渲染层不碰平台语法（CQ 转义/长度分条/发送退避全部在壳层）。

### 1.2 零 NoneBot 层清单与判定口径

| 层 | 放什么 | 不允许出现 | 判定命令 |
|---|---|---|---|
| core | 纯规则引擎：battle/damage/levelup/inventory/equipment/worldtime + message_format 渲染 | nonebot、CQ 码、群号、发送调用 | `pytest qbot_rpg/core`（不启 NoneBot 可跑） |
| world | 全局世界状态：地图/怪物池/野图 BOSS/全体限购/刷新补刷 | nonebot、群概念 | 同上（storage 打 :memory: 即可） |
| storage | SQLite：连接队列/事务/迁移/自动保存 | nonebot、引擎结算逻辑 | 同上 |
| content | loader/validator/registry/hot_reload | nonebot、业务状态 | 同上（纯文件+内存） |
| data | 领域类型：Player/BattleSnapshot/StatusInstance/ItemInstance/WorldState 等 | nonebot、任何上层模块 | 同上（仅标准库依赖） |

> 判定基准：【规则】L52 的"可脱离 NoneBot 单测"——CI 中 `pytest` 直接 import 五层模块并执行，任何 `ModuleNotFoundError: nonebot` 即失败（TC-01/TC-04）。

| 权限与频率 | 三级权限（机主/GM/普通）、无权限 GM 静默、指令防抖/单群限频/单日上限 | 【规则】L455-462/L473-480 |

### 1.4 依赖方向矩阵（R3 展开）

| 层 | 允许依赖 | 禁止依赖 | 备注 |
|---|---|---|---|
| commands（壳层） | nonebot 平台库 + 其余全部层 | 被任何层依赖 | 最外层，无人 import 它 |
| web（编辑器） | content（读写包）、core（模拟试玩）、storage（运营页只读）、data | nonebot；被任何层依赖 | FastAPI 独立服务（D-05） |
| core（引擎） | data、content（registry 只读）、world（写世界状态）、storage（经 repository 接口） | nonebot、web、commands | 战斗结算 → 快照落 storage 经接口注入 |
| world（世界） | data、storage、content（时间/刷新配置） | nonebot、core、web、commands | 世界状态 key=全局（D-06） |
| storage（持久化） | data | nonebot、core、content、world、commands | 纯存储，不含引擎语义 |
| content（内容包） | data（校验用类型） | nonebot、core、storage、world、commands | 不含运行时状态 |
| data（领域类型） | 仅标准库（dataclasses/typing/enum） | 一切上层 | 最底层，零外部依赖 |

### 1.5 放错层判定清单（评审拦截用，对应 R6）

| 现象 | 判定 | 正确落点 |

## 三、领域模型与类型约束

### 3.1 类型约束总则（硬约束）

- 所有公开函数必须带完整类型标注；内部函数至少标注参数与返回值（【规则】L73）
- 常用类型用 `typing`（`Optional`/`List`/`Dict`），Python 3.9 兼容写法，不追求 `|` 新语法（【规则】L74）
- 领域类型用 `TypeAlias` 或 **frozen dataclass** 表达，禁止裸 dict 满天飞（【规则】L75-90 正例：`@dataclass(frozen=True) class CombatantSnapshot: ...`）
- 手写 dict 结构断言一律收敛到 `content/validator.py`，禁止散落各处 `if "xxx" in data`（【规则】L92）
- 存档/快照结构建议 Pydantic 或 dataclass + 显式校验（【规则】L92）——本契约落地为 frozen dataclass + storage 层 round-trip 校验

### 4.2 内容包加载流程（loader 契约）

## 五、message_format 纯字符串契约

### 5.1 契约定义

```
输入：引擎结算的结构化结果（dataclass：BattleRoundResult / ActionResult / 面板数据…）
输出：str（纯文本，可含 emoji/换行/中文标点）

```
依据：【框架】L1622-1623「统一消息解析器（段级提取 at/图片/表情 + CQ 码转义防注入）；渲染层长度预算；发送出口统一封装含失败重试与风控退避」——**解析/发送 = 平台职责归壳层，渲染 = 平台无关职责归 core**。

### 5.2 纯字符串断言清单（渲染层）

| # | 断言 | 依据 |

| S1 | 渲染结果 `isinstance(x, str)` | D-04 |
