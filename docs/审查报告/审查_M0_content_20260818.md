## 五、🔴/🟡 问题清单（🔴 P0 / 🟡 P1/P2）

### 🔴 P0-1 防空转失效：坏包每 3 秒无限重试，`paused` 形同虚设 【静态推导】

- **位置**：`hot_reload.py:191-203, 221-229` + `run()` `hot_reload.py:136-141` + `_detect_changes` `hot_reload.py:164-180`
- **实际**：`_reload_sync` 中 `changed` 初值 `()`（L192）。`build_pack(...)` 一旦抛 `PackLoadError`（红拦/坏 JSON 的**主路径**），tuple 解包 `pack, changed = build_pack(...)`（L198）不完成，`changed` 保持 `()`；except 分支（L201-203）只读 `exc.errors`，**未重算已变更模块**。于是失败分支 `for m in changed: self._last_attempt[m] = ...`（L225-229）空转不写任何签名，`_last_attempt` 保持 `{}`（成功路径在 L261 清空过）。
  下一轮 `_detect_changes`（L178）判据 `sig != baseline and self._last_attempt.get(m) != sig`：`baseline` 是旧好包签名、`_last_attempt[m]` 为 None → 恒真 → 坏文件每 3 秒报告一次 → `run()`（L137-141）任何 `events` 非空即 `await asyncio.to_thread(self._reload_sync, "poll")`，**完全不检查 `self._paused`** → 即使 `_fail_count >= 3` 置 `_paused=True`（L231-233），仍然无限重试同一坏包。
- **应有**：3e2 BLK-5/TC-09（“连续失败阈值后自动暂停自动轮询、防空转不空转”，L141/L209/L249）+ 3e §4.6“幂等重试、无死锁”（L265）。同一坏配置不得在无人值守下每 3s 反复打转。
- **修复建议**：① 让 `PackLoadError`（或 build_pack 退出前）携带「已变更模块清单」，失败后逐一写 `_last_attempt` 签名（对错误注入的 manifest 同样）；② `run()` 循环将 `_paused` 纳入判别（paused 时仅对「签名 ≠ 最近尝试」的新事件尝试一次，成功后复位）；③ 单测补 TC-09 故障注入（3 次坏包 → 断言轮询停止重试、手动 /重载 仍可触发）。

### 🔴 P0-2 部位互斥环误判：任意单条互斥声明（含单边）即误报 R-5 环拦 【静态推导】

- **位置**：`validator.py:512-557`（`_check_mutex_cycle`）
- **实际**：edges 双向记录：`edges.setdefault(core,set()).add(other)` 与 `edges.setdefault(other,set()).add(core)`（L533-534）→ 一条“slot=w `excludes`=[s]”即生成 `{w:{s}, s:{w}}` 两条有向边。随后 L552-556 逐有向边 union-find：`union(w,s)` 返回 True（合并）后，第二条 `union(s,w)` 因已同集合返回 False → **误报 R-5 slot_mutex_cycle 并 `return`**。即：任何 `equipment[].excludes` 声明（包括最常见的双部位互斥，如 武器↔盾牌）必然红拦、整包拒绝加载。注释（L514-516）自称“含环（≥3 条边）”，但实现把两点间的多重边当环。
- **应有**：3e §2.1/§5.2 的“部位互斥成环”（L167 人话示例为 武器↔盾牌↔副手 三部位圈）——两部位互斥是合法语义，**不得红拦**；且违反 §2.3 兜底“不明确非法即合法”。双部位互斥被拒 = 把合法包误当非法（假阳性红拦），直接违背 field_meta.py 自述“避免误阻断合法包”（L13）。
- **修复建议**：无向边先规范化去重（`sort((u,v))` 成 `frozenset`/tuple 集合，每对仅一条边）再做 union-find；去重后的简单图上 union-find 检测到的成环边即 ≥3 个不同节点的真环。同时去掉命中即 `return`（D-01 要求多环全量收集，L45）。补 TC-08 变体：双部位互斥应通过、三部位环应拦。

### 🟡 P1-1 formula 安全例外：黑名单可被模板串插值绕过 + 块注释误伤 【静态推导】

- **位置**：`validator.py:58-74`（check_formula）+ `validator.py:77-104`（_strip_literals）
- **实际**：
  - 反引号模板串被整体当字面量剥离（L83-97），`${...}` 插值表达式随字符串一起跳过 → 藏在 `${}` 内的 `eval`/`Function`/`require` 不落入 `tokens`，**黑名单漏检（绕过）**。
  - 仅剥离 `//` 行注释（L98-101），`/* ... */` 块注释未剥离 → 注释内出现黑名单词（如 `/* process */`）会被 `_FORMULA_IDENT_RE.findall` 命中 → **误红拦（假阳性）**，且注释可被用来干扰合法公式。
- **应有**：3e §3.3（L448）AST 黑名单 + `new` 表达式必须可靠拒绝，不受字面量/注释掩蔽；安全例外虽不受“只建议不限制”覆盖，但也不应收紧出假阳性。
- **修复建议**：模板串中 `${...}` 插值片段单独剥出再扫描；补 `/* */` 块注释剥离；或 M0 引入最小 JS 词法器（tree-sitter / esprima 语义近似）替代“剥离式”字符扫描。补 TC-29 变体（`"${eval('x')}"` 应拦；`/* eval */` 注释不应误拦）。
