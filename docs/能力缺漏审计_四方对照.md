**编辑器机制实测结论（三条，全部可复现，决定后面所有「可见性」判定）**：

1. **左栏模块树 = 包 manifest 声明的模块，不是框架能力集。**
   `qbot_rpg/web/api.py:357` `declared = _declared_modules(manifest)`；`:378`
   `modules = [node(m, [m]) for m in declared if m not in child_set]`。
   实测 `api.list_modules('veinborn')` 左栏 22 个根模块，而框架目录 28 个 → **框架实现的 `fishing` 不在左栏**（仅 ⚙ 面板可见）。
   这正是一号原则要求纠正的点。

2. **`obj` / `map` 类型字段一律只读；嵌套叶子仍可编辑。**
   `qbot_rpg/web/api.py:582-592` `_EDIT_BY_WIDGET = {... "obj": ("readonly", False), "map": ("readonly", False)}`。
   实测 `api.entry_detail('veinborn','settings','alchemy')`：容器 `farming` `control=readonly`，但 `farming.enabled/harvest_sec/plots_max/trait_inherit` 与 `greenhouse.copy_slot/unlock_tier` 均为 `editable=True`。
   → 「嵌套子字段不可编辑」是**已知台账 #4/#6 的根因**（`docs/编辑器修改意见0915_台账与方案.md:47,49`）。

3. **未登记但数据里出现的键会被「实际值兜底」渲染**（`api.py:1534-1537`）。
   所以「可见」有两种来源：**框架登记**（一号原则要求）与**包里碰巧有数据**（脆弱，空白包即消失）。本审计严格区分：
   - 【模】= 独立模块（左栏 + 引擎元数据登记）
   - 【目】= 仅 ⚙ 模块目录可见（框架支持、包未启用）
   - 【嵌】= 仅作 settings/父模块嵌套 soft 字段可见（容器 readonly、叶子可编）
   - 【名】= 仅靠实际值兜底出裸键名
   - 【无】= 完全不可见
