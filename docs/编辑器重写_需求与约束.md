# 内容编辑器 · 重写需求与约束（2026-09-13 起）

> 背景：2026-09-13 按用户拍板**删除**了原 Web 内容编辑器（见 `02_遗留登记.md` #86）。
> 本文件是**重写版编辑器的唯一需求来源**：用户逐条拍板，逐条往下加，不得自行发挥。
> 交付纪律沿用既有约定：先出样式稿/方案给用户审 → 确认后再写实现；面向非技术用户；纯配置优先。

## 〇、定位（**最高优先级原则** · 用户 2026-09-13 纠正）

> 用户原话：「不要参考数据包的内容做，web编辑器是后面给策划用户用的，不是专门为这个数据包做的，
> 不要把数据包的专属东西作为通用框架的东西。」

0. **编辑器 = 通用工具**，服务对象是**未来的内容作者/策划**，**不是为 veinborn（或任何单个包）定制**。
   - **禁止**把某个包的专属业务结构写死进编辑器框架：例如「装备就是 10 项属性」「必须有套装/词条/孔位」
     「技能必须有 buff 表」这类**具体业务字段不得硬编码**。
   - **正确形态 = 元数据驱动**：界面读**内容包的模块声明**（`manifest.modules`）与**字段元数据**
     （`qbot_rpg/content/*_models.py` 的 `FieldMeta`：type / label / default / options / 分组）
     动态渲染表单与分区；换包 → 界面随之变化，**编辑器代码不用改**。
   - 真实数据（veinborn 的技能/装备条目）在样式稿与测试中**只作为示例内容**，不得成为框架假设。
   - 判断标准：**把 veinborn 换成另一个包，编辑器是否零改动可用**；做不到的设计一律推翻重来。

## 〇·补、验收口径（批 7 落地 · 2026-09-13）

> 第〇节的判断标准不变；本补记把「换包零改动」从原则落成**可重复执行**的验收（批7 新增登记）。

- **补-1（验收脚本）**：`scripts/editor_verify_packs.py` 遍历内容目录下**实际存在的全部内容包**
  （**动态发现、不写死任何包名/模块名**），对每个包调用编辑器只读 API 层六入口
  （包列表 / 模块树 / 条目列表 / 条目详情 / 条目索引 / 引用候选），断言：
  ① 不抛异常；② 结构完整（模块树 `count = own_count + Σ子`、条目数「模块树 / 条目列表 / 条目索引」
  三处口径一致、`field_count = Σ分组 count`、字段分组归属完整）；③ 字段全部可渲染（每个字段都有
  `type` 与可渲染 `widget`/`control`）；④ 未知 / 缺元数据键走兜底不崩。输出逐包报告表，exit 0/1。
  纳入 `tests/unit/test_editor_pack_switch.py`（含 tempfile 合成包反向探针、反向对照、只读护栏、通用性护栏）。
- **补-2（只读纪律）**：验收脚本与测试**不得写入真实内容包**；需要写盘的兜底探针一律用临时目录；
  测试须断言跑完验收后 `content/` 逐字节未变。
- **补-3（一键启动）**：`scripts/editor_start.sh` 默认 `127.0.0.1:8090`，`--pack` / `--content-root` /
  `--role` 可传；只监听本机，启动即打印安全暴露提示（SSH 隧道 / 内网）；启动失败给人话报错。
- **补-4（口径提醒）**：内容包数量以 `content/` 现场实际为准（本批实测 7 个真实包 + 2 个合成探针），
  任务书写「8 个」与现场不符时以现场为准，脚本按目录动态发现。

## 〇·补二、包展示元数据契约（批A 落地 · 2026-09-13）

> 依据 `docs/编辑器重写_数据包展示元数据下放方案.md`。本契约固定「包怎么声明展示元数据」，
> 换新包时编辑器/框架零改动即可显示中文。

- **文件名与位置**：`content/<包>/field_meta.json`，**纯 JSON**；不声明 → 完全按现状兜底（裸键），不报错。
- **顶层键只有六个**（其余一律报错，防各家写法漂移）：
  `schema_version`（必填，整数，当前只支持 `1`）、`module_labels`、`module_tree`、
  `field_labels`、`field_help`、`group_labels`。
  后续批次按同一「显式扩键」机制追加（`entry_merge` §〇·补六、`segment_pages` 批15、
  `id_prefix`/`id_width`/`entry_presets`/`entry_presets_disable` §〇·补八）；仍**不静默吞未知键**。
- **形态**：`module_labels` = 对象<模块名, 非空字符串>；`group_labels` = 对象<模块名,
  对象<组键, 非空字符串>>；`field_labels`/`field_help` = 对象<模块名, 展示表>，展示表的一项
  可为**非空字符串**（叶子中文名/说明）或**嵌套对象**（`_label`/`_help` 为本节点文案，
  其余键递归同形态）——批B 起支持嵌套 children（旧包只写字符串仍然合法）。
  `module_tree` 与包 manifest 的 `module_tree` 同形态（数组或「父: 子项」对象）。
  任一形态非法 → 解析层报错，指出**包名 + 出错键**。
- **优先级**：包声明 > 框架兜底。`field_labels`/`field_help`/`group_labels` 覆盖框架同键值，
  未声明键保持框架现状；`module_labels`/`module_tree` 以 `field_meta.json` 优先于 `manifest`
  的同名字段（`module_tree` 为整体替换）。详见方案 §二 优先级细则。
- **批B 起框架只保留结构**：`qbot_rpg/content/field_meta.py` 不再持有 `*_FIELD_LABELS` /
  `*_FIELD_HELP` / `*_GROUP_LABELS` / `*_CHILD_LABELS` / `*_CHILD_HELP` 等纯展示表；
  子字段结构来自自动生成的 `qbot_rpg/content/field_meta_child_structure.py`，中文名/说明由
  `content/<包>/field_meta.json` 承载（迁移脚本 `scripts/migrate_pack_field_meta.py` 幂等导出）。
- **纪律**：真实内容包内**不得**由测试/验收脚本写入该文件（需要时用 tmp 目录拷贝包）；
  框架代码不得写死任何包名/业务键。
- **契约出处**：本节的字段形态 / 优先级细则以《数据包展示元数据下放方案》**§三（目标结构）**
  与 §二（边界与优先级）为准；批D 起「新包自带中文名、编辑器与框架零改动」由探针包
  `content/zz_probe_packmeta/` 验证（方案 §四 批D）。

## 〇·补三、可启用模块目录契约（批8 落地 · 2026-09-13）

> 用户 2026-09-13 点名：顶栏 ⚙ 模块开关——空白包编辑器全空，小白不知道从哪开始。

- **模块目录（可启用清单）来自框架通用知识**，不是从当前包已有声明反推（空白包什么都没有）：
  `qbot_rpg/content/module_catalog.py::FRAMEWORK_MODULE_CATALOG` 登记各**模块键 + 通用中文默认名 +
  一句话用途 + 骨架形态 entry_type + 前置模块 requires**。
- **与「展示元数据下放」不冲突**：**模块种类是框架概念**（框架登记可启用哪些模块、骨架什么形态）；
  模块的**中文名/层级**属包展示声明 —— 包内 `field_meta.json.module_labels` / `manifest.module_labels`
  / `module_tree` 节点 label 声明了该模块中文名 → **优先用包的**，未声明才用框架通用默认名
  （优先级实现 = `qbot_rpg/web/api.py::module_catalog`，与只读层同一口径）。
- **启用的落盘语义**：勾选 → 写入该包 `manifest.json` 的 `modules` + 按 entry_type 创建最小骨架
  （**list → `[]`；map/object → `{}`**；文件已存在则不覆盖）；**校验 → 原子写 → 自动备份 →
  可回退**（复用批2 链路，不得绕过）。取消勾选 → **只从 `manifest.modules` 移除声明，保留数据文件**
  （人话黄提示「数据文件已保留，重新勾选即可恢复」）。
- **校验容忍的边界（不绕过校验器，只圈定作用域）**：空骨架模块自身的深结构红拦（如技能库空）语义是
  「先启用、后填写」→ 黄提示放行；停用被引用模块产生的 R-4 悬空引用 → 黄提示放行（「暂时摘下」）。
  其余任何红拦照常阻断落盘；被容忍项如实以黄提示返回，不静默。
- **依赖提示不硬拦**：目录声明前置关系（如派生链依赖技能、装备属于物品类）；缺前置仍可启用，
  只给黄提示「建议同时启用 X」。
- **空包首屏**：当前包未启用任何模块 → 编辑器给空态引导（「点右上角 ⚙ 选择要做的内容」+
  直接打开面板按钮），不留空白。
- **权限**：GM 只读身份下 ⚙ 面板勾选不可用（禁用视觉 + 说明）；写入层前置 403（与批2/6 一致）。
- **纪律**：框架目录不得写死任何包的专属业务字段；编辑器代码只认模块键与目录声明，换包零改动。

## 〇·补四、配色面板化 + 自定义背景图（批10 落地 · 2026-09-14）

> 用户原话（2026-09-14）：「弄成和设置一样一个按钮然后打开可以选择吧，顺便加个自定义背景图的功能，背景图可调透明度」

- **配色切换按钮化**：顶栏批9 的「配色：暗色 / 浅色 / 高对比」三个按钮 → **一个 `🎨 配色` 按钮**
  （与 `⚙ 模块` 同款位置与交互：点开弹层）。面板内三套主题**单选列表**（显示当前选中态 + 每项一句说明）。
  选择**立即生效并保留面板**（理由：用户可在面板里一边看主题一边调背景图透明度，满意后点「完成」；
  单选换肤不刷新、不触碰草稿）。
- **自定义背景图**：
  - 来源两种：**本地文件选择**（`FileReader` → dataURL）与 **图片 URL 输入**（先探一张，拉不到给人话提示）。
  - **存储 = 浏览器本地**：首选 `localStorage`（键 `qbot.editor.bg.image` / `qbot.editor.bg.opacity`）；
    **图片过大（配额超限）→ `IndexedDB` 兜底**；两者都不可用（隐私模式）→ 本次会话内存态 + 人话提示。
    **决定：不上传服务器**——编辑器当前无用户内容鉴权面、且该功能零服务端改动即可满足；
    同时**不写入任何内容包文件**（只存当前浏览器）。代价：换浏览器/清站点数据后背景图需要重设，
    面板内已用文案说明。
  - **应用方式**：页面底层 `background-image`（`cover` + `fixed`）；**内容与背景图之间必须有主题
    底色兜底层**（`.bgbase`，`--bg-scrim` 令牌，三套主题各给值），保证三套主题下正文可读。
  - **透明度滑块 0–100%**：实时生效（只改图片层 `opacity`），值存 `localStorage`；越界/非数字一律 clamp。
  - 另给「清除背景图」（恢复默认底色）与面板内**小预览**（缩略图 + 当前透明度效果）。
  - **失败兜底**：非图片文件 / 超大文件 / URL 拉不到 → 人话提示，不影响编辑器继续使用。
- **公共弹层组件**：`⚙ 模块` 与 `🎨 配色`**共用同一套** `.mp-*` 样式与 `EditorModal` 实现
  （打开 / 关闭 / 记住并回还触发按钮焦点 / `Esc` 关闭 / `Tab` 焦点环 / 点遮罩关闭 / 关键词筛选）。
- **无障碍**：面板 `role="dialog"` + `aria-modal="true"`，Tab 可达，`Esc` 关闭且焦点回到触发按钮；
  透明度滑块带 `aria-valuenow`（随拖动同步）。
- **纪律**：背景图功能**不得写入任何内容包文件**；编辑器代码不认任何包的专属业务字段/模块名。

## 〇·补五、内容包导出/导入（批11 落地 · 2026-09-14）

> 用户原话（2026-09-14）：「做一下数据包导出导入功能，方便用户之间互相分享。」

- **导出一个文件**：当前内容包 → 一个 `.ttrpack`（zip）。内容 = 包目录下顶层全部 `*.json`
  + 可选 `*.md`；另附 `export_meta.json`（`format` / `format_version` / 包 id / 名称 / 版本 /
  `ttr_version` / `ttr_commit` / `exported_at` / `files[]{path,size,sha256}`）。
  下载文件名含包名与日期。导出是**只读**操作（**GM 只读身份也允许**）。
- **导入**：选分享来的文件 → ① zip 结构安全 ② `export_meta.json`/`manifest.json` 合法 +
  sha256 完整性 ③ **过现有内容校验器**（红拦不落盘）④ 包 id 冲突处理（改名 / 覆盖且先自动备份）
  → 通过才落盘。落盘 = 在 `<content-root>/.ttrpack_tmp_*` 写全文件后 `os.replace` 原子搬成
  `content/<id>`（**新建一个包目录**；失败清理临时目录，**不留半成品**）。导入**必须 owner**。
- **安全（硬约束）**：Zip Slip（`../`、绝对路径、盘符、反斜杠、符号链接）一律拒绝；
  只接受 `.json` / `.md`（拒绝可执行 / 脚本 / 二进制）；压缩包体积、单文件解压后、解压后总量、
  条目数、压缩比五项上限，超限人话报错。
- **冲突**：同名默认拒绝并给人话可选项；覆盖前把旧包整体原子移到
  `<content-root>/.ttrpack_backups/<id>/<时间戳>/`（该目录顶层无 manifest，不会被当成内容包）。
- **CLI**：`scripts/pack_transfer.py`（`export` / `import` 子命令；参数 `--pack` / `--file` /
  `--content-root`，另有 `--rename` / `--overwrite` / `--json`），与网页端共用同一实现
  `qbot_rpg/content/pack_transfer.py`。
- **通用性**：不写死任何包名 / 模块名，任意内容包可导出、可导入。
- **纪律**：测试与验收脚本一律在临时目录拷贝包，绝不写真实内容包。

## 〇·补六、条目聚合展示契约（`entry_merge`，批12 落地 · 2026-09-15）

> 用户原话（2026-09-15，澄清后口径）：「我的意思是把属性和公式这个**放到设置里面去**，放在
> **和战斗参数的条目一起**」——即「设置」改名「基础」，属性（`stats`）/ 公式（`formula`）
> 的**条目**与战斗参数、死亡惩罚、装备槽位等**同列在中栏**（按来源分小节），
> **不是**做成「基础 ▸ 属性」的子模块层级。

- **声明位置与键**：`content/<包>/field_meta.json` 的顶层键 `entry_merge`（与
  `module_labels` / `module_tree` 同级；未声明 → 行为与现状**完全一致**）。形态：
  - 简写：`{"entry_merge": {"<目标模块>": ["<来源模块>", ...]}}`（来源默认不再左栏单列）；
  - 完整：`{"entry_merge": {"<目标模块>": {"sources": [...], "keep_top_level": [...]}}}`。
  `keep_top_level` = 仍保留左栏单列的来源（同时出现在左栏与聚合视图）；必须是 `sources` 子集。
- **语义（纯展示层）**：把 `sources` 的**条目列表**并入目标模块的条目列表展示（中栏按
  「来源模块」分小节聚合）。**数据文件 / 模块 id / 加载与校验路径一律不动**——点开并入条目后，
  编辑/保存仍**路由回其所属模块**（校验 → 备份 → 原子写 → 回读/回退，各走各自的模块链路）。
- **通用实现（框架侧零业务名）**：`qbot_rpg/content/field_meta_pack.py::parse_field_meta`
  严格解析该键（未知子键 / 重复 / 目标并入自身 / keep 非 sources 子集 一律报错）；
  `qbot_rpg/web/api.py::_entry_merge_map` 按包实际 `manifest.modules` 过滤后驱动
  `list_modules`（来源节点 `merged_into`、目标节点 `merged` / `merged_count` / `total_count`）
  与 `list_entries`（`merge_sections` / `total_count`）。**api.py 不写死任何模块名**。
- **计数口径（写死，三处自洽）**：
  - **左栏**：目标模块显示 `total_count` = 本模块 + 子模块 + 并入条目（标注「含并入」，
    悬停列出各来源条数）；来源模块若未 `keep_top_level` 则**不出现在左栏**。
  - **中栏**：页脚合计 = `list_entries.total_count`（各小节条数之和）；小节标题写明来源中文名。
  - **全局检索 / 条目索引**：仍按**数据所属模块**分组（`stats` / `formula` 各自成组，不聚合）；
    命中并入条目时跳转到聚合它的模块并打开该条目（保存仍写回原模块）。
  - **`editor_verify_packs.py` 的既有口径不变**：模块树 `count = own_count + Σ子`、
    模块树集合 == 条目索引集合 == 包列表 `module_count`（`entry_merge` 只是给来源模块加
    `merged_into` 标记，**不移动/不删减**模块树节点，故三处口径天然一致）。
- **纪律**：真实内容包内不得由测试/验收脚本写 `field_meta.json`；框架代码不得写死任何包名/业务键。

## 〇·补七、能力可见性契约（一号原则落地，批13 · 2026-09-15）

> 依据：`docs/编辑器修改意见0915_台账与方案.md` §〇·补 一号原则——**编辑器是框架的编辑器**，
> 显示全集 = 框架能力集；包声明只做展示层补充，**不得删减框架能力**；**空白包同样成立**。

- **左栏 = 框架能力集 ∪ 包声明**：`qbot_rpg/web/api.py::list_modules` 出参在既有
  `modules`（manifest 声明树）之外新增两组**只读展示**数据：
  - `views`：`entry_merge` 声明了、但未在 manifest 声明的**虚拟聚合视图**（如 veinborn 的
    `life`「生活」聚合 `proficiency/enhance/forge/recipe`）。视图**不落数据文件、不参与写入**，
    中栏按来源分小节聚合，编辑/保存仍路由回来源模块。
  - `available`：**框架目录里包尚未启用的模块**（`module_catalog.FRAMEWORK_MODULE_CATALOG`
    ∪ 包声明 − 已声明）；每行 `enabled=false`、`count` 取真实数据文件（无文件 = 0）、
    `implemented` 标注引擎是否已实装。前端左栏以「未启用」灰显 + **一键启用**（复用 ⚙ 模块
    开关同一写入链路）。
- **计数口径（写死、互不污染）**：
  - `modules` / `entry_index.modules` / `list_packs.module_count` 仍只算 **manifest 已声明**
    模块（换包验收 `editor_verify_packs.py` 的「模块树 ↔ 条目索引 ↔ 包列表」三处口径不变）；
  - 未启用候选的条目数 = 其数据文件的真实条数（文件不存在 = 0），界面上标「未启用／未实现」；
  - `entry_index.available`：未启用模块也进**全局检索候选 + 同命名空间 ID 唯一性判定**
    （保留数据仍可搜到、不撞 ID），但**不计入 `entry_index.total`**。
  - 一号原则自检：`scripts/editor_visibility_selfcheck.py` 断言任一包
    （空白包 / 功能齐全包）的左栏显示集 ⊇ 框架目录全集，且框架登记字段**只增不减**。
- **模块目录条目**：`gathering`（采集/挖掘）引擎未实装 → 目录仍列条目并标「未实现」、
  **不可启用**（不产生无法消费的空数据文件）；`farming/contest/assistant/quest_board/codex`
  的运行时配置当前落在 `settings.<段>`（目录条目 `settings_section` 标注）；
  `templates`（消息模板）为真实 `templates.json` 模块。`time_cycle`（时间天气）依定稿
  §7.1 挂「通用设置 → 【时间天气】卡片」，**不新增一级模块**。
- **消息前缀 vs 模板边界（U6，不合并）**：`settings.message_prefix` 管**回复首行身份标识**
  （等级/名字/称号的格式与渠道）；`templates.json` 管**全部消息文案的模板覆盖**。
  二者一个管「首行外壳」、一个管「正文文案」，各司其职，不合并为「消息」模块。
- **纪律**：上述全部为**展示层/类型登记**；`type/required/范围/枚举/引用目标` 只驱动编辑控件，
  **不改任何校验语义**（既有内容包 `check_pack` 全绿）。

## 〇·补八、自动 ID / 使用处覆盖 / 条目预设契约（批16 落地 · 2026-09-15）

> 依据：`docs/编辑器修改意见0915_台账与方案.md` §批 4 #7 / #10 / #11 与用户最新口径
> （「id 生成也可以用字母作为标头 + 数字序号作为后缀」→ 主 agent 裁决：**默认「前缀 + 序号」**，
> 拼音作为**可选附加**）。三条均为**新建界面 / 取值口径**声明，不改数据文件、不改校验语义。

### A. 自动生成 ID（#7）

- **默认 = `<前缀>_<序号>`**：序号**零填充 3 位**（宽度 1..12 可配，缺省 3）；
  序号取该模块（含同命名空间）现有**同前缀 id 的最大序号 + 1**，候选冲突则继续递增直到唯一；
  序号识别不区分零填充（`mat_1` 与 `mat_001` 都算序号 1）。
- **前缀来源（包声明优先）**：预设 `id_prefix` > 包 `field_meta.json.id_prefix[模块]` >
  框架 `ModuleMeta.id_prefix` > `ModuleMeta.kind` > **模块 id 归一推导**（小写、非字母数字转下划线）。
- **拼音为可选附加**：`pypinyin` 可导入时前端多一个「拼音 id」按钮（全拼 + 下划线）；
  **多音字 / 取不出拼音 / 未装库 / 转换失败 → 回落「前缀 + 序号」并明确提示**（不报错、不静默）。
  默认路径永远是「前缀 + 序号」。
- 生成结果**直接填进输入框、可手改**（不静默）；非法字符归一（小写 + 下划线）；
  查重与既有 ID 规则一致（slug 重复追加序号）。
- **只影响新建**：已存在的 id 一律不动（生成是只读操作，不写盘、不占位）。
- 实现锚点：`qbot_rpg/web/api.py::slugify` / `_module_prefix` / `id_rule_spec` /
  `_sequential_id` / `suggest_entry_id` / `suggest_pinyin_id` / `_pack_id_policy`；
  前端 `index.html::newIdentHtml` / `suggestIdFromName` / `EditorEntry.ruleText`。

### B. 概率/权重「使用处 > 定义处」（#10）

- **定义处**（`action.json` 的 `probability` / `weight`）保留为**默认值**；
- **使用处**（怪物 AI 行动表 `enemies.json.actions[]` 等引用处）声明同名字段即可覆盖；
- **取值顺序 = 使用处 > 定义处 > 缺省**；缺省与修前逐字段一致
  （`probability`→0 不入池、`weight`→1.0）；**显式 0 是有效覆盖**（不等于「未声明」）；
- 引擎接入点：`qbot_rpg/core/monster_ai.py::MonsterAI._param`
  （`_random_pool` 入池闸门 + `_weight_for` 权重基准共用同一解析）；
- **印记**：`marks.json` 无概率类键（已核查）→ **印记侧无需改动**；测试对此设事实断言，
  将来若出现概率类键会提醒按同口径补实现；
- 编辑器标注：定义处（`action` 模块 `probability`/`weight`）的 `FieldMeta.overridable_default=True`，
  说明卡出「**默认值（可被引用处覆盖）**」；使用处字段说明「留空 = 用行动定义处的默认值」。
  标注为**纯展示层**（`help_card.default_note` / descriptor `overridable_default`），判定不变。

### C. 条目预设（新建按模板，#11；批17 提升为框架通用默认）

- 包 `field_meta.json` 顶层键 `entry_presets`：
  `{"<模块>": [{"id","label","help?","fields","defaults?","id_prefix?","id_width?"}]}`；
- **框架默认**（批17）：`qbot_rpg/content/entry_presets.py` 提供**通用品类**默认预设，
  本次 = `items` 六种（材料/货币袋/药剂/礼包/装备/技能书）；**任何内容包（含空白包）都有**；
  预设引用的字段键必须在框架元数据里真实登记，由 `framework_preset_key_errors(table)` 断言校验；
- `fields` = 预设**关心字段**（顺序即表单项顺序；其余字段进「其他字段」折叠区**仍可编辑**，
  不永久隐藏——一号原则）；
  `defaults` = 初始值（叠加在字段元数据默认值之上）；`id_prefix` / `id_width` = 该预设下的 ID 口径；
- **生效预设 = 框架默认 ∪ 包声明**：同 id → 包声明**整体覆盖**框架默认（非字段级合并）；
  包新 id → 追加；包可在顶层 `entry_presets_disable: {"<模块>": ["<预设 id>", …]}` 里**关闭**
  框架默认（或包自己的）预设；无包声明 → 仍用框架默认；
- 新建流程：选预设 → 只显示关心字段 + 按 defaults 初始化；**不选预设 = 现状**（回归口径）；
  切换预设只重开新建表单，不改任何数据；
- 任何模块可配预设；无声明模块行为不变；`fields` 里声明了但模块没有的键 →
  `preset_missing_fields` 如实列出（不静默）；
- 写链路同源：`new_entry_slot(preset=…)` 供界面与 `editor_ops.create_entry(preset=…)` 共用，
  服务端按预设 defaults 初始化后叠加用户补丁（不依赖前端提交隐藏字段）。

**顶层键补充**（并入 §〇·补二契约）：`field_meta.json` 顶层键在既有六键 + `entry_merge` +
`segment_pages` 之外，新增 `id_prefix` / `id_width` / `entry_presets` / `entry_presets_disable`
/ `entry_tree`（§〇·补九）；形态非法一律报错（指出包名 + 出错键）。未声明 → 行为与现状完全一致。

**纪律**：以上全部不写死任何包名 / 模块名 / 业务字段名；换包零改动可用。

## 〇·补九、条目级层级 / 框架键全集 / 指令别名契约（批19 落地 · 2026-09-16）

> 依据：用户 2026-09-16 第二轮 9 条意见的 #4 / #6 / #7 / #8 / #9 / #5（显示完整性与归口）。
> 一号原则：**框架登记/实现的东西必须显示、可编辑**；包声明只做展示层补充。

### A. `entry_tree` —— 条目级层级挂载（#8）

用户原话：「炼金、任务板、锻造之类应该归入**生活**栏，却出现在**基础**栏里。环境事件、
时间天气应该像行动那样归在**地图**下。」左栏层级从「模块级」扩展到「条目级」。

**声明形态**（包 `field_meta.json` 顶层，通用、不写死任何名称）：

```json
"entry_tree": [
  {"parent": "life",
   "sections": [{"from": "settings", "id": "alchemy"},
                {"from": "settings", "id": "quest_board"},
                {"from": "settings", "id": "forge"}]},
  {"parent": "maps",
   "sections": [{"from": "settings", "id": "env_event"},
                {"from": "settings", "id": "time_cycle"}]}
]
```

- `parent` = 本包 `manifest.modules` 声明的模块，**或** `entry_merge` 的虚拟聚合视图；
- `sections` 每项 = `{from: <来源模块>, id: <条目 id>}`（简写 `"<来源>.<条目>"` 亦可）；
- `keep_top_level`（可选，缺省 `false`）：见下方两种挂载语义。

**两种挂载语义**：

| 类 | 触发 | 来源模块条目列表 | 计数 / 全局检索 |
|---|---|---|---|
| **移走**（默认） | 父节点是 manifest 声明模块，且 `keep_top_level=false` | 不再列出（「不再出现在原处」） | 从来源模块**改归父节点** |
| **显示挂载** | `keep_top_level=true`，或父节点是虚拟视图 | 保留原位 | 仍在来源模块（不双计） |

**编辑归属不变**：挂载条目照常编辑，写回**来源模块**的文件与校验（走既有校验 / 备份 /
原子写 / 回退链路）；条目列表项带 `mounted_from`，前端据此路由。

**计数与检索口径（写死，三处自洽）**：`list_modules.own_count` = `list_entries.count`
= `entry_index` 该模块 `count`；移走类的条目在来源模块三处同时减去、在父节点三处同时加上，
全包 `entry_index.total` 不变。虚拟视图父节点的挂载只在 `views[].mounted` 与
`list_entries.mounted_sections` 展示，**不进任何计数**（视图 `total_count` 仍 = `merged_count`）。
未声明 `entry_tree` 的包行为与现状完全一致（回归断言）。

### B. 框架键全集显示（`ModuleMeta.key_source`，#4）

map 形态模块可声明 `key_source`（来源名 → `qbot_rpg/content/framework_keys.py` 注册表）；
条目列表 = **包数据键 ∪ 来源键**：包已覆盖的标「已覆盖（包）」，来源有而包未覆盖的标
「默认（框架）」且可直接编辑 → 保存即写入包覆盖（走既有链路）。来源表由框架提供
（目前 = 消息模板全量表），编辑器读取层不写死模块名/模板键名。

### C. 指令别名视图（#7）

别名视图 = **框架内置**（各指令注册时自带的 `CommandSpec.aliases`，从既有装配实现读取）
∪ **包声明**（`settings.command_aliases`，既有 `AliasTable.from_config` 归一化）；同键以
包声明为准（标「覆盖同键」）。框架侧**没有**独立的静态别名表——本视图如实标注现状
（`framework_note`）。只读展示，不改路由与校验。

### D. 模块中文名回落链（#6）与公式中文名（#9）

- 模块显示名：包声明 → 框架目录 `module_catalog` 的 label → 模块键（不再回落裸英文键）；
- `formula` 模块按 `core/formula_loader.py` 的**实际消费面**登记中文名
  （`damage_base`/`heal_rate` 为兼容保留键，help 写明当前不消费；`battle_position.*` 与
  `damage.BattlePositionParams` 字段一一对应；`monster_def_rate`、`crit.negative_crit`/
  `elem_crit_step` 按消费面补齐）；包可用 `field_labels.formula` 覆盖。
- 模块页展示 `purpose`（目录一句话）、「当前包未使用」态；目录声明的 `overlap_with`/
  `overlap_note` 出**功能重叠黄提示**（如 `slots` ↔ `settings.slot_defs`），不硬拦。

## 一、字段与数据模型（用户 2026-09-13 拍板）

1. **不设「标签」门类**。技能等条目**没有独立的 tags 字段**。

   - **也可以直接留空**（留空 = 该条目列表里不出简述行）
   - 文件里「字段缺失」与「显式空串」语义不同：**缺失 → 引擎机制兜底生成标签**；**空串 → 作者明确留空，什么都不显示**
