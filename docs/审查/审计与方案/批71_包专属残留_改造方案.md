- **不动战斗数值**，但 `/图纸` 分支折叠、`/客制` 守卫、`/技能面板` 展示会变；不涉及伤害公式。

### 4.2 改后形状

采用**两层扩展点**，默认只做第一层（数据声明、无代码执行）；第二层是 E 系代码算子的可选兜底。

#### 第一层（推荐，本批做）：`settings.json` 的 `schema_ext` 数据声明

```json
{
  "schema_ext": {
    "enemies": {
      "parts": {
        "allow_keys": {
          "cls":            {"type": "str"},
          "break_behavior": {"type": "str", "enum": ["knockdown", "stagger", "none"]}
        }
      },
      "parts[].on_break": {
        "allow_keys": {
          "shard_sound": {"type": "str"}
        }
      }
    }
  }
}
```

- 结构：`schema_ext.<module>.<字段路径>.allow_keys = {键名: 约束}`；
  - `字段路径` 用点号 + `[]` 表示列表元素（`parts`、`parts[].on_break`），与报错 `field` 路径（`enemies.parts.3.cls`）同构；
  - 约束子集**刻意最小**：`type`（`str/int/number/bool/list/obj`）+ `enum`（可选）+ `required`（可选，布尔）。不放表达式/引用/自定义算子（那属于第二层）。
- **落点为什么是 `settings.json` 而不是 `field_meta.json`**：
  1. `check_pack` 已经收到 `settings` 模块，**零 loader 改动**；`field_meta.json` 目前不在 `modules` 里，validator 拿不到（若强行用，需要让 `loader`/`hot_reload`/`pack_protection` 都改为把包 `field_meta.json` 合进 `meta`，牵动面大）。
  2. 仓库文档口径把 `field_meta.json` 定为**展示元数据**、校验规则留框架（`docs/编辑器重写_数据包展示元数据下放方案.md:28`、`:116`、`:150`）。把「校验例外」放进 `settings` 与「行为配置在 settings」的既有分工一致；`field_meta.json` 继续只做展示。

#### 框架读取点

- `_Checker.__init__`（`validator.py:397`）：

  ```python
  raw = modules.get("settings")
  self._schema_ext = _parse_schema_ext(raw)   # 纯解析 + 形态校验；非法 → {}（或 R-5）
  ```

  `_parse_schema_ext` 是模块级纯函数：只接受 `Mapping`；`allow_keys` 仅接受 `str` 键 + `Mapping` 值；未知 `type`/未知约束键 → 记录一条 **R-5**（配置错误必须可见），并跳过该键（不静默放行）。
- `_check_enemy_parts`：
  - 允许键集 = 基础键 `("id","name","positions","break_threshold","target_priority","on_break")` ∪ `schema_ext["enemies"]["parts"]["allow_keys"].keys()`。
  - 报错消息里的「允许键」列表由该并集生成（包声明后错误信息也会反映声明，编辑器/作者自洽）。
  - 对声明的键做约束校验：`type` 不符 → R-1（`expect=<type>`）；`enum` 不符 → R-1。
  - `on_break` 的未知键分支（`:948-955`）同样改成「基础键 ∪ `schema_ext["enemies"]["parts[].on_break"].allow_keys`」。
- **可选同步**：`field_meta.py` 的 `parts.children` 可保持不登记（校验放行不依赖 meta）；若要编辑器也显示这两键，由包在**自己的** `field_meta.json` 里声明 `field_labels.enemies.parts.cls`（既有软字段机制，`content/field_meta_pack.py` `_apply_display` 会补 `soft_label` 子字段）。**框架字段表不再添加包键。**

#### 第二层（可选，E 系代码算子，本次可不做）

若某包需要「跨字段/跨模块」的自定义校验（数据声明表达不了）：

- 包内 `content/<pack>/ext/validators.py` 导出纯函数
  ```python
  def validate(module: str, path: str, entry: dict, modules: dict) -> list[dict]:
      """返回 issue 列表 [{field, kind, rule, msg, **detail}]；空列表 = 通过。"""
  ```
- 框架装载沿用 E1 的装载安全线：`settings.ext.enabled`（缺省 false）+ `--enable-pack-ext` 双闸；只从该包目录加载；异常/超时 → 该包扩展 **降级为不生效**（记录日志，不阻断校验）。

- 形状与 E1 同源，避免新造一套装载器。

#### 无声明时的兜底行为（必须与现状一致）

- `schema_ext` 缺失/空 → 允许键集 = 现状 6 键（`on_break` = 现状 3 键）；未知键报 `R16_part_unknown_key` / `R16_part_onbreak_unknown_key` **逐字不变**。

- **不动战斗数值**；只影响装配期红拦/黄提示与编辑器可见性。
- 若选第二层代码算子，引入「执行包内代码」的信任模型（同 E1/E2：只装可信包、双闸默认关、异常降级）。

   ```python
               return str(tpl_of(ctx, key) or default)
           except Exception:
               return default
       return default
   ```

   `ctx["tpl_of"]` **全仓从未被写入**（核验：`grep -rn '"tpl_of"' qbot_rpg/` 只有这一处读取 + `core/templates/__init__.py:35` 的 `__all__`）→ 该函数**无条件返回 `default`**。即：本文件 8 处 `_tpl(...)` 的硬编码串就是所有包的**实际文案**，连「key 注册了也读不到」。这解释了为什么 `battle_lock_*` 没进表也没人发现。
3. **单包 NPC 跨包可见**：字符串里的「驿站药婆」只对应 `content/veinborn/npc.json:177` `{"id":"npc_healer_apothecary","name":"驿站药婆·脉姑"}`（注意框架写的是**简称**，全名带 `·脉姑`）。其它包（test_demo 等）也会收到这条文案。

**伴生点**：`qbot_rpg/commands/explore_commands.py:611-612`

```python

              {"reason": "当前不在营地或副本安全区（驿站/营地可休息，或找驿站药婆疗伤）"})
```

#### 6.2.2 修复 `_tpl`（本条的隐藏前提）

`battle_launch_commands.py:351-356` 改为走真正的模板入口并支持占位符数据：

```python
from qbot_rpg.core.templates import tpl_of as _tpl_of

def _tpl(ctx, key, default, **data):
    try:
        return _tpl_of(ctx, key, data) or default       # 缺 key → 回落 default（零破坏）
    except Exception:
        return default
```

- 为什么必须改：不改的话 6.2.1 注册的 key 也读不到（`ctx["tpl_of"]` 恒缺失）。

- 调用点 `:430` 改为：
  ```python
  _tpl(ctx, _TPL_WEAK_BLOCK_KEY,
       f"❌ 你还在虚弱中（剩余 {_weak_left} 秒）——先回营地休整",
  ```

  default 串**去掉 NPC**（中性），保证「未注册 key / 未覆盖的包」也不含单包 NPC。
- 其余 7 处 `_tpl` 调用补 `**data` 与否都可（当前调用不传占位符，保持原样即可）；统一建议：无占位符的直接 `_tpl(ctx, key, default)`。
