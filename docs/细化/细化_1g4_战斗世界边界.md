### 1.1 丢失挂起状态流转（判定链）

```
战斗进行中（[1g1a·S1-S3 循环]）
  │ 玩家操作（/攻击 等战斗指令）
  ▼
① 惰性查询目标实例：仍在场？ ──是──→ 正常结算本回合（回 1g1a 主循环）
  │ 否（被他人击败/实例消失）
  ▼
② 提示「怪物丢失」（TPL-1G4-01A）→ 挂起子态 lost_pending={ target_ref, map_id, pending_since }（F-08）
  │
  ▼（玩家下一次操作）
③ 查询当前 spawn 配置（[2a1b·R23]）：
  ├─ 有刷新行且可刷新（未达 count 上限/出没条件满足）→ 等待刷新器补刷（respawn_minutes）
  │    ├─ 刷新成功 → 目标实例替换为新实例（满血）→ 提示「战斗继续」→ 玩家可操作开战（玩家侧状态保留）
  │    └─ 未到刷新时刻 → 继续挂起（无时限，LOST-01）
  └─ 无刷新行（spawn 删除/出没条件不满足）→ 提示「怪物已消失」→ 按退出结算（LOST-05）
  │
  ▼（挂起期间任意时刻）
  玩家主动 /逃跑 或「放弃」→ 按退出结算（LOST-05）；30 天无操作 → 僵尸回收（TIME-05）
```

- 挂起不落新增状态机：丢失挂起是**战斗会话的属性扩展**（F-08），不新增 [1g1a] 8 态之外的战斗状态；会话仍属 3.18 单会话互斥管辖（TIME-03）。
- 丢失期间的怪物实例由世界层管理：实例死亡即从场上移除，刷新补位（[2a1b·R23] count 上限约束），战斗会话只持有目标引用（id+name 冗余，[4a·SCHEMA-5]），不持有实例对象。
