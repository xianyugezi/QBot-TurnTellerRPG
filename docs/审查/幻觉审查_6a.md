## 三、P1（1 条）

### P1-1：§5.2 pierce 参数化 ADR 内部措辞矛盾（必填 vs 缺省）
- **位置**：细化 L245「增加**必填**参数 `target`」 vs L256「默认：`target` **缺省** = def（兼容 [效 L325]…）」
- **问题**：同一裁决内两行自相矛盾——「必填」则无「缺省」可言。R-03（细化_0 L59）与 1b（细化_1b L225）均已按「缺省 = def、可省略」定案，6a 作为权威落点（细化_0 明示「6a 为权威落点」）的「必填」表述为孤立措辞，实现者仅读 6a 会收到两套指令。
- **证据**：效 L316「pierce 无 target」（定稿现状），ADR 引入 target 的合理性成立；但必填/缺省必须统一。V-12 判定（pierce.target ∉ {def,spr} 红拦、缺省按 def 对位提示）隐含 target 可缺省，与「必填」冲突。
- **建议**：将 L245 改为「增加 `target` 参数（缺省 = def）」，删除「必填」字样，与 L256/R-03/1b 三处统一。

### P2-2：pierce.pct 字段由定稿布尔改为数值百分比，撞名未显式声明
- **位置**：细化 L248 `pierce := { target: "def" | "spr", pct: 0-100 }`；L256「pct 默认 30」
- **问题**：效定稿 L313-318 统一参数结构中 `pct` 为**布尔**（是否百分比，pierce 取 true）、数值走 `value`（L325 value=30·pct=true）。6a ADR 将同一字段名 pct 改为 0-100 数值并弃用 value——属有意参数化（R-03 已采纳），但未声明「pct 语义由布尔改为百分比数值、value 字段并入 pct」，实现者照效定稿 schema 会写出 `{value:30, pct:true, target:"spr"}` 而 6a 期望 `{pct:30, target:"spr"}`。
- **建议**：§5.2 补一句字段映射声明（value→pct、pct 布尔→数值），与效 L317 对齐说明。
