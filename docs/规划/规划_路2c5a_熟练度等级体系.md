## A. 配置与数据层（proficiency.json）

### A1. proficiency.json 加载与 7 级职业等级建模
- **定稿依据**：熟练 §一（proficiency.json = 通用框架机制，任何生活职业共用；proficiency 管等级成长，profession 管玩法入口）；§2.1（7 级默认名 见习→正式→精通→专家→大师→宗师→王，内容包可改名；职业等级与角色等级独立，两套尺子）；§5.1（字段表：id 必填唯一对应 jobs.json 生活职业 / tier_names 7 级称号 list 可改名 / sp_per_level / sp_panel / energy / job_tier_map / titles）；§八（4.1 内容包结构新增 proficiency.json 行；4.1.1 manifest 新增声明；4.2 元数据表；4.5 职业引用硬拦）。
- **实现要点**：
  - 加载器：路径 `proficiency.json` 按职业 id 索引（内容包可覆盖）；缺文件/缺条目 = 全默认兜底（系统可用）。
  - tier_names 默认 `["见习","正式","精通","专家","大师","宗师","王"]`，内容包可改名（任意 7 个名字，**顺序即等级序**）；改名后仍须 7 项且无重复（D1 校验）。
  - id 必须对应 jobs.json 中已登记生活职业（职业引用硬拦，§六 文案）；职业等级独立存储于 proficiency 条目，与角色等级互不折算。
  - 本任务落地全部默认字段（exp_sources / sp_per_level / sp_panel / energy / titles）的 schema 与默认值，供后续任务读取；不做任何结算逻辑。
- **验收标准**：默认 7 级名加载正确；内容包改名生效且等级序保持；职业 id 不在 jobs.json → 加载报硬错（§六 文案）；缺文件/缺字段全兜底不崩；职业等级与角色等级两套字段独立（断言互不折算）。

### A2. job_tier_map 称号→配方等级区间（settings.json · 可配）
- **定稿依据**：熟练 §2.1（settings.json `job_tier_map`：称号→配方等级区间，默认 见习 1-5 / 正式 6-10 / 精通 11-20 / 专家 21-30 / 大师 31-40 / 宗师 41-50 / 王 51+）；§5.1（job_tier_map 字段，默认值取 settings.json 配置）；§六（等级引用硬拦）。
- **实现要点**：
  - 从 settings.json 读取 job_tier_map（内容包可覆盖；缺失 → 默认区间表兜底）。
  - 解析服务（查表双向）：给定配方等级 → 返回所在职业称号；给定称号 → 返回区间 [min,max]（供配方门槛/委托档位等下游读取）。
  - 区间约束：7 档与 tier_names 一一对应、连续无空隙、整体覆盖 1 级以上；区间与 tier_names 长度不一致 → 加载期报错（回归 D1）。
- **验收标准**：默认区间逐档正确（1-5 / 6-10 / 11-20 / 21-30 / 31-40 / 41-50 / 51+）；边界值归档（5→见习、6→正式、50→宗师、51→王）；内容包覆盖生效；区间断裂或与 tier_names 长度不符 → 加载报错；查表接口单测（配方等级 ↔ 称号双向）。

### A3. 熟练经验成长曲线（每职业熟练值 + 曲线字段）
- **定稿依据**：熟练 §2.1（proficiency.json 承载「7 级默认名 + 内容包可改名 + 每职业熟练值 + 成长曲线」）；§5.1（每职业熟练值落点）；§八 判定顺序（熟练经验入账 → 升级判定 → SP 发放）；**开放项：§5.1 字段表未单列成长曲线字段名/公式 → 本任务定义实现字段 growth_curve 并回登记 4.2/4.5**。
- **实现要点**：
  - 存储：每条 proficiency 含 level（所在档级数）+ exp（当前档内熟练值）。
  - 实现字段（建议，回登记 4.2）：`growth_curve: {formula: "linear"|"exponential"|…, base: <int>, per_level: <int>}`；定稿未拍板公式 → 默认约束为「升级所需经验随职业等级严格递增」（防刷级，§九），曲线参数内容包可配；以「growth_curve 进入 4.2 元数据表 + 4.5 校验（曲线单调不降/无 0 值）」为回登记事项。
  - 溢出跨档：升级后剩余经验保留进入下一档。
- **验收标准**：默认曲线下由低到高各档所需经验严格递增；溢出经验跨档保留；内容包自定义公式生效；growth_curve 非法（负 base / 0 步长 / 非单调）→ 校验黄提示；回登记事项在代码注释/规划可见。

### A4. 熟练经验来源与倍率（制作/采集/战斗）
- **定稿依据**：熟练 §2.1（熟练经验来源：制作（合成/炼金/锻造）+ 采集 + 战斗，各生活职业可配经验倍率）；§5.1（exp_sources map，倍率可配）；§八（熟练经验入账发生在制作/采集/战斗结算时）；§九（刷级风险对策：经验来源倍率可配 + 采集/制作频率控制）；边界：路2c3 强化 D2（强化无熟练出口，已登记不产出）。
- **实现要点**：
  - exp_sources：`{craft: <倍率>, gather: <倍率>, combat: <倍率>}`，每生活职业可配；缺省 1.0。
  - 钩子接入：制作结算（合成/炼金/锻造，统一调用入账接口）、采集结算、战斗结算各调一次 `grant_proficiency_exp(job_id, amount, source)`；**强化不产出**（沿用路2c3 D2 断言）。
  - 防刷级：入账走框架频率控制（沿主文档 7 章防刷屏模式）；入账经验 = 基础经验 × 倍率；仅对绑定该生活职业的玩法入账（job_id 匹配）。
- **验收标准**：制作/采集/战斗三来源各 1 用例，入账 = 基础 × 倍率；倍率 0.5/2.0 配置生效；锻造/炼金合成与采集、战斗结算后 proficiency.exp 增加；强化结算后 exp 不变（断言）；频率控制触发时不入账并提示。

## B. 等级引擎与 SP

### B1. 熟练经验入账 → 升级判定 → SP 发放管线
- **定稿依据**：熟练 §2.2（每升 1 级职业等级 → 获得 1 点 SP，可累积，sp_per_level 可配）；§八 判定顺序（熟练经验入账 → 升级判定 → SP 发放）；§2.1（职业等级与角色等级独立）；§十 验收（升级 → SP 发放，sp_per_level 可配）。
- **实现要点**：
  - 统一入账接口 `grant_proficiency_exp`（A4 三来源调用）：累加 exp → 与 A3 曲线比对 → 跨级连升判定（一次入账可跨多级）→ 每级发放 sp_per_level 点 SP（累积于 proficiency.sp）→ 落存档。
  - 事务与幂等：入账 + 升级 + 发 SP 同写「SQLite 事务 + message_id 幂等」模式（路2c3 B4 同款），失败整体回滚，防双扣。
  - 升级提示：单条消息报告 职业 / 原等级→新等级 / 获得 SP；跨级连升逐级折叠提示（§九 防刷屏）。
  - 升级事件广播：供职阶门槛下游（配方等级区间/炼金三层漏斗）消费；本路只发事件不实现消费方。

- **验收标准**：单次入账跨 2 级 → SP 累计 = 2 × sp_per_level；sp_per_level=0 → 不发 SP；升级提示单条消息（折叠）；升级后无任何面板项自动解锁（移交 B2，断言为假）；事务失败整体回滚（exp/level/sp 三态一致）。

### B2. SP 面板分支自选解锁（等级到了自己选）
- **定稿依据**：熟练 §2.2（/技能面板 查看：分支自选解锁，**不是等级自动给**；解锁项内容包可配：品质上限 +10（可多次）/ 投入次数 +1（可多次）/ 特性位 +1（默认上限 3 普通，可配 1-6）/ 解锁复制/进化/挑战 / 采集量 +1 / 连锁上限 +1）；§2.3（每级解锁机制明细表，内容包可配）；§5.1（sp_panel 解锁项 list）；§六（等级引用硬拦）；§九（把「等级到了自动给」改为「等级到了自己选」= 成长自由度+重复可玩性）。
- **实现要点**：
  - sp_panel 解锁项 schema：`{id, name, desc, cost(SP 点数), max_times(可多次项), require_tier(可空), require_panel(可空)}`；require_tier 引用的等级必须在 tier_names 内（§六 硬拦）。
  - 核心语义：升级只发 SP 点（B1），**任何面板项均不随等级自动授予**；玩家自选解锁 → 校验 SP 余额与前置（等级/前置项）→ 扣 sp_points → 累计 sp_used → 即时生效。
  - 生效输出表：品质上限/投入次数/特性位（默认上限 3 普通，可配 1-6）/复制/进化/挑战/采集量/连锁上限各生效点由对应玩法读取（路2c 炼金/钓鱼/锻造引用，本路只产出状态）。
  - 可多次项按 max_times 限次数；sp_panel 为空 → 面板显示「无可用解锁项」。
- **验收标准**：升级后面板无任何自动解锁（自动给断言为假）；SP 不足拒绝解锁；require_tier/require_panel 不满足拒绝；可多次项超 max_times 拒绝；解锁后对应玩法限值即时变化（每类 1 用例）；解锁项引用不存在等级 → 加载硬拦（§六 文案）。

### B3. sp_used 与熟练度持久化（存档 3.7/3.17 对齐）
- **定稿依据**：熟练 §四（存档：熟练度 = proficiency 按职业（等级/熟练值/SP 点）；换包策略三选一复用框架 3.7）；§八（3.18/A.5 快照补：熟练度/SP/能量条 = 非会话持久状态，常驻存档）；§十 验收（熟练度/SP 全部入 3.7 存档，换包三选一复用）；**开放项：定稿以「SP 点」表述未单列字段名 → 落 `sp`（未用余额）/`sp_used`（累计已用）并回登记 4.2/3.18**。
- **实现要点**：
  - 存档条目（每职业一条）：`{job_id, level, exp, sp, sp_used, unlocked: [面板项 id 列表]}`；加载期一致性校验：sp_used ≤ 发放合计。
  - 持久化：随角色档案常驻（非会话状态）；写入走 B1 同一事务；快照 3.18/A.5 覆盖熟练度/SP/能量条。
  - 换包：同 ID 保留 / 红名 / 一键清除三选一（复用框架 3.7 策略口，不重实现）。
  - 迁移：旧档缺失 sp/sp_used → 按发放合计补算（默认 0）。
- **验收标准**：重启后 level/exp/sp/sp_used/unlocked 完整恢复；解锁与扣点同事务（崩溃恢复一致）；快照导出/导入含本组字段；换包三策略各 1 用例；旧档迁移补算用例。

## C. 指令与称号

### C1. /技能面板 指令（参数与返回格式）
- **定稿依据**：熟练 §2.2（`/技能面板 查看` 查看分支自选解锁项）；§八 7.1 指令表（/技能面板 已有转正登记）；§九（消息刷屏对策：一步一条 + 折叠渲染 + 频率控制）；§5.1（sp_panel / sp_per_level 读取）；**开放项：定稿仅给「查看」，子指令与返回字段由本任务按 §2.2 六类解锁项细化并回登记 7.1**。
- **实现要点**：
  - 参数契约：`/技能面板 [职业]` = 查看（缺省 = 当前默认/最近职业）；`/技能面板 解锁 <职业> <解锁项ID>` = 自选解锁；非法参数 → 用法提示。
  - 返回格式（查看）：职业 / 当前等级（含称号名）/ 熟练值 / SP 余额（已用/总计）/ 可解锁列表（cost + 前置 + 可多次余量）/ 已解锁列表；列表折叠渲染，一步一条消息。
  - 解锁路径：校验（B2）→ 扣 SP → 写 sp_used/unlocked → 单条消息「解锁成功 + 效果摘要」；挂接频率控制；解锁结果即时生效（B2 生效输出表）。
  - 职业参数非法 / 未练职业 / 无 SP → 明确提示。
- **验收标准**：查看 / 解锁 / 非法参数三用例；返回字段齐备（职业/等级/熟练值/SP 余额/可解锁/已解锁）；解锁扣点且即时生效；消息单条（列表折叠断言，无刷屏）；7.1 指令表转正落点可见。

### C2. 称号解析与王称号按职业独立授予
- **定稿依据**：熟练 §2.1（7 级第 7 级「王」── 炼金王/铸造王/钓鱼王/收集王…**按职业独立授予**）；§2.3（王：终极称号 = 全图鉴 + 专属配方 + 称号加成（全属性 +X% 可配）+ 群内称号展示；条件 = 该职业图鉴全亮；王称号**不唯一**，按职业独立授予）；§3.6（titles 注册表：source=king 由职业自动生成条目，id=职业 ID；授予逻辑与佩戴体系分离——本任务只到「授予并进入 title_state 可佩戴列表」，佩戴槽/消息前缀 [称号] 归佩戴路线，登记引用）；§八 判定顺序（王称号授予（图鉴全亮）→ 称号发放 → 进入 title_state）。
- **实现要点**：
  - 称号解析服务：7 级称号名读取自 tier_names（不硬编码）；王称号显示名默认 = 职业名 + 「王」（炼金王…），内容包可改。
  - 授予判定：该职业**图鉴全亮**（数据接口来自图鉴/收集系统，本路登记依赖并实现判定服务）；按职业独立——各职业互不影响；不唯一——同职业可多人拥有。
  - titles 注册表：source=king 条目由职业条目自动派生（id=职业 ID），无需手工配置；授予即写入 title_state 已拥有集合（§3.6/§四）。
  - 称号加成：全属性 +X% 可配（内容包），授予后生效；数值接入框架属性聚合（登记引用，不重复实现）。
- **验收标准**：A 职业图鉴满、B 职业不满 → 仅 A 授予（独立性单测）；图鉴未满不授予并提示进度；titles 中 king 条目自动生成（id=职业 ID，无需手工配置）；同职业两名玩家可各自获得（不唯一）；授予后进入 title_state 可佩戴列表（佩戴渲染交接登记）；称号加成配置生效。

## D. 校验、编辑器与可选钩子

### D1. 熟练校验器（等级/职业引用硬拦 + 配置一致性）
- **定稿依据**：熟练 §六（校验器新增行：等级引用「解锁项引用的等级『大师』不在 7 级称号表」= 硬（引用不存在）；职业引用「proficiency 的职业『炼金』不在 jobs.json」= 硬；能量配置「能量条开启但 max_by_tier 缺某级」= 提示）；§八（4.5 校验器登记）；§十 验收（等级/职业引用硬拦，其余提示）。
- **实现要点**：
  - 硬拦（阻断加载）：① sp_panel 解锁项 require_tier 引用不在 tier_names → §六 文案报错；② proficiency 职业 id 不在 jobs.json → 报错；③ job_tier_map 区间与 tier_names 长度/顺序不一致（A2 前置）。
  - 提示（黄，不阻断）：① energy.enabled=true 但 max_by_tier 未覆盖 7 级；② titles source 枚举非法（source ∈ king/contest/achievement/custom）或 id 重复；③ growth_curve 非正 / 非单调（A3）；④ sp_used 超发放合计（B3 加载检查）。
  - 聚合报告：加载期一次输出，不逐条刷屏。

1. A1 → A2 → A3 → A4（数据层：建模 → 区间 → 曲线 → 来源钩子）；

## 不变量（跨系统硬约束）

- 职业等级与角色等级完全独立（两套尺子，互不折算）；
- 任何面板解锁项都不随升级自动授予——升级只发 SP，玩家自选（sp_used 持久化）；
- 判定顺序固定：熟练经验入账（制作/采集/战斗结算时）→ 升级判定 → SP 发放；强化不产出熟练经验（路2c3 D2 边界沿用）；
- 王称号按职业独立授予（图鉴全亮门槛），不唯一；titles 注册表 source=king 条目由职业自动派生（id=职业 ID），不手工配置；
- 结算与落档统一「SQLite 事务 + message_id 幂等」模式（路2c3 B4 同款），防双扣；
- 能量条为可选软节奏，默认关；合成永不需能量（保底通道）；本路不实现 profession.json 生活玩法（另立路线）。
