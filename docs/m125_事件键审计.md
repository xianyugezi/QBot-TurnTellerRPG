## 4. 配置化风险（批5 关键结论）

**事件键=「写侧字面/常量 + 读侧前缀匹配」双面协议**，name 段一致是唯一契约，全链无哈希/外键。**凡消费走前缀匹配+剥壳拆 param 的键，name 可配零断链**；断链集中在：

1. **内容包条件字面量（最大风险）**：quest/npc/shop/achievements JSON 内 `{var:"[事件:副本通关]"}` 写死（content/demo 各包）——改名后前缀仍匹配但剥壳 name≠新 name → 读 0 恒不满足。**现有键名不可静默改，只能新增映射/别名或全量同步改包**。
2. **条件引擎 EVENT_PRESETS L183-188 + 各 content 校验器 COND_EVENT_PRESETS**：改名须同步，否则黄提示（非阻断）。
3. **精确键读**：hidden_trigger.py:298 / investigate.py:295 / adventure_log _prev_count 用常量 ec.get(base)——base 改 settings 后须同源读取，否则首见判定失配。
4. **双路写同键**：图鉴新增 3 处（codex.py:387、fishing_codex.py:172 字面量 + log_codex_new 常量）必须同源否则计数分裂；隐藏发现常规路 log_hidden_find 与兜底全键 investigate_commands.py:510 同理。
5. **前缀语法外壳不可配**：condition_engine L245、quest L431/L451、4 个内容校验器、assembly/context.py:795 _event_key_parts 均按 `[事件:` 前缀 + `]` 尾缀 + rsplit(":") 解析——**只可配置前缀后 name 段（如「副本通关」），`[事件:` 外壳与 `:target]` 拼装语法必须硬编码保留**（前缀是路由语法，区别 `[签到:`/`x_`/`[背包:`）。nested target 段只依赖外壳结构，安全。
6. 展示层 _count_key_name 只依赖 `:` 结构，安全；audit_store E1-E6 无关。

**settings events 段建议形态**：`events: {"签到":"签到","副本通关":"副本通关",…}`（name 段可配，写读统一经 settings 解析 + 缺省回退现字面量零破坏）；无写点的预置名（神鱼支线完成/钓鱼王/锻造王，仅成就 presets 引用）无需入配置。批5 改读点清单：7 字面量写入点 + adventure_log 6 常量 + ENV 常量 + hidden_trigger/investigate 精确读 2 处 + EVENT_PRESETS 2 处同步。
