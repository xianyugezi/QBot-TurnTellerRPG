# 内容编辑器 · 重写需求与约束（2026-09-13 起）

> 背景：2026-09-13 按用户拍板**删除**了原 Web 内容编辑器（见 `02_遗留登记.md` #86）。
> 本文件是**重写版编辑器的唯一需求来源**：用户逐条拍板，逐条往下加，不得自行发挥。
> 交付纪律沿用既有约定：先出样式稿/方案给用户审 → 确认后再写实现；面向非技术用户；纯配置优先。

## 〇、定位（**最高优先级原则** · 用户 2026-09-13 纠正）

> 用户原话：「不要参考数据包的内容做，web编辑器是后面给策划用户用的，不是专门为这个数据包做的，
> 不要把数据包的专属东西作为通用框架的东西。」

0. **编辑器 = 通用工具**，服务对象是**未来的内容作者/策划**，**不是为 veinborn（或任何单个包）定制**。
   - **禁止**把某个包的专属业务结构写死进编辑器框架：例如「装备就是 10 项属性」「必须有套装/词条/孔位」
     「技能必须有 buff 表」这类**具体业务字段不得硬编码**。
   - **正确形态 = 元数据驱动**：界面读**内容包的模块声明**（`manifest.modules`）与**字段元数据**
     （`qbot_rpg/content/*_models.py` 的 `FieldMeta`：type / label / default / options / 分组）
     动态渲染表单与分区；换包 → 界面随之变化，**编辑器代码不用改**。
   - 真实数据（veinborn 的技能/装备条目）在样式稿与测试中**只作为示例内容**，不得成为框架假设。
   - 判断标准：**把 veinborn 换成另一个包，编辑器是否零改动可用**；做不到的设计一律推翻重来。

## 一、字段与数据模型（用户 2026-09-13 拍板）

1. **不设「标签」门类**。技能等条目**没有独立的 tags 字段**。
2. **「简述」= 自由文本**（对应内容包 `brief`）：
   - 想写标签就写标签（如 `【伤害】【消耗】【连段】【派生】`）
   - 想写别的文本也行
   - **也可以直接留空**（留空 = 该条目列表里不出简述行）
   - 文件里「字段缺失」与「显式空串」语义不同：**缺失 → 引擎机制兜底生成标签**；**空串 → 作者明确留空，什么都不显示**
     （引擎侧实现见 `qbot_rpg/commands/basic_commands.py::skill_brief`）
3. **「详情」= 自由文本**（对应 `detail`），长文本，界面里给大的多行输入框。
4. 字段名一律**中文显示**（name/type → 名称/类型），且**中文名 + 原始键名并列**显示
   （中文为主、键名为辅，便于用户既看懂又能对上 JSON 键）；中文 label 只放显示层，不动数据层；
   字段无中文名时只显示原始键，不得凭空造词。

## 二、布局（用户 2026-09-13 拍板）

5. **编辑面板是主角**：占主要面积，**不要被挤到角落**（反对「左窄右窄、中间堆表格」的三栏挤压形态）。
6. **列表只需要名字**：条目列表**不必显示多列字段**（技能页只显示技能名即可），避免把空间让给表格。
7. **点一下就看**：点击列表条目 → 直接在编辑面板里显示该条目信息（不需要再点「编辑」按钮、不要弹小窗）。
8. 顶栏保留：内容包名、保存状态、当前身份。
14. **条目列表不用翻页**：列表用**滚动条**承载长列表（条数多时滚动），**不做分页控件**
   （用户 2026-09-13 补充）；滚动条要**细、低对比、不显眼**（自定义 `::-webkit-scrollbar` 细条，
   悬停才稍微明显），不要系统默认粗条抢视线。

## 二·补、编辑面板分区（用户 2026-09-13 反馈）

9. **编辑面板做分区切换（tab / 分段控件）**：右面板顶部一排页签，**默认只显示第一组**，
   其余字段组按需切换；不要把全部字段堆在一屏。
10. **「套装」等派生/附属信息挪到独立分区**，不出现在主属性区。
11. **装备属性必须列全 10 项**（游戏真实属性表 `content/<包>/stats.json`）：
    生命 hp / 法力 mp / 精力 stamina / 聚焦 focus / 敏捷 agi / 专注 foc / 精神 spr / 幸运 lck /
    攻击 atk / 防御 dfn。每项可填加成数值。
12. **技能要有「附加效果」分区**（用户点名：技能附加 buff 之类没做）：条目 = 效果类型 / 目标（自身·敌方）/
    名称 / 数值或层数 / 概率 / 持续；真实形态参考 `content/<包>/skills.json` 的 `effects`
    （`{"type":"mark_add","target":"self","mark":"sword_aura","count":15}`、`{"effect":"sw_aura_shield"}`、
    状态附加等）与 `consume_marks`（印记消耗）；支持多条、可留空。
13. **建议分区划分**（待用户确认）：
    - 技能页：`基本` / `数值` / `附加效果` / `文本`
    - 装备页：`基本` / `属性` / `词条·孔位` / `套装` / `文本`

## 二·补二、左侧导航结构（用户 2026-09-13 再补充）

14. **模块分类与条目列表拆成「两栏」**（用户 2026-09-13 澄清：**是两栏，不是上下两段**）：
    左起 **第 1 栏 = 模块分类导航**（技能 / 物品 / 怪物 / 地图 / 任务 …，来自包的模块声明）；
    **第 2 栏 = 当前模块的条目列表**（只名字，滚动条，无翻页）；**第 3 栏 = 大编辑面板**（占其余全部宽度）。
    三栏并列、各有独立标题条与边界线；**不许**把"技能/物品"这类分类名与"御剑·突/砺脊刃"这类条目名
    混排在同一栏里（用户原话：太挤了）。前两栏保持窄（合计约 350–400px），编辑面板仍是主角。
15. **模块层级（用户 2026-09-13 两次补充，最终形态）**：
    `技能 ▸ 效果 / 状态 / 印记 / 派生链`、`怪物 ▸ 行动`、`物品 ▸ 装备`
    （用户原话：装备是物品的一种；效果/状态/印记/派生链并入技能；行动并入怪物）。
    **全部由包的 manifest `module_tree` 声明**，编辑器不写死任何归并关系（换包/改声明即可，零代码改动）。
16. **装备归入物品**（用户原话：「装备就是物品的一种，归纳进物品里面吧」）：
    模块导航**不并列出现「物品」与「装备」**，而是**层级**：`物品 ▸ 装备`（装备作为物品下的子类/筛选）。
    **通用实现**：编辑器支持**模块层级（父子）**，归并关系由包的元数据声明，编辑器不写死"装备属于物品"
    —— 别的包若把装备声明为独立模块，界面照其声明显示。

## 三、交互取向（沿用既有约定）

9. **面向非技术用户**：字段中文名；新功能必须有引导（Tip / 帮助），不允许「静默」行为。
15. **发现性优先**：能点的东西要看得出来能点；不给用户需要背的隐藏操作。
16. 校验要给**人话提示**（哪一项、为什么不行、怎么改），而不是只报错码。

## 四、样式（待用户选定）

17. 2026-09-13 已出 4 版样式稿供选（暗色专业风 / 亮色卡片风 / 终端极简风 / 猎师主题风），
    初版按「三栏」做的——**因第 5/6/7 条布局约束，需按新布局（窄列表 + 大编辑面板）重做后再定版**。
18. 定版后：技能页 + 装备页各出一张作为实现基准（装备字段更密集：部位/稀有度/攻击/防御/词条/孔位/套装/绑定）。
