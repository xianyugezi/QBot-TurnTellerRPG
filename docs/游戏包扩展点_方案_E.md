# 游戏包扩展点方案（E · 让内容包自持代码，2026-09-14）

> **起因**：用户拍板 #6+#7「让游戏包能自己加指令、自己决定消息长什么样、自己带测试与脚本」。
> 这同时是**云海分支问题的根治**：他们之所以把 `cloudsea_*` 塞进 `qbot_rpg/`（框架目录），正是因为框架当时没有扩展点。
> **定位**：框架 = 引擎与契约；内容包 = 数据 + （可选的）**扩展代码**；编辑器 = 通用工具。三者分离（沿用第〇节原则）。
> **状态**：草稿 → **待用户审**。审过再分批实施。

---

## 一、目标与验收标准

1. **包能自己加指令**：包目录内声明指令（名/别名/参数/帮助）+ 自带处理函数 → 启动时被框架发现并注册；**框架不动一行**。
2. **包能自己决定消息样式**：文案覆盖（**已具备**）+ **可选**的自定义渲染/发送钩子。
3. **包能自己带测试与构建脚本**：约定的目录与运行方式（`pytest` 能按包发现、构建管线可分阶段跑）。
4. **判断标准**：造一个**新包**，只在包内放扩展文件 → 指令可用、样式生效、测试可跑；**框架与编辑器零改动**。

## 二、现状盘点（实测，2026-09-14）

| 能力 | 现状 | 结论 |
|---|---|---|
| 指令注册 | 中央注册表 `qbot_rpg/assembly/router_setup.py`（40 个 `qbot_rpg/commands/*` 模块的 `register_*` 函数元组）；`Router.register(spec, replace=False)` **重名冲突会 ValueError** | **无扩展点**（包无法加指令）；但冲突检测已在，可直接复用 |
| 消息文案 | `qbot_rpg/core/templates/__init__.py`：单一全量表 `template_table.json`；**`content/<pack>/templates.json` 覆盖同 key（深合并）** | **已具备** ✓（本项无需再做） |
| 渲染/发送 | `qbot_rpg_bridge/` 单一实现（发送器/渲染器集中） | **无扩展点** |
| 存档状态 | `player_pack_state(player_id, pack_id, state)`（批 D） | **已具备** ✓（包可直接用） |
| 包数据自描述字段 | 校验器已放行 `cls`/`break_behavior` 等键（批次 1）；字段元数据可下放包内 | **已具备** ✓ |
| 测试/构建脚本 | `tests/unit/**` 扁平 + `scripts/**` 零散 | **无按包约定** |

## 三、设计（三块扩展点 + 一条装载安全线）

### E1 指令扩展点（建议第一批做）
- **包内声明**（纯数据，非技术作者也能读）：`content/<pack>/commands.json`
  ```json
  { "commands": [
      { "name": "潮汐", "aliases": ["tide"], "usage": "潮汐 [查询|切换]",
        "help": "查看/切换当前潮位（云海专属）", "handler": "tide", "gm_only": false } ] }
  ```
- **包内实现**：`content/<pack>/ext/commands.py`，导出 `def tide(ctx, parsed) -> str`（返回值 = 玩家可见文本，走既有模板/渲染链路）。
- **框架侧装载**：bootstrap 时若该包**启用了扩展**（见装载安全），读 `commands.json` → 校验（名/别名**不得与框架指令重名**，冲突即**拒绝并明确报错**，不静默覆盖）→ 用 `CommandSpec` 注册进 Router。
- **框架暴露的稳定 API（`qbot_rpg/ext_api.py`）**：`ctx` 读取（玩家/设置/包状态）、`pack_state` 读写（复用批 D）、`tpl(key, data)`（模板，含包覆盖）、`rng`、`log`。**包代码只许 import 这个面**（其余 `qbot_rpg.*` 视为内部实现，不承诺兼容）。

### E2 渲染/发送扩展点（第二批）
- **默认**：走框架渲染器（现状不变）。
- **可选钩子**：包内 `ext/render.py` 导出 `def render(event, data, default_text) -> str | None` —— **返回 None = 用框架默认**；
  框架在拼最终消息前调用，仅对**该包**的事件生效（战斗/探索等事件类型按既有事件名）。
- **限制（重要）**：钩子**只许改写文本**，**不得**改结算/数值/状态（结算与渲染严格分离，避免包代码污染引擎）。
- 发送器同理：**默认共用**；包若要自定义投递（如换行策略/分段），走同一钩子面，不允许绕过。

### E3 测试与构建脚本约定（第三批）
- `content/<pack>/tests/` —— 包自带测试，`pytest` 按包发现（`conftest.py` 提供「以该包为内容根」的 fixture）；
- `content/<pack>/scripts/` —— 包自带构建/校验管线（设计稿→json 的 parse/assemble/verify，分阶段可重跑）；
- 框架只认**入口约定**（如 `build.py --check`），不规定内部结构。

### 装载安全（贯穿三块，必须先于 E1 落地）
1. **默认关闭**：`settings.ext.enabled`（缺省 `false`）+ 启动参数 `--enable-pack-ext` 双闸；未启用时**完全不读包内 `ext/`**。
2. **信任模型写进文档**：包内 Python = 可执行代码，**只装可信来源的包**（分享的 `.ttrpack` 若带 `ext/`，导入时明确提示"该包含扩展代码，需手动启用"）。
3. **路径约束**：扩展模块只从**该包目录内**加载；禁止符号链接逃逸；禁止 `..`。
4. **能力约束（不做的事）**：不提供网络/子进程/文件系统通吃的 API；`ext_api` 面刻意最小化。
5. **失败隔离**：扩展装载/调用失败**不得**让机器人与其他包崩溃 —— 记录日志 + 该扩展**降级为不生效**，玩家看到的是默认渲染与「该功能暂不可用」人话提示。

## 四、分批实施与验收

| 批 | 内容 | 验收 |
|---|---|---|
| **E1** | `ext_api.py` 最小稳定面 + `commands.json` 声明 + `ext/commands.py` 装载 + 重名拒绝 + 装载安全双闸 | 造探针包：包内加一条指令 → 框架零改动即可用；重名指令被拒且报错清晰；未启用扩展时该指令不存在 |
| **E2** | `ext/render.py` 钩子（返回 None 走默认）+ 事件白名单 + 渲染与结算隔离 | 探针包改写某事件文本；**结算数值一字不变**（对拍断言）；钩子抛错 → 落默认渲染不崩 |
| **E3** | `content/<pack>/tests` 与 `scripts` 约定 + 按包发现 + 构建入口 | 探针包自带测试被 `pytest` 收上；构建脚本 `--check` 可重跑 |
| **E4（可选）** | 把云海那 11 件 `cloudsea_*` 按本方案改写成**包内扩展**，作为真实样本验证（**需用户先给策划案/授权**） | 云海包在**不改框架**的前提下跑通其专属指令/渲染 |

## 五、不做的事（明确边界）

1. **不允许覆盖框架指令名**（重名一律拒绝，不做 `replace=True` 的包通道）；
2. **不允许包代码改结算**（只渲染/只读；数值与状态只能通过既有配置与 `pack_state`）；
3. **不做热加载**（改了包扩展需重启，与既有"内容更新需重启"一致）；
4. **不做跨包共享**（包之间不互调扩展；共享能力应提升为框架能力）；
5. **不改云海分支现状**（他们那 11 件仍留在他们分支；本方案是「以后他们可以按插件形态重做」的路径）。

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| 扩展代码拖慢/拖崩主流程 | 装载失败降级 + 调用超时/异常兜底 + 只允许同步纯函数式钩子（禁长任务） |
| 扩展 API 面一冻结就难改 | 面**刻意最小**（读/写状态/模板/日志），其余标"内部实现不承诺兼容"；`ext_api` 版本号随框架 major 走 |
| 包作者把业务规则写成代码 | 文档引导：**能用配置表达的先用配置**（如套装/技能档位现在全是数据）；`ext_api` 只解决"配置表达不了的"（新指令、特殊渲染） |
| 安全（执行第三方代码） | 默认关闭双闸 + 导入 `.ttrpack` 时对 `ext/` 明确警示 + 只从包目录加载 |
