## 一、引擎公开接口（engine/worldtime.py 扩展 · worldtime 时钟）

### 1.0 模块定位（引用 1.1）

`engine/worldtime.py` 现有「刷新/出没」现实钟点层**保留不动**，新增「游戏周期层」三周期（季节/时段/天气）作为**同模块扩展**，二者并存正交（时间天气 L28–34）。

| 层 | 职责 | 保留/新增 | 引用 |
|---|---|---|---|
| 现实钟点层 | `active_time "20:00-06:00"` 出没窗口、限购周期、签到日界 05:00 | 保留（不改） | 时间天气 L29 |
| 游戏周期层 | 季节/时段/天气三周期懒计算 + 变化检测 + 懒广播（本契约范围） | 新增 | 时间天气 L30–33 |

### 1.1 公开接口清单（IF01–IF12）

> 签名用类 Python 伪码；`now` 一律为 **UTC+8 秒级时间戳**（缺省 = 当前）。所有读取接口为纯函数（同刻同参必同值），可随时重算——**不存历史、不跑定时器**（时间天气 L61、L368）。

| # | 接口 | 签名（伪码） | 语义要点 | 引用 |
|---|---|---|---|---|
| **IF01** | 系统总开关 | `is_enabled() -> bool` | 读 `settings.time_cycle.enabled`；false → 查询提示未启用、条件键 [季节/时段/天气] 失效、spawn 时段过滤退化为仅 active_time | 时间天气 §L101、§L235；规划 M31 L621 |
| **IF02** | 季节查询 | `season_now(now: int|None = None) -> str` | 返回 `spring`/`summer`/`autumn`/`winter`（枚举固定写死，防碎片化） | 时间天气 §L40、§L53、§L44 |
| **IF03** | 时段查询 | `period_now(now: int|None = None) -> str` | 返回 `dawn`/`noon`/`dusk`/`night`/`midnight` | 时间天气 §L41、§L54、§L44 |
| **IF04** | 天气查询 | `weather_now(map_id: str, now: int|None = None) -> str` | **玩家当前所在图**的当前天气键（上下文绑定，经生效池抽签）；内容包自定义键 | 时间天气 §L57、§L180、§L182 |
| **IF05** | 生效池 | `map_pool(map_id: str) -> list[str]` | 覆盖池（maps.weather_pool，非空）else 默认池；返回键列表（排序后供种子计算） | 时间天气 §L138、§L166–167、§L58 |
| **IF06** | 周期索引/节拍 | `cycle_tick(kind: str, now: int|None = None) -> int` | kind ∈ `season/period/weather`；`season_idx`=`floor((now−ANCHOR)/(season_days×86400))%4`、`period_idx`=`floor((now−ANCHOR)/(period_minutes×60))%5`、`weather_tick`=`floor((now−ANCHOR)/(weather_minutes×60))`；纯函数、缓存索引仅供变化检测 | 时间天气 §L50–55、§L61；规划 M32 L626 |
| **IF07** | 倒计时 | `time_remaining(kind: str, now: int|None = None) -> int` | 距下次变化 **秒**（季节性显示折算天+时）；`/时间` 数据源 | 时间天气 §L245–246、§L253 |
| **IF08** | 确定性抽签 | `map_weather(map_id: str, tick: int, now: int|None = None) -> str` | `生效池[pick(sha256(生效池键排序+str(tick)))]`；同 tick 同池跨群/进程/重启同值 | 时间天气 §L57–58、§L84；规划 M37 L655 |
| **IF09** | 变化检测钩子 | `check_changes(player, map_id) -> list[Change]` | **每条指令处理前**调用；比较 time_state 缓存索引与公式重算值 → 产出变化列表（Change = kind + 新旧值）；一次最多合并 3 条，顺序固定 季节→时段→天气；离线跨多周期只报最新值一次 | 时间天气 §L62、§L63、§L90、§L372；规划 M34 L636 |
| **IF10** | 懒广播 | `maybe_broadcast(changes: list[Change], ctx) -> None` | `broadcast.enabled` **默认 false（不播报，仅记录）**；开启后按 IF09 产物 → 季节→时段→天气合并一行 ≤3 条；跨群去重（time_state「各周期已播索引」+ map_weather_seen）；不打断战斗、战斗结算后补播 | 时间天气 §L89–93；规划 M34 L636 |
| **IF11** | 世界状态存档 | `load_time_state() / save_time_state() -> None` | 读写 `world_state.time_state`（season_idx/period_idx/weather_tick/map_weather_seen）；每指令处理/战斗结算后事务保存；换包字段级迁移（缺补默认/多忽略）；去重 = 缓存与重算相等不播 | 时间天气 §L273–287；规划 M35 L641 |
| **IF12** | 配置变更重排 | `recalc_on_config_change() -> None` | 改 season_days/period_minutes/weather_minutes/池 → 旧缓存索引失效自动重算 + 黄提示「时间配置已变更，周期重新铺排」（不拦截）；后续周期全部按新配置推进 | 时间天气 §L64、§L346、§L371 |

**接口约束（横向一致性）**：
- 三周期**互不读写对方状态**（实现零耦合），任何时刻值可由公式重算（时间天气 §L368、§L369）。
- `now` 缺省取当前 UTC+8；接口不接受群 id —— 周期值为**全局世界**唯一（时间天气 §L127、§3.8 全局世界对齐）。
- 位置无关性：除 IF04/IF05/IF08 外，一律不依赖玩家/地图上下文。

## 二、条件键接入（[季节:X] / [时段:X] / [天气:X]）

### 2.1 注册（互译表 4.2.3.1 新增 3 行，单口登记）

| 条件英文键（机器键/存储/校验用） | 中文变量键（展示/编辑面板用） | 值域（枚举固定/自定义） | 引用 |
|---|---|---|---|
| `{ var: "season", op: "eq", param: X }` | **[季节:X]** | X ∈ spring/summer/autumn/winter（固定写死） | 时间天气 §L178、§L40、§L44 |
| `{ var: "period", op: "eq", param: X }` | **[时段:X]** | X ∈ dawn/noon/dusk/night/midnight（固定写死） | 时间天气 §L179、§L41、§L44 |
| `{ var: "weather", op: "eq", param: X }` | **[天气:X]** | X ∈ 注册天气集（内容包自定义，default_pool 键） | 时间天气 §L180、§L42 |

- **语义**：季节/时段为**全局值**；天气按**玩家当前所在图**取值（上下文绑定，与 `{var:"item_count"}` 同构）（时间天气 §L182）。
- **简写归一**【工程补白】：定稿 §4.0 用 `{var:"season", param:X}` 简写（L178–180），§4.4 示例用 `{var:"season",op:"eq",param:"summer"}`（L216–217）——二者等价；**存储与校验统一用完整形** `{var, op:"eq", param}`（与条件引擎 {var,op,value,param} 统一语法对齐，任务定稿 L20/L25；NPC 定稿 §4.0 L183）。
- **登记落点**：条件引擎注册表（互译表 4.2.3.1 / 规划路1 T22 变量大全 / 路3 F2 注册表）新增三键 + 互译表中英文双登记；三键在**条件编辑器**可选（规划 M40 L671）。
- **求值接线**：条件引擎求值器遇 `var∈{season,period,weather}` 时由 worldtime 时钟供给值 —— `season→IF02`、`period→IF03`、`weather→IF04(player.map_id)`、`op` 用 `eq`、`param` 承载枚举值比对；`value` 不参与（eq+param 判定）【工程补白：等价于 param==当前值 ? true : false】。

## 三、spawns/出没链路（怪物出没时段调用入口）

> 出没时段是 **maps.json spawn 行**属性（时间天气 §L140–148、§L206–211），不是 enemies.area。enemies.json 的 `area` 字段 = 栖息地图（图鉴/编辑器/掉落关联展示用，怪物 §L22–23）。spawn 表字段 schema 已由 **2a1b** 细化（2a1b §二 2.1，enemy/count/respawn_minutes/active_time/seasons/periods/weather_weights）；本节只契约**调用入口与语义执行点**。

### 3.0 出没链路接口（入口 3 处）

| # | 入口 | 触发点 | 语义 | 引用 |
|---|---|---|---|---|
| **E1** | **进入地图钩子 → 补刷** | 玩家 /进入 新图 / 指令处理时 | 按时间差折算补刷：`spawn_available` 判定 + `respawn_interval` 折算 → 补至 count 上限；零定时器 | 时间天气 §L61(L懒计算对齐 3.6 补刷)；规划 M08 L480–483、M34 L636 |
| **E2** | **周期边界变化钩子 → 存在性变更** | IF09 check_changes 产出的时段/季节变化 | seasons/periods 结束 → **移除在场怪并提示「对方逃跑了」**（3.16 出没时段边界规则同样适用）；天气/季节**不驱逐**战斗中怪物 | 时间天气 §L209、§L91；规划 M09 L485–490 |
| **E3** | **刷新计时折算** | 补刷结算时 | 有效刷新间隔 = `respawn_minutes / weather_weights[当前图当前天气]`（weight≥1 刷更快、0<w<1 更慢、**0=该天气不刷**）；只影响刷新/补刷，**不驱逐已在场怪物** | 时间天气 §L210；规划 M10 L491–493 |

### 3.1 出没判定函数（供给 E1–E3）

| # | 函数 | 签名（伪码） | 语义 | 引用 |
|---|---|---|---|---|
| **S1** | 出没判定 | `spawn_available(row: SpawnRow, now: int) -> bool` | `active_time`（现实钟点）∩ `seasons` ∩ `periods` **AND 叠加，全部满足才出没**；任一段为空 = 该维度不限；系统总开关关（IF01=false）→ 仅 active_time 生效 | 时间天气 §L235（正交并存）、§L209（叠加）、§L208（AND） |
| **S2** | 刷新折算 | `respawn_interval(row: SpawnRow, map_id: str, now: int) -> float秒` | `respawn_minutes × 60 ÷ weather_weights[IF04(map_id, now)]`；未配权重默认 1；权重 0 → 返回 `inf`（该 tick 不刷） | 时间天气 §L210、§L147 |
| **S3** | 副本地图继承说明 | —（无新接口） | 副本经 `maps` 引用地图 → 刷怪配置**自然继承**，E1–E3 在副本内同样生效（探索/BOSS 双副本共用同一地图刷怪） | 副本 §L191、§L207、§L229–232 |

> 战斗中怪物存在性：时段边界（E2）按既有语义「对方逃跑了」移除；天气/季节**永不驱逐**战斗中怪物（只有 E2 的时段/季节边界驱逐），天气只影响刷新计时（E3）——两规则刻意区分（时间天气 §L210、§L91、§L424）。

## 四、任务 / NPC 对时段键的复用（配置组合，零新增机制）

### 4.1 任务（quest.json 发布/显示条件）

```json
// 夏季限定 + 午夜雷雨限定发布条件（时间天气 §L216–217 示例原样对齐）
{
  "id": "quest_summer_festival",
  "conditions": [
    { "var": "season",  "op": "eq", "param": "summer" },
    { "var": "period",  "op": "eq", "param": "midnight" },
    { "var": "weather", "op": "eq", "param": "storm" }
  ]
}
```
- 语义：三条件 AND 满足才发布/显示（条件组合 = 事件窗口）；不满足 = 任务板不出现（时间天气 §L215–216；任务定稿 L20–35 L119–121 提示态）。
- 可叠加现实时间维度：`start/end`（现实时间/活动期）与三键作为**叠加条件**互不冲突（签到活动表口径，时间天气 §L218）。

### 4.2 NPC（npc.json interactions 交互条件）

```json
// 午夜 + 雷雨 → 特殊对话选项；不满足 = 置灰/隐藏/提示（NPC 定稿 §L119–122）
{
  "id": "witch_interaction",
  "actions": [
    { "action": "dialogue", "text": "暴雨夜访客……",
      "condition": { "var": "period", "op": "eq", "param": "midnight" },
      "extra": { "var": "weather", "op": "eq", "param": "storm" } }
  ]
}
```
- 交互三态（隐藏/置灰/提示）由 NPC 条件系统既有机制承担，**无新增代码**；选项级条件按需挂在 condition 上（NPC 定稿 L119–122、L175）。
- 复用边界：任务/NPC 引用三键走统一条件引擎求值（§2.1），与 `{var:"level"}`、`{var:"item_count"}` 等既有键完全同构（NPC 定稿 §4.0 L183–191）。

### 4.3 正交边界（明确不联动）

- 商店限购周期（每日/每时/每周/每月）、签到日界 05:00、排行榜刷新 = **现实钟点层**，**不**接入三键（防语义混淆）（时间天气 §L234）。
- 现实钟点 `active_time` 与五时段键**并存正交**：前者管「几点现实时间」，后者管「游戏周期第几段」——可同时配置（AND 叠加）（时间天气 §L235）。
