# 框架级扩展设计 v1.2：通用效果事件分派器（功能三）

> 承接 veinborn 预设包需求 + 用户「把硬编码时点特例改成可配置可调用」。
> 铁约束：纯配置可用（effects.json/statuses.json 声明事件）、零硬编码、既有行为零破坏（无事件配置 = 原样）。
> 现状实证全部跑码确认（2026-09-02）。

---

## 一、现状缺口（实测）

### 1.1 已存在的时点机制（零散、硬编码、不统一）

| 时点 | 现状 | 触发载体 | 可配置？ |
|---|---|---|---|
| 战斗开始 | enemy special_actions `battle_start` | monster_conditions（功能一已扩展读印记） | ✅ 怪物侧 |
| 行动结束 | `tick_after_action`（decay_carrier 衰减） | effects.py L1268 | ❌ 仅衰减 |
| 回合结束 | `tick_turn_end`（dot/再生/回复/印记/计数） | effects.py L1230 | ❌ 硬编码清单 |
| 死亡 | on_death 事件钩子（effects L1183 side_effect 标记） | effects.py 死亡判定 | ❌ 只标记不触发动作 |
| 换季 | on_season_change → L2 proc 容器 | battle.py `_fire_season_event` L1304 | ⚠️ 季节专用特例 |
| 状态施加 | `_after_apply`（仅免疫计数/衰减落库） | effects.py L697 | ❌ **不触发动作** |
| 状态移除/过期 | `_remove_status` / tick 移除 | effects.py L290/L751 | ❌ **不触发动作** |
| 效果触发事件 | effects 定义 `trigger: on_attack/on_hit/on_skill/on_turn_start/...` | 1b 契约 L51 有枚举 | ❌ **无引擎消费**（全库 0 引用） |

### 1.2 关键实证

- effects.json/statuses.json 定义**有 `trigger`/`on_tick`/`actions`/`effects` 字段**（statuses.json burn 有
  `on_tick: burn_dot` + `effects: [burn_dot]`；test_demo 实查），但：
  - `trigger` 事件字段：全库零消费（grep 实证）——on_attack/on_hit/on_skill/on_turn_start 等**只是死配置**；
  - `_after_apply`：只做免疫计数/trigger_halve 落库，**不执行状态 actions/on_gain**；
  - `_remove_status` / dispel / tick 过期：**无 on_lose/on_expire 触发**；
  - 死亡：只 append `{"type":"death", trigger:"on_death"}` side_effect 标记，**不触发任何 effects actions**；
  - 战斗开始/结束：无通用配置事件（battle_start 只在怪物 special_actions，战斗结束无）。
- 状态 `on_tick`（burn_dot 每回合灼烧）：被 tick_turn_end 消费（走 dot_pool 结算），是**状态级特例**非通用事件。

### 1.3 结论

框架**没有统一的效果事件分派器**：所有时点（战斗开始/结束、行动前/后、回合前/后、效果获得/消失、
死亡、换季）各做各的、多数硬编码、部分只标记不触发。veinborn「受威胁转化/部位结算/buff 到期爆炸/
专精翻面触发」等机制无底座。

## 二、功能设计：统一事件分派器

### 2.1 事件时点枚举（对齐 1b §2.5 既有 trigger 值域 + 扩展，全配置化）

```
EVENT_POINTS = (
    "battle_start", "battle_end",          # 战斗开始/结束
    "action_start", "action_end",          # 每行动开始/结束（玩家+怪物）
    "turn_start", "turn_end",              # 回合开始/结束
    "status_gain", "status_lose",          # 状态获得/消失（含驱散/过期/层变）
    "mark_gain", "mark_lose",              # 印记获得/消失（含满层/被清）
    "death", "revive",                     # 死亡/复活
    "on_attack", "on_hit", "on_skill",     # 伤害链事件（攻击/命中/技能）
    "season_change",                       # 换季（现特例收编）
)
```

### 2.2 数据源声明（纯配置，两处）

```jsonc
// A. effects.json 条目可带 trigger（对齐 1b §2.5 枚举）——触发时执行该效果 actions
{"id": "thorns", "name": "荆棘反伤", "class": "special", "type": "pursuit",
 "trigger": "on_hit", "chance": {"mode": 100},
 "actions": [{"type": "damage", "value": "20%", "target": "self"}]}

// B. statuses.json 条目可带 on_gain / on_lose / on_expire（对齐既有 effects/on_tick 形态）
{"id": "shield_break", "name": "护盾碎裂", "type": "buff",
 "on_lose": [{"effect": "explode_damage", "overrides": {"value": 50}}]}   // 消失时爆炸
```

### 2.3 分派器核心（新模块 qbot_rpg/core/event_dispatcher.py，纯规则引擎零 NoneBot）

```python
def dispatch_event(event: str, side: str, snapshot, registry, *, ctx_vars=None,
                   runtime=None, depth=0) -> list[dict]:
    """在时点 fire 匹配 trigger=event 的效果/proc/状态 on_xxx 动作。
    - 数据源：effects.json（trigger 字段）+ statuses.json（on_gain/on_lose/on_expire 字段）
      + 装配注入的 procs（season_procs 同款机制收编）
    - 每个候选效果：chance roll（三态 mode）→ 执行 actions（复用 execute_action，功能二归一已通）
    - max_triggers_per_turn/battle 计数（effect_triggers 桶既有）
    - 深度上限 chain_depth（防递归）
    - 无候选/未配置 → []（零行为变化）
    """
```

分派器**不持有状态**（快照/注册表注入），可独立单测 + battle 接线。

### 2.4 battle 接线（收敛硬编码特例，替换为统一调用）

| battle 方法 | 时点 | 接线 |
|---|---|---|
| `start()` 末尾 | battle_start | `dispatch_event("battle_start", ...)` 替代怪物 battle_start 特例（保留怪物 AI 既有路径——它走 special_actions，两轨并存但互不冲突；或登记统一） |
| `start_turn()` | turn_start | dispatch turn_start |
| `_do_action_inner` 开头/结尾 | action_start / action_end | dispatch（玩家+怪物行动） |
| `_settle` / 战斗结束 | battle_end | dispatch battle_end |
| `tick_turn_end` 内 | turn_end | dispatch turn_end（与既有 tick 清单并列，不动既有逻辑） |
| apply_status 成功 | status_gain | `_after_apply` 内补 dispatch status_gain（执行状态 actions/on_gain——**新能力**） |
| _remove_status / dispel / tick 过期 | status_lose | 补 dispatch status_lose/on_expire（**新能力**） |
| mark_add/mark_remove/clear | mark_gain / mark_lose | effects 内 mark 动作后补 dispatch（**新能力**，veinborn 部位破坏满层结算） |
| 死亡判定 | death | on_death side_effect 标记处补 dispatch death（**真触发动作**） |
| `_fire_season_event` | season_change | **收编**：改为调 dispatch_event("season_change")（season_procs 机制并入，旧调用保留兼容或迁移） |
| 伤害管线 | on_attack/on_hit/on_skill | damage_pipeline 命中后 dispatch（挂载点：_resolve_damage_action 命中后 / pipeline 内） |

### 2.5 状态 on_tick 特例收编（可选，二期）

statuses.json `on_tick` 现被 tick_turn_end 硬编码消费——收编为 status 条目通用 trigger
（`trigger: "turn_end"` + actions），tick_turn_end 改为 dispatch turn_end 统一处理。
**本期先不动 tick_turn_end 既有逻辑**（风险高），只加并行 dispatch，on_tick 保留兼容。
