## 四、② 设计缺漏项（6 = P1×4 + P2×2）

### G1（P1）｜element_modifier 触发容器未实现（定稿 §7 框架级容器）
- 应有：效果定稿 §7「触发容器：proc … **｜ element_modifier 元素附加/转化**」（L299）；细化_1b §3.3 容器 2 个含 element_modifier（L235）；细化_2c4c 等已有 content 示例引用 `effects:[{"action":"element_modifier",...}]`（细化_2c4c L143、规划文档 L182）。
- 实际：`execute_action`（L1452-1660）无 element_modifier 分支，命中「元素附加/转化」动作将走 L1660 `未知 L0 动作类型` 兜底（静态推导）；全 qbot_rpg 无 element_modifier 实现。
- 隐含：**「16 直行 + 3 修正器 + proc」清单里，唯一缺的就是定稿 §7 触发容器之一 element_modifier**（与 H2 同源）。
- 建议：实现 element_modifier（元素附加/转化副作用）或显式登记为批2 延后项。

### G2（P1）｜魔法穿透（pierce target=spr 无视精神）未承接
- 应有：效果定稿 §3.2「魔法穿透｜伤害结算时，无视对方一定百分比精神」（L121）；细化_0 R-03 / 细化_1b §3.2 pierce 参数化 `{target: def|spr, pct}`（target=spr 走元素通道/精神抵抗段，细化_1b L225）；有效防御 = 防御×(1−内置破防)×(1−穿透)（§7.1 L339）。
- 实际：`execute_action` pierce 分支（L1468-1473）只读 `dfn`（防御通道），**完全忽略 `target` 参数（def/spr）与精神通道**；且仅记录 `effective_defense` side_effect（L1472），未进入任何方程序列落地减伤。
- 佐证：覆盖审计_B L96 已标「魔法穿透'无视精神'未承接」→ 缺失 #4。
- 建议：pierce 按 target=def/spr 分流，spr 走精神系数；与战斗数值层公式接线。

### G3（P1）｜反弹「按 % 减伤并反弹」——减伤半支缺失（核心拦截链规则偏离）
- 应有：效果定稿 §3.4③「反弹（**按 % 减伤**并反弹；反弹伤害不触发反弹）」（L138）、§3.3 反弹「受伤害时，**减少对方伤害一定百分比**，并对对方造成等值伤害」（L128）、细化_1g2 §2.1 ③「按 % 减伤并反弹等值伤害给对方」（L85）。
- 实际（静态推导）：`_stage_reflect`（L1128-1147）仅 append `{"type":"reflect",...}` 反弹事件后 **原样 `return d`**（L1147），未对受击方减伤；battle 侧 `_deliver_reflect`（battle.py L1237-1256）只把反弹伤害回注攻击方。→ 受击方仍受全额伤害（100 命中 20% 反弹 → 受击方 100、攻击方 −20，定稿语义应为受击方 80、攻击方 −20）。
- 备注：细化_1b B-3「对方受 20」仅断言反弹侧数值，未断言受击方减伤半支；但定稿与细化_1g2 行文均含「按 % 减伤」——实现缺失，需裁决收敛（引擎按 §3.4 执行）。
- 建议：反弹阶段将 `d` 按 pct 先减伤再续入 ⑦ 扣血，反弹伤害等值回注（链复杂度受 §3.5 环检测约束）。

### G4（P1）｜tpl_* 生存模板（§7.2）零实现 + 内容三表空表（数据空表历史教训#2）
- 应有：效果定稿 §7.2「生存模板库」标准 ID：`tpl_shield_30/15、tpl_mitigation_10/8/15/30、tpl_lifesteal_10、tpl_heal_lost/max/regen/heal_mp`（L344-380）；实现层规划文档「默认内容必须非空：内置效果模板库（§7.1 三模板 + §7.2 生存四类）…随仓库落盘」（L142）。
- 实际：qbot_rpg 全库（grep `tpl_`）**零定义/零解析/零展开**；`prepare_defense` 不识别 `{effect:"tpl_*", overrides:{}}` 结构（L984-1055 仅按 raw.type 匹配）；docstring「状态动作按 L0 模板归口（§7.2 生存模板四类）」（L969）无实现支撑。`qbot_rpg/data` 目录**无 effects.json/statuses.json/marks.json**（内容三表为空，符合历史教训#2 空表形态）。
- 职责边界说明：tpl 模板的"定义/展开"属内容装载层（content/{loader,registry}.py），引擎层需识别展开后的 type；本项为内容面 + 引擎 docstring 声称的双重落空。建议批2 随内容包落地默认模板表并补 end-to-end 用例。

### G5（P1）｜免死约束校验器接线缺失（§9.2-6 / §6.4 H1 / 细化_1b D-6，历史教训#3）

### G6（P2）｜反击（§3.3 防御特效之一）无引擎归口
