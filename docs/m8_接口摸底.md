## 二、会话管理

### 2.1 SessionManager 现状（`qbot_rpg/world/session.py`，40 行）

- **整文件是仅签名占位**（L24-40）：`acquire(player_qid, session_type)` / `release(player_qid)` / `get_active(player_qid) -> Optional[Any]` / `suspend(player_qid, snapshot)` / `restore(player_qid) -> Optional[Any]` 全部 `raise NotImplementedError`。

### 2.2 实际会话持久化路径（已实装）

- **占位/释放**：`repository.upsert_session(SessionRow)` / `delete_session(qid)`（见 1.3）；`sessions.player_qid` 主键即互斥约束（schema.py L58-62）。
- **战斗会话退出结算唯一入口**：`battle_boundary.settle_exit_idempotent`（`world/battle_boundary.py` **L821**）：
  `async def settle_exit_idempotent(*, session: object, settlement_kind: str, message_id: str, repository: object) -> bool` —— 单事务 `delete_session(qid) + write_idem_key(key)`（L879-884），幂等键 command=`"settle:{kind}"`；**M8 调合会话的 /放弃 /确认 终态结算可仿照此模式**。
- **会话互斥判定**：`battle_boundary.session_mutex_decision`（L702）。
- **战斗快照续玩**：`world/snapshot_resume.py` `resume_from_snapshot(player_ctx, snapshot, battle_factory=None, watcher=None) -> dict`（L295），完整性键 = `ai_state`/`combo_state`/`turn`（L105）；`non_combat_exit`（L475）。
- **世代绑定**：`snapshot_resume.pick_registry_snapshot(watcher, generation)`（L200）/ `rebind_registry_for_snapshot`（L243）——热重载世代重绑定契约已实现，SessionManager 世代绑定（RSM-08）归 D5 未实装。

### 2.3 对 M8 的结论

- 调合会话状态机（§4.6：无会话→会话中→挂起(战斗)→恢复→确认/放弃）**不需要新表**：sessions 表 + `session_type IN ('alchemy','challenge_alchemy')` 已就绪；payload_json 存配方ID/材料链/连锁/特性/触媒/PP/步骤/version。

- `count(player, item_id) -> int`（L308）跨行求和。
- **`POTION_USE_COUNTS_KEY = "potion_use_counts"`**（**L56**）；`potion_use_counts(player)`（L168）返回 `player["potion_use_counts"]` 可变 dict（potion_type→次数），注释明确：**回合推进重置 / 入战斗快照（中断恢复不重置）由战斗入口负责**，引擎只提供落点。
- 操作对象 = **玩家状态 dict**（ctx 玩家表示，`player["inventory"]` 为可变 list、元素=ItemInstance）；配置注入构造器（capacity/max_single_add/now_fn）。

### 5.2 物品实例（`qbot_rpg/data/item.py` L20-37）

```python
@dataclass(frozen=True)
class ItemInstance:
    item_id: ItemID; name: str; count: int
    quality: str            # 四档（normal/fine/epic/legendary，basic_commands.QUALITY_LABELS L155）
    bound: bool
    stack_max: int = 99
    slot: Optional[str] = None
    stats_bonus: Dict[str, float] = {}
    traits: Tuple[str, ...] = ()     # 特性（tuple 冻结语义）——M8 特性继承/装饰珠落点
    cooldown_until: Optional[str] = None
```
- 存档行编解码：`repository._item_from_dict`（repository.py L176）兼容 `item_id/name/count/quality/bound/slot/stats_bonus/traits/cooldown_until`，未知键多忽略。
- 物品数据加载形态：`items.json` = list of dict（如 `content/demo_full/items.json`：`{id, name, type:"consumable", price, effects:[...], usable}`）→ loader `_register_def`（loader.py L131）按 `kind="item"` 进 `registry.tables["item"]`。

**M8 结论**：合成/炼金产物入包走 `InventoryEngine.add_item`；品质/特性/绑定直接由构造的 `ItemInstance` 携带；合成材料扣减走 `remove_item`（材料不足/绑定拒绝语义已内置）。

### 6.2 战斗快照（`qbot_rpg/data/battle.py` + `core/battle.py`）

- **`battle_alchemy_used` 应挂哪**：挂到 `core/battle.py to_snapshot()` 返回的 dict 顶层键（快照随 sessions.payload_json 持久化），且**中断恢复不清零**（规划 L1571/1574 要求）。快照 dict 已有 `timestamps`/`stats_collector` 等扩展键先例（battle.py L922/L1740 附近），新增一个顶层计数键成本低。
- **`potion_use_counts` 现有结构**：键常量在 `inventory.py` L56（`POTION_USE_COUNTS_KEY`），落点是玩家态 dict `player["potion_use_counts"]`（非快照），由战斗入口负责回合推进重置 + 中断恢复不重置——M8 可把它一并纳入战斗快照（或保持玩家态 + 战斗内读）。

### 6.3 世界边界（`qbot_rpg/world/battle_boundary.py`）

- 丢失判定链 `decide_lost(...)`（L147）；`apply_lost_pending(snapshot, lost_pending) -> BattleSnapshot`（L194）。
- 脱战回血 `decide_heal_and_unlock(...)`（L262）/ `heal_and_unlock_tx(...)`（L276，接口预留 NotImplementedError）。

**M8 结论**：战斗即时调合（限 1 次/场）计数 = `to_snapshot()` dict 新增 `battle_alchemy_used`；一回合道具限次可复用 `potion_use_counts` 落点模式。
