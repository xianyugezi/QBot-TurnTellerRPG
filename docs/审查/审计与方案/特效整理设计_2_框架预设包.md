## 0. 本设计的三条硬口径

### 0.1 口径一 · 轴一律取**乘法系数**形态（`_mult`），`1.0` = 原样

搜集报告对「修正轴」给了两套写法，本设计**取后者并统一**：

| 写法 | 中性值 | 出处 | 本设计裁决 |
|---|---|---|---|
| 百分点增量 `_pct`：`实际 = 基准 × (1 + pct/100)` | `0` | 报告3 §3 统一口径（并指出它与既有 α3 一致：`core/battle.py:3032`/`:3254`） | **降级为兼容别名** |
| 乘法系数 `_mult`：`实际 = 基准 × mult` | `1.0` | 报告4 §3 开头（"`1.0` 为中性，`<1` 与 `>1` 各是一种玩法"）；报告5 轴-1/轴-2 | **采为本设计的标准形态** |

**为什么选 `_mult`**：① 直接对齐用户拍板的起点例（`healing_received_mult: 0.5` = 重伤 / `1.5` = 强疗）；
② 与既有唯一的乘法先例同族（α3 技能增幅 `1 + 总计/100`，`core/equip_mods.py:13`、`:96-104`）；
③ `<1` / `=1` / `>1` 的语义自解释，内容作者不需要记住"0 是原样"这种反直觉约定。

**兼容换算**（唯一、写死在一处，不在消费点各写一遍）：

```
mult = 1 + pct/100        # 旧 _pct 键 → 新 _mult 轴
pct  = (mult - 1) * 100   # 反向，展示用
```

### 0.2 口径二 · 双向优先；确需单向的必须写「为什么不能双向」

- **双向轴**：`<1` 与 `>1` 是同一条轴的两个玩法方向，**不为任一方向单独造键、单独造 debuff**。
- **单向轴**：本设计**逐条给出理由**（不同乘区、钳制语义、计数语义、枚举语义、经济失衡等），见 §0.3 与 §1.6。
- 已知的**不可合并**例外（防过度抽象，来自报告3 §3.5 与报告1 §3.3）：攻/防两侧（`status_chance_mult` vs `status_resist_mult`）、
  施疗/受疗两侧（`healing_dealt_mult` vs `healing_received_mult`）、`action_speed_mult` 与 `action_recovery_mult` **二选一**。

### 0.3 口径三 · 范围/上下限**由包声明**，不写死在消费点

- 每族在预设包里声明 `range: [min, max]` 与（可选）`cap`；引擎只做"读取声明的钳制"，
  不把数值写进代码。先例是 `_DEFAULT_CONFIG` 式的**可配钳制**（`core/effects.py:111-124`：`chain_depth=3`、
  每回合 10 次、每场 99 次、S6 单属性 ±100%、S7 组合 100%）。
- 已有**引擎侧硬上限**继续生效、不因本设计放宽（如穿透比 `pierce_pct` 封顶 100，
  `data/gear_stats.py:131`；减伤 `min(total, 1.0)`，`core/effects.py:1091-1098`）。

### 0.4.3 明确**单向**的轴（附「为什么不能双向」）

| 轴名（建议键） | 语义 | 单向范围 | 为什么不能双向 |

| `lifesteal_pct`（=既有 `absorb_hp`） | 造成伤害 × pct% 回血 | `0 … 100`（`data/gear_stats.py:104`、封顶 `:128`） | 负值"造成伤害反而掉血"无自然语义；`>100` 回血超过伤害、经济失衡。反吸血需求由 `healing_received_mult` 表达（报告3 §3.2 原话） |

### 0.5 预设 JSON 的字段契约（对齐 `gear_stats.py` 与既有 `effects` 形状）

**关键前置约束（作者必须知道）**：装备 def 上的数值字段**只有登记进 `GEAR_DISPLAY_KEYS` 才会被提取**
（`extract_bonus` 遍历该表，`data/gear_stats.py:178-189`；全集见 `:116-119`）。
**未登记的键会被静默丢弃** —— 因此**每个新轴必须先在 `data/gear_stats.py` 注册一行**，
否则预设"看起来配了、实际不生效"。

**契约 A · 数值轴预设（可直接落到装备 def 的扁平字段）**

```jsonc

  "preset_id": "weapon_heavy_wound",          // 稳定 id：<slot>_<family>
  "name": "重创",                              // 中文名（展示）
  "slot": "weapon",                            // weapon | armor | accessory | any
  "family": "healing_received",                // 轴族（同族=同轴，用于互斥/取极值判定）
  "axis": "healing_received_mult",             // 使用的轴（§0.4 的键；未注册=不生效）
  "direction": "down",                         // up | down（双向轴的哪一端；仅元数据）
  "tiers": {                                   // 档位阶梯：只改数值，不改轴与触发
    "normal":   { "healing_received_mult": 0.85 },
    "advanced": { "healing_received_mult": 0.70 },
    "rare":     { "healing_received_mult": 0.50 }

  "stack": "mult",                             // add | mult | max_only | unique
  "conflict_group": "healing_received",        // 同组=互斥（沿用 traits 的 group 语义，见 §3）
  "range": [0.0, 2.0],                         // 包声明的上下限（引擎只读取，不写死，见 §0.3）
```

② 命名被动注册表 `traits.json`：`{id, name, rarity, effects:[...], group, repeatable, source}`

**档位与既有 `rarity` 的冲突（待裁决）**：本设计用**三档**（普通/进阶/稀有），
而 traits 注册表 `rarity` 是**两档** `("normal","super")`（`content/field_meta.py:2483`）。
两种收敛方案二选一：**(a)** 给装备预设扩枚举为 `("normal","advanced","rare")`，与 traits 的 `("normal","super")` 并存；
**(b)** 复用两档，把"稀有"表达为 `super` + `enhance_level` 高阶。
**本设计默认取 (a)**，因为预设是**打造/掉落期的新概念**，与 M8 炼金特性的 `rarity` 不是同一套池子；此处需用户拍板（见 §4.3）。

## 1. 预设词条集

> **分组**：部位（武器 / 护甲 / 饰品 / 通用）× **档位**（普通 / 进阶 / 稀有）。
> **档位口径**：预设本体声明 `tiers` 三档取值，掷取时落一档（详见 §0.5 的 JSON 契约）；
> 档位只改**数值**，不改**轴**与**触发方式** —— 这样作者选一次族，档位由掉落/强化决定。

### 1.0 分层规则（部位 × 档位怎么定）

**部位分配原则**（让作者的默认预期成立，避免"防御词条出现在武器上"）：
- **武器**：进攻轴为主（伤害/会心/穿透/吸血/冷却/攻速/附加点伤/转化），允许**代价型负向**（削自己会心/延长冷却）；
- **护甲**：防御轴为主（承伤/受疗/反伤/免伤/控制抗性/状态时长），允许**代价型正向**（易伤/缠身）；
- **饰品**：资源与结算轴为主（消耗/获取/回复速率/掉率经验/行动条/层数），偏"元游戏"；
- **通用**：触发与结构类（proc/叠层/套装/持久成长/异常累积），可挂任意部位。

**档位数值梯度原则**：
- 乘法轴（`_mult`）：`普通 → 进阶 → 稀有` 的**偏离 1.0 的幅度**大致按 `1 : 2 : 3.4` 放大；
- 加算轴（`delta`）：按 `1 : 2 : 3` 步进；
- 单向轴（`0..100`）：按 `约 1 : 2 : 3` 步进，且**上限不被本设计放宽**（既有封顶继续生效）；
- 所有梯度都写进预设包的 `tiers`，**引擎不硬编码**（§0.3）。

|---|---|---|---|
| 武器 | `weapon_crit_up` 会心锋刃 | `crit_dmg_mult` ↑ 1.10/1.25/1.40 | 会心倍率是**乘区**，与暴击率相乘 |
| 武器 | `weapon_lifesteal` 汲血 | `lifesteal_pct` 3/6/10（单向） | 既有 `absorb_hp`（`data/gear_stats.py:104`）**零新引擎** |
| 饰品 | `common_attr_pct` 属性铭文·% | `crit` 5/10/15 百分点 | 既有 COMBAT 键，可负（`data/gear_stats.py:103`） |
| 饰品 | `accessory_stack_gain` 涌流 | `stack_gain_mult` ↑ 1.25/1.50/2.00 | 触发型层数（如"每次会心叠层"）快速堆叠 |
| 通用 | `common_proc_crit` 会心迸发 | `proc{trigger:on_crit}` | 需新增 `on_crit` 时点 |

**轴组合逻辑**：`暴击率（COMBAT 键，加算+封顶） × 会心倍率（crit_dmg_mult，乘区） × 吸血比（lifesteal_pct，单向上限 100）`。
**关键交互**：① 吸血与"造成伤害"挂钩，所以**增伤轴会顺带放大吸血**（经济双吃），需要包侧给 `lifesteal_pct` 更保守的档位；
② `weapon_crit_up` 与 `weapon_crit_down` **同族互斥**；③ 与 `super_crit_lv` 档位键**并存**时须写明叠乘顺序（§3.1）。

### 2.2 减疗压制 —— 「一条轴吃三个方向」

| 位 | 预设 | 轴与档位 | 说明 |
|---|---|---|---|
| 武器 | `weapon_wound` 重创 | `healing_received_mult` ↓ 0.85/0.70/0.50 | **负半轴**：重伤 |
| 饰品 | `common_buildup` 异常积蓄 | `buildup{init,step,cap,decay}` | 命中累积→达阈值才挂重伤，避免一发入魂 |
| 通用 | `common_proc_hit` 灼痕 | `proc{on_hit}` + 挂减益 | 提高覆盖率（需 on_hit 接线） |
| 饰品 | `accessory_cost_down` 节流 | `resource_cost_mult` ↓ | 让压制循环能持续 |

**轴组合逻辑**：同一族 `healing_received` 的三个用法 —— `0.85` 减疗 / `0.50` 强重伤 / `0` 禁疗（甚至 `<0` 治疗反转，见 §0.4.1 范围 `-1.0…3.0`）。
**关键交互**：① 与目标自身的 `healing_received_mult`（正向，如 `armor_heal_up`）**乘算**，形成"减疗 vs 强疗"的对攻；
② 与 `healing_dealt_mult`（施疗侧）**是两侧、不合并**（§0.2 例外）；
③ 与既有 `heal_amp_pct` 的关系见 §3.1（那是施疗侧、且当前无消费点）。

### 2.3 层数叠伤 —— 「叠得快 ≠ 叠得高」

| 位 | 预设 | 轴与档位 | 说明 |
|---|---|---|---|
| 武器 | `weapon_stack_gain` 涌流之刃 | `stack_gain_mult` ↑ 1.25/1.50/2.00 | 每次施加**层数**变多 |
| 武器 | `weapon_stack_cap` 拓层之刃 | `stack_cap_add` +1/+2/+3 | 层数**上限**变高（另一条轴） |
| 饰品 | `common_attr_pct` 属性铭文·% | 每层属性（`stat_modifier`） | 既有叠层机制（`core/effects.py:466-638`） |
| 通用 | `common_stack_threshold` 蓄能爆发 | `stack_threshold_effect{threshold,consume,action}` | 满层消耗→一次性爆发 |
| 饰品 | `accessory_stack_cap_down` 缚层 | `stack_cap_add` -1/-2/-3 | **反向用法**：压低上限对抗"叠层型敌人" |

**轴组合逻辑**：`叠加速率（stack_gain_mult） × 叠加上限（stack_cap_add） × 每层强度（stack_potency_mult）`，三者**互相独立**。
**关键交互**：① `stack_potency_mult` 需新引擎——`_aggregate_boost`（`core/battle.py:952-981`）当前**不乘 `stacks`**；
② 战斗结束清零用 `decay`（`core/effects.py:499`）；③ 层数上限**默认只有 3**（`stack_default_max`，`core/effects.py:122`），预设必须显式覆写，否则"拓层之刃"白给。

### 2.4 反伤坦克 —— 「受伤越多、回敬越狠」

| 位 | 预设 | 轴与档位 | 说明 |
|---|---|---|---|
| 护甲 | `armor_flat_red` 巨壁 | `dmg_reduction_flat` 2/4/6 | 与比例减伤**不同乘区** |
| 护甲 | `armor_taken_down` 坚壁 | `dmg_taken_mult` ↓ 0.92/0.85/0.75 | 归并 `immune_dmg`（乘算叠乘） |
| 护甲 | `armor_thorns` 荆棘 | `reflect_pct` 8/15/25（单向 0-100） | 既有 `_stage_reflect`（`core/effects.py:1136-1160`） |
| 护甲 | `armor_counter_amp` 反制强化 | `counter_damage_mult` ↑ 1.25/1.50/2.00 | 放大回敬（`core/battle.py:791`） |
| 护甲 | `armor_fatal_guard` 不屈 | `fatal_guard_max` 1/2/3 | 既有免死（`core/effects.py:105-106`） |
| 通用 | `common_proc_struck` 受创反噬 | `proc{on_struck}` + 给攻击者挂减益 | 需新增 `on_struck` |

**轴组合逻辑**：`减伤（两条不同乘区） × 反弹比（单向） × 反击倍率（双向） × 免死次数（单向计数）`。
**关键交互**：① 反弹伤害**不再二次反弹**（既有防环）；② 减伤越高、反弹值越低（因为按**所受伤害**算）→ **两条轴天然互相压制**，包侧需给"反弹按减伤前/后计算"的口径；
③ 与 §2.1 吸血流互为天敌（吸血方吃反弹）。

### 2.5 贪婪苦修（经济流）—— 「一条 reward_mult 两个方向」

| 位 | 预设 | 轴与档位 | 说明 |
|---|---|---|---|
| 饰品 | `accessory_greed` 贪婪 | `reward_mult{scope:drop}` ↑ 1.10/1.25/1.50 | **正半轴** |
| 饰品 | `accessory_ascetic` 苦修 | `reward_mult{scope:exp}` ↓ 0.80/0.60/0.40 | **负半轴**（同一条轴、不同 scope） |

### 3.3 叠加与互斥的执行规则（谁在哪个入口归并）

**唯一聚合入口链（不新开第二套）**：
`ItemInstance.stats_bonus`（`data/item.py:60`）→ `core/equipment.aggregate_bonus`（`core/equipment.py:872`）
→ `data/gear_stats.route_bonus_into`（`data/gear_stats.py:192`，`_pct` 拆层、COMBAT/PLACEHOLDER 例外）
→ 属性层 `attributes.bonus[flat|pct]` + 战斗桥 `combatant_updates`（`:221`，按 `COMBAT_TO_COMBATANT` 封顶 `:122-134`）。
**符文**走同一入口（`core/equipment.aggregate_bonus` 的"符文贡献"段 → 同一 `route_bonus_into`），
**强化特殊词条**也已并入 `stats_bonus`（`data/item.py:79` 注释）。

| 规则 | 口径 | 落点 |
|---|---|---|
| `stack: add` | 同键**加算**（FLAT 白值、`delta` 轴、百分点轴） | `route_bonus_into` 现状（`data/gear_stats.py:205-218`） |
| `stack: mult` | `_mult` 轴**累乘**（多件相乘） | 🆕 需在 `aggregate_bonus` 增一层 `mult`（或统一"逐件相乘"）；**不建议**把 `_mult` 塞进 `pct` 层 |
| `stack: max_only` | 同族多来源**取最极端值**（如 `weakness` 类增伤） | 由 `conflict_group` + 预设解析器执行；与报告5 轴-7 `stack_mode` 同族 |
| `stack: unique` | 同族**只允许一件** | `conflict_group` → traits `group`+`repeatable=false`（`content/field_meta.py:2484-2485`）或 `mutual_exclusions`（`core/equipment.py:710`） |
| 双向轴两端互斥 | 同族 `direction=up/down` 预设**不可同时装**（如"坚壁 + 破绽之甲"） | 解析期按 `conflict_group` 拒装；复用 `equipment.validate_slot_exclusions`（`core/equipment.py:359`） |
| 条件实例 vs 常驻实例 | 同轴**乘算**（如"坚壁"×"逆境低血减伤"） | 由消费点按顺序乘；条件门控走 `eval_condition`（`core/condition_engine.py:731`）/ `combo.evaluate_condition`（`core/combo.py:508`） |
| 攻/防两侧不合并 | `hit_mult` vs `evasion_mult`；`status_chance_mult` vs `status_resist_mult`；`healing_dealt_mult` vs `healing_received_mult` | **三条"不合并"红线**（§0.2；报告3 §3.5 原话） |
| 二选一 | `action_speed_mult` 与 `action_recovery_mult` **只留一条** | 数学上互为倒数，并存会指数级叠加（报告3 §3.5 原话） |
| 既有封顶不放宽 | 穿透比 100（`data/gear_stats.py:131`）、减伤 `min(total,1.0)`（`core/effects.py:1091-1098`）、免死 1-3（`:115`）、S6/S7 = 100%（`:120-121`） | 轴层的 `range` 只能**收紧**不能放宽既有引擎上限 |
