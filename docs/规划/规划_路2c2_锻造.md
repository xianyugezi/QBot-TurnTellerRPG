## 任务清单（20 条）

### T1 · forge.json 骨架与 settings 段初始化
- **定稿依据**：§12.4 settings 段；§十二引言（forge.json 为锻造模块数据文件）；§1.2 表（品质四档跨系统唯一注册表，forge.json 不重复定义）
- **实现要点**：
  - forge.json 顶层段：`forge_tree` / `forge_sets`(P1 预留) / `forge_augments`(P2 预留) / `settings`
  - settings 键：`forge_fee: 节点等级×10`（可配）、`synth_ratio_3to1: true`、`straight_forge: true`、`decompose_rate: {正式:0.4,…}`（复用炼金分解规则）、`exp_per_forge: 节点等级×2`
- **验收标准**：文件结构键齐全、默认值与定稿一致；加载后 settings 各项可查询；品质枚举不在此文件重复定义（引用 items.json 四档）

### T2 · 锻造节点 schema 与 items 双源仲裁
- **定稿依据**：§12.1 节点字段全集；§12.1.1 引用关系 / 覆盖·追加仲裁 / 两种配置模式；v1.0.1 变更批 2C
- **实现要点**：
  - 字段：`id / name / item(必填，别名 output_item 二选一不双写) / type(weapon|armor_head|armor_body|armor_hand|armor_leg|armor_foot，须与 items 条目类型匹配) / level / parent / branch / stats / slots / materials / cost / rarity(四档枚举) / monster_source(可空) / final / augmentable`
  - 装备实例 = items 基础属性 + 节点改造：**覆盖**（节点声明键为准）+ **追加**（未声明键继承 items）；rarity 节点优先、未配则继承 items.quality
  - 校验：item 引用存在、类型匹配、改造键须在 items 元数据键空间内（防新键漂移）、同键冲突给"覆盖生效"黄提示（不拦截）
- **验收标准**：对每个节点，合并实例属性可复现；覆盖/追加用例各 1 组通过；`item` 与 `output_item` 双写配置报错；类型不匹配配置报错

### T3 · 装备派生树结构与最终强化约束
- **定稿依据**：§4.1 树结构（MHW 派生树拓扑）；§4.2 规模建议；§4.3 最终强化；§11 /锻造树
- **实现要点**：
  - 每部位一棵树：weapon + 防具×5 部位；边 = `parent` 派生 + `branch` 转线；每线终点 `final:true`，展示约定前缀 `■`（最终强化神兵）
  - 规模建议：主干 8–12 级、每级 2–3 分支、每线最终强化 1 个；武器 300–500 节点、防具 500–800 节点（15000 物品总量内）
  - 最终强化解锁钩子：客制(P2) / 专属孔位 / 图鉴里程碑；为 /锻造树 分页视图提供数据源
- **验收标准**：样例树（铁剑主干线 + 一分支线 + 炎剑线）可构造；载入无环、每线恰一个 final 节点；遍历可列出父子/分支全部可达关系

### T4 · forge 树级联删除与红名机制
- **定稿依据**：§12.1.2（批 2C 修复）；框架 6.9 级联删除语义
- **实现要点**：
  - 删 items 装备 → 二选一（编辑器删除时作者确认）：① 节点及子树保留标红（/锻造 拒绝、/图纸 显示"已失效：物品已删除"）；② 整棵子树移除 + 父节点 branch 引用同步清理
  - 删 forge 节点 → 已锻造实例保留旧属性（快照，不回溯）；未锻造子链二选一（可配）：① 子节点上提重连（parent 指向原父的父，链不断）；② 整支移除并清理引用
  - 级联后运行共享校验器复查，不残留悬空引用（对齐 6.9）
- **验收标准**：红名/移除两条路径各 1 组测试通过；删节点后已铸实例属性不变；重连后链路完整；复查零悬空引用

### T5 · 素材两档注册与来源提示
- **定稿依据**：§5.1 两档素材；§5.2 素材获取
- **实现要点**：
  - 普通素材：矿石/草药/皮骨（采集/挖掘/垂钓/小怪掉落/商店可买——金币回收口）；稀有素材：怪物素材/宝玉（大怪/精英/BOSS 掉落，复用 loot.json 稀有保底机制）
  - 每条素材标注来源（采集点/怪物/商店）；每怪 2–3 种素材（皮/爪/宝玉）；素材在 items.json 登记为材料类（编辑器素材表复用物品编辑）
- **验收标准**：样例素材条目含来源标注字段；怪物素材与 loot.json 掉落关联成立；商店基础素材可购（金币回收口生效）

### T6 · 3:1 稀有合成（合成引擎 kind=combine 实例）
- **定稿依据**：§5.1 P1 扩展（3 普通→1 稀有）；§12.4 `synth_ratio_3to1`；框架 4.1 recipe.json 统一 schema
- **实现要点**：
  - 以 kind=combine 配置实例登记于 recipe.json（N 素材→1 高级素材，原素材数值不变）；不为锻造另起合成引擎
  - 开关 `synth_ratio_3to1`（默认 true，内容包可关）；铸造 SP 解锁条目（§10.1 SP 面板：3:1 合成）
- **验收标准**：开启时 3:1 合成产出 1 稀有素材；关闭后合成不可用；配置实例通过 Recipe 引擎 schema 校验

### T7 · 素材即进度查询服务
- **定稿依据**：§2.1 #8 素材即进度；§3.4 当前持有；§11 错误模板"缺 X×N"
- **实现要点**：
  - 素材库存查询：持有数 / 需求数逐项对比；缺口项带缺口数与来源提示
  - 供 /锻造 错误提示与 /图纸 进度显示两处复用（单一查询接口）
- **验收标准**：查询返回持有/需求逐项列表；不足项含缺口数与来源；被 /锻造、/图纸 两处调用且结果一致

### T8 · /锻造 <节点> 原子锻造
- **定稿依据**：§1.2 边界铁律 1（100% 成功、失败/随机留邻居）；§2.1 #1 零会话原子、#6 成功率 100%；§3.1/3.2 新手流/升级流；§11 指令表；§12 顶部指令分隔规范；§12.1.2 红名拒绝
- **实现要点**：
  - 零会话原子：一条指令出结果，无会话状态（明确不启用框架 3.18）；同原子内完成全部校验+扣素材+扣金币+产装+发经验（防热重载/双扣）
  - 前置校验顺序：节点存在且非红名 → 铸造等级 ≥ 节点 level → parent 已锻造（沿树顺序）→ 素材足 → 金币够（forge_fee）
  - 素材够即成功：确定性、无任何随机分支；失败零消耗（不扣素材/金币）
  - 错误模板：素材不足 →"缺 火龙鳞×2（来源：火龙掉落/商店）→ /图纸 查看全链"；等级不足 →"需要 精通 级，当前 正式（还差 40 熟练）"
  - 参数分隔：数量用 `*`（/锻造 铁剑*2）、多项目用 `,`
- **验收标准**：成功用例一条指令产出装备+扣素材+扣费+发经验；缺素材失败零消耗且错误模板文本匹配；红名节点拒绝；热重载/并发下无重复产出

### T9 · 直锻模式 + 预览流 + /确认
- **定稿依据**：§2.1 #7 直锻模式；§3.3 预览流；§12.4 `straight_forge`；§11（/确认 为预览流第 2 步）
- **实现要点**：
  - `straight_forge: true`（默认）→ /锻造 一键出结果（小白流）
  - 关闭后（深度模式）两步：/锻造 <节点> 预览 → 卡片（属性/素材/需求等级/孔位/可继续锻造链）→ /确认 执行锻造；预览不扣任何资源；/确认 复用 T8 的原子执行（素材校验在同一原子内）
  - 两模式由 settings 切换，产出路径完全一致
- **验收标准**：默认模式 /锻造 直接成功；深度模式预览卡片字段齐全；预览后无 /确认 则不产出不消耗；确认后结果与直锻一致

### T10 · /图纸 <装备> 全链预览
