## 一、判定顺序与公式总览

### 判定顺序（写死）
```
命中 → 会心 → 格挡 → 双通道（物理/元素独立取整后相加）→ 防御率 → 伤害拦截链 → 扣血
```

> **判定顺序与拦截链阶段序（pipeline_order · 可配）**：默认按本文（命中→会心→格挡→双通道→防御率→拦截链→扣血），效果系统拦截链 8 阶段为权威序；**开放 arena 为 formula.json 可配的 `pipeline_order` 有序数组**（默认值＝现序，仅放开通道，行为零变化；内容包可自定义顺序，超范围提示不拦截）。实现层作承接登记（contract_deviations），随公式配置化阶段落地。

### 公式总览（执行级）
```
① 命中率   = clamp(专注 / (专注 + K_hit × 对方敏捷), 10%, 95%)   K_hit = formula.hit.k（默认 0.2，可配）
            miss → 伤害 0（提示"未命中"）
② 会心     = P=√幸运÷2，r≤P 高级 / r≤P×3 中级 / 其余低级（数值源 = formula crit.*（可配），见 §五 5.1；本行为默认展示）
            倍率 2.2/1.7/1.3 + 0.05×超会心Lv（物理+元素共用一次判定；超会心档数与每档倍率 = formula crit.crit_mult_up（默认 Lv1-3 = 0.05/0.10/0.15，可配；Lv0=无加成；档数扩展见承接登记））
③ 格挡     = min(40%, 专注/(专注+150))；成功 → 总伤害 ×0.5；魔攻击无视格挡
④ 物理通道 = max(1, floor(攻击值 × 技能倍率 × 类型克制 × 会心倍率
                          × 防御系数 × 怪物防御率))（monster_def_rate 见下方配置化说明）
            攻击值 = 力量（斩/打/突）｜智力（魔，防御对位=精神）
            防御系数 = K_def / (有效体质 + K_def)   K_def = 100
            有效体质 = 体质 × (1 − 破防%)（打类型内置破防 20%）
⑤ 元素通道 = max(1, floor(装备元素攻击 × 技能元素倍率 × 元素弱点 × 会心倍率
                          × 元素减伤系数 × 怪物防御率))（monster_def_rate 见下方配置化说明）
            元素减伤系数 = K_def / (元素抗性 + K_def)
⑥ 总伤害   = max(1, floor((物理 + 元素) × 格挡(×0.5) × 防御指令(×0.5) × 乱数))
            乱数 ∈ [0.9, 1.1]（一次判定，双通道共用）
⑦ 拦截链   = 效果系统伤害拦截链（减伤→护盾→反弹→吸收→免疫→续行→扣血，顺序以效果系统 §3.4 为准，2026-08-16 对齐）→ 最终扣血
```
取整策略：通道末 floor（保留双通道灵魂，砍逐段 floor；deep_floor 开关保留）

> **怪物防御率配置化（monster_def_rate · R-09 回写）**：怪物防御率（monster_def_rate）＝**每怪物可配字段**（enemies.json per-monster，≥0，默认 1.0 ＝ 普通同玩家不减免/不增伤）；战斗引擎取目标 combatant 配置乘入双通道末因子。R-09 拍板（2026-08-18）：让内容包作者每只怪都能调；默认 1.0 不参与乘法。实现与细化见：细化_1a §1.11 / contract_deviations R-09。

### 回合死亡判定顺序（写死）
> 回合状态机边界在本层写死（对齐技能派生定稿 §十二 回合时序「回合开始 dot/控制结算 → 玩家行动 → 怪物反击 → 回合结束 tick」；
> 与效果系统 §3.4 拦截链⑦扣血 → ⑧死亡判定衔接）。**判定顺序写死不可配**，仅标注「可配」项可在 formula.json `death_check` 段调整（§5.1）。

```
① 回合开始：dot/持续伤害结算（拦截链扣血后即查，效果系统 §3.4）
② 死亡判定（回合开始即死）：死亡 → 跳过其本回合行动
   · 玩家死 → 战斗失败标记（结算时机见 ⑧）
   · 怪物死 → 战斗胜利标记
③ 行动阶段：先手行动结算（含连段/多段）
④ 击杀判定（每次扣血后立即检查，非等整回合）：
   · 击杀发生在连段套中 → 后续段数照常执行（鞭尸浪费伤害，套内稳定哲学）；
     套完结后目标退出战场，下一回合自动消失（不结算其行动）
   · BOSS/最后目标死亡 → 战斗立刻结束（⑧），不清算后续段数（不鞭尸）
⑤ 后手行动判定：
   · 目标未死 → 正常执行
   · 目标已死 → 后手行动仍推进但无目标：默认转为普攻兜底（打向剩余目标，
     无剩余目标则空挥/待机；可配 skip=直接跳过）；被先手击杀的怪物本身不执行反击（写死）
⑥ 回合结束 tick：持续回合扣减/冷却递减/效果衰减（效果系统 §3.1）
⑦ 同回合互杀（双方死亡标记同轮并存）→ 战斗结束 = 平局（可配 player_loss=玩家败）
   判定基准（可配二选一，默认 order）：
   · order「先判定后手」：后手行动结算完毕后再统一判定——先手击杀生效 → 先手胜；
     先手反伤/同归于尽致死且后手亦死 → 平局；回合开始 dot 双杀（无先后）→ 平局
   · hp_ratio「剩余 HP 比」：比较致死结算前一刻双方剩余 HP 百分比，高者胜（相同 → 平局）
⑧ 战斗结束判定时机：胜负/奖励/掉落/快照清理统一在当轮事件末尾结算一次；
   BOSS/最后目标死亡 → 立刻结束（不再进入下一轮，未执行的后续事件作废）
⑨ 与 3.17 战斗中断恢复的先后：中断快照只落回合边界（回合开始前/回合结束 tick 后），
   回合内不落快照 → 死亡结算天然先于快照写入，恢复后状态 = 最近回合边界，无「恢复在死亡判定前/后」歧义
```

### 2.2 武器类型倍率（weapon_type_mult，可配）
```
斩击 ×1.0 ｜ 打击 ×1.0 ｜ 突击 ×1.0 ｜ 魔 ×1.0
（类型差异用 type_affinity 倾向替代，见 2.3；倍率表预留）
```

### 2.3 攻击类型倾向（type_affinity，可配开关）
```
- 打类型：内置破防 20%（对高防御怪收益）
- 突击类型：命中 +5%（对高敏捷怪收益）
- 斩击类型：会心 +5%（对高 HP 怪收益）
- 魔类型：无视格挡（对高专注怪收益）
- 总开关 type_affinity_enabled（默认开，作者可关回纯弱点差异化）
```

### 4.2 技能倍率预算
```
普攻 100% ｜ 小技 150-200% ｜ 大招 250-400%（技能 power 建议预算区间；上限统一只建议不限制：formula.power.max=500（滑条）/ formula.power.formula_max（JS 公式，默认同 max），均可配【400 预算顶统一为 formula.power.*】）

倍率封顶：派生累计 ≤1.5×（技能派生定稿）
```

### 4.3 怪物属性基线（三档难度）
| 档位 | HP | 攻击 | 防御 | 敏捷 | 专注 | 斩杀回合 |
|---|---|---|---|---|---|---|
| 普通 | 100-380 | 同玩家 | 同玩家 | 低 | 低 | **3-8 回合** |
| 精英 | 800-1500 | ×1.2 | ×1.3 | 中 | 中 | 10-15 回合 |
| **BOSS（高难）** | **3000-8000** | ×1.3 | ×1.5 | 高 | 高 | **15 分钟+ ≈ 40-60 回合** |

### 4.4 难度分层设计（用户约束：高难 15 分钟+）
```
- 普通怪：3-8 回合（通勤快刷，5 分钟内）
- 精英怪：10-15 回合（有机制，10 分钟内）
- BOSS 战：15 分钟+（≈40-60 回合，按每轮 15-20 秒估算）
  · BOSS 高 HP 但单回合伤害可控（防秒杀）
  · 阶段机制：HP 阈值触发行为变化（狂暴/召唤/印记反制）
  · 【高难职业博弈操作感】：
    - 多资源轴管理（连段/印记/MP 三轴同时运转）
    - 循环切换时机（输出循环⇄防御循环⇄控场循环）
    - 打断/霸体读招（BOSS 蓄力时用打断技，防打断用霸体派生）
    - BOSS 印记反制（BOSS 叠印/清印，玩家消除博弈）
    - 续航压力（MP/药剂/连段节奏在长盘中的规划）
```

- 50 级尖峰：≈3374（不破万 ✅）

### 4.6 HP/MP 经济
```
- 药剂回复：普通药 30% HP / 中 50% / 大 80%（可配）

## 五、formula.json 唯一配置源

### 5.1 结构（默认值版）
```json
{
  "schema_version": 1,
  "damage": {
    "base_attack_mult": 1.0,
    "rng": [0.9, 1.1],
    "floor_mode": "channel_end",
    "deep_floor": false
  },
  "hit": {
    "k": 0.2,                    // K_HIT 唯一源 = hit.k（默认 0.2，可配；战斗数值层/玩家属性/效果表达式引用同键；实现层 damage.py 公式验收权威口径一致）
    "cap_min": 10, "cap_max": 95
  },
  "crit": {
    "p_coef": 0.5,               // P(%) = √幸运 × p_coef（默认 0.5 → 幸运 100 时 P=5%，可配）
    "cap": 95,
    "tiers": {"high": 2.2, "mid": 1.7, "low": 1.3},   // 各档倍率（可配）
    "tier_p": [1, 3],            // 降档边界 r≤P 高级 / r≤P×3 中级（可配）
    "crit_mult_up": {"lv1": 0.05, "lv2": 0.10, "lv3": 0.15}   // 超会心档位加成（Lv0=无加成；每档倍率可配；字段名/结构对齐实现层 damage.py CritMultUp）
  },
  "block": {
    "k": 150, "cap": 40,
    "magic_ignores": true,       // 魔攻击无视格挡
    "halve_after_block": true    // 格挡减半（组队多段预留）
  },
  "defense": {
    "mode": "ratio",             // 除算减伤（覆盖框架减法）
    "k": 100,
    "pierce_types": {"blunt": 0.2}  // 打类型内置破防
  },
  "weakness": {
    "type_mult": 1.3,
    "element_mult": 1.3
  },
  "weapon_type_mult": {
    "slash": 1.0, "blunt": 1.0, "thrust": 1.0, "magic": 1.0
  },
  "type_affinity": {
    "enabled": true,
    "blunt_pierce": 0.2,
    "thrust_hit": 0.05,
    "slash_crit": 0.05,
    "magic_ignore_block": true
  },
  "elements": {
    "earth": "地", "fire": "火", "water": "水", "wind": "风",
    "thunder": "雷", "crystal": "晶", "moon": "月", "void": "无"
  },
  "luck": {
    "enhance_rate": 0.05,       // 强化成功率幸运修正
    "effect_prob": 0.05,        // 效果触发概率幸运修正
    "max_mod": 0.2
  },
  "derived": {
    "max_total_mult": 1.5       // 技能派生倍率封顶
  },
  "power": {
    "max": 500,                  // power 滑条上限（默认 500，可配）【统一为 formula.power.max】
    "formula_max": 500           // power JS 公式路径上限（默认 = power.max，可独立配置）【统一为 formula.power.formula_max】
  },
  "effects_link": {
    "intercept_order": ["shield", "reduce", "immune", "revive", "reflect"],
    "pierce_cap": 0.6
  },
  "death_check": {
    "mutual_kill_result": "draw",     // 互杀结果：draw=平局 / player_loss=玩家败（可配）
    "mutual_kill_basis": "order",     // 互杀判定基准：order=先判定后手 / hp_ratio=剩余HP比（可配）
    "no_target_action": "fallback",   // 后手无目标：fallback=普攻兜底 / skip=直接跳过（可配）
    "boss_end_immediate": true        // BOSS 死亡立刻结束（不清算后续段数）
  }
}
```

### 5.2 引用规则
```
- enhance.json → 引用 luck.enhance_rate
- effects.json/statuses.json → 引用 effects_link.*
- skill_chains.json → 引用 derived.max_total_mult
- enemies.json → 弱点表只写 {元素ID: 倍率}，元素 ID 由 formula.json 注册表约束
- 战斗引擎 → 引用 death_check.*（判定顺序本身写死不可配，仅结果/基准/兜底可配）
- 其他模块引用参数，不复制数值
```

### 5.3 校验器（15 条人话规则）
```
1. 参数范围（hit.k 0.05-1 / cap 10-100 / crit.tiers 1.0-3.0）
2. 倍率提示（type_mult/weakness 超 2.0 → 警告"注意克制收益"）
3. 引用存在（元素 ID ∈ 注册表）
4. 概率三态合法
5. 交叉一致性（crit.tiers 低<中<高；crit.crit_mult_up lv1<lv2<lv3 递增）
6. 每怪弱点为 0 → 警告"该怪无弱点，元素武器无发挥空间"（允许无弱点）
7. 管线顺序不可改（校验 formula 未声明顺序）
8-14. 其余数值全部提示不拦截（K/破防/封顶默认值可配，超范围警告）
15. 死亡判定顺序写死：death_check 仅结果/基准/兜底可配，不接受顺序字段（配置顺序字段 → 黄提示）
```

## 六、难度分层 × 职业难度联动

```
- 普通怪（3-8 回合）：🎮 简单职业舒适区（直接输出循环）
- 精英怪（10-15 回合）：🔄 进阶职业发挥（双轴循环收益）
- BOSS 高难（15 分钟+）：🌀 复杂职业主场（多循环切换/读招/资源规划）
  · 高难职业博弈操作感 = BOSS 机制倒逼：
    BOSS 蓄力 → 打断技读招
    BOSS 叠印 → 消除/消耗博弈
    BOSS 狂暴 → 切换防御循环（霸体派生）
    长盘续航 → MP/药剂/连段节奏规划
  · 简单职业打高难：可行但效率低（数值碾压不够，机制吃亏）——难度档位设计意图
```

| 风险 | 对策 |

## 八、伤害构成统计（per-action 收集器 + 木桩战报）

> 来源：新功能建议 #5（训练木桩与伤害构成统计）落地——一个收集器养三个功能（木桩战报 / 战报分享卡建议 14 / 平衡教练建议 12）
> 用途：玩家看懂"强化/配装提升在哪"——普攻/技能/dot/追击各占多少、物理 vs 元素通道占比、会心/格挡/破防/弱点收益可见

### 8.1 收集时机与记录字段（per-action，每段伤害一条）

```
- 收集时机：判定顺序 ⑦ 拦截链 → 扣血 后按"段"写入（连段/多段每段独立记录，套内稳定语义同 §一④ 击杀判定）
- 每段伤害记录（建议 schema，字段可配）：

{
  "source": "skill_fireball | basic_attack | dot_burn | combo_3rd",  // 来源：技能 ID/普攻/dot/追击
  "seg": 3,                    // 连段段数（第 N 段；单段=1）
  "ch_phys": 214,              // 物理通道值（通道末取整后，格挡/防御指令/乱数前）
  "ch_elem": 96,               // 元素通道值（无元素=0）
  "crit": "high",              // 会心档：none/low/mid/high（§一②）
  "blocked": false,            // 格挡（§一③）
  "pierce": 0.2,               // 破防率（打类型内置 20% + 破防类效果，§一④）
  "penetrate": 0,              // 穿透（减伤拦截穿透，effects_link.pierce_cap 相关）
  "weak_type": 1.3,            // 类型弱点倍率（无=1.0）
  "weak_elem": 1.3,            // 元素弱点倍率（无=1.0）
  "final": 310                 // 最终值（拦截链后实际扣血）
}
```

- 按来源聚合：同 source 求和 → 总伤害/占比（%）排序；另出 通道占比（物理/元素）、最大连段段数、会心次数
- 快照：统计随战斗快照保存（框架 3.18 battle snapshot；持久化登记由收尾统一执行）
```

### 8.2 展示（木桩战报 + 普通战斗可选）

```
- /木桩 战斗结束后（默认）：展示伤害构成列表——按来源汇总 + 占比（如：火球术 520（42%）｜普攻 310（25%）｜灼烧 210（17%）…），
  一行摘要 + 折叠明细（QQ 文字防刷屏，复用 5 条/页分页规则）
- 木桩模式可选实时（可配）：每回合末一行摘要（总伤害/最大单段/本回合会心数），战后全量
- 普通战斗默认不展示明细（只收集，供战报分享卡/平衡教练），作者可开战后明细
```

### 8.3 存档：dummy_log（最近 N 次，可配）

```
- 玩家存档环形缓冲：最近 N 次木桩记录（默认 5，可配 0=关；建议 1-20）
- 记录字段：时间/木桩档位 id/回合数/总伤害/来源占比摘要/最大单段/会心次数/格挡次数
- 用途：换装前后对比（打一次看一次，强化收益一目了然）；跨次对比走玩家侧记录即可，不另立统计页
- 查询：/木桩 记录（或复用 /日志 排版，建议不限制）
```

### 8.4 formula.json 落点（可配）

```json
{
  "stats_collector": {
    "enabled": true,          // 总开关（默认开；关=不收集不展示，普通战斗/木桩均无明细）
    "dummy_log_size": 5,      // dummy_log 保留次数（0=关）
    "dummy_realtime": false   // 木桩模式每回合实时摘要（默认关，战后全量）
  }
}
```

### 8.5 校验器 / 编辑器

```
校验器：stats_collector 字段类型校验；dummy_log_size 范围提示（1-20，超范围黄提示）；source 引用存在（技能 ID ∈ skills.json，黄提示）
编辑器：木桩战报预览（模拟器跑一遍直接看构成表）；统计开关通用设置卡片
```
