## 二、数值口径 · 用户授权主 agent 裁定
> 用户原话：「**数值口径你决定吧，反正又不是硬编码，到时候根据需要改就行了。**」

裁定原则：**全部做成可配（包声明/元数据），给默认值 + 可调范围**；文档写明每个数的依据与影响。

| # | 项 | 裁定 |
|---|---|---|
| **N1** | 品质经验模型 | 采用 B 路提案：`单次经验 = Σ(材料品阶基数 × 相性加成系数 × 件数边际 × 互动乘子) × 全局衰减`；cost 约束 = `总 cost 上限(按图纸档缩放) + 每材料 cost`；**参数全部落包声明** |
| **N2** | 防退化两条约束 | **必做**：① 图纸声明**等级带 + 主材料槽**；② **cost 上限随图纸档缩放**（否则出现"低阶便宜材料填满预算"的单一最优解） |
| **N3** | 总 cost 上限量级 | 默认钉在"**刚好到 10 级 + 少量冗余**"（B 路推：10 级阈值≈4040，上限≈4200，超投空间 ~4%）；**按图纸档缩放**，全部可配 |
| **N4** | 品质系数乘区 | **0.80–1.50**（面板总倍率 0.795–1.075），在"装备这一份预算"内分配；可配 |
| **N5** | 分解回收率 | 先占位：`精粹 = 投入价值 × k1(0.30–0.40) × k2(图纸档 0.40–0.60) × β^色序(β=0.5–0.7)`，与既有 `decompose_rate`（0.40→0.65）并存；标"待实际数据校准" |
| **N6** | 品质经验粒度 | 按原案"**每次打造独立**"：单次打造内累计、打造结束后清零（**不跨件累计**） |

## 三、用户新增的两条要求（本轮补充）

### 补充 1 · **装备占比 40% → 60%**
- 用户原话：「把装备占比在不改变其他数值的情况下提高到 60%，其他地方你看需要怎么调整就安排一下就行了。」
- **主 agent 裁定（执行口径）**：
  - 现状基线：面板 = `白值 7 : 装备 8 : buff 5`（合计 20 单位）→ 装备占 **40%**（依据 `docs/审查参考/阶段一数值模型v2:32` 及三路报告引用）。
  - **保持白值与 buff 的绝对数值不变**（这是"不改变其他数值"的直接含义），**放大装备贡献**至 60%：
    `装备 8 → 18`（18/(7+18+5)=**60%**），即**装备预算 ×2.25**；白值 7、buff 5 不动。
  - **连锁调整（授权范围内，主 agent 安排）**：面板总功率由 20 → 30 单位（+50%）⇒ **怪物侧与战斗数值层按同一比例重校**（目标：**保持既有斩杀回合数与手感不变**），按战斗数值层定稿的"三档推演（无buff下限/半buff中值/满buff上限）"口径重算，用既有**蒙特卡洛/斩杀回合**验证工具做**修前 vs 修后对照**。
  - **实施落点**：① 装备数值来源（词条/强化/品质乘区）的**总额度参数**上调配平；② 战斗数值层的怪物侧基线同步；③ **全部参数化**，不写死。
  - **独立成批**（数值校准批），与功能批解耦，便于回滚。

### 补充 2 · **材料相性共享给深度炼金**
- 用户原话：「材料相性这个设定可以共享给深度炼金用，相性影响药剂效果之类的。」
- **主 agent 裁定**：**相性是通用机制**，不属打造私有 →
  - 落点为**通用层**（如 `core/affinity.py` + 包声明数据），**打造与深度炼金共用同一套相性定义/池/互动规则**；
  - 深度炼金的消费方式：**相性 → 药剂效果**（效果强度/附加效果/成功率等，具体口径在炼金侧细化时定，本系统只提供**通用相性 API**）；
  - **不得**在两处各写一套相性（唯一源）；深炼金侧的接入点留出**稳定接口**，等其细化时使用。

## 六、用户补充（2026-09-19 二次）：**「合成」提升为打造与炼金的公用系统**

> 用户原话：「把"合成"作为一个**打造和炼金的公用系统**，用户们**可以不选择启用打造和炼金，只启用合成**，也就是说不管是**合成装备还是合成药剂合成材料**之类都可以走这个。然后再分别是**炼金（深度炼金）**和**打造（深度打造）**。因为我感觉打造没必要再分出来一个类似合成的东西独立出来，本来就是极度简化用的，干脆合一块对玩家来说应该更简单。」

### 主 agent 可行性判定：**方便**（现有零件 ≈ 80%，只需归位，不需重写）
| 需求 | 现有依据 | 结论 |
|---|---|---|
| 合成是公用层 | 炼金定稿 `:18`「第 1 层【合成】（跨职业）」、`:5`「**合成（跨职业）→ 炼金（职业专属）→ 深度炼金（大师解锁）**」、`:36`「合成/炼金/深度炼金（三层生产）」 | ✅ 定稿本就把合成定为**跨职业公用层** |
| 玩家可**只启用合成** | 总纲 `:2719`「可裁剪模块声明：`settings.json` 各模块段 `mode` 字段（full/simple/off）」；`:2720`「炼金 `alchemy.mode` —— full 三层漏斗 / **simple 仅合成层（投料合成，无炼金层/深度炼金/职业等级/特性/能量条）**」 | ✅ **现成机制**，"只启用合成"= simple 档 |
| 合成载体 | `core/synthesis.py`（引擎，已消费 `synth_allowed`）· `/合成` 指令已注册（`alchemy_commands.py:165 SYNTH_CMD`，在 parsers 白名单内）· `recipe` 模块（框架目录 `module_catalog.py:83`「合成配方：材料与产出」） | ✅ 零件齐 |
| 打造不再自带"简化合成" | 原批 40 计划"打造自带基础合成" | ✅ **改为复用公用合成层 → 更省事** |

### 目标架构（三层 + 三条启用路径）
```
合成（公用层：装备 / 药剂 / 材料 皆可走；极度简化的投料产出）
  ├─ 炼金  → 深度炼金   （职业专属 → 大师解锁；走 recipe + alchemy 三层漏斗）
  └─ 打造  → 深度打造   （本方案；走 recipe 公用合成 + 打造深度层）
```
- **三条启用路径（互相独立，包声明驱动）**：①`只启用合成` ②`合成 + 炼金(深度炼金)` ③`合成 + 打造(深度打造)`；也可三者全开。
- **深度打造的基础合成调用公用层**（`recipe` + `core/synthesis.py`），自己只做**深度层**（图纸/材料相性/随机属性与套装词条/品质经验/强化词条/符文/淬炼）。

### 落地动作（归位，非重写）
1. **指令归位**：`/合成`（及 `/投料` 等合成族）从 `alchemy_commands` **提到公用层**（新模块或既有 `recipe` 的指令组），**保持指令名与行为不变**（回归对拍）；
2. **启用粒度**：`mode` 三态扩展为**三条路径的启用矩阵**（合成 / 炼金 / 打造 各自开关），**缺省 = 现状**（不启用打造时零变化）；
3. **打造复用公用合成**：深度打造的"投料→基础产出"走 `recipe`/`synthesis`，**不新造第二套合成**；
4. **编辑器**：「合成」作为**独立可启用模块**（`recipe` 已在框架目录）；打造/深度打造在其之上；
5. **红线（回归）**：既有炼金三层漏斗口径**不得破坏**——"只启用合成"必须**逐字段等于**现有 `alchemy.mode=simple` 行为。
