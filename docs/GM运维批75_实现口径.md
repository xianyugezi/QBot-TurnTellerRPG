## 四、`定时=` 的处置（登记缺口，不硬造）

`/广播 <消息> 定时=HH:MM` **未实现**，只做即时广播。两条硬阻塞（实证）：

1. 框架**零 apscheduler**既有机制——`qbot_rpg/assembly/runner.py` 明记「零 apscheduler ·
   懒清理」，M12 摸底文档亦列「定时广播需按同口径实现或引入调度」；本批不引入常驻调度。
2. 现有解析器 token 合法字符集 `parsers._ALLOWED_TOKEN_RE` 不含 `:` ，
   `定时=20:00` 在解析层即判「未知分隔符」（`/广播 通知 定时=20:00` → `p.error`），
   处理器拿不到该键值。

处置：处理器对能到达的 `定时=<值>` 键值（如无冒号写法）做**即时广播 + 结果附
「定时=暂不支持（已登记）」**，并把 `定时=<值>` 记入审计；对 `定时=HH:MM` 则由解析层
如实报 TPL-12。定时调度本身登记为缺口，见 `docs/矛盾与待裁决登记.md` X11。

## 五、`/玩家查询` 脱敏口径（有依据）

- 依据：`docs/审查参考/开发规则文档.md:485`「日志脱敏：QQ 号/API Key」+ 5b G9「不返回背包/收益/
  聊天气泡等敏感明细」。
- QQ 号：`mask_qq` 保留头 2 位 + 尾 2 位，中段 `*`（`PLAYER_QUERY_MASK_HEAD/TAIL` 可配）；
  长度不足退化「首字符 + *」。
- 字段最小化：只出 等级 / 货币（限 `PLAYER_QUERY_MAX_CURRENCIES` 条）/ 最近在线 /
  封禁状态；数据源经 `ctx["player_lookup"]` 注入，渲染层不接触背包/收益/聊天字段。
- 最近在线：`humanize_ago` 相对时间（刚刚 / N 分钟前 / N 小时前 / N 天前 / 未知），
  文案在模板表（`gm_ago_*`）。
- 未注册 → 领域错误模板（目标不存在 ≠ 静默，5b G9）。
