## P1（要改）

### P1-1　§4.2 NPC 复用示例使用了 NPC 定稿 schema 不存在的动作枚举/字段，未标【工程补白】

**位置（2a4c 内）**：§4.2 示例 JSON（L167–174）。

**示例写法**：
```json
{
  "id": "witch_interaction",
  "actions": [
    { "action": "dialogue", "text": "暴雨夜访客……",
      "condition": { "var": "period", "op": "eq", "param": "midnight" },
      "extra": { "var": "weather", "op": "eq", "param": "storm" } }
  ]
}
```

**定稿实际（NPC）**：
- 数组键为 **`interactions`**（NPC L143「npc.json interactions 数组」），无 `actions` 字段；
- 动作枚举为 quest/shop/heal/give_item/buff/repair/teleport/intel/tutorial/reply 十类（NPC L126–137），**无 `dialogue`**；最接近的「特殊对话」应落 reply（聊天回复，text[]），但也只是近似；
- interactions 子字段表（NPC L157–175）含 text/condition/quests/shop_refs/cost/heal/items/repeat/effects/turns/map/intel_refs/tutorials，**无 `extra`**；双条件组合应走条件引擎嵌套 any/all/not（NPC §4.3 L251）。

**问题**：语义（午夜+雷雨→NPC 特殊对话）确可追溯到时间天气 L215（NPC 交互条件）/L395（午夜雷雨 NPC 特殊对话），但示例的 JSON 形体（`actions`/`dialogue`/`extra`）全部在 NPC 定稿 schema 之外，且未按文档自定规则（L10）标【工程补白】。本文件是接口契约文档，照抄示例必然校验失败（动作枚举非法/未知字段），并与同文档 §2.2 消费方表「npc.json interactions condition」的表述自相矛盾（文本正确，示例失实）。应改为 interactions 数组 + 合法动作（如 reply）+ 条件组合写法，或显式标【工程补白】并注明为非 schema 示意。

**证据**：NPC L126–137/L143/L157–175/L251（对）；2a4c L167–174（错）。
