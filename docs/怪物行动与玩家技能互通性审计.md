# 怪物行动系统 ↔ 玩家技能系统 · 互通性审计

> 日期：2026-09-09 ｜ 范围：veinborn 内容包 + 引擎执行链 ｜ 方法：键集对比 + 引擎级互转直发实验 + 黑盒隔离层验证

## 一、结论概要

- **引擎层同构（T24 设计注释原文：「技能=怪物行动=一次出手，复用玩家伤害通道」）**：
  怪物行动与玩家技能共用 defs 合并表（skills+action 同表，ComboEngine resolver 同源）、
  同一 `_resolve_combo_action` → `_resolve_damage_action` 通道；effects/status/marks/位置
  （position_rule/air_policy/reposition）等机制对双方一视同仁。
- **配置/指令层双库隔离**：技能走 skills.json + skill_validator（V 系，31 键）；
  行动走 action.json + validator R 系（14 键）；玩家指令只解析技能表（「攻击 幼兽扑咬」→
  「❌ 没有这个技能」）；怪 AI 只从 enemy.actions 引用行动表；校验器互相红拦
  （enemy 引用技能 id、链引用行动 id 均拦）。
- 命名空间：技能 id 与行动 id 当前零冲突（前缀分治：rb_/vc_/va_/vs_/sw_/po_/vg_/cw_/vd_ vs bb_/gj_/gt_…），
  合并表无覆盖风险。
- **方向性结论**：怪→玩家技能方向引擎已全通（数值/效果/位置/门禁自动适配），
  未来做「Boss 偷技能/技能怪用」类机制零引擎改动；玩家→怪行动方向存在 P1（数值口径）
  与 P2（intent 空转）两个坑，但双层隔离下无现实触发面，登记不改。

## 二、引擎层互转实验（绕过指令/校验直发）

| 场景 | 结果 |
|---|---|
| A. 玩家用怪行动 def（do_action skill_id=bb_cub_bite，power 0.5） | ❌ 数值崩坏：0.5/100=0.005 → 伤害 1 点保底（通道 max(1)） |
| B. 怪用玩家技能 def（enemy_act skill_id=rb_slash，无 mult） | ✅ 自动 power/100=1.1×：怪用 86 vs 玩家同技能 54（atk/dfn 差量级一致） |
| C1. 怪用 sw_guard（guard_up mitigation 40% self） | ✅ effects 全执行：mitigation_added + mark_add，怪防御 40% 挂上 |
| C2. 怪用 sw_vault（reposition self air） | ✅ 位置效果相对语义自动适配：position_changed，怪真升空（height=air） |
| D. 怪用 sw_thrust（consume sword_aura 50，怪无此印） | ✅ 门禁安全拒：ok=False 不耗回合不崩 |
| E. gj_armor 直发（power 0 intent 防御 无 effects） | ⚠️ 零效果零减伤——防御语义在 type=guard 通道，不在 action resolve 通道 |
| E2. MonsterAI 决策路径 | 蓄力类（gj_charge）效果承载于 ai_state charging 状态机（mult 0 占槽→后续释放） |
| G. id 命名空间 | 技能∩行动 = 空集 |

## 三、差异性明细（核心 5 条）

1. **数值制（唯一硬伤源）**
   - 技能：power 110 制（110=110%），mult=power/100（battle.py L2112-2121）
   - 行动：power 小数制（0.5=50%），MonsterAI.decide 直转 mult
   - 互转：玩家用行动 def → power/100 把 0.5 当 50 处理成 0.005（×0.01 崩坏）；
     怪用技能 def 无 mult 时 resolve 自动 power/100 → 正确
2. **字段面**：技能 31 键 vs 行动 14 键
   - 技能独有 24：type/effects/energy_cost/energy_gain/mp_cost/consume_marks/hits/
     hit_mod/crit_mod/block_mode/tag/armor/interrupt/job_restrict/job_form/level/
     derive_only/chain_refs/break_power/air_policy/position_rule/revert_form/desc
   - 行动独有 6：weight/probability/intent/tags/hungry/apply_mark
   - 引擎 get 容错缺省 → 互转不崩；但技能独有机制（印记消耗/资源/连段/形态）在怪侧无消费方
3. **效果承载机制**：玩家=effects 编排（effects.json 原子 + 技能 effects 列表）；
   怪物=intent 声明 + MonsterAI 状态机（蓄力 charging / 起身 get_up / 意图预告）；
   action def 全库 69 条零 effects 先例——引擎通道已预留
   （battle.py `_ai_action_dict` effects setdefault 归一）但内容零使用
4. **attack_type 口径**：技能英文（slash/pierce/blunt/thrust…）；行动中文（打）+tags（物理/蚀）
   ——引擎 `_normalize_attack_type` 双向归一，互通无碍
5. **渲染**：同通道 actor 分流（你{技能} / {怪}{行动名}），黑盒怪行动渲染正常

## 四、问题清单与建议

| # | 问题 | 现实触发面 | 建议 |
|---|---|---|---|
| P1 | 玩家引擎层用怪行动=power/100 错误口径（×0.01 崩坏） | 无（指令层/校验层双层隔离） | 登记不改；未来做「怪行动可玩家使用」类内容（御兽/技能掉落）时统一 power 口径或行动加玩家使用标记走 110 制 |
| P2 | intent 型怪行动（防御/蓄力/召唤）效果依赖 AI 状态机，脱离 AI 上下文=空转（gj_armor 直发零效果） | 无 | 同上；防御类行动若需直发语义，应转 effects 表达或 type=guard 通道 |
| P3 | 怪用带演化链的玩家技能会按怪侧条件求值触发链 | 无（校验拦+无内容混用） | 内容把关即可 |
| P4 | 正向资产：怪用玩家技能全通 | — | 未来「Boss 偷玩家技能/玩家技能怪用」零引擎改动，需校验放行+内容配置 |
