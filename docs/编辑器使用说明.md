# 内容编辑器 · 使用说明

> 面向内容作者 / 策划，不需要懂代码。
> 编辑器是**通用工具**：界面里出现的模块、字段、分组、下拉候选，全部来自你选中的那个内容包自己的声明；
> 换一个内容包，界面自动跟着变，编辑器本身不用改。

---

## 〇、一分钟上手

1. 启动（见 §一）：一条命令，或者让技术同学给你一个网址。
2. 浏览器打开 **http://127.0.0.1:8090/**。
3. 顶栏左边选**内容包** → 第 1 栏点**模块** → 第 2 栏点**条目** → 第 3 栏改字段。
   （空白包第 1 栏是空的？点顶栏右上角 **⚙ 模块** 勾选要做的内容类型，见 §一·5。）
4. 改完点 **保存**。出错了看提示（红/黄，见 §四）。
5. **改错了**：点顶栏右边的 **回退到上一份备份**，内容回到上一次保存之前（见 §四·3）。
6. **想把包发给别人 / 收到别人的包**：顶栏点 **📦 导出/导入**（见 §九）。

## 一、怎么打开

### 1. 启动方式

在项目根目录执行：

```bash
bash scripts/editor_start.sh
```

默认监听 `127.0.0.1:8090`，终端会打印一行访问地址，形如：

```
访问地址： http://127.0.0.1:8090/
```

常用的可选参数（都可以不传）：

| 参数 | 作用 | 默认 |
|---|---|---|
| `--pack 包名` | 打开时默认选中哪个内容包 | 内容目录里第一个 |
| `--content-root 目录` | 从哪个目录读取内容包 | 仓库的 `content/` |
| `--role owner` / `--role gm` | 权限位：可编辑 / 只读预览 | `owner` |
| `--host 地址` / `--port 端口` | 监听地址 / 端口 | `127.0.0.1` / `8090` |

例如：

```bash
bash scripts/editor_start.sh --pack 你的包名 --role owner --port 8090
```

启动失败时脚本会打印**人话原因**（缺解释器 / 缺依赖 / 端口被占用 / 内容目录找不到 / 包名不存在等），
并给出对应的处理办法，不会只丢一串报错。

### 2. 怎么安全地给别人看（SSH 隧道 / 内网）

编辑器默认**只监听本机**（`127.0.0.1`），外面访问不到，这是有意的安全默认值。
如果内容包在服务器上、你想在自己电脑的浏览器里用，推荐用 **SSH 隧道**，不要直接把端口开到公网：

```bash
# 在你自己的电脑上执行（把 用户名/服务器 换成你的）
ssh -N -L 8090:127.0.0.1:8090 用户名@服务器地址
```

然后在自己电脑浏览器打开 `http://127.0.0.1:8090/` 即可。
若确实在同一可信内网，也可以 `--host 0.0.0.0` 监听所有网卡，但**只建议在内网、且明确知道谁能访问时**这么做。

### 3. 权限位（机主可编辑 / GM 只读）

顶栏右侧的 **身份** 下拉可以切换：

- **机主 · 可编辑**：能改字段、能保存、能新建/删除条目、能回退。
- **GM · 只读预览**：只能看，不能改（保存 / 新建 / 删除 / 回退按钮全部置灰）。
  适合给外部的人看内容、或者你只想核对不想误改时使用。

> 只读身份下如果硬要新建，编辑器会明确提示「当前身份为只读预览，不能新增条目」。

### 4. 选择内容包

顶栏左侧的 **`pkg=`** 下拉列出内容目录里的所有内容包（名字来自每个包的 `manifest.json`）。
换包后：第 1 栏模块、第 2 栏条目、第 3 栏字段都会**按新包的声明重画**——这就是「换包零改动」。

### 5. 模块开关 ⚙（空白包先从这里开始）

如果这个内容包刚建、里面什么都没有，第 1 栏会是空的。这时点顶栏右上角的 **⚙ 模块**，
会弹出「模块开关」面板：

- 面板列出**这个包可以启用的全部内容类型**（技能 / 物品 / 地图 / 怪物……，名字优先用包自己的叫法，
  包没起名时用通用默认名），每一项都带一句「它是做什么的」。
- 想做什么内容，就把对应项**勾上**。勾选后：左侧第 1 栏立刻出现这个模块，编辑器会建一个空的
  数据文件（空列表或空对象）让你开始写。这些改动会先**校验、自动备份，再原子写盘**；
  写得不对不会落下半套。
- 有些模块有前后关系（比如「派生链」通常要配合「技能」、「装备」属于「物品」）。只勾后一个时，
  面板会给一句**黄色提醒**「建议同时启用 X」——只是提醒，不挡你操作。
- **取消勾选不会删数据**：它只是把这个模块从包里「摘下来」，原来的数据文件会**保留**；
  想反悔就再勾回来。面板底部的 **回退最近一次模块变更** 可以把 `manifest` 复原到上一次变更前
  （所有数据文件同样保留），适合刚点错时救一下。
- **GM 只读身份**下可以打开面板查看，但勾选框是灰的、不能改（面板里会写明原因）。

#### 推荐组合（批65：一键勾选一组常用模块）

面板顶部新增「**推荐组合**」区，列出框架自带的几组常用模块（中文名 + 一句话说明 + 适用人群 +
模块数），例如「基础 RPG 包 / 生活冒险包 / 故事探索包」。点一下就是**累加勾选**：

- **不覆盖你已勾的**：组合只做「加上去」，不会取消你手动勾选的任何模块。
- **依赖自动补勾**：组合里没写的**前置模块**（比如采集要的地图、符文要的效果）会自动一并勾上，
  应用后的提示里会写明「已自动带上：……」（只是提示，不挡你操作）。
- **可一键撤销**：整套组合只写一次 `manifest`，点面板底部 **回退最近一次模块变更** 即可把整组
  一起撤销（数据文件始终保留），适合刚点错时救一下。
- **组合只是快捷方式**：不会减少面板里可见的模块——框架能力全集照旧全部列出，也能照旧逐个勾选。
- **包可覆盖 / 追加 / 关闭组合**：内容包作者可声明自己的组合，见 §十·10。

第 1 栏「未启用 · 框架能力 N 项」分组旁也有一行同样的引导：可以直接点一项启用，也可以去
⚙ 面板用「推荐组合」一次勾一组。

### 6. 服务器常驻部署（批63：systemd 常驻 + 一键隧道）

> 面向「内容包在服务器上、用户不登服务器」的场景。**普通本地使用看 §一·1 即可，本节可不看。**

**部署后是什么样**：编辑器由 systemd 常驻服务 `qbot-editor` 托管，只监听服务器本机
`127.0.0.1:8090`（公网不可直达），**开机自启、挂了自动拉起**。用户在自己电脑上双击
「编辑器隧道」脚本开一条 SSH 隧道，浏览器自动打开 `http://127.0.0.1:8090` 即可编辑。

- **用户日常**：双击隧道脚本 → 黑窗口别关 → 浏览器自动打开 → 改完保存。详见交付包里的
  《使用说明.txt》（由 `scripts/gen_editor_tunnel_kit.sh` 生成）。
- **管理员命令**（在服务器上，需要 root / sudo）：

  ```bash
  systemctl status qbot-editor            # 看状态（active / enabled / 内存）
  curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8090/   # 期望 200
  systemctl restart qbot-editor           # 重启（改了内容包或配置后用）
  systemctl stop qbot-editor              # 临时停
  systemctl start qbot-editor             # 再开
  journalctl -u qbot-editor -n 50         # 看日志
  ```

- **重新部署 / 改配置**（unit 由脚本统一生成，别只改 `/etc/systemd/system/qbot-editor.service`）：

  ```bash
  sudo bash scripts/deploy_editor_service.sh              # 生成 unit + 开机自启 + 启动
  sudo bash scripts/deploy_editor_service.sh --status     # 只看状态
  sudo bash scripts/deploy_editor_service.sh --no-start   # 只安装/启用，不启动
  sudo bash scripts/deploy_editor_service.sh --uninstall  # 回滚：停服务 + 取消自启 + 删 unit
  ```

  可覆盖的环境变量：`EDITOR_SERVICE_NAME` / `EDITOR_REPO` / `EDITOR_VENV_PY` / `EDITOR_HOST` /
  `EDITOR_PORT` / `EDITOR_ROLE` / `EDITOR_PACK`（默认 `veinborn`，显式置空 = 内容目录第一个）/
  `EDITOR_CONTENT_ROOT` / `EDITOR_MEMORY_MAX`（默认 `512M`）。

- **生成用户交付包**（私钥 + 双击脚本 + 使用说明 → zip）：

  ```bash
  bash scripts/gen_editor_tunnel_kit.sh
  # 产出：/root/deliverables/editor_tunnel_kit.zip
  ```

  ⚠ zip **内含私钥**，只放在用户自己电脑上、不要外传；本脚本从不回显私钥内容。

- **安全红线**：不要把 `--host` 改成 `0.0.0.0`（编辑器本身无登录/密码，开到公网等于裸奔）；
  远程一律走 SSH 隧道。unit 里另有 `MemoryMax=512M` 兜底（服务器无 Swap）。

**批63 新增脚本登记**（仅部署脚本，不改任何功能代码）：

| 脚本 | 作用 | 写到哪里 |
|---|---|---|
| `scripts/deploy_editor_service.sh` | 安装/查询/卸载 `qbot-editor` systemd 常驻服务 | `/etc/systemd/system/qbot-editor.service` |
| `scripts/gen_editor_tunnel_kit.sh` | 生成一键隧道交付包（`.bat` / `.command` / 使用说明 / 私钥 → zip） | `/root/deliverables/editor_tunnel_kit.zip` |

> 部署现状（批63 实测）：服务 `enabled + active`；`curl http://127.0.0.1:8090/` = `200`；
> 杀掉进程后 `Restart=always` 约 3 秒自动拉起并恢复 `200`；常驻内存约 **51 MiB**。

## 二、界面长什么样（三栏）

从左到右三栏，各有独立标题条与边界线：

### 第 1 栏：模块分类

- 列出当前内容包声明的**模块**（例如设置 / 物品 / 怪物 ……，名字来自包自己的声明，不写死）。
- 有上下级关系的模块会**缩进显示**（例如「物品 ▸ 装备」），归并关系同样由包声明决定。
- 模块后面的数字是**条目数量**；含子模块的模块会标「（含子项）」，鼠标悬停可看「本模块 N + 子项 M」的明细。

### 第 2 栏：条目列表

- 只显示当前模块下的**条目名字**（不堆一屏表格，给编辑面板让出空间）。
- 条目多时用**细滚动条**上下查看，**不翻页**。
- 上方有：**+ 新建条目**、**过滤当前模块**（在这个模块里按名称/ID 找）、**全局检索**（跨模块找，见 §六）。

### 第 3 栏：大编辑面板（主角）

- 顶部显示当前条目名、ID、以及「字段数 / 分组数 / 是否可编辑 / 元数据来源」。
- 工具栏：**校验 / 保存 / 取消 / 删除条目**，右边是**备份状态**与**回退到上一份备份**。
- 中间就是字段表单，按**页签分组**展示（见 §三·2）。
- 只读身份下，工具栏按钮会置灰，字段以只读形式展示。

### 顶栏

内容包选择器（`pkg=`）、左侧的**保存状态**（「已保存」或「未保存改动 N 项」）、
右侧的 **📦 导出/导入**（分享内容包：导出此包 / 导入别人的包，见 §九）、
**⚙ 模块**（模块开关，见 §一·5）、**身份**与权限标签。

## 三、怎么改

### 1. 先选模块，再选条目

第 1 栏点模块 → 第 2 栏点条目 → 第 3 栏出现该条目的字段。点一下就直接显示，不需要再点「编辑」。

### 2. 页签（分组）

字段按内容包声明的**分组**分成一排页签，默认只显示第一组，其余点页签切换。
页签名字和顺序来自内容包自己，编辑器不写死「基本 / 数值 / 附加效果」这类词。
某个分组在本条目里没有字段时，会显示空态提示，而不是消失。

### 3. 普通字段（文本 / 数字 / 开关 / 下拉）

- 文本：短文本用单行框；长文本（简述、详情等）给**大的多行输入框**。
- 数字：只接受数字；非法输入会按原样保留并交给校验提示。
- 开关：勾选框，勾上 = 是。
- 下拉：候选来自内容包声明的枚举值。
- 字段标签是「**中文名（原始键名）**」：中文为主、键名为辅，方便你既看懂又能对上文件里的键。

### 4. 列表字段（可增删行）

- 列表字段下方就是一张可编辑的表，**每一行是一条**。
- **加一行**：点「+ 添加一行」。
- **删一行**：点该行右侧的删除按钮。
- 当一行里有「对象 / 条件 / 键值表」这类**嵌套内容**时，界面会自动改成**一行一块**的排版
  （标量字段横排在第一行，嵌套内容各自换行、占满宽度），不会挤成横着滚动的宽表格。
- 全是简单值的列表（例如一串数字/名字）仍用紧凑表格。

### 5. 引用字段（选择别的条目）

引用字段保存的是**目标条目的 ID**，但界面上会显示成**名字**：

- 点引用框展开候选（可输入关键字筛选），选中即可。
- 候选在换成别的包后会自动重新读取。
- 如果填的 ID 在当前包里**找不到对应条目**，编辑器会**标黄提示**（不阻断保存），
  例如「该引用指向的目标不存在：xxx」。
- 引用目标在当前包还没有任何候选时，也会给一句黄提示，说明可能是「目标模块还没建立」。

### 6. 条件行 / 键值对表格

有些字段（比如派生条件、数值覆盖、印记消耗表）用专门的编辑器：

- **条件行编辑器**：一行一个条件（主体 / 比较符 / 数值），支持两层嵌套与「与 / 或」组合。
- **键值对表格**：可增删行，键和值都可以是引用选择器（取决于内容包声明）。

### 7. 字段说明气泡（悬停 / 点击看解释）

**每个字段的中文名都是可以点/悬停的**（鼠标移上去，或点一下把它钉住）：

- 悬停：弹出说明卡，移开自动收起。
- 点击：钉住不消失，再点一下或按 **Esc** 关闭。
- 说明卡内容由编辑器**自动拼装 + 内容包人工补充**，通常包括：
  类型、是数值还是比例、建议范围、默认值、是否必填、候选值、引用目标、
  以及「提示」一行（必填 / 候选 / 0 = 不限等）。
- 如果某个字段**内容包没有登记元数据**，卡片会如实标注「**元数据未登记**」，
  编辑器按实际值的类型兜底展示，不会瞎猜、也不会报错。

> 面向非技术用户：看不到说明时，先点一下字段名；没有说明卡的字段，说明这个包还没给它写帮助。

### 8. 改动标记与草稿

- 你改动的字段会标上「**● 已改动**」，顶栏显示「**未保存改动 N 项**」，条目名旁会有 `*`。
- **改动先进草稿**，只有在点保存时才真正写文件；没保存前可以点「**取消**」全部还原。
- 改回原值，改动数会自动减少；全部改回后回到「已保存」。
- 切换条目/模块前若有未保存改动，编辑器会弹窗提醒，不会静默丢失。

## 四、怎么保存 / 出错了怎么办

### 1. 校验 vs 保存

- **校验**：只检查、不写文件。会把人话提示列出来（哪一项、为什么不行、怎么改）。
- **保存**：先**校验**，通过后写文件；不通过（有红拦）就**一个字节都不写**。
- 没有改动时，两个按钮是灰的（没东西可校验/保存）。
- 只发送你**改过的字段**（增量保存），不会覆盖你没碰过的内容。

### 2. 保存时后台做了什么

一次保存会按顺序做四件事，全部成功才算保存成功：

1. **校验**：有红拦 → 直接停下，不写文件。
2. **备份**：把当前模块文件复制一份为 `<模块名>.json.bak`。
3. **原子写**：写到一个临时文件再整体替换，避免断电/崩溃留下半个文件。
4. **回读复核**：重新读一遍确认写对了；万一没写对，**自动回退到刚才的备份**并如实告诉你。

任一步失败都会明确报错，并保证内容文件不被改坏。备份失败时，本次写入会被取消。

> **注意**：每个模块只保留**一份**备份（`<模块名>.json.bak`），下一次保存会覆盖上一份。
> 所以「回退」是回到**最近一次保存/删除/新建之前**的状态，不是任意历史版本。

### 3. 改错了怎么救（重点）

**最常见、最有效的救法：点「回退到上一份备份」。** 位置在第 3 栏工具栏最右边。

- 适用场景：刚才保存错了、删错条目、新建后发现不对、批量操作想反悔。
- 操作：点 **回退到上一份备份** → 弹窗确认「当前文件内容会被备份覆盖」→ 确定。
- 效果：**整个模块文件**恢复到最近一次写入之前的样子。
- 回退按钮什么时候是灰的：
  - 当前模块**还没有备份**（说明还没保存过；备份会在你第一次保存/删除/新建后生成）；
  - 当前身份是 **GM 只读**；
  - 正在请求中。
- 如果连备份也救不了你（比如你已经保存了两次、备份也被覆盖了）：
  内容文件在 `content/<包名>/<模块名>.json`，可以让技术同学用版本管理（如 git）里更早的提交恢复。

> 小技巧：做**大改**之前，先点一次保存（生成一份「改前」备份），再继续改；这样回退点更安全。

### 4. 红色提示与黄色提示分别什么意思

| 颜色 | 叫法 | 含义 | 会不会拦保存 | 你该做什么 |
|---|---|---|---|---|
| 🔴 红 | **红拦** | 这一项**必须改对**才能保存（例如数字填了文字、ID 重复、必填为空） | **会**。红拦存在时，不写任何文件 | 按「怎么改」那一行修正，直到红色消失 |
| 🟡 黄 | **黄提示** | 只是**提醒**，内容仍然可以保存（例如引用指向了不存在的条目、删条目时有人引用它） | **不会** | 确认没问题就可以继续；不放心就先不保存/先处理引用 |
| 🟢 绿/无 | 完成 | 校验通过、保存成功 | — | 无需处理 |

每条提示都尽量写成「**哪一项 · 为什么 · 怎么改**」，不会只给你一个错误码。

### 5. 保存时的常见失败与处理

- **「校验未通过：本次未写入任何文件（红拦）」**：看红色条目逐条改。
- **「备份失败，已取消本次写入」**：一般是磁盘/权限问题，内容包没被动过；请联系技术同学检查磁盘空间与目录权限。
- **「写入失败：文件未改动（原子写未完成）」**：同上，重试；反复失败就找技术同学。
- **「写入后复核未通过，已自动回退到上一份备份」**：本次改动**没生效**、已自动还原；可以重试或先排查。
- **「请求失败：……」**：编辑器服务可能已退出或网络断了；确认服务仍在运行，刷新页面重试。
- **黄色「引用指向的目标不存在」**：保存会成功，但那条引用是空的；建议先把目标条目补上。

## 五、新建 / 删除条目

### 新建条目

1. 第 1 栏先选好模块，点第 2 栏上方的 **+ 新建条目**（只读身份下置灰）。
2. 编辑器会给出一个**建议 ID**，并按内容包元数据的默认值初始化其它字段。
   - ID 是条目之间互相引用的名字；**默认按「前缀 + 序号」生成**（如 `item_001`，序号零填充；
     前缀来自内容包声明或模块名，宽度可在内容包里配置）。
   - 名称填好后可以点 **按名称生成** 重新取一个不重复的 ID；环境装了拼音库时还会多一个
     **拼音 id** 按钮（按中文名生成全拼 id，如 `long_lin_jia`）——名称含多音字或取不出拼音时，
     编辑器会**自动回落「前缀 + 序号」并在下方说明**，不会报错。
   - 生成结果**直接填进输入框，可以自由修改**（不静默）。
   - ID **同模块 / 同命名空间内必须唯一**：重复或格式非法会**即时标红**，创建会被拦下。
   - 已经存在的条目的 ID **不会被自动生成改动**。
3. 如果这个模块在内容包里配了**条目预设（模板）**，ID 输入框上方会出现「条目预设」下拉：
   - 选一个预设 → **只显示它关心的字段**（初始值按预设填好）；其余字段收进下方的
     **「其他字段」折叠区，仍可编辑**（只是默认收起，不会被删掉）。
   - 不选预设（保持默认项）→ 与以前一样显示全部字段。
4. 补好字段后点 **创建条目**；不想建了点 **放弃并关闭**。
5. 创建同样走「校验 → 备份 → 原子写 → 回读复核」；建错了可以**回退**撤销。

### 删除条目

1. 在第 2 栏选中要删的条目，点工具栏的 **删除条目**。
2. 会弹**二次确认**，写清楚：删哪个、不可撤销、可回退。
3. 如果**有别的条目引用了它**，确认框里会额外列出引用者（最多先显示 10 条），并说明
   「删除后这些引用会指向不存在的条目（**黄提示、不拦截**）」。
   - 默认**不会因为被引用就禁止删除**；引用者以黄提示列出，方便你自己判断。
4. 确认后执行删除，同样会先**自动备份**，所以删错了可以**回退**恢复。

## 六、检索

两套检索各管各的，互不干扰：

### 模块内过滤（第 2 栏上方「过滤当前模块」）

- 只在**当前模块**里按**名称或 ID** 过滤条目。
- 输入即时生效，纯本地过滤，不打扰服务器。
- 清空输入框即恢复完整列表。

### 全局检索（第 2 栏「全局检索（跨模块）」）

- 在**整个内容包**里按名称/ID 找，结果**按模块分组**列出。
- 点某条结果会**自动切到对应模块并选中该条目**，直接开始编辑。
- 有全局检索词时，中栏显示分组命中结果；清空后回到「当前模块」的普通列表语义。
- 换内容包后，全局检索结果会作废重来，避免拿旧包的结果跳错地方。

## 七、常见问题（FAQ）

**Q：黄色提示 / 红色提示到底什么区别？**
A：红色 = 必须改对才能保存（会拦）；黄色 = 只是提醒、可以保存。详见 §四·4 的表。

**Q：为什么「保存」按钮是灰的？**
A：通常是这几种：正在请求中；当前是 GM 只读身份；新建态下主表单的保存不适用（请用新建面板的「创建」）；
或者**你还没有改动**（没有改动就没有东西可保存）。

**Q：为什么「回退到上一份备份」是灰的？**
A：当前模块还没有备份（还没保存/删除/新建过），或身份是只读，或正在请求中。先保存一次就会生成备份。

**Q：我改了很多字段，只保存了部分？**
A：编辑器只提交你**实际改过**的字段，没碰过的内容不动。顶栏的「未保存改动 N 项」是当前草稿里改过的数量。

**Q：字段上写着「元数据未登记」，是坏了吗？**
A：不是。表示这个内容包还没给该字段写类型/中文名等元数据；编辑器按实际值的类型兜底显示，仍可编辑保存。

**Q：引用框显示黄色，能保存吗？**
A：能。黄色表示「引用的目标找不到」，保存会成功但那条引用是空的；建议先把目标条目补上再保存。

**Q：删条目时提示「有 N 个条目引用了它」，为什么不拦住我？**
A：按设计，被引用**默认不拦**，只把引用者列出来（黄提示），由你决定是否继续。删完后悔可以「回退」。

**Q：中栏说「26 条」，左栏模块却显示「104（含子项）」，对不上？**
A：对得上。左栏对**含子模块**的模块显示的是「本模块 + 子模块」的合计，悬停可看明细；中栏是该模块自己的条数。

**Q：一次能撤销多少步？**
A：只有**一步**：回到最近一次写入（保存/删除/新建）之前。做重大改动前先保存一次，会让这一步更保险。

**Q：界面是只读的，改不了？**
A：顶栏「身份」切到 **机主 · 可编辑**。如果切了还是不行，确认启动时没有用 `--role gm`。

**Q：换内容包会丢东西吗？**
A：不会。换包只是换显示，正在编辑的未保存改动会被守卫拦下并提醒；需要保存的请先保存再换。

**Q：怎么把我的内容包发给别人？**
A：顶栏点 **📦 导出/导入 → 导出此包**，会下载一个 `.ttrpack` 文件，把它用 QQ / 网盘发出去即可。
导出只是读取、不改内容包；GM 只读身份也能导出。详见 §九。

**Q：别人发来的 `.ttrpack` 怎么用？**
A：顶栏 **📦 导出/导入 → 导入包**，选那个文件再点「导入包」。检查通过后它会作为一个**新内容包**出现。
同名时编辑器会问你是「换个名字导入」还是「覆盖现有包」（覆盖前自动备份原包）。详见 §九·3。

**Q：导入会不会把我的包弄坏？**
A：不会。导入是**新建一个包**；任何一步检查不过都**不写入任何文件**，也不会留下半个包。
只有你明确选择「覆盖」时才会替换原包，而且替换前会自动备份到 `.ttrpack_backups/` 下。

## 九、分享内容包（导出 / 导入）

**一句话**：导出 = 把你的内容包打成一个文件发给别人；导入 = 收到别人的文件后装进自己的编辑器。

### 1. 怎么把包发给别人（导出）

1. 顶栏点 **📦 导出/导入**（在 ⚙ 模块 右边）。
2. 在「导出此包」一栏确认当前包的名称，点 **导出此包（下载 .ttrpack）**。
3. 浏览器会下载一个文件，名字形如 `你的包名-20260914.ttrpack`。把它通过 QQ / 网盘发给对方就行。

说明：

- 导出的是**整个内容包**（所有数据文件 + `manifest.json` + 展示元数据 + 说明文档），不是当前这一条。
- 导出只是**读取**，不会改动你的内容包；**GM 只读身份也可以导出**。
- 文件里附了一份「导出信息」（`export_meta.json`），记录了包名、版本、TTR 版本或提交号、导出时间，
  以及每个文件的校验值（sha256）；对方导入时用它核对文件有没有损坏或被改动。

### 2. 收到别人发的文件，怎么装进来（导入）

1. 先把 `.ttrpack` 下载到自己电脑（QQ / 网盘点下载）。
2. 顶栏点 **📦 导出/导入** → 「导入包」一栏点文件选择框，选中那个 `.ttrpack` → 点 **导入包**。
3. 编辑器会依次检查：文件是不是压缩包、里面有没有可疑路径或不该有的文件、大小是否正常、
   导出信息与文件清单是否对得上、内容能不能过校验器。
4. 全部通过后，这个包会作为**一个新内容包**出现；编辑器会自动切到它（也可以在顶栏 `pkg=` 里选）。

> 导入是**新建一个包**，不会动你已有的包。任何一步没通过都会**明确告诉你原因，并且什么都不写入**
> （不会留下半个包）。导入**必须用可编辑身份**；GM 只读预览下「导入包」是灰的（导出不受影响）。

### 3. 包名撞车了怎么办（冲突）

如果你导入的包名（`pkg=`）和已有的包一样，编辑器会给出三个选择：

| 选择 | 会发生什么 | 什么时候用 |
|---|---|---|
| **换个名字导入** | 新包用你起的另一个名字装进来，原包一个字节都不动 | 想两个版本都留着对比 |
| **覆盖现有包** | 用新包替换旧包；**替换前旧包会自动备份**到内容目录的 `.ttrpack_backups/` 下 | 确认新包就是要替代旧包 |
| **取消** | 什么都不做 | 只是想看看 |

> 「覆盖」的备份是**手动找回**的：内容目录下 `.ttrpack_backups/<包名>/<时间戳>/` 就是被替换掉的旧包，
> 需要时把那个目录整体复制回 `content/<包名>` 即可。

### 4. 出错了怎么看

导入失败的提示分两部分：「**失败：…**」（发生了什么）和「**怎么处理：…**」（下一步该怎么办）。常见情况：

- **「这不是一个有效的压缩包」**：文件没下载完整，或对方发的不是 `.ttrpack` / `.zip`。
  让对方重新导出、你重新下载。
- **「压缩包里缺少 export_meta.json」**：这不是编辑器导出的内容包（例如是随手压的普通文件夹）。
  请对方用编辑器「导出此包」重新发。
- **「想越出目标目录 / 是符号链接 / 出现不允许的文件」**：文件可疑（可能藏了危险路径或脚本），
  编辑器已拒绝。请对方确认来源后重新导出。
- **「超过体积上限 / 解压后总大小超过上限」**：包太大或文件异常。请对方精简内容，或联系技术同学调高上限。
- **「校验不一致：文件…与导出时不同」**：文件在传输中被改过或损坏。让**对方重新导出**再发一次。
- **「内容校验未通过（红拦）：本次未写入任何文件」**：包里的内容本身有错（例如引用了不存在的条目）。
  请对方在原包里改好、重新导出；你这边什么都没有被写入。
- **「已经存在同名内容包」**：就是上面的「冲突」，按 §九·3 选择改名或覆盖。
- **只读身份点不动「导入包」**：GM 只读预览不能导入；把顶栏「身份」切到 **机主 · 可编辑** 再试。

### 5. 命令行（给技术同学 / 服务器批量用）

不想开网页、或者要在服务器上批量搬运时，可以用同一个实现：

```bash
# 导出（--file 省略时写到当前目录，文件名含包名与日期）
python scripts/pack_transfer.py export --pack 包名 --file /tmp/分享包.ttrpack

# 导入（同名冲突：--rename 换名字 / --overwrite 覆盖且先自动备份）
python scripts/pack_transfer.py import --file /tmp/分享包.ttrpack
python scripts/pack_transfer.py import --file /tmp/分享包.ttrpack --rename 新包名
python scripts/pack_transfer.py import --file /tmp/分享包.ttrpack --overwrite
```

`--content-root 目录` 可指定内容目录（缺省仓库的 `content/`）；加 `--json` 输出机器可读结果。
退出码 `0` = 成功，`1` = 失败（人话原因与处理办法打在屏幕上）。

## 八、把文件放在哪（想手动核对时看）

- 每个内容包一个目录：`content/<包名>/`，入口是 `manifest.json`（声明这个包有哪些模块）。
- 每个模块一个文件：`content/<包名>/<模块名>.json`。
- 每次保存/删除/新建会在**同目录**生成/覆盖备份：`content/<包名>/<模块名>.json.bak`。
- 界面里的模块名、字段中文名、分组、候选值都来自内容包的声明；编辑器本身不针对某个包定制。

> 如果你要确认「编辑器有没有偷偷改别的文件」：它只在保存/删除/新建时动**当前模块的那一个 `.json`** 和它的 `.bak`，
> 不要用编辑器以外的方式在它运行时同时改同一个文件。

## 十、数据包作者：可选声明（预设 / ID 前缀 / 使用处覆盖）

> 这一节是给**写内容包的人**看的（改的是 `content/<包名>/field_meta.json` 与数据文件，不是编辑器代码）。
> 这些声明都是**可选**的：不写 → 编辑器与引擎完全按以前的行为工作（框架自带的六种通用预设除外，见下）。

### 1. 框架自带的六种通用预设（批17 起；批18 细化；任何包都有）

编辑器框架自带六种**物品通用预设**，**空白包打开新建界面也有**：

| 预设 id | 界面名 | 主区字段（顺序即表单顺序） | 初始值（节选） | 建议 ID 前缀 |
|---|---|---|---|---|
| `material` | 材料 | name,type,desc,rarity,material_tier,source,price | `type=material` | `mat` |
| `currency_pouch` | 货币袋 | name,type,desc,usable,effects | `type=currency`、`usable=true`、`effects=[]` | `pouch` |
| `potion` | 药剂 | name,type,desc,usable,effects,price | `type=consumable`、`usable=true`、`effects=[]` | `potion` |
| `gift_box` | 礼包 | name,type,desc,usable,effects | `type=gift_box`、`usable=true`、`effects=[]` | `gift` |
| `equipment` | 装备 | name,type,desc,slot,price,dfn,atk,hp,mp,str,con,spr,lck,spd,mag,agi,atk_pct,dfn_pct,hp_pct,crit | `type=equipment` | `eq` |
| `skill_book` | 技能书 | name,type,desc,usable,effects,price | `type=skill_book`、`usable=true`、`effects=[]` | `book` |

- 预设**只收窄显示面**：主区只放「关心字段」，其余字段收进「其他字段」折叠区——**仍可编辑**，
  不会永久隐藏（一号原则）；不选预设 = 与以前一样显示全部字段。
- `type` 用通用英文品类值；`material` / `consumable` 与现有内容包的取值习惯一致
  （`currency` / `skill_book` 也在引擎类型词表内；`equipment` / `gift_box` 是通用品类词，
  引擎背包筛选暂未收录，会归到「其他」，不影响数据与校验）。
- 生效预设 = **框架默认 ∪ 包声明**；包可以**覆盖同 id、追加新预设、关闭某个默认**（见下一条）。
- **批18 细化**：装备预设主区补齐全部属性白值（`hp,mp,str,con,spr,lck,spd,mag`，连同原有
  `agi`），顺序为「标识/部位 → 攻防 → 属性白值 → 百分比/会心」；药剂预设明确**持续回合写在
  被引用的效果条目上**（效果的「持续」/`turns` 字段），物品条目不设持续字段；货币袋 / 技能书
  预设说明「开出的内容走效果列表」，分别需要 `gain_currency`（给货币）与 `learn_skill`（学技能）
  效果类型（效果类型在新建效果条目时下拉可选）。
- 生成建议 ID 时，前缀顺序是：**预设 `id_prefix` > 包 `field_meta.json.id_prefix[模块]` >
  框架元数据 > 模块名**；例如按「材料」新建、名称为空时给出 `mat_001`。

### 2. 自定义 / 覆盖 / 追加 / 关闭预设——`entry_presets` / `entry_presets_disable`

想让「新建材料」只显示名字和说明、不把威力/冷却等干扰项摆在眼前，就在包内 `field_meta.json`
里声明 `entry_presets`（顶层键，按**模块名**分组）：

```json
{
  "schema_version": 1,
  "entry_presets": {
    "items": [
      {
        "id": "material",
        "label": "材料",
        "help": "材料只需要名字和说明；类型固定为 material。",
        "fields": ["name", "desc"],
        "defaults": {"type": "material"},
        "id_prefix": "material",
        "id_width": 3
      }
    ]
  }
}
```

- `id` / `label`：预设的机器名 / 界面显示名（必填，同模块内 `id` 不能重复）。
- `help`：在预设下拉下方显示的一句话说明（可选）。
- `fields`：这个预设**关心的字段键**（必填、非空）。新建时只把这些字段放主区，
  其余字段自动收进「**其他字段**」折叠区——**仍然可编辑**，不会永久隐藏。
- `defaults`：新建时的初始值（可选；叠加在字段元数据的默认值之上）。
- `id_prefix` / `id_width`：这个预设下建议 ID 的前缀与零填充宽度（可选；见下一条）。

任何模块都能配预设；没配的模块 → 用框架默认（若该模块有，如 `items`）或与以前一样。

**覆盖 / 追加 / 关闭**（生效预设 = 框架默认 ∪ 包声明）：

- **覆盖**：声明与框架默认**同 id** 的预设 → **整体**以包声明为准（不是字段级合并，避免歧义）；
- **追加**：声明框架没有的 id → 追加到框架默认之后；
- **关闭**框架某个默认（或关闭包自己的预设）：在 `field_meta.json` 顶层加
  `entry_presets_disable`（按模块分组，列出要关闭的预设 id）：

```json
{
  "schema_version": 1,
  "entry_presets_disable": {"items": ["gift_box"]}
}
```

关闭后该预设从下拉里消失；关闭一个不存在的 id = 无害空操作。

### 3. ID 前缀与序号宽度——`id_prefix` / `id_width`

默认建议 ID 是 `<前缀>_<序号>`（如 `material_001`，序号取现有同前缀最大序号 +1，零填充 3 位）。
前缀的取值顺序是：**预设 `id_prefix` > 包 `field_meta.json.id_prefix[模块]` >
框架元数据 > 模块名**。想固定某个模块的前缀/宽度，在包内声明：

```json
{
  "schema_version": 1,
  "id_prefix": {"items": "material"},
  "id_width": {"items": 3}
}
```

`id_width` 取 1~12 的整数（缺省 3）。生成结果会直接填进输入框，作者可以手改。

### 4. 行动概率/权重在使用处覆盖（怪物 AI 行动表）

行动定义（`action.json`）里的 `probability` / `weight` 是**默认值**；**引用处**（例如
怪物行动表 `enemies.json` 的 `actions[]`）写了同名字段就**以引用处为准**。取值顺序：

> **使用处 > 定义处 > 缺省**（两处都不写 = 与以前一致：`probability` 默认 0 不入池、`weight` 默认 1.0）

最小示例（同一只怪物在不同行动上微调概率/权重，不必去改 `action.json`）：

```json
{
  "id": "some_monster",
  "name": "某怪物",
  "actions": [
    { "action": "bb_slam",       "probability": 1, "weight": 40 },
    { "action": "bb_tail_sweep", "probability": 1, "weight": 20 },
    { "action": "bb_roar" }
  ]
}
```

上面第三条 `bb_roar` **没写** `probability`/`weight` → 用 `action.json` 里 `bb_roar`
的定义处默认值；前两条写了 → 用行动表里的值。编辑器里，定义处的概率/权重说明卡会标注
「**默认值（可被引用处覆盖）**」，使用处则提示「留空 = 用行动定义处的默认值」。

> 印记（`marks.json`）当前**没有**概率类字段，所以印记侧不需要改；将来若新增，请按同一
> 「使用处 > 定义处」口径实现。

### 5. 效果类型：给货币 / 学技能（批18）

框架自带两个**通用效果类型**，作者在 `effects.json` 里新建效果条目时，**「类型」是下拉**
（候选含全部常见效果类型），选到即可；物品 `effects` 只填引用 id。

| `type` | 用途 | 字段 | 说明 |
|---|---|---|---|
| `gain_currency` | 使用物品时**给货币** | `currency`（引用货币表 `settings.currencies[].id`）、`amount_min`、`amount_max` | 在 `[amount_min, amount_max]` 内随机；`amount_min == amount_max`（或只写 `amount_min`）＝固定金额 |
| `learn_skill` | 使用物品时**学技能** | `skill`（引用 `skills.json`）、`level`（≥1，可留空 = 1 级） | 已学会 → 幂等，不重复授予、不改既有等级 |

示例（货币袋 + 技能书各一条效果）：

```json
[
  { "id": "open_coins", "name": "开出金币", "type": "gain_currency",
    "currency": "coins", "amount_min": 100, "amount_max": 300 },
  { "id": "learn_power_strike", "name": "领悟强击", "type": "learn_skill",
    "skill": "power_strike", "level": 3 }
]
```

要点：

- **持续回合属于效果**：药剂等物品的持续回合写在**被引用的效果条目**上（效果的「持续」/
  `turns` 字段），物品条目本身**不设**持续字段（避免两个来源）。
- 边界（保存时会红拦）：`gain_currency` 必须给 `currency`，且 `amount_min`/`amount_max`
  至少写一个；`amount_min > amount_max`、金额为负、`currency` 不在货币表里、`learn_skill`
  缺 `skill` 或 `level < 1` 都会拦下。引用目标（货币 / 技能）缺失同样拦下。
- 随机取金额用的是引擎既有随机源（卡池/掉落同一套，可复现），不是另开一套。

### 6. 让某模块的条目「并进」另一个模块显示（批20 · `entry_merge_filtered`）

场景：装备本来就是物品的一种——`items.json` 里有 `slot` 的那些条目其实就是装备，但装备页
只显示 `equipment.json` 里的条目。声明下面这段，装备页就会**同时列出**这些物品条目（界面标
「来自 物品」），点开编辑仍然**写回 `items.json`**：

```json
"entry_merge_filtered": [
  { "target": "equipment", "from": "items", "where": { "has": ["slot"] } }
]
```

- `where` 支持「有某键」（`has`）与「某键等于某值」（`eq: {"type": "weapon"}`），两者可一起写
  （都要满足）；省略 `where` = 全部并入。——**无条件并入请用 `entry_merge`**（整模块并入）。
- 只增不减：来源模块（物品页）的条目、计数、检索**完全不变**；目标模块计数**含**并入条目
  （装备页实测 9 + 128 = 137 条）。

### 7. 长列表按分组折叠（批20 · `entry_groups`）

「效果 76 条 / 行动 78 条」这类长列表可以按某个字段（或 ID 前缀）折成可折叠小节：
**首节默认展开，其余收起**，点小节头展开。例如按效果类型分组：

```json
"entry_groups": {
  "effects": { "by": "field", "field": "type",
               "labels": { "mark_add": "施加印记", "heal": "治疗" } }
}
```

- `by`：`field`（按该字段的取值，如 `type`）或 `id_prefix`（按 ID 第一个下划线前缀）。
- `labels` 里**键的先后顺序**就是小节顺序；不写 `labels` 时按条目数从多到少排。
- `other_label`（缺省「其他」）给取不到值的条目；`collapsed: false` 让小节点默认也展开。
- 不声明 `entry_groups` 的模块 = 现状（一条平铺列表）。

右栏的「二级页签」（同一个大分组里的字段再分页）由**框架元数据**的子分组驱动，作者可用
`subgroup_labels` 覆盖显示名：

```json
"subgroup_labels": { "npc": { "base": "标识与类型" } }
```


### 8. 改 ID 会被拦一下（批21 · 引用检查）

**ID 是内容之间互相引用的名字**：把一条已经被引用的条目改 ID（改标识），会让所有引用它的
地方「断链」。编辑器现在会在保存前**扫一遍谁引用了它**：

- 有引用 → 弹窗列出引用方（最多 10 条 + 总数），写明「改名会断链」；点**取消**则一个字节都不写；
- 点**确定**才保存；引用方**不会被自动改写**（保持旧名），保存后校验会如实报
  「这里指向的『旧名』在内容里找不到」——这不是编辑器坏了，是提醒你去改引用方；
- 没有任何引用时，改 ID 与以前完全一样（不弹窗）。

删除条目同样会先列出引用者（前若干条 + 总数 + 「删除后这些引用会失效」），确认后才删。

### 9. 写盘后会自动回读（批21 · 防坏数据）

保存 / 新建 / 模块启停 / 导入 `.ttrpack` 时，编辑器在写盘后会**重新读取刚写的文件**并与
「应该写入的内容」逐字比对：文件被截断、半写或内容对不上 → **明确报错并自动回退到上一份
备份**（绝不假装成功）。这一步只读刚写的那个模块，不整包重载，正常保存几乎无感。

### 10. 覆盖 / 追加 / 关闭「推荐组合」（批65 · `module_presets` / `module_presets_disable`）

「推荐组合」默认由**框架**提供（一批常用模块的中文名 + 一句话说明 + 模块键清单）。内容包可以
在 `manifest.json` 里声明自己的组合，规则是**框架默认 ∪ 包声明**：

```json
{
  "module_presets": [
    { "id": "basic_rpg", "label": "本包基础", "help": "本包的一句话说清。",
      "audience": "面向谁", "modules": ["items", "skills"] },
    { "id": "my_loop", "label": "我的玩法闭环", "help": "……", "audience": "……",
      "modules": ["skills", "maps"] }
  ],
  "module_presets_disable": ["life_adventure"]
}
```

- **同 `id` → 包声明整体覆盖框架默认**（不是逐字段合并），位置仍在框架默认的位置；
- **新 `id` → 追加**到框架默认之后（保持包声明顺序）；
- **`module_presets_disable` → 关闭**列出的组合（写不存在的 `id` 是无害空操作）；
- **包没声明 → 框架默认组合照旧全部显示**（一号原则：不因包没声明而消失）。

组合里的 `modules` 只列**这个组合想表达的能力**；应用时引擎会按框架模块目录的 `requires`
**自动补全前置依赖**，所以不必也不该手写全依赖链。`modules` 里的模块键必须是框架已登记
（或本包 `manifest.modules` 已声明）的键——写错会在应用时以**黄提示**如实列出并跳过，不会
静默启用一个空模块名。

## 十一、批量录数据：模块级 CSV 导入 / 导出（批34）

> 依据：框架设计文档 §6.7（CSV 批量导入导出）/ §6.11（编码自动检测）/
> §6.12-05（导入顺序与验证）/ §6.12-20（CSV 双向防公式注入）。
> 定位：**进阶通道**，与卡片表单并存、数据互通；不写死任何内容包的模块名或字段名。

**一句话**：把当前模块导出成一张表，用 Excel / WPS 拉表填数，再导回来。
导出是**只读**的（不改内容包）；导入走和其它编辑一样的「校验 → 自动备份 → 原子写 → 回读复核」。

### 1. 导出（模块级）

1. 左栏选中一个模块 → 点模块标题下方的 **导出 CSV**。
2. 浏览器下载 `<包名>-<模块名>.csv`。

导出规则：

- **列头 = 该模块框架元数据的字段**，形如 `中文名(键)`（没有中文名 / 是键列时只写键）。
  「一号原则」：框架登记过的字段**都出列**，哪怕这个包里一条都没配（值为空格）。
- **一行 = 一条条目**，行序与内容包里的条目顺序一致（映射型模块按键的先后）。
- **列表 / 对象型字段**（如标签数组、属性对象）用 **JSON 文本**填写，例如 `["a","b"]`、`{"w":1,"h":2}`；
  这是**可逆**编码（导入时按列类型解析回原结构）。
- 包数据里出现、但框架元数据没登记的键，会被追加成 `*键名` 列（值固定按 JSON 文本处理），保证往返不丢字段。
- **编码固定 UTF-8 带 BOM**，行尾统一 `\n`：Excel / WPS 双击打开不乱码。
- **公式注入防护**：文本单元格以 `=` `+` `-` `@` 开头时，导出会**前置一个 `'`**（例如 `=cmd|...` 变成 `'=cmd|...`），
  这样用 Excel 打开不会被当公式执行；这是 CSV 边界的编码，导回来会**还原成原文**，内容包里不会多出 `'`。

### 2. 导入（模块级）

1. 左栏选中模块 → 点 **导入 CSV** → 选择文件 → 选「行序」「同 id 已存在怎么办」→ 点**导入**。
2. 结果区给人话摘要：**成功 N 条 / 跳过 M 条 / 失败 K 条（共 T 行）**，逐行列出失败原因与跳过明细。

导入规则：

- **编码自动识别**（§6.11）：UTF-8（含 BOM）与 GBK 都能直接导，不必手动转码；都认不出会明确报错。
- **保持 CSV 行序**：
  · 「追加到末尾」（默认）→ 新条目按 CSV 里的先后追加；
  · 「插入到指定位置」→ 新条目作为一个整体插到「位置 N」（位置从 0 开始，即第 N 条之前）。
- **逐行引用校验**：引用型字段（如「效果」「掉落物品」「地图」等）指向的目标必须已存在
  （包内其它条目，或这批 CSV 自己新增的条目）。有缺失 → **逐行报错**（第几行、哪个字段、期望哪个 id），
  **默认整批拒绝**：一个字节都不写，**也不会生成备份**。
- **冲突策略**：
  · 同 id 已存在 → **默认「跳过」**，并在报告里列出（**绝不静默覆盖**）；
  · 只有明确选「覆盖」时，才会**原地替换**该条目（位置不变）。
- **导入前自动备份**：真正写盘前会把当前模块复制成 `<模块名>.json.bak`（可用工具栏「回退到上一份备份」恢复）；
  整批被拒时不会产生备份。
- **公式注入防护**：如果 CSV 里的文本单元格是**裸的危险文本**（以 `=` `+` `-` `@` 开头、不是我们自己导出的），
  导入时会先**中和**（前置 `'`）再写入内容包。
- 结果区报错给出「第几行 + 第几个字段 + 期望目标」，例如
  「第 3 行：字段『效果』引用了不存在的 effect：『e_missing』」。

### 3. 单元格编码速查（可逆）

| 内容 | 单元格写法 |
|---|---|
| 字段没配置（键缺失） | 留空 |
| `null` | `\N` |
| 空字符串 `""` | `\E` |
| 列表 / 对象 / 映射 | JSON 文本（如 `["a","b"]`、`{"w":1,"h":2}`） |
| 布尔 | `true` / `false` |
| 整数 / 小数 | 直接写数字（如 `3`、`1.5`、`-2`） |
| 文本 | 原样写（前导 `\` 会被转义成 `\\`；危险前缀会被中和，见上） |

> 数字 / 布尔的负号不会被中和（`-2` 就是 -2）；只有**文本**单元格才做注入中和。

### 4. 本版不做 / 如实说明

- **单对象模块（如「通用设置」）暂不支持 CSV**：这类模块没有「每行一条条目」的概念，
  点导出会明确提示「不支持」，继续用表单编辑即可（这是本批如实登记的边界，不是静默失败）。
- **认不出的列会被忽略并给提示**：请用导出的 CSV 改数，不要自行新增列头；需要加字段要先在框架元数据里登记。
- 导出/导入**只作用于当前模块**；跨模块引用是否正确，由导入时的逐行引用校验兜底。

### 5. 接口（给技术同学）

- `GET /api/pack/{包}/module/{模块}/export_csv` → `text/csv`（UTF-8 带 BOM；只读，GM 也可用）。
- `POST /api/pack/{包}/module/{模块}/import_csv?mode=append|insert&position=N&on_conflict=skip|overwrite`
  → 请求体 = CSV 文件原始字节；返回 `{ok, summary:{success,skipped,failed,total}, errors, skipped, backup, message}`。
- 导入必须**可编辑身份**（GM 只读 → 403）。
