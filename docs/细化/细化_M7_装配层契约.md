> 版本：v1.0 · 类型：实现层细化契约（M7 A 系列 · 地基）
> 权威依据：细化_M7_交互补全总纲（A-01~A-05）+ 各指令壳 ctx 消费契约（docstring 实测）+ processing.py/router.py/sender.py/Repository 真实接口（read 核对 2026-08-28）
> 现状基线：六指令组（quest/shop/checkin/basic/battle/register+shortcut/status）register_xxx_commands 全部「批次6/7 装配待接线」（make_context=None → 【待接线】）；无 Router 构造点；无 NoneBot 入口；processing.py 幂等入口已实装待驱动。
> 编号规则：任务 A-xx；规则 RA-xx；验收用例 TCA-xx

## 〇、一句话契约

> 装配层 = 把 M4-M6 已实装的引擎 + 指令壳 + 路由基建串成**可运行的完整入口**：单一 make_context 工厂（事件+存储+世界 → 完整玩家 ctx）→ Router 构造与全指令注册 → processing 幂等入口驱动 + 发送出口 → NoneBot 桥接层（内核零 NoneBot）→ world 装配（GameWorld/会话/续战/热重载）。纯装配零引擎改动。

## 一、A-01 make_context 工厂（装配层核心）

### 1.1 工厂形态（RA-01）
- 模块：`qbot_rpg/assembly/context.py`（新，装配层独立目录，依赖矩阵：assembly → core/world/storage/content/data，不得被 core 反向依赖）。
- 签名：`make_context(event: Mapping, deps: AssemblyDeps) -> dict`——event={group_id, user_id, message, channel}；deps=装配依赖容器（见 1.2）。
- 纯函数纪律：make_context 只**组装**（读）不写业务；写操作由各引擎在事务内完成；确定性（rng/now 注入）。

### 1.2 AssemblyDeps 依赖容器（RA-02）
| 依赖 | 类型 | 来源 |
|---|---|---|
| repo | Repository | storage（DB 连接/事务/玩家读写） |
| game_world | GameWorld | world（registry 注入装载 + world_state） |
| registry | content registry | loader 装载（含 hot_reload 世代） |
| settings | Mapping | settings.json 装载 |
| queue | PerPlayerQueue | processing（per-player 串行） |
| session_mgr | SessionManager | world/session（战斗/对话会话） |
| rng_factory | Callable | 确定性 RNG（seed 工厂） |
| dayroll | Callable | 今日键（refresh_time 对齐） |
| time_query / weather_query | Callable | 环境快照（season/period/weather） |

### 1.4 事务写路径（RA-04）
- 指令处理器 handler(tx) 契约（processing 已定）：`handler(tx) -> {ok, message, ...}`——tx 内读玩家/校验/扣减/写回（tx.upsert_player）+ 同事务 write_idem_key。
- make_context 提供**读快照**（事务外）；事务内由 handler 经 tx 重新读权威值（幂等三件套 D2 语义）。

## 三、A-03 processing 驱动与发送出口

### 3.1 processing 驱动（RA-08）
- `qbot_rpg/assembly/runner.py`（新）：`async run_command(event, deps) -> str`——完整链路：
  ① route_and_expand（3c：快捷→别名→白名单→忽略；会话路由 dialog_active）→ ParsedCommand
  ② make_context(event, deps) → ctx
  ③ handler = 指令组 handler（闭包捕获 ctx + tx 业务写）——各指令组 register 已绑定
  ④ process_message(repo, queue, message_id, group_id, player_qid, command, handler, sender)（真实签名，read 核对）
  ⑤ sender 闭包：apply_message_prefix（M5 prefix_wiring）→ Sender.send（CQ 转义/分片/重试）
- 幂等键三元组：message_id（触发消息）/ group_id（缺失 "dm" 哨兵）/ player_qid。

### 3.2 发送出口（RA-09）
- Sender（真实 API：cq_escape/segment_by_length/Sender.send）——传输层；前缀注入在调用 sender.send 前（prefix_wiring 注释已明示由装配层调用）。
- 分片：segment_by_length 4000 字上限（QQ 平台 MAX_MESSAGE_LENGTH）——长回复多段发送。
- 前缀：apply_message_prefix（settings message_prefix 7 字段）——玩家回复首行注入；系统消息豁免。

### 3.3 清理调度（RA-10 · 收口 D2 IDEM-7/POOL-4）
- cleanup_idem_keys 调度（7 天窗口清理，D2 IDEM-7）：runner 启动时注册（定时器/懒清理，零 apscheduler——对齐 WIR-04 schedule_polling 模式）。
- PerPlayerQueue 超时（D2 POOL-4，**processing 无此能力，装配层新增模块**）：消费者挂起超时（wait_for）→ 丢弃/重试/幂等键兜底，验收断言（ADR-08）。

## 四、A-04 NoneBot 插件入口（可选适配层）

### 4.1 桥接层（RA-11 · 零 NoneBot 内核）
- 独立目录 `qbot_rpg_bridge/`（不在 qbot_rpg 包内，**内核零 NoneBot import 铁律**，G0 门禁）。
- 结构：`bridge/nonebot_plugin.py`（on_message 事件）→ 事件字段映射（group_id/user_id/message/channel）→ `assembly.run_command` → 发送回 QQ。
- 会话路由：NoneBot 消息 → route_and_expand（含 dialog_active 会话路由）→ 分发。
- 无 NoneBot 环境：CLI/测试走 `assembly.run_command` 纯函数驱动（装配冒烟脚本）——平台无关。

### 4.2 启动装配（RA-12）
- `assembly/bootstrap.py`（新）：`bootstrap(deps) -> AssembledApp`——loader 装载（红拦校验）→ registry 快照 → GameWorld.load(world_state) → SessionManager → Router 构造注册 → queue/repo 接线 → watcher 调度（热重载 WIR，M6 已建）→ run_command 就绪。
- 启动冒烟：注册自检 + 白名单一致 + 关键指令 handler 可调（TCA-03）。
