## 二、数据模型草案

> 原则：**孔位/镶嵌执行复用 `core/jewel.py`**（H1 共享基础设施，`docs/深度打造_决策记录.md:13`）；**符文效果另立解析层**；**镶嵌状态与 `uid` 绑定落档**。以下「形状」是可开工口径，命名可再定，但**语义与落点建议冻结**。

### 2.1 符文定义（内容包数据）

**建议落点**（二选一，推荐 A）：
- **A（推荐）· 独立内容模块 `runes.json`**：与 `recipe.json`/`traits.json` 同级的 list 模块；一个条目 = 一个符文定义。理由：符文定义含「跨装备类型差异表」，塞进 `items.json` 会污染物品表；独立模块便于编辑器按「符文」页签呈现、便于校验器专项。
- B · `settings.runes` 段（obj）：与 `settings.forge` 同风格，省一个模块登记。理由：若希望「深度层配置集中」。

**建议形状（草案）**：

```
runes.json 条目（list 元素）
{
  "id": "rune_blade_burn",            // 必填、非空、全局唯一（同 items.id 命名空间独立）
  "name": "灼刃符文",
  "tier": 1,    // 必填、enum {1,2,3}（R3 独立刻度，禁与 quality 混）
  "family": "burn",                   // 必填、非空：同族判定（3 合 1 的输入族，R5）
  "icon": "…",    // 可选，展示
  "desc": "…",
  // ---- R2：同符文在不同装备类型的效果差异表 ----
  "by_equip_type": {
     "default":  { "stats": {"atk": 6} },                 // 兜底（必须存在）
     "weapon":   { "stats": {"atk": 9} },                 // 键 = items.type 或 slot（Q5 裁决）
     "armor_body": { "stats": {"dfn": 8} }
  },
  // ---- R4：1 阶纯数值（stats 走 gear_stats 键空间，禁自造键）----
  // ---- R6：2 阶特殊效果（引用 effects 注册表）----
  "effects": [ { "effect": "rune_grievous_wound", "overrides": {"value": 20} } ],
  // ---- R7：3 阶偏向性（形状待 Q7 裁决后补）----
  "bias": null
}
```

**校验点（建议进 `content/validator.py` 或 `alchemy_settings` 同风格专项）**：
1. `tier` ∈ {1,2,3}，红拦（R3）。
2. `tier==1` → 必须有 `by_equip_type[*].stats` 且键集必须属于 `GEAR_NUMERIC_KEYS`（`data/gear_stats.py`），红拦自造键（R4）。
3. `tier>=2` → `effects` 引用存在（effects 注册表），红拦悬空引用（R6）。
4. `by_equip_type` 必须含 `default`；其余键必须是合法 `items.type`/`slot` 值（Q5 定后启用），未知键黄提示（对齐 slots 模块引用检查的宽严口径）。
5. `tier==3` 且 `bias` 非空时按 Q7 结论校验。
6. `family` 相同的符文才允许互为 3 合 1 输入（R5）。

### 2.2 孔位与镶嵌状态（复用 / 扩展 / 替代 —— 给建议与理由）

**（a）孔位定义：复用 `slots.json`（J-1），扩「全局默认」。**
- 复用理由：`core/jewel.py:331-342` 已把 `ctx["slot_defs"][equip_id]` 定义为孔位来源；`slot_level` 1-3 与校验已就绪（`content/alchemy_settings.py:594`）；决策记录 H1 把「孔位镶嵌」列为共享基础设施。
- **扩展点**：现状是「逐件登记」，原案要「所有装备固定三孔」。建议在 `settings` 增加孔位缺省段（命名待定，如 `settings.rune_sockets.default_count=3`），**「未登记 → 用默认 3 孔」**；已登记 → 用登记值（向后兼容）。这样 `content/veinborn/slots.json` 保持 0 条也能三孔。
- **不建议替代**：另造一套孔位表会与 `jewel.py` 双轨，违反 H1，且 module_catalog 已就 `slots.json` 与 `settings.slot_defs` 的重复给黄提示（`qbot_rpg/content/module_catalog.py:87-100`）——再增第三套会使「归口」问题恶化。

**（b）镶嵌状态：新增 `persistent_state` 容器，键 = `ItemInstance.uid`（推荐）。**
- **落点**：`player.persistent_state["rune_sockets"] = { "<item_uid>": [ "<rune_id>"|null, "<rune_id>"|null, "<rune_id>"|null ] }`（变长数组 = 该件孔数；`null`=空孔）。
- **为什么不用 `ItemInstance` 字段**：`ItemInstance` 是 `frozen=True`（`data/item.py:39`），镶嵌要 `dataclasses.replace` 换行；且 `_item_from_dict`（`storage/repository.py:185-208`）需逐字段补读。可行，但改面大。
- **为什么不用 `EquipmentSlot`**：**已知潜伏缺陷** —— 卸装/后装覆盖会丢弃 `EquipmentSlot` 的 `slot_level/locked/gems`（`core/equipment.py:47-49`）；若符文状态挂这里，必然复现「卸下再穿 → 符文丢失」。而 `uid` 是**背包实例身份**，卸装不改背包行，天然规避。
- **为什么这个容器形状**：与批 26 α 组的既有落点**完全同构** —— 装备来源技能容器就是 `player.persistent_state` + 装配层镜像 ctx（`core/equip_mods.py:33-35,213-241`）。复用同一模式，装配层 `assembly/context.py` 只需多镜像一键。
- **孤儿登记**：装备被分解/出售后 `rune_sockets[uid]` 会留孤儿 → 需在分解/出售/丢弃入口清理（登记为待办；Q9 决定是否接受孤儿或改用 ItemInstance 字段）。

**（c）镶嵌执行：复用 `JewelSystem` 的 mount/unmount 语义，新增符文专用入口。**
- 复用：战斗内禁插拔（`core/jewel.py:319-325,507-515`）、一槽一物（`core/jewel.py:586-595`）、无损拆珠（`core/jewel.py:635-717`）、投放/返还 hook（`core/jewel.py:437-456`）都是通用骨架。
- **必须绕开**：`slot_accepts` 的「槽级≥珠档」门票（`core/jewel.py:199-217`）是**装饰珠规则**（SOCK-02），**不适用于符文三阶**（符文无「槽级」概念）。符文 mount 走独立校验（Q4 定门槛），但共用槽位读写。
- **激活读取**：符文效果消费方**一律经 `JewelSystem.active_sockets()`**（`core/jewel.py:363-373`）——副手失活自动继承（R10/R11），零额外分支。

### 2.3 三合一规则（R5/R8）

- **执行器形状可复用**（`core/upgrade.py:636-700`）：1 输入条目 × count≥3、产出 +1 阶、禁跳级、原子提交、跨进程事务由指令壳包裹。
- **必须新增**：符文档位解析器 —— 既有 `_jewel_tier_of` 读 `item.quality`/`item.tier` 并经 `QualitySystem.index_to_tier`（4 档）（`core/upgrade.py:702-716`），**与符文三阶不兼容**。建议新增同形状的 `_rune_tier_of`（读 `tier:1..3`），或给 recipe 条目加显式 `rune_tier` 字段（对齐既有 `jewel_tier` 显式标注位 `upgrade.py:713-715`）。
- **配方配置**：建议新增 `recipe.json kind=upgrade` 实例（每族 × 每阶一条），如 3×一阶同族 → 1×二阶；3×二阶同族 → 1×三阶（R8）。是否**同 id** 由 Q8 裁决。
