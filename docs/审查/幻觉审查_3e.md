### P1-1 红拦 R-3「非数字」归类与定稿 L153 口径偏差，且未写入 §0.3 ADR
- **位置**：§2.1 R-3 行（细化 L137）、TC-04（细化 L373）
- **声明**：「NaN/Infinity 属 R-1 或 R-3 均可，统一归 R-3」；TC-04 断言 `NaN / Infinity → R-3`
- **定稿原文**：L153 第 1 类=类型错误，明示例「数字填成文字 / **NaN** / null」——**NaN 在定稿中明确列为类型错误示例**，并被细化 R-1 定义自身同时引用（R-1 定义也含「NaN / null」）
- **问题**：①与定稿 L153 归类口径偏差（定稿把 NaN 归类型错误，细化统归 R-3）；②细化内部自相矛盾——R-1 定义含 NaN，R-3 又声称「统一归 R-3」；③按文档自身 §0.3 变更纪律「任何偏离【规则】之处必须写入 §0.3」，此归类决策未记录 ADR
- **影响**：TC-04/R-3 的 `kind` 取值与定稿 L153 冲突，影响 commands 层人话翻译分支；属可行动差异
- **建议**：整改为「NaN/null 按 L153 归 R-1 类型错误；Infinity 归 R-3 非数字」，或写入 §0.3 ADR 声明归类依据

### P1-2 stats.json 属性键非 snake_case 判为「结构错误红拦」：将命名规范升级为拦截规则，未写 ADR，有过度拦截风险
