## 一、设计哲学：任务系统 = 条件系统

```
- 任务类型不枚举（0 类）——type 只是编辑器模板/展示标签
- 判定 100% 由统一 conditions 数组驱动（3 种原语：值型/累计型/事件型）
- 条件全部基于统一条件引擎 {var,op,value,param}（NPC 定稿 4.0）——中文变量键经别名映射互译为英文条件键（[背包:铁矿] ≡ {var:item_count, param:"铁矿"}，见下方别名映射/NPC 4.3）
- 作者自造任务形态：选变量 + 填条件 + 配奖励 = 新任务（零新增代码）
- 任务系统 = 变量体系的第一非战斗消费者
```

### 条件三原语（统一条件引擎 {var,op,value,param}，NPC 定稿 4.0）
```
① 值型（当前值比较）：
   { "var": "item_count", "op": "ge", "value": 20, "param": "铁矿" }  // [背包:铁矿] ≥ 20
   { "var": "level", "op": "ge", "value": 10 }                          // [当前等级] ≥ 10
② 累计型（长线计数）：
   { "var": "kill_count", "op": "ge", "value": 5, "param": "岩皮鼬" }  // [累计击杀:岩皮鼬] ≥ 5
   { "var": "gain_count", "op": "ge", "value": 30, "param": "铁矿" }   // [累计获得:铁矿] ≥ 30
③ 事件型（事件触发，var 固定前缀 [事件:事件名]）：
   { "var": "[事件:落石]", "op": "ge", "value": 1 }                    // on_mechanic("落石") 次数 ≥ 1
   { "var": "[事件:dungeon_clear]", "op": "ge", "value": 1, "param": "熔岩洞窟" }  // 通关熔岩洞窟
```
> op 符号双写等价：>= ≡ ge ｜ > ≡ gt ｜ <= ≡ le ｜ < ≡ lt ｜ = ≡ eq ｜ != ≡ ne（NPC 4.1，全文示例统一用英文 op）

### 条件键别名映射（中文变量键 → 英文条件键）
```
- 条件引擎键空间为英文（NPC 定稿 4.3）；中文变量键（变量体系 v1.2）经显式别名映射互译：
  [背包:铁矿] ≡ { var:"item_count", param:"铁矿" }；[累计击杀:岩皮鼬] ≡ { var:"kill_count", param:"岩皮鼬" }…
- 【唯一权威主表】：NPC 系统设计定稿 §4.3 互译表（下表为任务侧常用键速查，字段口径以主表为准）
- 校验器/编辑器按主表互译：编辑面板显示中文变量键，配置存储与校验一律用英文条件键
```

| 中文变量键（变量体系） | 英文条件键（var + param） | 说明 |
|---|---|---|
| [当前等级] | level | 玩家等级 |
| [背包:X] | item_count + param:X | 背包物品数量（泛化引用） |
| [累计获得:X] | gain_count + param:X | 长线计数（本系统新登记） |
| [累计击杀:X] | kill_count + param:X | 长线计数（本系统新登记） |
| [副本通关:X] | dungeon_clear + param:X | 副本通关次数 |
| [图鉴完成度] | codex | 图鉴解锁 %（落点 codex_state，见怪物模块 §九） |
| [主线进度] | main_progress | 主线进度（取值语义见下方注） |
| [熟练度:X] | prof_level + param:X | 熟练等级（7 级体系） |
| [声望:板] | reputation + param:板ID | 声望等级（5 级制，param 缺省=全局；落点 reputation_state，见 §五） |
| 事件原语 on_*("目标") | [事件:事件名] + op:ge + value:次数 + param:目标 | 事件型（③） |

**【main_progress 取值语义（v1.0.4 补定义，修复缺漏批2C）】**
- 默认语义：已完成 main:true 主线任务计数（done 计数）——随任务完成结算递增，落 longline_counters（主线任务完成数）；条件引擎读到的即该整数
- 可配语义（内容包二选一或组合，编辑器下拉选择）：
  ① 整数序号：当前主线章节序号（沿 unlock_chain 链推进，= 主线链上已解锁的最深序号）
  ② 完成状态数组：主线任务 done 状态数组，取值 = 已 done 计数 或 当前章节号（由配置决定）
- 示例：[主线进度≥3] ≡ {var:main_progress, op:ge, value:3}——默认语义下即"已完 3 个主线任务"
- 校验器：main_progress 条件与主线链可达性互查（黄提示"主线进度≥N 但主线链不足 N 个任务"）

## 二、quest.json 数据结构（极简字段 + 默认值兜底）

```json
{
  "id": "q_ore_20",
  "name": "收集铁矿",
  "desc": "村长需要 20 个铁矿",
  "type": "collect",               // 展示标签/模板（非判定依据）
  "conditions": [                  // 判定条件（统一条件引擎 {var,op,value,param}）
    { "var": "gain_count", "op": "ge", "value": 20, "param": "铁矿" }  // [累计获得:铁矿] ≥ 20
  ],
  "consume": false,                // deliver 消耗 = true / collect 计数 = false（收敛一个布尔）
  "reward": "exp=50,coins=80",     // 内联键值串 = 统一 reward 条目数组的序列化糖（解析器等价，见 §2.1）
  "board": {"slot": "daily", "refresh": "daily", "limit": 3},
  "timed": null,                   // 限时修饰符（可选）
  "unlock_chain": null,            // 链式任务（可选，前置任务 ID）
  "zone": null,                    // 地图/副本关联（可选，副本子任务限定用；ref dungeon.json/maps.json，见字段表）
  "filter": null,                  // 炼金三档评价过滤子句（可选，如 quality>=精良）
  "bonus": null                    // 条件倍率奖励（可选，如 无伤交付 奖励×1.5）
}
```

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| id | str | 自动 | 唯一 |
| name | str | 必填 | 任务名 |
| desc | str | 空 | 描述 |
| type | str | collect | **展示标签**（collect/deliver/slay/explore/intel...编辑器模板，非判定依据——判定全由 conditions 驱动） |
| conditions | list | [] | **判定条件数组**（统一条件引擎 {var,op,value,param}；值型/累计型/事件型三原语；中文变量键经互译表映射，见 §一/NPC 4.3） |
| consume | bool | false | true=交付消耗（deliver）/ false=计数（collect） |
| reward | str 或 list | 空 | 统一 reward 条目数组（物品 {item,count} / 货币键值 / 组合，见 §2.1）；内联键值串（exp=50,coins=80,item:铁矿*3）为同一解析器的序列化糖，解析器等价展开 |
| board | obj | 默认 | 任务板（槽位/刷新/上限） |
| timed | obj | null | 限时（deadline 现实时间懒计算） |
| unlock_chain | str | null | 前置任务 ID（链式） |
| zone | str | null | 地图/副本关联（ref dungeon.json / maps.json 的 ID），可空；副本子任务限定用（zone 限定，不占板槽位）；§九 示例已用（q_explore_corridor / q_slay_beetle）；校验器引用检查 |
| filter | obj | null | 交付过滤（品质/特性/数量要求） |
| bonus | obj | null | 条件倍率（满足加分项奖励×N） |

### 2.1 奖励条目 schema（统一 · 任务/签到/NPC/怪物掉落四系统共用）

```json
// 统一 reward 条目：四系统共用同一入账管线，只配条目不配实现
// ① 物品条目：{ "item": "ID", "count": N }（引用 items.json）
{ "item": "铁矿", "count": 3 }
// ② 货币/数值键值条目：{ "coins" | "gem" | "exp" | "rep": N }
{ "coins": 80 }   // 金币（settings 货币键空间）
{ "gem": 3 }      // 宝石
{ "exp": 50 }     // 经验
{ "rep": 20 }     // 声望（可选模块；rep = reputation 值入账 → reputation_state，见 §五）
// ③ 组合数组：多条目按序入账
"reward": [ { "exp": 50 }, { "coins": 80 }, { "item": "铁矿", "count": 3 } ]
```

- 物品键固定 `item`（引用 items.json）；货币键 coins/gem 走 settings 货币键空间；exp/rep 为数值直入账
- **内联键值串（item:铁矿*3 / exp=50,coins=80）＝ 同一解析器的序列化糖**——解析器等价展开为条目数组，存储与校验以结构化条目为准（旧内联串由导入器自动展开，无需手改）
- **发放器唯一实现 = 框架 reward 解析器**（物品入包 / 货币入账 / exp / 声望）——签到 rewards、NPC give_item、怪物掉落只配条目不另立发放逻辑
- 等价写法：签到 items[]{id,count} 的 id 键 ≡ 物品条目 item 键；怪物掉落条目在本 schema 上扩展概率/条件/数量区间字段（见怪物定稿 §八）

## 三、任务板机制

### 3.1 主线任务（常驻，用户拍板）
```
- 主线 = 常驻任务列表（随时可接取，不消失）
- 随时随地接取（/任务 里主线置顶）
- 引导作用：引导玩家进入新地区（主线=地区入口引导）
- 兜底作用：玩家自由行动腻了/不知道下一步 → 主线拉回（方向锚）
- 实现：任务标记 main: true（常驻不刷新不移除）
```

### 3.2 差异化支线（NPC 条件触发，用户拍板）
```
- 支线 = NPC 挂【发任务条件】，玩家与 NPC 互动时按满足条件发布不同任务
  · NPC 配置多个候选任务 + 各自条件（等级/进度/选择/状态/熟练度）
  · 玩家互动 → 匹配第一个满足条件的任务发布
  · 不同玩家/不同状态 → 不同任务（差异化）
- 例：铁匠 NPC
  · 条件：采集熟练 < 3 → 发布"采集矿石"任务（补缺漏技能）
  · 条件：等级 ≥ 10 → 发布"打造武器"任务（战斗向）
  · 条件：主线进度 ≥ 3 → 发布"特制武器"任务（地区进阶）
  · 条件写法统一条件引擎 {var,op,value,param}（采集熟练<3 ≡ {var:prof_level, op:lt, value:3, param:采集}；等级≥10 ≡ {var:level, op:ge, value:10}；主线进度≥3 ≡ {var:main_progress, op:ge, value:3}）
- 平衡作用：玩家探索到后面区域但采集熟练低 → NPC 发采集任务（平衡缺漏技能）
- 与任务板区别：板=每日刷新通用任务；NPC=按条件差异化的支线（事件牌组）
```

### 3.3 事件牌组哲学（熟悉内容预设 + 动态顺序，用户拍板）
```
【地区牌组设计（走完=熟悉地区）】
- 设计时先设定玩家需熟悉的内容：
  ① 精英怪支线：打赢某精英（= BOSS 机制的弱化版/残缺版，熟悉 BOSS 机制）
  ② 收集类支线：采集/挖矿（熟悉地图通道——不开放全地图传送，玩家需知道地区有哪些地图）
- 顺序不固定（动态）：
  · 玩家属性低 → 先给简单任务
  · 玩家属性高 → 直接给战斗任务
  · 已探索到后区但采集熟练低 → 给采集任务（平衡缺漏技能）
- 整体流程仍要走（熟悉内容都覆盖，只是顺序按玩家状态调整）
【孤寂卡/自由时间】
- 无弱引导 = 玩家自己打副本/探索（通过该地区副本后自由）
```

### 3.4 指令闭环 + 板规则
```
/任务        → 查看任务列表（主线置顶 + 板上任务 + NPC 支线）
/接取 3      → 接取 3 号任务（序号不带 *）
/任务信息   → 查看已接任务进度
/交付 2      → 交付 2 号任务（consume=true 扣物；自动计数任务只需 /交付 领奖）
/放弃 2      → 放弃任务（可配惩罚，默认无）
/与 NPC 对话  → 与当前地图 NPC 互动（触发条件匹配 → 发布差异化支线）

板规则（默认值兜底，全部可配）：
- 槽位：daily 槽（每日刷新）+ 可选 weekly/event 槽（多板）
- 刷新：每日懒计算刷新（重置时刻默认 05:00 可配，与签到/商店同刻对齐）
- 接取上限：同时接取 ≤5（可配 0=不限）
- 每日完成上限：≤10（防刷，可配 0=不限）
- 重复衰减：同一任务重复完成奖励递减（默认关）
- 声望：可选模块（见五）
- 主线：常驻不移除（main: true）
```

**【双任务板指令归属（v1.0.4 仲裁，修复缺漏批2C）】**
- `/任务` = 玩家任务板（主线 + quest.json 板槽任务 + NPC 支线）；本节指令（/接取 /交付 /放弃 /任务信息）默认作用于玩家任务板
- 炼金委托板（profession.json quest_board，职业熟练度与生活系统设计定稿 §3.1，每 N 天刷新委托）为**独立板**：指令改 `/委托`（或 `/任务板 <板名>`，内容包可配别名），不占用 /任务 路由
- 冲突仲裁：同一指令双系统响应时以本节为准——裸 `/任务` `/接取` `/交付` 归玩家任务板；委托板操作必须带板前缀（`/委托 查看` `/委托 接取 3` `/委托 交付 <委托> <道具>`）
- 落点说明：职业熟练度与生活系统 §3.1 / 炼金定稿指令表中的 `/任务` 指令行建议同步改为 `/委托`（本批未触碰该两文件，交由后续批次/父 agent 协调登记）

## 四、进度存储（三表设计）

```
① longline_counters（框架级长线计数表）
   - 累计击杀/累计获得/图鉴进度/副本通关——任务只读（跨任务复用）
   - 存于玩家存档（3.7），任务系统不重复计数
② quest_active（进行中任务表）
   - 接取的任务 + 当前进度（ID+名称冗余，对齐 3.18 快照原则）
   - 非会话（无锁/无超时，碎片化友好）
   - 热重载：删配置降级提示不报错
③ quest_daily（每日防刷表）
   - 今日完成数/接取数/重复衰减计数
   - 每日重置（懒计算，默认 05:00）
```

## 五、声望体系（可选模块，A 版保留）

```
- 默认关（内容包按需开）
- 声望值：完成委托任务 +N（板配置）
- 声望等级：默认 5 级（陌生→熟悉→信赖→崇敬→传说，可配改名）
- 声望商店：解锁专属商品（shop.json 联动，声望门槛）
- 炼金委托板：委托任务品质评价 → 声望加成（品质高=声望多）
- 声望双源归一：任务板 rep 奖励 与 委托板交付评价（生活系统 §3.1"交付评价→声望升阶"）并入同一 reputation_state（值+等级），不另立双套（见下方换算）
- 星级评价替代：filter（交付品质过滤）+ bonus（加分项倍率）——不做加权评分
```
- **声望值/声望等级落点 = 玩家存档 reputation_state（框架 3.7 持久化语义总表，登记由批内另一 agent 同步）**：值 + 等级（5 级制，可配改名）+ 来源板 ID（param 缺省=全局）统一存 reputation_state；reward 条目 `rep`（§2.1）= reputation 值入账（**不入货币表**——声望=进度门槛非支付货币，组2 F4 仲裁）；条件键 [声望:板]（var:reputation）、商店声望门槛（shop.json reputation_required）读同一来源——任务系统只声明"完成委托任务 +N（板配置）"，不另立存储（重叠检查组2 F3 补登记）

**【声望值→等级换算（v1.0.4 补定义，修复缺漏批2C）】**
- **存档存值、条件读级**：reputation_state 存累计声望值（不存等级）；条件键 [声望:板]（var:reputation，读等级）与商店门槛（shop.json reputation_required {level:N}）由值换算等级得出——两级之间不再悬空
- 默认 5 级阈值表（数值全部可配，编辑器可改；等级名沿用 §五 可配改名）：

| 等级 | 名称（可配改名） | 累计声望值下限 |
|---|---|---|
| L1 | 陌生 | 0 |
| L2 | 熟悉 | 100 |
| L3 | 信赖 | 300 |
| L4 | 崇敬 | 600 |
| L5 | 传说 | 1000 |

- 换算规则：达到阈值即升阶（值 ≥ 阈值 → 等级 = 满足的最高档）；等级**只升不降**（默认，可配降级——生活系统 §3.1 截止未交惩罚 -10% 值，若值跌破当前级阈值，按可配规则处理：保级或降级）
- 可配替代：阈值表可换成长公式（如每级阈值 = base × 等级^grow，默认近似 base=100, grow=2），编辑器提供"当前值 → 等级"预览
- 校验器：商店 reputation_required.level 超出内容包最高阈值 → 黄提示"声望门槛永不可达"（对齐审查 C5 项）

## 六、与全系统联动

| 系统 | 联动 | 说明 |
|---|---|---|
| 炼金委托板 | 委托任务 = deliver + filter（品质/特性）+ bonus；指令=/委托 独立板（§3.4 仲裁）；声望产出同源并入 reputation_state（§五） | 材料收购出口闭环（collect 不消耗，收购走 deliver） |
| 副本子任务 | 副本 subquests 引用 quest ID（zone 限定，不占板槽位；zone 字段见 §二 字段表） | 探索/机制学习/情报/清剿 |
| 图鉴 | intel 任务：[图鉴完成度]（codex）条件 / 情报解锁奖励 | 图鉴进度=任务条件（落点 codex_state，见怪物模块 §九） |
| 商店/签到 | 声望商店解锁（门槛读 reputation_state）/ 签到联动奖励 | 可选 |
| 掉落 | 收集任务与掉落联动（[累计获得]→gain_count） | 不抢材料（collect 计数不扣） |
| 变量体系 | 任务条件全用变量（新登记 4 类：累计获得→gain_count/累计击杀→kill_count/图鉴情报→codex/声望:板→reputation，见 §一 别名映射） | 变量体系第一非战斗消费者 |

## 七、编辑器（零代码）

```
- 任务页：基本信息表单（名称/描述/标签下拉）+ zone 下拉（地图/副本引用，可空）
- 条件表单：变量面板（分组下拉选择变量）+ 运算符 + 数值（结构化，非 JS）
  （任务条件=结构化原语，安全简单——与派生条件一致，JS 只用于效果值；变量面板显示中文变量键，保存时按 NPC 4.3 互译表转为英文条件键存储）
- 奖励配置：统一 reward 条目表单（物品下拉+数量 / 货币键值，见 §2.1）——内联键值串仅作导入/导出序列化糖
- 板配置：槽位/刷新/上限/声望开关
- 链式任务：unlock_chain 下拉（前置任务）
- 校验器：引用存在（变量/物品/怪物）/条件合法（op 枚举/值类型）/死配置提示
```

## 八、校验器

```
硬拦（4 类）：引用不存在（物品/怪物/变量/zone 地图副本）/类型错误/负数/结构错误
黄提示（10 类）：条件永假/奖励超基准/链式任务死链/重复衰减异常/板上限冲突/声望商店引用缺失/main_progress 主线链可达性/声望门槛超最高阈值...
模板："『铁矿』物品不存在，先去物品页添加" ｜ "条件 gain_count(累计获得:铁矿)≥20 永不满足？确认数值"
- 条件键互查：中文变量键 ↔ 英文条件键按 NPC 4.3 互译表互译校验（旧 {type,var,op,value} 结构=黄提示"旧格式，建议迁移"）
```

## 十、风险与简化

| 风险 | 对策 |
|---|---|
| 条件系统上手难 | 编辑器结构化条件表单（变量下拉+运算符+数值，非 JS）+ 预置模板（收集/击杀/交付一键） |
| 任务类型太多 | 不枚举（条件驱动）——作者自造，编辑器模板引导 |
| 收集与炼金抢材料 | collect 计数不扣物；收购走 deliver 消耗（出口闭环） |
| 限时碎片化冲突 | 现实时间懒计算 + 接取时明确倒计时 + 可配无惩罚 |
| 任务进度热重载失效 | quest_active ID+名称冗余（3.18 原则），删配置降级提示 |
| 声望膨胀 | 声望商店门槛 + 委托品质评价限制 |
