## 五、缺失汇总（❌ 3 个功能点 = 1 个独立主题；⚠️ 4 项）

### 缺失-1（❌ P2，3 个功能点合并 1 主题）：单机向编辑器三页无细化承接

- **定稿证据**：【单机】L91「隐藏要素页（条件组合表单 + 线索引用 + 可达性检查显示）」/ L92「环境事件页（窗口条件 + 效果引用下拉）」/ L94「日志卡片（记录类型勾选 + 快照开关）」/ L116 编辑器登记
- **现状**：细化_5a 仅契约六页 CRUD（技能/职业/怪物/地图/任务/商店，P-06 六页归口）＋元数据驱动壳机制；3f §12 显式声明「不含：编辑器 UI 实现（L89-96 预留）」；4c §14 同样「不含：编辑器 UI」；4d 仅登记「阶梯模板一键插入」与「编辑器作者视角回放」语义。三页表单（条件组合/窗口条件+效果下拉/记录类型勾选）在全工程 64 份细化中**零承接**（grep 隐藏要素页/环境事件页/日志卡片 = 0 命中，仅 3f/4c 提到不含）。
- **影响用例**：3f TC-21（可达性检查依赖编辑器显示）、3f R-16（线索引用显示）、单机 L9x 全部编辑器验收——校验器可达性机制有契约（3f R-16），但**作者配置入口无表单**，作者配置隐藏要素/环境事件/日志模板只能手写 JSON，违背「编辑器零代码」硬约束（迁移文档 L89）。
- **分级理由**：P2——编辑器属设计层工具（同 覆盖审计_D P2-7 时间天气编辑器 UI、覆盖审计_F F-23 钓鱼卡片页同模式缺口），机制契约已声明，不阻塞引擎实现；建议并入 4f/5a 收尾批。
- **建议**：① 5a 扩展「可插拔页面注册表」：单机向玩法包含 3 个页面定义（页 → 模块文件 → 元数据表），复用 5a P-07 元数据驱动渲染；② 隐藏要素页表单 = 条件组合（复用 2b4 conditions 表单）+ 线索引用列表 + 可达性检查只读区（读 3f R-16 校验结果）；③ 环境事件页 = 窗口条件三键下拉（[季节][时段][天气]）+ 效果引用下拉（npc_appear/quest_window/shop 限时/monster_boost，枚举见 3f R-24）；④ 日志卡片 = 六类 tag 勾选 + 快照开关（字段见 3f E-01）；⑤ 作者视角时间轴预览（S-45）随此批实现（只读计算器，数据源=3f R-16 漏斗三层回放）。

### 风险-1（⚠️ P1，依赖悬空）：冒险日志「事件实例通道」写入/存储契约未落任何细化

- **定稿证据**：【单机】L51「数据源：longline_counters + 事件计数」；3f D-01（L49）将冒险日志条目收敛为「事件实例通道（事件注册表 NPC 4.3.2 配套的实例计数）扩展 snapshot/first_seen 两字段」承载 300 条环形——**该通道的存储表结构、写入 API、环形容量实现无任何细化定义**。
- **现状**：NPC 4.3.2（事件注册表）预置 6 事件中仅 `[事件:NPC对话:ID]` 有写入契约（2b2 T15）；覆盖审计_E P1-1 已确认其余 5 事件「全工程无写入契约」；单机新增的 [事件:环境事件:ID]/[事件:隐藏发现:ID] 虽有 3f R-24/R-14 写入语义（环境演出/发现即计数），但底层事件计数/实例通道的 schema 与存储落点悬空——**冒险日志 6 类记录（3f R-02）与 300 条环形（3f E-01）在实现层缺少地基**。
- **建议**：在 4a 存储层（或 3f 补一节）登记 event_instance 表/键空间（event_id/tag/template_id/params/snapshot/first_seen/ts + 环形容量，字段即 3f E-01 八列），并明确事件计数（条件引擎事件型读取源）与实例列表（日志展示源）的存储关系；写入侧按 3f R-24/R-14/2b2 T15 同款「结算点同事务 + message_id 幂等」补契约。

### 风险-2（⚠️ P2）：GM 系统日志默认条数两细化冲突

- **定稿证据**：3f §1.7（L159）「默认展示最近 50 条（可配），分页 20 条/页」vs 5b G8（L146）「条数=N 键值，默认 20，上限 50」——同一功能的默认值互相矛盾。
- **建议**：统一为一方（建议 5b 默认 20 对齐 3d 列表分页上限惯例，或 3f 默认 50 对齐「保留最近事件」容量语义），并在 3f ADR 或 5b 补一行显式裁决；实现时以 3c 指令表登记行收口。

### 风险-3（⚠️ P2）：ai_state 快照字段未落契（与覆盖审计_C M-03 同源）

- **定稿证据**：迁移文档 L119 待办「4.2 enemies 元数据/触发 13 类/ai_state 快照——附 C 已做部分」；细化_1e 覆盖了 元数据与 13 类（A05/R2），但全篇未定义 ai_state 字段级 schema（仅 F14 chains 声明「本表只登记不展开」）；1g3 §1.2 的 ai_state（boss_phase/action_table_state/…）与 A.5 六字段（state/phase/chain_pos/chain_queue/charge/trigger_cooldowns/intent）是两套字段名。
- **建议**：1g3 §1.2 增补 A.5 六字段映射表（见 覆盖审计_C M-03 建议），随 5d 测试体系收尾批闭合。

### 风险-4（⚠️ P2）：指令登记依赖「收尾批」

- 3f §七 / 4d §4.1 / 4c §七 的指令登记（/日志 双视图、/调查、/图鉴、/成就、/称号）均标注「收尾统一执行」，3c 指令表中暂无这些行的实现契约落点——属既有惯例（对齐怪物 L373），不阻塞，但需 4f/3c 收尾批一次性登记，避免实现期指令路由缺表。
