## ① 战斗快照结构（battle snapshot，字段级）

### 1.1 快照落点约束（定稿写死，不可偏离）

| # | 约束 | 来源 |
|---|---|---|
| S0 | 中断快照**只落回合边界**（回合开始前 / 回合结束 tick 后），回合内不落快照 | 【战斗定稿 L66-67】 |

### 1.3 字段取值来源核对（防悬空）

- `units[].hp/mp` 恢复语义：副本内 HP/MP 不恢复，唯一例外=安全区 /休息（【副本定稿 L92/L249】）→ 恢复端不得凭空补满。
- `ai_state.boss_phase` 由 HP 阈值推导但必须显式持久化：死亡结算 BOSS 保留时阶段随血量回退（【副本定稿 L124】）。
- `turn` 与 `snapshot_at.boundary` 双写：恢复端只需读一处即可确定续战点（S0 语义落地）。

## ② 中断恢复流程（超时 / 锁屏 / 退出 → 续战）

### 2.1 触发源与判定（退出规则，用户拍板）

| 触发 | 处理 | 来源 |
|---|---|---|
| 战斗进行中 退出 / 超时 / 锁屏 | → **战斗快照续玩**（ai_state+combo_state 全保留，套内也可续） | 【副本定稿 L80】 |
| 非战斗状态离开副本区域 | → **副本重置**（下次满状态重打） | 【副本定稿 L81】 |
| 安全区 /休息 | ≠ 离开副本：不重置、不打断进度、快照/进度保留 | 【副本定稿 L83/L104-106】 |
| 副本内死亡 | ≠ 战斗中断：走 §2.2 死亡结算（复活点/checkpoint 回退/BOSS 保留或重置） | 【副本定稿 L111/L114-121】 |

### 2.2 落盘时序（写死约束）

```
中断信号（退出/超时/锁屏）
   ↓
① 等待当前回合边界（回合开始前 / 回合结束 tick 后；回合内不落快照，不打断回合内结算）  【战斗定稿 L66-67】
   ↓
② 死亡判定已先于快照完成 → 恢复后状态 = 最近回合边界，无「恢复在死亡判定前/后」歧义     【战斗定稿 L67】
   ↓
③ 序列化 battle snapshot（§1.2 全字段，含 stats_collector）                            【战斗定稿 L333】
   ↓
④ 持久化登记（与副本进度保存合并执行：中途退出保存进度，下次从换区点继续）             【战斗定稿 L333】【副本定稿 L260】
   ↓
⑤ 恢复入口明示：「战斗中断可续玩，离开副本将重置」                                     【副本定稿 L82】
```

### 2.3 恢复时序

```
玩家回到恢复入口（明示文案 S5）
   ↓
① 读取快照 → 校验 schema_version / 引用存在（unit id ∈ 存档、enemies.json、dungeon.json）  【副本定稿 L270-273 衔接】【战斗定稿 L5.3 校验器 L254-265】
   ↓
② 恢复单位状态（HP/MP/PV/护盾/增减益/dot/冷却）、ai_state、combo_state、回合数            【副本定稿 L80/L105】【战斗定稿 L58】
   ↓
③ 恢复副本位置（map_id/zone/checkpoint）→ 从换区点继续                                  【副本定稿 L260】
   ↓
④ 若快照为套内（连段未完结）→ 从当前 seg 继续执行本套                                   【副本定稿 L80】
   ↓
⑤ 战斗结束（胜负/奖励/掉落）→ 快照清理（当轮事件末尾结算一次）                          【战斗定稿 L64】
```

### 2.4 边界与一致性规则

- 快照与副本进度的「原子性」：中途退出保存进度与快照同批落盘（【战斗定稿 L333】持久化登记由收尾统一执行；【副本定稿 L260】），失败则整体回滚，不允许出现"有快照无进度"。
- 死亡 ≠ 中断：恢复入口不提供"死亡后恢复战斗"路径；死亡一律走 §2.2（【副本定稿 L111/L129】）。
- 虚弱衔接：复活后虚弱 1 分钟内禁入非安全区（含 BOSS 房），期间进度/BOSS 状态保持（【副本定稿 L134-135】）。
