## 〇、契约总则

### 0.1 术语表

| 术语 | 定义 | 依据 |
|---|---|---|
| 签到 = 奖励日历 | 签到表是"连续登录奖励"的配置载体，**不枚举奖励类型**——奖励 = 物品/货币/exp/声望 四元素任意组合（统一 reward 条目 schema） | 【签到】L13/L60 |
| 签到表 | 多表并存：`loop` 常驻循环 / `monthly` 月度 / `activity` 活动；一表一数组条目，互不冲突 | 【签到】L6/L14/L77 |
| 连签 streak | 连续签到天数，**每表独立计数**；断签（间隔>1 天且 reset_on_break=true）→ 归 1 | 【签到】L14/L56/L67 |
| 月度累计 monthly_total | 当月签满 N 天即给奖励，**不要求连续**（碎片化铁律：断签不清零，月底冲刺钩子） | 【签到】L15/L57 |
| 补签 makeup | 可选模块默认关；补签卡（物品）或货币付费两通道任一满足即可用 | 【签到】L15/L58 |
| 懒计算日界 | 重置时刻默认 **05:00**（可配）；玩家操作时取存档键与当前现实时间比较跨期补算，**唯一判定**；凌晨 0-5 点仍算前一天 | 【签到】L96/L106 |
| 生效表 | 结算管线只遍历生效的签到表：activity 表 start/end 由懒计算判定，未开始/已过期 → 自动停用不报错 | 【签到】L78 |
| 幂等 | 同日重复 /签到 → "今天已签到"（version 幂等，不重复发奖） | 【签到】L26/L118 |

### 0.2 一句话契约

> 签到 = 由 checkin.json 配置的「**奖励日历**」——loop/monthly/activity 三种表可**多表并存**（同文件多数组条目），
> 每次 `/签到` 走写死管线（懒计算跨天判定→领 daily→streak 里程碑→monthly_total→写存档→汇总）**一次完成所有生效表**并**汇总单条消息**输出（今日奖励+连签天数+进度 8/31+各表流水）；
> 各表连签独立计数、月度累计不要求连续、活动表过期懒计算自动停用、同日重复幂等返回"今天已签到"；
> 补签为可选模块默认关（补签卡/货币付费，max_per_month 0=不限）；列表模板 5 条/页上限。

### 0.3 决策记录（ADR，均为对定稿空白的显式收敛，标注【工程补白】）

| 编号 | 决策 | 理由 | 影响用例 |
|---|---|---|---|
| D-01（补白） | **day 编号口径**：每日奖励 day = 周期内第几天——monthly 表 = 自然月当日(1..当月天数)；loop 表 = 本期第 N 天 mod cycle_days（余 0 → cycle_days）；activity 表 = 与 start 的日差+1 | 【签到】L55 仅定 "day 1..N 轮转 + monthly N=当月天数"，未给三种表的 day 具体计算式，此为本契约统一口径 | TC-09/TC-13/TC-20 |
| D-02（补白） | **幂等返回仍带进度**：同日重复 /签到 → 首行"今天已签到"，随附各生效表当前连签+进度（**不重复发奖**） | 【签到】L26 只定幂等不重复发奖；为防玩家困惑，随附进度不重发奖励 | TC-25 |
| D-03（补白） | **补签语义**：补签所补回的日期计入 signed_days 并**参与连签连续性**（挽回 streak 断签）；同一天已补过 → 幂等返回不重复扣费 | 【签到】L58 只定"补签"行为未定其对连签的归属，断言补签用于断签挽回 | TC-19~24 |
| D-04（补白） | **bonus 乘算口径**：倍率统一作用于结算时**本次实际发放**的 items.count / coins / gem / exp（向下取整），不追溯历史奖励 | 【签到】L79 定"结算时统一乘算"未定量化细节 | TC-33 |
| D-05（补白） | **发奖失败不中断**：reward 解析器单条失败（物品不存在）黄字跳过，**不吞整次签到**，当表后序条目/后序表继续结算 | 【签到】L220 验收标准"发奖失败兜底"落地为逐条跳过语义 | TC-27 |
| D-06（补白） | **monthly_total 跨月清零**：月度累计对齐 quest_daily（当日行月度清零语义），自然月切换后归 0 重新累计；签到总天数 longline 跨周期保留只增不减 | 【签到】L102「长线只增不减」+ L104「每日清零」并读后的对齐裁定 | TC-18 |

## 二、一次 /签到 流程（所有生效表结算 → 汇总单条消息）

### 2.1 入口

```
/签到             → 一次完成所有生效表，汇总单条消息输出
/签到 补签        → 补签（makeup.enabled 时可用，消耗补签卡或货币）
```
依据：【签到】L21-23。

### 2.2 生效表启停判定（懒计算，先过滤再结算）

```
遍历 checkin.json 全部签到表 → 逐表判定生效性：
  · loop / monthly       → 常驻，恒生效（type=常驻，period.start/end=null）
  · activity             → start/end 由懒计算判定：
                             start 未到  → 未开始 → 自动停用（不报错）
                             end 已过    → 已过期 → 自动停用（不报错）
生效表集合 = 过滤后剩余的表；一次 /签到 只对该集合结算
```
依据：多表并存【签到】L77 + 「未开始/已过期 → 自动停用，不报错」【签到】L78。

### 2.3 结算管线（写死，判定顺序结构依赖，逐表独立执行）

```
对每个生效表：
① 懒计算跨天判定：存档 last_date vs 今天
   同天 → "今天已签到"（幂等返回，不重复发奖，见 §五）
   跨天 → streak+1；断签（间隔>1 天且 reset_on_break）→ streak 归 1
② 领 daily[day]（day = 周期内第几天，D-01 / §1.4）
③ streak 里程碑检查（达到 days 阈值 → 额外发奖）
④ monthly_total 检查（本月累计天数达到阈值 → 额外发奖）
⑤ 写存档：last_date / streak / month_total / signed_days[] / makeup_used（checkin_state，§5.3）
⑥ 汇总输出本表：今日奖励 + 连签天数 + 进度（"8/31"）
结算期间 bonus（D-04）对本次实际发放值统一乘算；发奖失败单条黄字跳过不中断（D-05）。
```
依据：【签到】L62-73（①~⑥ 六步原文）+ L79（bonus）。

### 2.4 汇总单条消息输出模板（防刷屏）

## 三、连签与独立计数

### 3.1 每表独立连签（互不冲突）

- **多表并存**：常驻循环表（loop）+ 月度表（monthly）+ 活动表（activity）可**同时生效**，一次 /签到 全部结算【签到】L77。
- **独立计数**：各表各自维护独立 streak / signed_days / month_total，互不合并、互不冲突【签到】L14。
- 存档按表 ID 键控：`checkin_state[<表ID>] = { last_date, streak, month_total, signed_days[], makeup_used }`【签到】L110。

### 3.2 连签递增与里程碑

| 规则 | 说明 | 依据 |
|---|---|---|
| 跨天递增 | 跨天（≠同天）→ streak+1 | 【签到】L67 |
| 里程碑额外发奖 | 连续签到达到 streak[] 的 days 阈值 → 额外发奖（每日奖励之外叠加） | 【签到】L69/L56 |
| 漏打处理 | 只按签到日推进；离线多天跨周期不逐日重放（懒计算跨期补算，见 §五） | 【签到】L96 |
| 里程碑不重复 | 每档 days 阈值每周期至多触发一次（按 signed_days/当期计数比对，补白防重复发奖） | 精神延伸【签到】L118 version 幂等 |

### 3.3 中断规则（断签判定）

| 场景 | reset_on_break=true（默认） | reset_on_break=false | 依据 |
|---|---|---|---|
| 每日连续（间隔=1 天） | streak 正常 +1 | 同左 | 【签到】L67 |
| 断签（间隔>1 天） | **streak 归 1**，连签里程碑重来 | pass：归 1，改按累计口径延续（断签不重来） | 【签到】L67/L56/L132 |
| 月度累计 monthly_total | **不受断签影响**：断签不清零，当月签满 N 天仍发奖（碎片化铁律） | 同左 | 【签到】L57/L15/L103 |
| 签到总天数 longline | 只增不减，跨周期保留 | 同左 | 【签到】L102 |

**碎片化铁律**：断签不挫败——月度累计不要求连续（月底冲刺钩子）；补签为可选模块默认关；凌晨不骚扰（重置时刻默认 05:00，0-5 点仍算前一天）【签到】L15。

## 五、幂等（同日重复 /签到 → 今天已签到）

### 5.1 幂等判定（version 幂等，防双发/防刷签）

```
懒计算跨天判定（§2.3 ①）：存档 last_date vs 今天
   同天 → 直接返回 "今天已签到"，不重复发奖（仍附当前各表进度，D-02）
   跨天 → 正常结算（streak+1 / daily / 里程碑…）
```
依据：【签到】L26「同日重复 /签到 → '今天已签到'（幂等，不重复发奖）」+ L118「version 幂等：签到同日重复 → '今天已签到'（防双发）」。

### 5.2 对应的快照原则（3.18 非会话持久状态）

| 原则 | 落地 | 依据 |
|---|---|---|
| ID+名称冗余 | 存档记录 item_id + item_name 双字段（热重载/换包后旧条目仍可显示与结算） | 【签到】L117 |
| version 幂等 | 同日重复 → "今天已签到"（防双发/刷签） | 【签到】L118/L208 |
| 旧配置结算 | 连签 streak 按旧配置口径结算，新配置下个周期生效 | 【签到】L119 |
| 30 天回收不适用 | 签到状态为常驻存档不回收（僵尸回收仅限会话管理器：战斗/调合） | 【签到】L120 |
| /状态 不提示 | /状态 不提示签到（非会话） | 【签到】L121 |

### 5.3 懒计算为唯一判定（不依赖定时器）

- 所有周期状态**不依赖定时器**：玩家操作时取存档周期键与当前现实时间比较，跨周期即补算（复用框架 3.6 补刷模式）【签到】L96。
- apscheduler 定时器仅做**双保险**（每日计数重置 + 公告推送），核心判定永远懒计算——**服务器重启/离线多天不丢不炸**【签到】L96。
- 统一周期键：重置时刻默认 **05:00**（可配），日期归属 = 重置时刻之后算新一天（凌晨 0-5 点仍算前一天）；与 quest_daily 的 refresh_time 共用同一配置键，**商店/任务/签到三表同刻对齐**【签到】L106。
- 与任务三表对齐：longline_counters（签到总天数只增不减）/ quest_active（月度累计不因断签清零）/ quest_daily（签到当日标记每日清零）【签到】L102-104。
