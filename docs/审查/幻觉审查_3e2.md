## 三、P2 清单（6 条）

### P2-1 §1.1 T6：服务器侧更新方式表述与定稿不符（轻度错位）
- 细化 T6 说：`玩家/服务器 pull 后运行 /重载 使新配置生效`。
- 【框架】L1503 明确：「服务器端：git pull 后**重启服务**」（非 /重载）；玩家侧「更新后 /重载」见【规则】L433（README/群公告告知）。L1493-1506 总体支持 git 分发渠道。
- 判定：渠道依据真实（【框架】L1493-1506、【规则】L200/L433 均命中），但把「服务器重启」并入「/重载」属表述窄化，建议改为「玩家 pull 后 /重载 / 服务器 pull 后重启」。

### P2-2 §1.2 TRG-2：哈希动机说明为细化自补、未标【补白】
- 细化补充「哈希防 mtime 伪造/编辑器同秒覆盖」。定稿（【规则】L174、【框架】L774）仅写「文件 mtime/哈希检测」，无动机解释。
- 判定：内容不违背定稿，但属合理的工程解释性延伸，依「补白显式标注」纪律应标【补白】。

### P2-3 §6 TC-02：成功回执示例为细化新增、未标【补白】
- 细化断言「成功后人话回执（如『已重载：3 个模块变更生效』）」。定稿只在失败路径要求人话提示（【规则】L178/L321），**成功回执无定稿依据**。
- 判定：测试断言新增了定稿未要求的成功回执行为，且未标【补白】。示例文案本身无害，但行为承诺超出定稿，建议补标并在实现时以「仅提示不刷屏」口径收敛（与 D-06 一致）。

### P2-4 §6 TC-13：日志行为断言为细化新增、未标【补白】

### P2-5 §6 TC-05：指标口径改写（事件循环响应 <200ms）
