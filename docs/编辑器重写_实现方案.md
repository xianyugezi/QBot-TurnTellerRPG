# 内容编辑器 · 实现方案（终端极简风 · 分批实施）

> 用户 2026-09-13 拍板：**用「终端极简风」写**（样式稿 `s3/e3`）；**分多批、一个功能一个功能来**；
> 技能条目必须有**派生界面**（派生条件 / 派生技能 / 派生消耗）。
> 需求侧唯一来源：`docs/编辑器重写_需求与约束.md`（第〇节「通用工具」原则优先于一切）。
> 本文件 = 实施侧唯一来源：架构、批次划分、每批验收门禁。**不写进本方案的功能一律不做**。

## 一、不变量（每批都必须满足，违反即回退）

1. **通用性**：编辑器不为任何内容包定制。模块列表来自 `manifest.modules`，字段与分组来自字段元数据
   （`qbot_rpg/content/*_models.py` 的 `FieldMeta` / `FieldMetaTable`）。判断标准：**换一个包，编辑器零改动可用**。
2. **元数据驱动渲染**：字段类型 → 控件的一对多映射写在一处（见 §三），业务模块不得新增特例分支。
3. **面向非技术用户**：字段中文名；必须有人话提示；新功能要有引导，不静默。
   · **三栏并列**：①模块分类栏 ②条目列表栏 ③大编辑面板——前两栏各自独立（不混排分类名与条目名），
     合计仍窄（约 350–400px），编辑面板占其余全部宽度（用户 2026-09-13：是两栏不是两段）；
     装备归入物品 = **模块层级**由包元数据声明（`物品 ▸ 装备`），编辑器不写死归并关系。
4. **纯配置优先**：内容侧不新增硬编码；模板/文案可被内容包覆盖（沿用游戏侧既有机制）。
5. **落盘安全**：任何写盘都走原子写 + 备份；写前校验；不破坏包（校验不过不落盘）。

## 二、形态与技术选型

| 项 | 选型 | 说明 |
|---|---|---|
| 宿主 | 复用原编辑器形态：本地 HTTP 服务（FastAPI）+ 单页前端，`scripts/editor_host.py` 起服 | 默认 `127.0.0.1:8090`；公网默认关（隧道/反代另配） |
| 前端 | 单页静态页（零构建、零 CDN） | 终端极简风样式 token 独立成文件，便于换肤 |
| 鉴权 | 保留原语义：首次访问引导设密 → 登录；会话内存态（重启重登） | 机主 / GM 只读预览的权限级 |
| 落盘 | 沿用 `qbot_rpg/content/atomic_store.py`（原子写 + 变更条目形态） | 不新写存储层 |
| 校验 | 复用现有校验器 + `FieldMetaTable`（不手写字段清单） | 红拦/黄提示语义不变，编辑器只做展示 |

## 三、元数据 → 界面的映射（唯一实现点）

**需补的元数据维度（本方案第 1 项实际改动）**：现有 `FieldMeta` 有 type/required/default/ref_target/enum/范围/概率，
**缺「分组/分区」**。补一个可选维度（如 `group: str` 或 `section: str`），缺省时按「模块默认分组」兜底。
这样才能做到「页签 = 元数据声明的分组」而不是编辑器写死。

字段类型 → 控件（一对一映射表，集中实现）：

| FieldMeta.type | 控件 | 备注 |
|---|---|---|
| `str` | 单行文本 | 长文本用 `str` + 模块声明 `multiline`（或 `text`） |
| `int` / `float` / `number` | 数字输入（步进按类型） | 有 `range_min/max` 时显示为提示，不硬拦 |
| `bool` | 开关/复选 | |
| `enum` | 下拉（选项来自 `enum`） | |
| `ref` | **引用选择器**（可搜、显示目标 `ref_target` 的名称） | 引用目标来自 `ref_target` |
| `list` | **可增删行表格**（列 = 元素字段元数据；行尾删除 + 「+ 添加一行」） | 列表元素若为 `obj`，列名取元素字段元数据 |
| `obj` | 折叠字段组 | |
| `map` | 键值对表格（可增删） | |
| `formula` | 表达式输入 + 实时求值预览 | |
| 条件类（派生条件等） | 条件行编辑器（左 = 来源/主体，中 = 比较，右 = 阈值） | 通用形态；具体键名由包的元数据声明 |

> **批 2 已实现范围**：上表**标量控件**（单行文本 / 多行文本 `str` + `multiline` / 数字 / 布尔 /
> 枚举下拉 / 引用下拉）已可编辑；`list` / `map` / `obj` 批 2 只读展示（可增删行表格与引用搜索归批 4）。
> 映射集中在 `qbot_rpg/web/api.py`（`_WIDGET_BY_TYPE` + `_EDIT_BY_WIDGET`，见 §四 批 2 实现锚点），
> 业务模块不得新增特例；长文本另有「含换行 / 超长」启发式兜底（元数据未声明 `multiline` 时）。

## 四、分批实施（一批一功能，每批独立验收）

> 进度：批 0 ✅ 令牌+组件总览（`/root/editor_design/`）｜批 0.5 ✅ 三栏骨架 + 三栏重画（s3/e3）｜批 1 ✅ 只读骨架｜批 2 ✅ 编辑与保存

> **批 2 实现锚点**（代码位置与调用链，便于后续批次与复核）：
> · 控件映射**唯一实现点** = `qbot_rpg/web/api.py`：`_WIDGET_BY_TYPE`（type→形态）+
>   `_EDIT_BY_WIDGET` / `control_of` / `is_editable_widget` / `editable_form`（形态→编辑控件，含 multiline→textarea）；
>   前端只读 `descriptor.control` 渲染，不认字段类型。
> · 草稿态 = 前端（`static/index.html` 内联纯 JS 模块 `EditorDraft`，标记块 `EDITOR_DRAFT_BEGIN/END`）：
>   改动→草稿、未保存计数、取消清空、切换条目/模块/包与关窗守卫（`canLeave`）。
> · 写链路 = `qbot_rpg/web/editor_ops.py`：
>   `validate_entry` = `api.entry_slot` → 补丁 → `check_pack`（现有唯一校验入口，红拦/黄提示）；
>   `save_entry` = 红拦不落盘 → `atomic_store.backup_modules`（.bak）→ `atomic_store.write_modules`（原子写）
>   → 回读 `check_pack` 复核，失败自动 `restore_modules_from_backup`；
>   `rollback_module` = 从 .bak 原子恢复；`module_backup` = 回退入口可见性。
> · 权限位 = 沿用 `permission_store` 角色：机主(owner) 可编辑 / GM(gm) 只读预览；
>   只读身份在 `editor_ops.require_edit` 前置拒绝（Forbidden 403），不依赖前端隐藏按钮；
>   批 2 不做登录页，启动参数 `--role` + 顶栏开关（`/api/session/role`）表达。
> · 宿主编排 = `scripts/editor_host.py`（`/api/session`、`…/validate`、`…/save`、`…/backup`、`…/rollback`、`/api/pack/{p}/refs/{target}`）。

> 每批都必须：① 代码 + 测试 ② **实机截图发用户**（终端极简风） ③ 台账登记 ④ 全量测试绿 + 校验器绿

- **批 0 · 设计令牌定稿**：把定稿样式（终端极简风 s3/e3）抽成样式 token 文件（色/字/间距/控件态），
  出 1 张「组件总览图」（按钮/输入/页签/表格/提示/空态）供你确认 → 之后所有批都照它画。
- **批 1 · 只读骨架**：宿主起服 + **内容包选择器** + **三栏骨架**（第1栏=模块分类导航【支持层级：物品 ▸ 装备】、
  第2栏=当前模块条目列表【只名字/滚动条/无翻页】、第3栏=大编辑面板，只读渲染，面板顶部标注元数据来源）
  + 条目详情**只读**渲染（字段类型 → 只读展示；面板顶部标注「字段由元数据生成 · N 字段 · M 分组」）。
- **批 2 · 编辑与保存**：可编辑控件 + 草稿态（未保存改动提示）+ 校验 + **原子写落盘** + 自动备份 + 回退。
- **批 3 · 分区页签**：按元数据分组渲染页签（默认只显示第一组），分组顺序由元数据决定。
- **批 4 · 列表型与引用型字段**：可增删行表格（列表）+ 引用选择器（ref，含搜索与名称显示）。
- **批 5 · 技能派生界面**（你点名）：派生链编辑——「触发技 → 步骤（**派生条件** / **派生技能** / **派生消耗** / 数值覆盖）」；
  实数据形态：`skill_chains.json` 的 `{trigger_skill, steps:[{from,to,condition{count|self_marks|target_marks},consume,mode,variant_override}]}`
  ——**通用实现**（引用字段 + 条件行 + 数值覆盖组），不写死"派生"这个业务词以外的东西。
- **批 6 · 增删条目 + 检索**：新增/删除条目、ID 生成规则、搜索/过滤。
- **批 7 · 终验**：全量回归 + 实机抽查（多包切换验证「换包零改动」）+ 文档定稿 + 使用说明。

## 五、不做的事（明确排除）

- 不做富文本编辑、不做多人协同、不做版本 diff 视图；不复刻已删除的旧编辑器目录结构（新写）。
- 不把任何内容包的专属业务结构（属性表/套装/词条/buff 表）写进编辑器框架——它们只作为元数据声明的示例。
- 不在本方案外"顺手"加功能；需要就新开一批并先更新本文件。
