## 一、设计哲学与架构

### 1.1 一句话哲学
> **效果是数据（effects.json 唯一数据源），行为是动作（原子动作），语义是引擎（四模型）。**
> 作者只声明语义标签（frame/decay/resist/immune），不写逻辑；裁决管线由框架引擎统一执行。
> 唯一数据源 = **效果配置家族（effects/statuses/marks 三表）**。

### 1.2 三层分工（GBF 管结构 / DM 管行为 / 参考管表达）
```
结构层（怎么叠/怎么存）← GBF：叠加框架 Dual/Single、累积/等级制、来源同侧、数值上限、弱体耐性、免疫盾 Mount
行为层（怎么耗/怎么互动）← DM：三型衰减、施加后抗性、免疫vs护盾分工
表达层（怎么触发/怎么呈现）← 用户参考：触发概率三态、持续双维、特效家族、增减益分类、刻印→印记
```

### 1.3 三层分类
```
L2 特殊效果 special —— 事件驱动、概率触发、可带冷却、挂来源方（追击/反击/反弹/偷取/穿透/续行/免疫）
L1 增减益 status —— 挂目标方、双维持续（turns×charges）、叠加规则（强化/反制/治疗/弱体/封锁/伤害）
L0 原子动作 atomic —— 无概率无持续的执行体（damage/heal/stat_modifier/dot/control/proc/shield/...）
```
- L2/L1 的"身体"都是 L0 动作列表；L2 按事件触发，L1 按 tick/次数结算
- 印记（marks.json）是独立第四类标记，施加/消除/条件复用 L0 动作与统一寻址
- 特殊效果/增减益/原子动作均可配置到任意挂载点（装备/套装/技能/敌人/道具），挂状态给装备仅警告平衡风险

### 1.4 挂载点（六处统一引用/内联）
```
skills.json（技能）｜ items.json（装备）｜ effects.json（套装效果）
statuses.json（状态）｜ traits.json（特性）｜ enemies.json（敌人技能）
```

### 1.5 旧配置自动迁移
- 内联 effects 数组 → effects.json ID 引用（热重载自动迁移）
- 语义字段取默认值（frame:single、decay:none、resist:off），旧配置零改动可跑

## 二、触发概率体系（参考原味）

### 2.1 概率三态
```
- -1：必定触发
- 0~100：固定概率
- +0~100：幸运修正（公式 =（√我方幸运 - √对方幸运 + 概率）%）
- 边界：-1 不参与幸运修正；0~100 固定不修正；+0~100 修正
```

### 2.2 装备概率表达式与锁定
```
- 支持 "～" 和 "d" 组合："+3～6d4" = 进行 3~6 次 d4（受幸运影响）
- 装备概率【获得装备时计算并锁定】，锁定后 = +[锁定后概率]（不再受幸运影响）
- 锁定概率随装备实例持久化（获得时写入实例，天然随存档，不漂移）
```

### 2.3 同类效果规则（参考原味）
```
- 同类特殊效果互相独立，触发一次后不再触发其他同类
- 同类增减益互相叠加，但持续时间不互相叠加
```

### 2.4 触发上限（防刷，双重）
```
- 每回合触发上限（默认 10，可配）——防单轮递归刷屏
- 每场战斗触发上限（默认 99，可配）——防整场无限触发
- 【免死类（续行/致命免疫/不死续行）默认每场 1-3 次，可配 0=不限】
- 快照记录 effect_triggers 计数（中断恢复不丢上限）
- 特效链深度上限（默认 3，可配）——防递归无限
```

### 2.5 proc 触发容器（框架 3.4 扩展）
```
proc = 通用特效容器：{trigger(事件), chance, cooldown, actions(子动作列表)}
- 特效模板（追击/反击/续行等）= proc + 预置参数
- 触发事件枚举：on_attack/on_hit/on_skill/on_death/on_turn_start/on_turn_end/...
```

## 三、特殊效果全表（攻击/防御特效）

### 3.1 公共参数
```
作用范围：装备/套装/技能
触发概率：三态（2.1）+ 装备表达式锁定（2.2）
冷却时间：默认为 0，回合单位，支持 ～/d 表达式
  安全区清除所有冷却（副本安全区除外，见副本定稿 §2.1）；野图/副本安全区用 /休息 指令减冷却
  （默认 3 回合，可配，与技能冷却一致——语义见下【/休息 指令语义】）
 冷却剩余回合入快照（effect_cooldowns，中断恢复不白嫖）
QQ 适配：特效一句式反馈（"⚔️ 追击！额外 12 伤害"），合并进一轮消息
```

【/休息 指令语义（战斗外指令 · 已登记框架 7.1 指令表）】
```
- 使用时机：非战斗回合（战斗外指令）；战斗中不可用（战斗内请走战斗行动指令）
- 可用地点：野图（非战斗状态）＋ 副本安全区（副本定稿 §2.1）；其余场景（战斗中/副本非安全区）不可用
- 效果（数值全部可配，倾向百分比）：
  · 冷却缩减：当前冷却中的技能/特效冷却 −N 回合（默认 3，可配）
    ——作用域=当前冷却中的冷却项（技能冷却与特效冷却同池递减，见 3.1）；不在冷却中的不受影响
  · HP/MP 恢复：部分恢复（默认各 20%，可配；支持固定数值或百分比，倾向百分比）
- 防刷：一天使用次数上限（默认 3 次，可配；0=不限），次数随存档持久化（快照 rest_usage）
- 与安全区清除的关系：/休息 = 减冷却，≠ 安全区全清（全清仅在"进入安全区"时触发，见 3.1/4.1）
- QQ 适配：一句式反馈（"🛌 休息：冷却 -3，HP/MP 恢复 20%"），并入 /帮助 速查
```

### 3.2 攻击特效（4 类，抢攻已砍）

| 特效 | 效果 | 子型 |
|---|---|---|
| **追击** | 造成伤害时，按伤害百分比额外造成一次伤害（可配伤害公式） | 普攻/技能/弱点/暴击追击 × 自/固定/弱点属性 |
| **生命偷取** | 造成伤害时，按百分比回复生命 | 普攻/技能偷取 |
| **物理穿透** | 伤害结算时，无视对方一定百分比防御 | 普攻/技能穿透 |
| **魔法穿透** | 伤害结算时，无视对方一定百分比精神 | 普攻/技能穿透 |

### 3.3 防御特效（5 类）

| 特效 | 效果 | 子型 |
|---|---|---|
| **反击** | 敌人攻击后，造成一次普攻伤害（可配公式） | 受伤/回避/格挡反击 |
| **反弹** | 受伤害时，减少对方伤害一定百分比，并对对方造成等值伤害（可配公式） | — |
| **伤害吸收** | 受伤害后，回合结束时按受伤害回复一定百分比生命（可配公式） | 护盾吸收（护盾挡的伤害也计入） |
| **战斗续行** | 受致命伤害时，保留 1 点生命（触发瞬间回复，可配） | 治疗续行（触发后回复）/ 不死续行（触发后数回合无敌；无敌是否挡 debuff 可配） |
| **致命免疫** | 受致命伤害时，免疫这次伤害 | 非致命免疫（受伤害时免疫） |

### 3.4 伤害拦截链总顺序（默认管线，可配数组，P0-1）
```
受伤害时按此顺序结算（默认管线，可配数组调整顺序，异常顺序如"死亡判定在扣血前"仅警告）：
① 减伤/减免（mitigation 类：普攻/技能/异常/暴击/属性）
② 护盾先扣（shield 吸收量）
③ 反弹（按 % 减伤并反弹；反弹伤害不触发反弹）
④ 伤害吸收（记录反弹后实伤，回合末回复）
⑤ 致命免疫/非致命免疫（全额免伤，消耗 triggers 计数）
⑥ 战斗续行（锁 1 血）
⑦ 扣血
⑧ 死亡判定
```
```
- "免疫不挡伤害" = 限定【状态免疫】（挡负面状态不挡伤害）；致命免疫/非致命免疫 = 伤害免疫（挡伤害）
- 不死续行无敌 = 免疫全部伤害（是否挡 debuff 可配）
- 续行与致命免疫同时存在：致命免疫先判（H1 同类型互斥建议下，作者不会同时配，但引擎按管线执行）
```

### 3.5 特效级联规则（含递归限制，P0-2）
```
- 追击/偷取/穿透互相可链（追击触发偷取）
- 【递归限制】：
  · 派生伤害（追击/反弹/穿透）不触发对侧反击/反弹
  · 派生伤害不触发同类自身（追击不触发追击）
  · 特效伤害不进 on_attack 事件（特效=附加伤害非攻击）；需要时用 on_hit 显式配置
  · 链深度上限（默认 3，可配）
- 多个同种特效只触发一个
- 特效攻击不进连段轴/不吃打断/不受霸体影响（边界：特效是附加伤害非行动）
- 校验器：特效链环检测（图论环检测，防反弹乒乓死循环配置）
```

## 四、增减益全表

### 4.1 持续双维（参考原味 + 结算时点）
```
- 持续回合 × 可触发次数 双维：
  · 回合 0 + 次数 10 = 触发 10 次后消失
  · 回合 10 + 次数 0 = 10 回合内无限触发
  · 任意维度 -1 = 永不被安全区清除，/休息 的 −N 回合/N 次亦不作用于 -1 维
- 结算时点（P0-3）：
  · 次数在【触发时】扣减
  · 持续回合在【回合结束 tick】扣减（写明与 dot/控制结算顺序）
  · 衰减在【携带者行动结算后】扣减（P0-3/H8：携带者每次行动结算后衰减一次，非双方都衰减）
- 安全区清除所有增减益；/休息 指令对持续双维 −N 回合/N 次（默认 3，可配，语义见 §3.1【/休息 指令语义】）
- 副本安全区不清除增减益，只触发一次相当于 /休息 的效果（副本定稿 §2.1：安全区内手动使用 /休息；
  "进入自动结算一次/每副本一次"为可配项）
```

### 4.2 增益（强化/反制/治疗/其他）
| 分类 | 效果 |
|---|---|
| 强化 | 属性提升、多重追击 |
| 反制 | 减益免疫（弱体/封锁/伤害/驱散分型）、驱散（强化/反制/治疗分型）、净化（弱体/封锁/伤害分型）、伤害减免（普攻/技能/异常/暴击/属性分型） |
| 治疗 | 再生（回合末回复生命） |
| 其他 | **刻印 → 印记**（无法消除指示物，同名叠加，技能根据印记数变化——并入印记系统） |

### 4.3 减益（弱体/封锁/伤害）
| 分类 | 效果 |
|---|---|
| 弱体 | 属性下降 |
| 封锁 | 混乱（行动变随机普攻，受击解除）、沉默、睡眠 |
| 伤害 | 中毒/灼烧类持续伤害 |

### 4.4 驱散/净化对象寻址
```
- 统一寻址：{target: self/enemy, filter: 分类, count}
- 驱散 = 清目标增益（filter：强化/反制/治疗）
- 净化 = 清目标减益（filter：弱体/封锁/伤害）
- 免疫 = 拦截下一次指定类型（filter 同上）
- FIFO 顺序消除（先施加的先被清）
- 【印记引导（H7）】：净化/驱散命中印记时给引导反馈
  （"🧹 净化！但诅咒印无法被净化，需消除类技能"）；印记行对可消除印高亮
```

## 六、四大模型（GBF × DM 整合）

### 6.1 模型一：叠加规则（GBF）
```
- 叠加框架 stack_frame（下拉）：
  · single（默认）：同类高覆盖低（新覆盖旧）
  · dual：不同框架并存相加（两个降攻技叠出压制流）
  · stack：累积叠层（设上限 max_stack，默认 2-3）
- 等级制：带 Lv 效果（冰结/感电）等级制叠加（max_level 默认 5）
- 来源同侧：同来源同侧只保留一个，强覆盖弱、等强覆盖重置持续时间
- 数值上限：攻防提升满值上限（+100%，可配）
- 【三维组合上限（H3）】：dual×累积×等级总加成上限（校验器理论最高值检查）
```

### 6.2 模型二：衰减与持续（DM 三型 × 持续双维）
```
- decay 衰减下拉（DM 三型）：
  · none（默认）：不衰减
  · halve：每次行动数值减半（中毒/再生/荆棘型）
  · decrement：每次行动数值 -1（虚弱/易伤/控制型）
  · trigger：触发时 -1/减半（护盾/闪避/镜像一次性型）
- 衰减主体（H8）：携带者每次行动结算后衰减一次（非双方都衰减）
- 与持续双维共存：衰减 = 数值消退节奏；持续双维 = 存在时长
- 结算时机：行动结算后（与 3.1 回合时序对齐）
```

### 6.3 模型三：耐性与抗性（GBF 弱体耐性 × DM 施加后抗性）
```
- 弱体耐性（GBF）：影响弱体命中率
  · hit_rate：基础命中率（默认 100 必中）
  · 目标耐性修正：耐性越高越难命中
- 施加后抗性（DM）：施加 debuff 后目标获得对应抗性
  · 默认关（resist_gain: false），内容包可开
  · 开启后：越挂越难（控制类"少量多次"优于一次堆高）
- 抗性表：战斗内 per-actor（入快照）
```

### 6.4 模型四：免疫体系（GBF 免疫盾 × DM 免疫vs护盾 × 参考致命免疫）
```
- 免疫 vs 护盾分工（DM）：
  · 状态免疫挡负面状态，不挡伤害
  · 护盾挡伤害，不挡 debuff
- 免疫矩阵（immune_vs 维度，statuses.json 字段）：
  · status：状态免疫（挡负面状态，不挡伤害）
  · damage：伤害免疫（致命/非致命免疫，全额免伤）
  · interrupt：打断免疫（免疫打断=清连段类动作）——【霸体 = 该维度免疫，由 armor 提供】；
    霸体语义归口本体系「对打断维度的免疫」，技能派生定稿 armor 为语义源引用（armor=true ⇔ immune_vs 含 interrupt）
  · all：全免疫（不死续行无敌，是否挡 debuff 可配）
- 免疫盾 Mount（GBF）：单次弱体盾（抵消下一次弱体）
- 致命免疫/非致命免疫（参考）：受致命伤害免疫（伤害免疫）
- 战斗续行：受致命伤害保留 1 点生命
- 消耗性免疫：可配 triggers 计数（免疫 N 次后消失）
- 【免死约束（H1）】：免死类默认每场 1-3 次（可配）+ 同类型互斥为默认（可配 allow_dual_fatal_guard）
  （校验器提示"已装备致命免疫，战斗续行将不生效"）；PVP 可禁用免死类
- 免疫拦截链顺序见 3.4 伤害管线（护盾→免疫→续行→扣血）
```

## 七、原子动作词汇表（L0 定稿，含 aoe 保留）

```
直行动作（主动执行）：
  damage 直接伤害 ｜ heal 回复 ｜ stat_modifier 属性修正
  dot 持续伤害（tick 回合开始/结束） ｜ control 控制（skip_turn 概率）
  status_apply 施加状态 ｜ dispel 驱散 ｜ shield 护盾（吸收量/破盾条件，P0-4 新增）
  mark_add/mark_remove/clear_marks 印记
  summon 召唤/临时单位 ｜ convert 素材转换（N→M） ｜ interrupt 打断（清连段）
  【interrupt 唯一实现（归口声明）】：打断的唯一定义 = 本词汇表 L0 原子动作，效果执行一律走 effects.json 引用；
  技能派生定稿 tag「interrupt」（仅派生语义标记）、技能库行动库布尔字段 interrupt、
  怪物行动 AI「打断=套完结」均为其语义引用或副作用表现——不另立实现、不重复定义规则
  aoe 范围效果（1v1=对目标+提示，保留 3.4 已有）
```

### 7.1 减防 / 易伤 / 穿透模板（三模板归口 · 组6 F4）

```
定位：攻击方侧「提升对高防目标伤害」语义的唯一出口 = 以下三条正式模板（effects.json 模板库）；
技能只写 ID + 覆盖参数，不再各自内联 / 自造参数结构。

统一参数结构：
{ "type": "def_down"|"vulnerable"|"pierce", "target": "con"|"physical_def"|"damage_taken", "value": 20, "pct": true }
- type：模板枚举（三选一）
- target：作用属性（def_down 可特化 physical_def；vulnerable 固定 damage_taken；pierce 无 target）
- value：数值（def_down/vulnerable 为增减量；pierce 为无视防御百分比）
- pct：是否百分比（def_down/pierce=true；vulnerable=false）

三类模板：
| 模板 | 语义 | 落点 | 默认参数 |
|---|---|---|---|
| ① 减防 def_down | 降低目标防御属性（属性减防） | L1 status（stat_modifier 弱体） | target=con · value=-20 · pct=true |
| ② 易伤 vulnerable | 目标受击伤害增加（damage_taken 通道） | L1 status（stat_modifier 弱体） | target=damage_taken · value=0.3 · pct=false |
| ③ 穿透 pierce | 本次伤害无视目标防御 X% | L0 结算修正器（3.2 物理/魔法穿透） | value=30 · pct=true |

五实现映射（组6 F4 全部归口，数值不变）：
| 原实现 | 映射模板 | 说明 |
|---|---|---|
| 剑士断空斩 def_down（con -20% pct） | ① def_down | target=con · value=-20 · pct=true（模板默认值） |
| 斗士碎甲击 armor_break（con -20% physical_def） | ① def_down | 物理防御特化：target=physical_def · value=-20 · pct=true（原 scope:physical_def 并入 target 字段；自造 ID apply_armor_break/armor_break 删除） |
| 弓手弱点击破 weak_expose（damage_taken -0.3） | ② vulnerable | target=damage_taken · value=0.3（原 weak_expose ID 并入模板） |
| 打类型内置破防 20%（战斗数值层 type_affinity.blunt_pierce） | ③ pierce（倾向通道） | 武器类型倾向自动生效，见下方边界 |
| 穿透（弓手贯穿箭 30% / 连段版翔天 40%） | ③ pierce | L0 修正器，技能 overrides.percent 覆盖 |

边界：内置破防 vs 穿透（两行）：
- 内置破防 = 打系武器类型倾向（type_affinity.blunt_pierce，战斗数值层 formula.json）：携带打击类武器自动生效，无状态无消耗，数值不可配
- 穿透 = 技能/效果修正器（L0 pierce）：按技能显式配置生效（贯穿箭 30% / 翔天 40%），可挂任意攻击类型，不依赖武器类型
- 叠加关系：有效防御按 防御 ×（1−内置破防）×（1−穿透）结算，具体管线顺序归战斗数值层，本小节只声明语义归属

同语义唯一性：该语义只允许走以上三模板 + 内置破防倾向；校验器对自造同义 type / x_ 通道给提示（建议不拦截，禁止第 6 个实现）。
```

### 7.2 生存模板库（护盾 / 减伤 / 吸血 / 回复 四类归口 · 组6 F3）

```
定位：生存类效果（护盾/减伤/吸血/回复）语义的唯一出口 = 以下四类正式模板（effects.json 模板库）；
技能只写「模板 ID + 覆盖参数」，不再各自内联 / 自造参数结构、不重复登记同名效果 ID。
生存模板库 = 框架效果模板（编辑器模板库一键插入），职业只填参数；数值以职业填写为准（原数值一律不变）。

统一参数结构：{ "effect": "tpl_<类>_<默认值>", "overrides": { value / turns / stat / trigger / scope ... } }
- effect：模板 ID（下表标准 ID）；overrides：职业覆盖参数（只写要改的字段，不写 = 模板默认值）

四类模板参数表：
| 模板 | 语义 | 标准 ID | 默认参数 | 可覆盖 |
|---|---|---|---|---|
| ① 护盾 shield | 吸收伤害（拦截链②，先扣盾再扣血） | tpl_shield_30（基准 30%max）· tpl_shield_15 | value=30%max_hp · turns=2 · target=self | value（%max 或固定值）、turns |
| ② 减伤 mitigation | 受击伤害减免（拦截链①） | tpl_mitigation_10（基准 10%）· tpl_mitigation_8/15/30 | value=10% · scope=all · turns=-1（常驻） | value、turns、scope；受击耗资源结构 = trigger on_hit + 资源消耗 + 每回合上限 1（标注型参数，非新模板） |
| ③ 吸血 lifesteal | 造成伤害时按伤害 % 回复生命（L0 结算修正器） | tpl_lifesteal_10（基准 10%） | value=10% · 触发=on_attack（随伤害自动结算）· scope=skill | value（8/12 等覆盖）、scope |
| ④ 回复 regen/heal | 生命回复：即时 heal 或回合末再生 regen | tpl_heal_lost（30%lost 基准）· tpl_heal_max（30%max 基准）· tpl_regen（10%max·回合末基准）· tpl_heal_mp（MP 变体，value=3 基准） | tpl_heal_lost：value=30%lost_hp · 时点=即时；tpl_heal_max：value=30%max_hp · 时点=即时；tpl_regen：value=10%max_hp · 时点=回合末；tpl_heal_mp：stat=mp · value=3 | value（%max/%lost/固定值）、stat（hp/mp）、时点（即时/回合末/on_turn_start/on_turn_end/on_skill）、turns |

时点矩阵声明（两行，衔接组1 F4 + 组6 F3）：
- 回复四路时点（组1 F4）：即时 heal ／ 造成伤害时 lifesteal ／ 受伤害后回合末 伤害吸收 ／ 回合末 再生——四个时点语义不同，不得混用；模板库文案标注，防作者把四种当一种配置
- 回蓝触发时点（组6 F3，四选一矩阵）：即时（主动技）／ on_turn_start ／ on_turn_end ／ on_skill——MP 回复一律走 tpl_heal_mp + trigger/时点覆盖，不再自造回蓝效果 ID

F3 全量归口映射（数值一律不变）：
| 原实现 | 映射模板 | 覆盖参数 |
|---|---|---|
| 减伤被动 ×4：斗士意志 10% / 灵巧身法 10% / 硬气 8% / 棍势 10% | ② tpl_mitigation_10 | 斗士/弓手/棍势=模板默认；硬气 overrides value=8 |
| 护盾+减伤组合 ×4：钢盾架势 30%+10% / 水之壁障 30%+10%（方案稿）/ 水镜壁垒 30%+15% / 寒冰护体 35%+再生（方案稿） | ① tpl_shield_30 + ② tpl_mitigation_10/15 | 钢盾架势=模板默认×2；水镜壁垒 ② turns=2；寒冰护体 ① overrides value=35%max + ④ tpl_regen（方案稿仅标注引用方式，不改文档） |
| 受击耗资源减伤 30% ×2：能量屏障（元素法师）/ 气合护体（炼气版） | ② tpl_mitigation_30 | 结构标注：trigger=on_hit + 资源消耗 1（energy/qi）+ max_triggers_per_turn=1 |
| 吸血 ×3：气刃突刺 8% / 龙穿连舞·终 12% / 穿龙翔天 12% | ③ tpl_lifesteal_10 | overrides value=8 或 12 |
| 回复 ×2：剑心呼吸 30%lost / 和风细雨 35%max+再生 3 | ④ tpl_heal_lost / tpl_heal_max + tpl_regen | 剑心呼吸=模板默认；和风细雨 overrides value=35%max / turns=3 |
| 回蓝 ×6（3 触发时点 + 主动即时）：战意(on_turn_start·2) / 元素亲和(回合末·3) / 疾风回气(on_turn_start·3+条件) / 周天炼气(on_skill·3) / 炼气心法(on_turn_end·3) / 气合蓄势(主动·10) | ④ tpl_heal_mp | trigger 按时点矩阵选一 + overrides value |
| 形态状态减伤：腾空架势 10%（3 回合）/ 气旋闪 15%（2 回合） | ② tpl_mitigation_10/15 | overrides turns=3 / 2（敏捷修正为 stat_modifier，非模板类） |
| 护盾 ×2：升龙破 15%max（2 回合） | ① tpl_shield_15 | 模板默认 |

同语义唯一性：护盾/减伤/吸血/回复语义只允许走以上四类模板；校验器对自造同义 type / x_ 通道给提示（建议不拦截）。
受击耗资源减伤、回蓝触发时点等为模板参数/标注，不另立模板、不重复登记效果 ID。
```

## 九、编辑器 / 校验器 / 级联删除

### 9.1 编辑器（效果页+印记页同卡）
- 效果页：特殊效果/增减益/原子动作三标签页 + 特效模板库（一键插入，含 §7.1 三模板 + §7.2 生存四类）
- 印记页：同卡标签页（marks.json 配置）
- 状态定义表单：类型/分类/叠加框架下拉/衰减下拉/耐性/免疫
- 动作字段注册表（4.2 元数据，全模块共用一张表）

### 9.2 校验器
```
1. 效果 ID 引用存在性（技能/装备/特性/状态/敌人）
2. 印记引用存在性 + 条件 vs 叠加上限矛盾
3. 概率范围（-1 或 0-100）与表达式合法性
4. 衰减类型枚举合法 + 衰减主体合法
5. 特效链环检测（图论环，防反弹乒乓）+ 链深度 ≤ 上限
6. 免死类互斥提示 + 免死类触发上限提示（默认 ≤3，可配，超限警告）
7. 三维组合理论最高值检查（dual×累积×等级）
8. 消除技检查（cooldown≥1、全消≥3）
9. 引用失效兜底（删配置按"无效果"降级不报错）
```

### 9.3 级联删除
- 删效果 → 清理技能/装备/特性/状态引用
- 删印记 → 清理 mark_add/remove/条件引用
- 热重载：快照冗余存储（ID+名称），删配置降级不报错

## 十一、风险与简化

| 风险 | 对策 |
|---|---|
| 效果分散（六表各写各的） | effects/statuses/marks 三表唯一数据源 + ID 引用 |
| 配置负担 | 默认值兜底 + 特效模板/生存模板库 + 下拉 |
