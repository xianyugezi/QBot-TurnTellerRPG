## 五、② 设计缺漏清单（定稿/细化要求但实现没有）

### 🔴 P0-1 marks.json 定义 schema 与定稿 10 字段不符（AT-01/03/04/05；evaluator 无载体；V-8 默认内容失败）
- **位置**：content/field_meta.py L105-113（marks_fields）；qbot_rpg 全库无生产 marks.json（仅 tests/fixtures/packs/legal/marks.json 一条且字段不符）；marks.py L226-239（只读 max_stack/polarity/duration 三个定义字段）。
- **实际**：marks_fields = {id, name, type(enum "mark"), max_stack, duration, probability, require_status, apply_status, apply_effect}——缺失定稿 §二 10 字段中的 **icon / appliable_to / polarity / element / desc**（5 项），反多出 status 型字段 **probability/require_status/apply_status/apply_effect**（非定稿 marks 字段）；duration 按 `F_DURATION(number)` 而非 `"battle"/"turns:N"` 字符串。内置样例仅 test fixture 的 fire_mark 且也无 polarity/appliable_to/element/desc（`"duration": 0` int，「curse_mark」缺失）。
- **应有**：定稿 §二 10 字段（L212-214「id|name|icon|type=mark|max_stack|appliable_to|polarity|element(可选引用)|duration|desc」）；细化 §1.1 字段表（行 52-61）含 appliable_to ⊆ {self,enemy}、element ∈ formula 注册表；验证 AT-01（10 字段全加载+未登记字段拒绝）、AT-03（appliable_to 空/非法→拒绝）、AT-05（element 未注册→拦截）、AT-04（极性非法→拒绝、实例与定义一致）；V-8「marks.json 随仓库落地内置样例 火印/诅咒印」（行 91）。
- **影响**：marks.py 的 polarity_of()（L226-232）因定义无 polarity 字段而**恒兜底 positive**（威胁印/诅咒印永不成立）；appliable_to/element/icon/desc 无任何配置与校验载体（AT-01/03/04/05 全部不可达）；兑换「evaluator」（敌人印记可配每回合触发效果，细化 §4.3/§七）亦无任何配置字段。任务提示的 AT-01/03/05 缺漏 = 属实，且根因在 schema 表而非 marks.py 本体。
- **证据**：field_meta.py L105-113；细化_1d §1.1 表行 52-61、V-8 行 91、AT-01 行 241、AT-03 行 243、AT-05 行 245、AT-04 行 244；定稿 §二 行 36-51、§八 行 212-214。

### 🔴 P0-2 条件原语规范实现零接线，且实战语法与定稿 §5.1 规范失配（AT-14）
- **位置**：marks.py L366-410（evaluate / eval_condition / MarkCondition）；combo.py L372-399（_eval_marks）/L468-472；battle.py L1150-1159（_marks_lookup）。
- **实际**：`MarksManager.evaluate` / `eval_condition` / `MarkCondition` 全 qbot_rpg **零调用方**（含 tests，grep 实证），即"方法本体零调用"。实战条件路径 = battle._marks_lookup → **mm.total/mm.count**（battle L1150-1159）→ combo._eval_marks（combo L372-399），该路径只识别 **{"has": [ids], all?}** 方言（test_combo.py L156/175/176 亦用 has 方言）。定稿 §5.1 / 细化 C-1..C-5 规范语法：

  - `{"marks_set": {"all": ["地","水","火","风"]}}` → 同上 ids_l 空 → 无 min/max → **恒 True**。
- **应有**：细化 §3.1 C-1..C-5（行 146-150）与定稿 §5.1（行 138-142）语法求值一次、施放前快照（行 153）；AT-14 五型各一断言（行 264）。
- **影响**：按定稿语法配置印记条件的派生技能，印记条件**恒满足**（反安全方向，派生无条件触发）；规范五型语义只在死代码 evaluate 中存在。AT-14 不可达。
- **证据**：marks.py L366-410；combo.py L379-399（`ids = sub.get("has")`、无 min/max 顶层键时 return True）；battle.py L1150-1159；细化 §3.1 行 144-150 / §5.1 行 138-142；AT-14 行 264。
- **修复建议**：battle._marks_lookup 或 combo 印记子句改接 `marks_manager().evaluate`（按 kind 五型+syntax），或 _eval_marks 增加对规范语法（单印 {mark_id:{min/max}}、marks_set {all:[...]}）的解析；未识别键→安全失败（False）。
