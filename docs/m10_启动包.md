## 〇、M10 一句话定位

**钓鱼 = 生活系统第五件套（内容包玩法包）**：在垂钓点抛竿 → 懒计算等待 → 鱼讯意图预告（微动/拉扯/猛烈）→ /收杆 三选一（满力/自动/止损）→ 出鱼结算（鱼种×大小×重量×冠级六档）。**机制零新增纯配置**——复用 maps 采集点 / farming 懒计算 / 怪物 AI 意图预告 / reward 发放器 / codex_state / proficiency / 炼金 recipe。用户原创**冠级体系**（大小×重量六档，纯图鉴记录不碰数值）。

## 二、核心机制速览（开工前必读，防走偏）

1. **冠级六档**（§2.2，用户原创 ★）：逆金冠 0.25% / 大金冠 0.25% / 金冠 9.5% / 大银冠 1.0% / 银冠 17.0% / 普通 72.0%；判定顺序**写死**：逆金冠→大金冠→金冠→大银冠→银冠→普通（混合极端 size≥95 且 weight<5 按金冠）
2. **冠级纯收藏**（§2.3 铁律）：只做图鉴记录与社交展示，**不参与**价值/经验/售价——差分测试必须为 0
3. **收杆三选一**（§1 M5）：满力（升级 roll，+稀有度/冠级概率）/ 自动（基础 70/25/5）/ 止损（提前收，饵已计扣）；**无小游戏**（用户拍板删除 M5 蓄力小游戏）
4. **mode 三态**（v1.0.1）：full 完整流程 / simple /钓鱼 直接出鱼（无等待鱼讯鱼王）/ off 关闭拒绝
5. **鱼王事件**（§1 M7）：猛烈鱼讯金闪 → 鱼王 BOSS 战（enemies 引用，复用 BOSS 引擎）；enabled=true / window_daily=2 / chance=0.3
6. **钓鱼王称号**（§四）：图鉴全亮（含鱼王事件 2 次）授予；MC 200 次中位 ~332 竿（种子 2026）
7. **数值锚点**（§四）：普通饵单次期望 ≈22.8 金（净 +12.8），日 20 次 ≈256 金，**低于战斗不冲击经济**
8. **鱼讯参考文案**：微动=小鱼 / 拉扯=中鱼 / 猛烈=大鱼或鱼王（说明特点不教攻略，图鉴不写判定公式）

## 四、关键接口缺口（开工前先摸底确认）

1. **farming.harvest_sec 懒计算签名**：种植的定时收获函数是否可直接复用给钓鱼等待（参数/返回形态），还是需薄包装。
2. **monster_intent 意图预告**：三类鱼讯（微动/拉扯/猛烈）是否直接复用现有意图分类器，还是 fishing 需自建轻量意图生成。
3. **codex type=fish**：codex 分册当前枚举（craft 等）如何扩展 fish 类型 + 冠级记录字段落点。
4. **reward 统一发放器**：出鱼结算（图鉴点亮+熟练经验+金币/物品）是否一条 reward 调用搞定。
5. **鱼王 BOSS 战接线**：enemies 引用鱼王 → 是否走现有 BOSS/战斗引擎入口（参考 M9 锻造与战斗的联动方式）。
6. **proficiency 钓鱼职业实例**：proficiency.json 加 fishing 职业实例是否影响既有逻辑（参考 M9 加铸造职业的先例）。
7. **模板配置化**：所有钓鱼消息模板走 `tpl_of(ctx, "fish_*", {...})`（templates.json 白名单），**禁止写死**——沿用 M9 后全仓模板配置化铁律。

## 七、坑位提醒（M8/M9 部署实测教训，必读）

1. **F3 嵌套事务**：抛竿/收杆原子指令在 processing 的 repo.tx 内运行，内部不得再自开 repo.tx
2. **Def→dict 表注入**：ctx["fishing"] 走 _table_from_registry 必须转 raw dict + resolve 单参包装
3. **qid 键注入**：ctx["qid"] 必须注入（仅 qq_id 时 _qid_of 读不到 → 会话/存档主键错）
4. **单测掩盖部署 bug**：直测引擎不暴露装配层问题——每批须 run_command + 真实 DB 全链路实测
5. **用户拍板不可擅改**：冠级纯收藏（不碰数值）、收杆无小游戏、判定顺序写死、说明不教攻略——都是定稿铁律
6. **随机可复现**：冠级/收杆概率必须种子化（种子 42/2026 可复现），实现不得用裸 random（无固定种子）
7. **来源纯度**：冠级体系是用户原创，借他版机制（鱼讯=怪猎意图预告）需显式标注来源
8. **模板写死零容忍**：沿用全仓模板配置化铁律，任何新消息模板进 templates.json 分区
