## 三、P1 问题清单（必改）

### P1-1［DEC-04 区块，跨文档矛盾+定稿未支持推导］
- **2c4c L112（DEC-04）**：「宝石实收 = ⌊基础值 × 回收率⌋」；且 L112 末「低阶分解（正式-精通）宝石产出建议**关闭/减半**，完整宝石产出随大师「分解回炉」放开」。TC-27（L280）「宝石（精良基础值 3 按回收率折算）」。
- **对照**：同批 `2c4b` L104（DEC-03）：「宝石 = 分解时成品**最终品质档对应基础值**：普通 1/精良 3/史诗 8/传说 20（可配）；两段式结算」——**平铺口径，无 ×回收率、无大师闸门**。两文档对同一结算给互斥公式。
- **定稿证据**：L224「分解基础值：普通 1/精良 3/史诗 8/传说 20（可配）」、L419 `gem:{分解:{common:1,uncommon:3,rare:8,legendary:20}}`——只给平铺基础值，**全文无一处声明宝石×回收率**；L169「返还=配方材料×回收率向下取整」的×回收率**明确限定"配方材料"**；L207「回收 40-60% + 产出宝石」中"回收"指材料侧，"产出宝石"并列。L248「宝石×5」为叙述示意（两口径均验算不符：传说×0.6=12、平铺档 3/8/20，均≠5），2c4c 对其"叙述示意值"判断正确。
- **裁决倾向（上报不裁决）**：按定稿字面，**2c4b 平铺口径更贴定稿**；2c4c 的×回收率与大师闸门均属定稿未定义的推导+新增门控，且与同批文档矛盾。**建议**：统一为平铺基础值（或提交用户/仲裁定案后两文档同步），TC-27「按回收率折算」改为「平铺 3」，DEC-04 低阶关闭/减半门控与 2c4b SRC-01 的来源口径（无级别门控）二选一。

### P1-2［CMB-07，A+B 分隔符冲突（任务点 b）］
- **2c4c L79（CMB-07）**：「参数 A+B 以 `+` 分隔；…实现统一为 A+B 项内可带 `*`：`/成品合成 炼狱爆弹·改*2`」；TC-12（L250）「/成品合成 炼狱爆弹·改*2」、TC-17（L255）「/特性合成 攻击+15%+攻击+10%」均以 `+` 作 A/B 分隔。
- **对照**：`2c4d` L55（注2）+ P-09/P-12/P-13（L165/200/213）+ SEP-09/12/13（L171/207/219）：「`A+B` 记法在实现层落为**两个空格位置参数**——物品/特性名禁用 `+`（【分隔符】L58），不存在解析歧义」；【分隔符】L19「`+` 是等级/数值标记，不用于分隔」、L46-51「位置参数 ≤2（空格）」、L58「物品/配方/装备/特性/珠名：禁止空格、禁止 `* , = + /`（保留字符）」。定稿 L12 已声明全部指令遵循分隔符规范。

### P1-4［TC-02，宝石累计数值不自洽（任务点 c）］
- **2c4c L230（TC-02）**：「升阶全链路：3×普通 → 精良 → 3×精良 → 史诗 → 3×史诗 → 传说，每级 10 宝石；终态 传说攻击珠 = 普通珠×27 + **宝石 30** 换 1 颗」。
- **静态推导验算**（按 BEL-12/L230「10 宝石/次」= 每次 3 颗同档→1 颗高 1 档计一次）：
  - 珠数：1 传说 = 3 史诗 = 9 精良 = 27 普通 → **普通珠×27 ✅ 正确**（3³ 金字塔）。
  - 操作次数：27 普通→9 精良（**9 次**）→3 史诗（**3 次**）→1 传说（**1 次**）= **13 次 × 10 = 130 宝石**。
  - "宝石 30"只含 3 档跃迁（普通→精良→史诗→传说 各 1 次），**漏计"凑齐 3 颗同级"所需的重复升阶操作**；若按仅 3 次操作，则仅消耗 3 普通+3 精良+3 史诗（链上珠数≪27），"27 珠+30 宝石"两数在数学上不存在自洽解。
- **佐证**：同批 `2c4b` L147（TC-11）同样含混（「9 普通→1 精良」（应为 3 精良）、「累计扣 30+10+10」50 也不闭合）。
- **结论**：TC-02 数值错误。**建议**：改为「宝石 130（13 次 ×10）」或明确注明"只计 3 档跃迁、不含凑数重复升阶"的统计口径；2c4b TC-11 同步修订。

### P1-5［settings gem 键名与定稿分裂］
- **2c4c L186（§2.3）**：`"分解": {"normal": 1, "fine": 3, "epic": 8, "legendary": 20}`；L127/152 items.json `quality: "normal"`——键名枚举 **normal/fine/epic/legendary**。
- **定稿证据**：L419 `gem: {分解:{common:1, uncommon:3, rare:8, legendary:20}}`、L411 `quality_tiers: {common:0-39, uncommon:40-59, rare:60-79, legendary:80-100}` —— 定稿 JSON 键名统一为 **common/uncommon/rare/legendary** 并明示「↔ 普通/精良/史诗/传说」映射。
- **结论**：2c4c（及 2c4e QLT-02 L38，批次内自洽）与定稿 $10.6 键名口径分裂；2c4b TC-23 要求"校验器校验 gem 键枚举合法"，键名分裂将直接造成内容包与校验器口径歧义。**建议**：统一为定稿 common/uncommon/rare/legendary（或细化显式声明键别名映射表）。
