## 六、风险与坑位

1. **G0 分层：web 依赖方向**。web/api.py L4-5 声明 `web → {content, core, storage, data}`，任何层不得反向依赖 web；`web` 不得 import `commands`（指令壳层）——/api/reload 复用 GmBackend 时需把 watcher 操作下沉到 content 或经依赖注入，不能反向引 commands。同理 editor/ 服务层保持零 NoneBot（fishing_editor_service 已示范，L63-64 铁律）。
2. **循环 import**。field_meta 与各专项校验器已确立「schema 之家单向持有」模式（field_meta.py:34-40、627-627 注释：forge/fishing/alchemy 定义自包含持有防循环）；正式表注入时新增模块（skill/job/ai/hidden/env_event/log_card 元数据）必须沿用此模式，禁止 field_meta ↔ 专项 models 双向 import（G0 TC-03 静态 import 图铁律）。
3. **认证安全**。5 条认证【缺】全新建：密码 bcrypt/argon2 加盐（5a L148 补白）、token 服务端维护、互踢需会话表、防爆破 5 次锁 15 分钟、公网默认关 + HTTPS 强制 + CSP/CSRF（AU-05）。**切勿自研哈希/加密**；CSP 头 + 渲染转义（XSS）需在响应中间件层统一。
4. **原子写盘**。SV-06 temp+rename 必须落 `content/<pack_id>/` 同目录（跨文件系统 rename 非原子）；**全部文件写完统一触发重载**（不能逐文件触发，否则半套配置窗口）；写盘失败（磁盘满/权限）需回滚已写文件并报人话。现状无任何写盘代码，全新建。
5. **快照回退与"绝不半套配置运行"**。热重载回退机制已就绪（hot_reload.py:352-380），编辑器保存路径必须**复用同一条管线**（保存 → reload → 失败回退），不能另起校验逻辑，否则两套语义漂移（TC-11/14 红线）。
6. **编辑锁/版本冲突**。PUT base_version 409（AU-06/编辑锁）需在写盘层维护版本号；5a 附录 A 声明「编辑锁 UI 不实现」但 API 语义要留（L146、L179）——注意与「从不阻断保存」SV-02 的边界：409 是并发冲突不是校验拦截。
7. **单包框架限制**。PR-03/M-06 的 editor.json 与 /api/packs/active 的「切换启用包」受 TRG-6 单包约束（hot_reload.py:197）；/api/packs 需要包枚举（扫描 content/ 目录），切换启用需要重装配 watcher——现状无包管理代码。
8. **event 键前缀与命名收口**。EV-02 契约写 `longline_counters` 的 `event_count:<事件键>`，现状直接存原键（event_bus.py:150）；event_instance vs event_log 命名差异。改动会连锁影响条件引擎读取（condition_engine.py:601 读 event_counts 非 longline_counters——**实际读取源已与契约口径有出入**，收口前先对齐契约 EV-02 与实现，避免改坏既有条件求值）。
9. **木桩特判**。EV-06 怪物击杀「训练木桩 tier:training 不计」未见特判（battle_commands.py:729 无条件过滤），M12 需补；改前 grep 测试断言（硬计数断言连锁，m12_启动包 L128）。
10. **field_meta 表结构扩展**。FieldMeta 缺中文名/描述字段（P-07 四要素+中文名）；补字段会影响 validator 构造（FieldMeta 是 dataclass，加字段需默认值向后兼容）。fishing_editor_service 的 desc 补白模式（E-2）可参考但那是服务层输出形态，正式表应原生携带。
11. **技能/职业页依赖未接线**。skill/job 两页引擎侧无模块（6a/6b 契约未落地），M12 编辑器无法凭空渲染——需确认是编辑器里程碑内补最小登记（skills.json/jobs.json ModuleMeta+namespace）还是依赖后续里程碑。
12. **fastapi 依赖与测试隔离**。requirements.txt 无 fastapi/uvicorn；api.py 已做惰性 import 占位（L17-23）保证核心层可导入。M12 加依赖后需保持此模式（测试不装 fastapi 也能跑核心层），且 web 路由测试需 mock watcher/registry（避免反向依赖装配）。
13. **前端规模**。六页壳 33 规则中 P-01~P-08/C-01~C-07 全部是前端交互规格（固定视口/左列表右卡片/抽屉/滑条/公式面板），M12 若全量实现前端工作量最大；建议按 m12_启动包 路1A 先做 editor.json + 元数据表单渲染 + CRUD 后端，前端壳最小可用（表格+表单+抽屉）再迭代。
14. **级联删除风险**。5a DELETE 级联（删怪物→地图/掉落；删物品→掉落/商店/任务奖励；删地图→通道下拉；删职业→技能分配/转职）+ 5a2 M-05 扩展（NPC→地图挂点/shop_refs/任务/教学；签到表→checkin_state；效果→环境事件）是**跨模块写盘**，必须与 SV-06 原子写盘联动（整包一次写完再重载），并复用 validator 复查（TC-03/TC-08）；forge_cascade.py 可参考其级联模式但域不同。
15. **/商店 列表 收口**。SM-04 余额行（契约 L366）+ SM-06 紧凑格式 + 4f 帮助组登记三处小缺口；改动 shop_commands/shop.py 时遵守「壳层只渲染、引擎给数据」边界（shop_commands.py L21-23 铁律）。
