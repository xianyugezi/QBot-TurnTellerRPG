## 0. 用户需求（原话精确，逐条落点对照）

| # | 用户原话 | 落点 |
|---|---|---|
| ① | 四季：默认 7 天切换一次，用户可以配置几天变更一次，必须整数 | settings.json `time_cycle.season.season_days`（默认 7，整数 ≥1） |
| ② | 时间段：晨午昏夜和午夜五个时间段，60 分钟切换一次（默认），用户可以配置，最低 30 分钟，必须整数 | settings.json `time_cycle.period.period_minutes`（默认 60，整数 ≥30） |
| ③ | 天气：全局统一变更，最低 30 分钟变化一次，默认 60 分钟；配置默认天气池，每次变化随机抽取一个；地图可以单独配置天气池（覆盖），如果地图没有单独配置天气池则统一使用默认天气池 | settings.json `time_cycle.weather`（weather_minutes 默认 60 整数 ≥30 + default_pool）+ maps.json 每图 `weather_pool`（覆盖，缺省用默认池） |

**语义裁定（本方案解释）**：
- 「全局统一变更」= **变化节奏与周期锚点全局统一**——同一时刻全世界一起进入下一天气周期（全世界一个 weather_tick）；「地图覆盖池」= 该图天气**取值**从覆盖池抽取（无覆盖图 = 默认池），故同一时刻不同地图天气可以不同，但变化时刻全世界一致。
- 三套周期**互相独立**：季节（天级）/ 时段（分钟级）/ 天气（分钟级）各自从同一锚点整除推进，**不强行对齐边界**（时段跨季节边界、天气与时段同时刻变化均自然发生，见 §9）。

## 一、周期引擎（三套周期键 + 懒计算 + 全局广播，对齐 3.6）

### 1.1 架构位置

```
engine/worldtime.py（现有：刷新/出没，3.6）→ 扩展为【时间轴引擎】
  ├── 现实钟点层（保留不动）：active_time "20:00-06:00" 出没窗口、限购周期（3.11 每日/每时/每周/每月）、签到日界 05:00
  └── 游戏周期层（新增）：
      ├── 季节周期 season：N 值（默认模板 4），周期长 = season_days × 86400s
      ├── 时段周期 period：N 值（默认模板 5），周期长 = period_minutes × 60s
      └── 天气周期 weather：取值 = 生效池抽签，周期长 = weather_minutes × 60s
```

### 1.2 三套周期键（唯一注册表，默认模板枚举，内容包可扩展）

| 周期 | 键（存储/条件用） | 中文名（展示用） | 周期长（可配） | 说明 |
|---|---|---|---|---|
| 季节 | `spring` / `summer` / `autumn` / `winter` | 春 / 夏 / 秋 / 冬 | `season_days` × 1 天（默认 7） | 默认模板 4 季节：春→夏→秋→冬，顺序固定循环（可扩展，如节气/潮汐/无季节） |
| 时段 | `dawn` / `noon` / `dusk` / `night` / `midnight` | 晨 / 午 / 昏 / 夜 / 午夜 | `period_minutes` 分（默认 60，≥30） | 默认模板 5 时段：晨→午→昏→夜→午夜，顺序固定循环（可扩展） |
| 天气 | 内容包自定义键（见 1.4） | 内容包自定义（如 晴/多云/雨/雷雨/雪/雾） | `weather_minutes` 分（默认 60，≥30） | 值 = 生效池抽签（见 1.3） |

- 季节/时段枚举**开放可配**（内容包可扩展，如节气/潮汐/无季节等时间向内容包；默认模板保持 4 季节 春夏秋冬 / 5 时段 晨午昏夜午夜，顺序固定循环）。防碎片化通过『默认模板统一』保留：内容包若自定义季节/时段枚举，需**显式声明完整枚举集**（settings `time_cycle.season.enum` / `time_cycle.period.enum`），校验器只比对「引用键 ∈ 声明枚举集」，对档位数量/命名只提示不拦截。天气枚举 = 内容包自定义（不变）。
- 键格式与既有条件键一致（英文小写），互译表新增 3 行（见 §四 4.0）。

### 1.3 懒计算（与 3.6 补刷同构，零定时器）

```
锚点 ANCHOR = 2000-01-01 00:00:00 UTC+8（世界起点 = 春季·晨·天气第 0 抽）
now = 当前 UTC+8 时间戳

season_idx   = floor((now - ANCHOR) / (season_days × 86400)) % len(season.enum)   # 0..N-1（默认模板 4：0春 1夏 2秋 3冬，顺序固定循环）
period_idx   = floor((now - ANCHOR) / (period_minutes × 60)) % len(period.enum) # 0..N-1（默认模板 5：0晨 1午 2昏 3夜 4午夜，顺序固定循环）
weather_tick = floor((now - ANCHOR) / (weather_minutes × 60))            # 全局统一变化节拍

地图天气 map_weather(map_id, weather_tick) = 生效池[pick(seed)]
  seed = sha256(生效池键列表(排序后) + str(weather_tick))  →  确定性伪随机（跨群/跨进程/重启一致）
```

- **不存历史、不跑定时器**：任何时刻的周期值可由公式重算（对齐 3.6「玩家操作时按时间差补刷」）。
- **变化检测钩子**：每条指令处理前调用 `time_engine.check_changes(player, map_id)`，比较世界状态缓存索引，产出变化列表 → 广播（§五）。
- **离线跨越多周期**：只按「最新值」播报一次，不逐条追报（对齐 3.6 补刷上限思想，防刷屏）。
- **配置变更即重排**：改 season_days/period_minutes/weather_minutes/池 → 后续周期全部按新配置推进，旧缓存索引失效自动重算（黄色提示「时间配置已变更，周期重新铺排」，不拦截）。

### 1.4 天气池与抽签

```json
"time_cycle": {
  "weather": {
    "weather_minutes": 60,
    "default_pool": [
      {"key": "clear",     "name": "晴",   "emoji": "☀️"},
      {"key": "cloudy",    "name": "多云", "emoji": "☁️"},
      {"key": "rain",      "name": "雨",   "emoji": "🌧️"},
      {"key": "storm",     "name": "雷雨", "emoji": "⛈️"},
      {"key": "fog",       "name": "雾",   "emoji": "🌫️"}
    ]
  }
}
```

- 每次变化（weather_tick +1）从**生效池**等概率抽一个（用户原话「随机抽取一个」；权重为后续版本预留，v1 不做）。
- 抽签**确定性**：seed 绑定（池键列表 + tick），同一 tick 全世界同值（同池时），重启不重抽——懒计算刚需。
- 池编辑（增删天气）→ 抽签序列整体重排（可接受，黄色提示）。

### 1.5 全局广播（可配，懒触发）

- 广播 = 变化检测产物，**默认懒模式且默认关闭**（2026-08-16 用户拍板）：不设后台定时器；`broadcast.enabled` 默认 false 不播报，作者开启后玩家指令时发现周期变化 → 在该指令所在群附一行播报（`☀️ 天气转晴` / `🍂 进入秋季` / `🌙 已入夜`）。
- 播报顺序固定：季节 → 时段 → 天气（同一时刻多周期变化时按序合并一行，最多 3 条）。
- **变化不打断战斗**：战斗会话内每回合开始重读当前时段/天气（懒计算），仅用于数值与状态行提示；不中断战斗流，播报挂到**战斗结算后**（对齐 3.16「怪物出没时段边界」只影响怪物存在性，天气/季节不驱逐战斗中怪物）。
- 可配项（settings）：`broadcast.enabled`（默认 false）/ `broadcast.mode`（lazy 默认；timer 真定时器为后续扩展，v1 不实现）/ `broadcast.template`（可改文案）。
- 去重：世界状态 time_state 记录「各周期已播报索引」（§六），跨群不重复广播（全局世界，3.8）。

## 二、全局设定结构（settings.json `time_cycle` 段）

```json
"time_cycle": {
  "enabled": true,                  // 系统总开关（false 时 /时间 /天气 提示未启用、条件键 [季节]/[时段]/[天气] 失效，附 K K.2）
  "season": {
    "season_days": 7,                     // 整数 ≥1，默认 7（用户原话①）
    "enum": ["spring", "summer", "autumn", "winter"]   // 季节枚举（默认模板 4：春夏秋冬，顺序固定循环）；内容包自定义需显式声明完整枚举集（可扩展节气/潮汐/无季节）
  },
  "period": {
    "period_minutes": 60,                 // 整数 ≥30，默认 60（用户原话②）
    "enum": ["dawn", "noon", "dusk", "night", "midnight"]  // 时段枚举（默认模板 5：晨午昏夜午夜，顺序固定循环）；内容包自定义需显式声明完整枚举集
  },
  "weather": {
    "weather_minutes": 60,                // 整数 ≥30，默认 60（用户原话③）
    "default_pool": [ {"key":"clear","name":"晴","emoji":"☀️"}, ... ]   // 非空、键唯一（用户原话③）
  },
  "broadcast": {
    "enabled": false,                     // 变化广播总开关（默认关——2026-08-16 用户拍板：不主动播报，玩家 /时间 /天气 自查）
    "mode": "lazy",                       // lazy（默认）| timer（预留）
    "template": "{emoji} {name}"          // 播报文案模板，占位符 {type} {name} {emoji} {map}
  },
  "combat": {                             // 战斗天气修正（可选，默认关，见 §四 4.6）
    "weather_mult": {
      "enabled": false,
      "mults": { "rain": 0.95, "storm": 1.1, "fog": 0.9 }
    }
  }
}
```

- 落点：settings.json（框架 4.1 通用设置文件），新增 `time_cycle` 段；manifest modules 数组**不需要**新增模块名（无独立文件）。
- 全部为**全局唯一**配置（世界只有一个季节/时段/天气节拍，3.8 全局世界对齐）。
- 防碎片化：默认模板统一（4 季节/5 时段，顺序固定循环）；内容包自定义季节/时段枚举需显式声明完整枚举集，校验器只对「引用键 ∈ 声明枚举集」做一致性检查，对档位数量/命名只提示不拦截。

## 三、地图天气池（maps.json 覆盖，缺省用默认池）

```json
// maps.json 每图顶层新增字段（可选）：
{
  "id": "misty_forest",
  "name": "迷雾森林",
  "weather_pool": ["fog", "rain"],        // 覆盖池：只引用默认池已注册键；缺省/空数组 = 用默认池
  "monsters": [
    {
      "enemy": "幽灵",
      "count": 5,
      "respawn_minutes": 10,
      "active_time": {"from": "20:00", "to": "06:00"},   // 现实钟点（3.6 保留）
      "seasons": ["autumn", "winter"],                   // 季节限定（可选，空=全年）
      "periods": ["night", "midnight"],                  // 时段限定（可选，空=全天）
      "weather_weights": {"fog": 2, "rain": 0.5}         // 天气出现率倍率（可选，默认 1；0=该天气不刷）
    }
  ],
  "gather_points": [
    {
      "id": "gp_1",
      "item": "灵草",
      "rate": 0.3,
      "rarity": "rare",
      "weather_mods": [                                  // 天气修正（可选）
        {"weather": "rain", "rate_mult": 1.5, "rarity_shift": 1},
        {"weather": "storm", "rate_mult": 0}             // 0 = 该天气下不出
      ]
    }
  ]
}
```

规则：
1. `weather_pool` 元素必须 ∈ 默认池已注册天气键（校验器硬拦，引用不存在）；空数组 / 缺省 = 统一用默认池（用户原话③）。
2. 该图天气值 = `map_weather(该图, weather_tick)`——从覆盖池抽（有覆盖）或默认池抽（无覆盖）。
3. 天气权重/修正字段全部**可选**，不配置 = 不参与天气联动（向后兼容，旧地图零改动可跑）。

## 四、影响面全开（消费方规划）

### 4.0 条件引擎新键（互译表 4.2.3.1 新增 3 行，单口登记）

| 条件英文键（机器键） | 变量大全中文变量（展示/公式键） | 说明 |
|---|---|---|
| { var: "season", param: X } | [季节:X] | 当前季节 == X（X ∈ 季节枚举注册表，默认模板 4 季节） |
| { var: "period", param: X } | [时段:X] | 当前时段 == X（X ∈ 时段枚举注册表，默认模板 5 时段） |
| { var: "weather", param: X } | [天气:X] | 玩家**当前所在图**的当前天气 == X（X ∈ 注册天气集） |

- 语义：季节/时段为全局值；天气按玩家所在图取值（上下文绑定，与 {var:"item_count"} 同构）。
- 消费方（任务/NPC/签到活动表/副本/成就）引用新键**零新增机制**——事件/活动窗口 = 配置组合（见 4.4）。

### 4.1 钓鱼（现有消费方，钓鱼定稿 §三 鱼种表扩展）

```json
// fishing.json 鱼种行新增两个可选字段（空 = 不限制）：
{
  "id": "silver_carp", "name": "银鳞鲤", "rarity": "normal",
  "seasons": ["spring", "summer", "autumn"],   // 季节偏好（空=全年）
  "periods": ["dawn", "noon", "dusk"],         // 五时段偏好（空=全天）
  "hours": ["00:00-24:00"]                     // 现实钟点（3.6 语义，保留兼容）
}
```

- 出鱼判定：当前季节 ∈ seasons **且** 当前时段 ∈ periods（任一配置了就过滤；全空 = 不限制）→ 否则该鱼不入池（或按 0 权重）。
- 钓鱼定稿 v1.0 的「时段」字段正式对齐到五时段键（深度版方案的季节偏好字段同步落地）；现实钟点 hours 保留为附加过滤层（正交）。
- 鱼王事件窗口（fishing 定稿 §三 king_event）可叠加天气条件：`king_event.weather: ["storm"]` 可选（雷雨夜鱼王活跃——内容配置，非新机制）。

### 4.2 采集（稀有度随天气）

- maps.json 采集点 `weather_mods`（§三）：`rate_mult` 乘采集概率（0=不出）、`rarity_shift` 平移稀有度档位——稀有度档位沿用统一稀有度注册表（provenance/rarity 注册表驱动，可配；唯一口径如 common/uncommon/rare/epic/legendary），本系统默认使用 4 档（普通/稀有/金色/✨），档位平移 clamp 到注册表档位（炼金金色素材链路自动受益）。
- 例：雨天山蘑菇出率 ×1.5 且稀有档+1 → 天气驱动采集策略。

### 4.3 怪物出现率

- maps.json 怪物行新增 `seasons` / `periods` / `weather_weights`（§三）：
  - seasons/periods = 限定过滤，语义与 active_time 对齐并叠加（全部满足才出没）；**3.16 出没时段边界规则同样适用**（季节/时段结束 → 场上怪物移除，"对方逃跑了"）。
  - weather_weights = 出现率倍率，作用于刷新计时：`有效刷新间隔 = respawn_minutes / weight`（weight≥1 刷更快，0<w<1 更慢，0=该天气不刷）。**只影响刷新/补刷，不驱逐已在场怪物**（天气不打断战斗，与 3.16 的时段边界刻意区分）。
- 例：雷雨夜幽灵权重 ×3 + 午夜限定 → 天气+时段双驱动刷怪点。

### 4.4 事件活动窗口（条件引擎，零新机制）

- 任务（quest.json 发布/显示条件）、NPC（npc.json 交互条件）、签到活动表（checkin.json activity 表 start/end + 条件）、副本事件（dungeon.json 事件牌组）、成就（achievements.json 条件）——统一引用新键：
  - `{var:"season",op:"eq",param:"summer"}` → 夏季限定任务
  - `{var:"period",op:"eq",param:"midnight"}` + `{var:"weather",op:"eq",param:"storm"}` → 午夜雷雨限定事件
- 签到活动表 start/end 仍为现实时间（懒计算，签到定稿 §3.4），新键作为**叠加条件**（活动期内 + 季节/时段/天气窗口），互不冲突。

### 4.5 图鉴情报

- enemies.json `lore` 条目新增可选 `condition`（复用条件引擎）：满足才显示该条情报。
  - 例：`{"var":"weather","op":"eq","param":"storm"}` → 雷雨天解锁「幽灵弱点：雷元素」线索。
- fishing 图鉴 codex 鱼类条目同理（`condition` 可挂季节/时段，图鉴文案自然揭示生态规律，不写公式）。

### 4.6 战斗天气修正（可选，默认关）

- settings `time_cycle.combat.weather_mult`（§二）：`enabled` 默认 **false**（防数值倾斜，尊重战斗数值层定稿的伤害公式纯净性）；开启后总伤害 × 当前图当前天气倍率。
- 计算时点：**每回合开始**读取当前天气（懒计算）；战斗中途天气变化 → 下一回合生效 + 状态行提示一次，**不打断战斗**（§1.5）。
- 不改 formula.json 伤害公式本体（天气倍率为外挂层，公式层保持纯净）；校验 mults 键 ∈ 注册天气集。

### 4.7 正交关系（明确不联动）

- 商店限购周期（3.11 每日/每时/每周/每月）、签到日界 05:00、排行榜刷新 = 现实钟点层，**不**接入游戏周期层（防语义混淆）。
- 现实钟点出没时段 active_time（3.6/9）与五时段键**并存正交**：前者管"几点现实时间"，后者管"游戏周期第几段"，怪物/鱼种可同时配置（AND 叠加）。

## 五、QQ 适配

### 5.1 查询指令（指令表 7.1 冒险指令新增 2 行）

| 指令 | 说明 |
|---|---|
| `/时间` | 当前季节（距下次变化 X 天）/ 时段（距下次 X 分钟）/ 天气（距下次 X 分钟）；未注册玩家提示"请先 /注册" |
| `/天气` | 当前所在图的天气 + 生效池（覆盖池/默认池标注）+ 距下次变化分钟 + 该图天气联动摘要（有天气修正的怪物/采集点提示，不教具体数值） |

示例输出：
```
/时间
```

## 九、数值（时间轴示例与对齐规则）

### 9.1 默认参数时间轴

```
锚点：2000-01-01 00:00 UTC+8 = 春季 · 晨 · 天气第 0 抽
默认配置：季节 7 天/季（28 天一轮）· 时段 60 分/段（5 小时一轮）· 天气 60 分/抽

2026-08-16（夏）：
  00:00  季节边界（若 8/16 恰为换季日）→ 夏→秋（00:00 同时是时段/天气边界）
  00:00  时段：午夜→晨 ｜ 天气：抽下一签
  01:00  时段：晨→午 ｜ 天气：抽下一签
  ...
  05:00  时段：午夜→晨（一「游戏日」= 5 小时 = 5 段走完一轮，1 现实日 ≈ 4.8 个游戏日）
```

### 9.2 对齐规则（三周期独立推进，共锚不共界）

1. **各自整除**：三个周期都从同一锚点整除取索引，互不读写对方状态——实现上无耦合。
2. **时段跨季节边界**：季节在 00:00 切换（整数天整除），时段按自身分钟数推进；若时段配置非 60 的约数（如 45 分），换季时刻时段可能处于中段——**时段不重置、不补算**，继续走自己的节拍（例：秋第 1 天 00:10 时玩家看到的时段 = 该时刻按公式算出的段，可能是「晨」也可能仍是「午夜」，取决于 45 分对齐）。
3. **天气与时段独立**：天气 tick 与时段 tick 各自从锚点整除；同一时刻两者可同时变化（默认 60 分整点对齐时 00:00 经常重合）——按固定播报顺序（季节→时段→天气）合并播报，互不影响数值。
4. **边界重合 = 自然现象**：默认配置下季节边界（00:00）必与时段/天气边界（整点）重合，属正常；播报合并为一条消息，去重防刷屏。
5. **变化检测一次指令最多播 3 条**（季节+时段+天气），离线跨多周期只播最新值。

### 9.3 节奏量级参考

| 参数 | 默认 | 一轮 | 1 现实日轮数 | 说明 |
|---|---|---|---|---|
| 季节 | 7 天 | 28 天（四季） | 1/28 轮 | 季节 = 长线节奏（钓鱼生态/限定怪） |
| 时段 | 60 分 | 5 小时（五段） | 4.8 轮 | 时段 = 短线节奏（出没/窗口） |
| 天气 | 60 分 | 60 分/抽 | 24 抽 | 天气 = 高频扰动（采集/事件/修正） |
| 天气最低 30 分 | — | 30 分/抽 | 48 抽 | 下限 30 分保证可感知变化 |

- 三层节奏**错位叠加**（天级/小时级/分钟级），玩家任一操作时刻都有「当前值」可查，且变化可预期（/时间 /天气 倒计时）。

- `/时间` `/天气` 查询（§5.1 示例）：季节/时段/天气 + 变化倒计时——**只报状态不教规则**（对齐钓鱼定稿「说明特点不教攻略」）。

- 玩法体现（消费方组合示例）：
  - 钓鱼：`/天气` 显示雷雨 → 去雷雨限定鱼种的钓点（图鉴情报提示"雷雨天出雷纹鲤"）→ 鱼种生态自然浮现。

## 十二、风险与对策

| 风险 | 对策 |
|---|---|
| 天气"随机"但确定性抽签 = 序列可预测 | 种子含 tick + 池键，序列伪随机已够玩家视角；v1 不做真随机（懒计算刚需）；如后续要真随机 → 存档落"当前天气+下次变化时刻"，仍可懒推进（预留路径） |

| 战斗中被天气/季节打断 | 明确规则：天气/季节不驱逐怪物、不打断战斗；仅 3.16 时段边界（含新 seasons/periods 限定）按既有语义处理 |

| 战斗天气修正破坏数值经济 | 默认关（respect 战斗数值层定稿），开启属运营选择；倍率限制黄提示（0.8~1.2 区间外提示） |
