## 二、每指令契约（22 条逐条）

> 编号沿用细化_2c4d：解析 P-xx / 守卫 GU-xx / 流程 F-xx / 消息 M-xx / 分隔符 SEP-xx。实现组以本节为**逐项核对基准**（batch_plan 铁律 5）。

### 1. /合成 ⟨配方⟩*⟨数量⟩（第 1 层 · 跨职业快捷生产）
- **参数解析**（P-01/SEP-01）：位置参数 1 = `配方名*数量`；`*` 紧贴配方名后、`*` 后纯数字；数量默认 1；上限默认 **2147483647**（`max_qty` 可配，拍板⑤），超限提示「最多一次使用 N 个」**不拦截**；`*` 左名称优先精确匹配、失败按序号解析；配方名禁空格/禁保留字符 `* , = +`（`+N` 在本指令禁用）。
- **前置守卫**（GU-01~04）：GU-01 settings.alchemy.mode ≠ off → GU-02 配方存在且任一制造/资源职业等级 ≥ 配方 level → GU-03 `synth_allowed=true`（深度配方默认 false，开启仅提示「此深度配方可被合成，将绕过深度炼金玩法」不阻断）→ GU-04 **原子校验**：材料+金币全量满足才执行，否则全拒+差异提示「缺 水结晶×5 + 金币 30」。
- **流程**（F-01）：事务内复核 → 扣材料+金币 → 产标准版（品质固定、无特性、无过程；标准珠带固定 base_effects）→ 熟练经验=配方等级×1（可配）→ 合成图鉴点亮 → 不耗调合能量（保底通道）。
- **消息模板**（M-01）：成功 `✅ 魔力药水 ×10（消耗：水结晶×20 + 草药×10 + 金币 100）`；失败=错误模板全集（材料不足/等级不足）。
- **会话态**：无（不建会话）。
- **实现批次**：批2 路2A（引擎+指令壳）。
- **数据落点**：recipe.json（kind=craft/materials/cost.coins/synth_allowed/master_only）；inventory.add_item/remove_item；熟练度 dict `player["proficiency"]`；codex_state（图鉴点亮）；settings.alchemy.synth_exp/max_qty。

### 2. /炼金 ⟨配方⟩ [触媒=⟨触媒⟩ | 自动]（第 2 层 · 开启调合会话）
- **参数解析**（P-02/SEP-02）：位置参数 1 = 配方名；位置参数 2 限固定子词 `自动`（一键投料）或键值 `触媒=⟨触媒名⟩`（`=` 键值修饰）；第 3 参数起强制走键值/列表；固定子词表（追加/预览/自动/查看/确认/放弃/续）优先于物品匹配；触媒未注册仅提示（注册制）。
- **前置守卫**（GU-05~08）：GU-05 炼金职业见习+ → GU-06 能量 ≥1 格（**仅 energy_enabled=true 生效**，R-08 默认关；关则直通不扣能量不显示上限）→ GU-07 单玩家无活跃调合会话（全局互斥，私聊+多群同）→ GU-08 触媒使用需炼金职业 ≥ **专家**（R-07，`catalyst_unlock_tier` 可配；`自动`/不带触媒参数不触发本守卫）。
- **流程**（F-02）：校验通过 → 开启会话（无会话→会话中；快照含配方ID+触媒+材料链+连锁+特性+PP+步骤+version）→ 扣能量 1 格（R-08 关时不扣）→ 展示面板（材料清单/属性刻度/特性位/PP/投入次数预算）→ 进入投料→继承→确认链；`自动` = 一键投料自动配平（配平失败原子拒绝，批4 路4C）。
- **消息模板**（M-02）：成功 `📖 火焰弹（配方Lv5）：材料：火药×1(火2) 矿石×1 任意×1` + `属性刻度：火≥6 显现"范围爆炸" | 特性位 2/3 | PP 5/5 | 投入次数 4`；失败=等级不足/能量不足/会话互斥。
- **会话态**：开启（alchemy 类型）。
- **实现批次**：批4 路4A（开会话）；路4C（自动 子词/批量）。
- **数据落点**：sessions 表（session_type='alchemy'，payload_json=会话快照含 version）；settings.alchemy.energy_enabled/energy_max/catalyst_unlock_tier；recipe.json catalyst[]；items.json（触媒 type）。

### 3. /投料 ⟨材料1⟩,⟨材料2⟩,… [追加]（第 2/3 层 · 链式投料）
- **参数解析**（P-03/SEP-03）：位置参数 1 = 材料列表（`,` 分隔，全角/半角等价、不空格）；单项可带 `材料*N`；位置参数 2 = 固定子词 `追加`；列表内逐项解析顺序固定：先 `,` 拆 → 再 `*` 拆数量 → 再 `=` 拆键值。
- **前置守卫**（GU-09~12）：GU-09 调合会话中（含深度）；无会话 → 「当前没有调合会话，先 /炼金 <配方> 开始」→ GU-10 **战斗拦截**：战斗中 → 「战斗中使用 /即时调合 <配方>（不进入调合会话）」→ GU-11 不超槽位（「投料超槽位」；深度 6 槽/核心槽/3 普通+1 金）→ GU-12 材料在背包且数量足够。
- **流程**（F-03）：逐项入料 → 连锁段数=相邻同属性对数（连续 n 个 = n-1 段；同属性按材料当前属性，触媒改变后按新属性）→ chain_map 段数→效果等级 → 属性刻度累计（element_req 阈值）→ 反馈附可继承特性清单；稀有金色素材→金色超特性候选（第 4 位独占）；✨觉醒素材→隐藏效果候选；成品/装备可入料（全物入料，专家级）。
- **消息模板**（M-03）：成功 `⚗️ 火+7 | 连锁 2 段 | 可继承特性：灼烧强化(PP1) 回复量+5%(PP1)`；深度 `🔥 连锁 5 段 → 效果等级 5`；刻度达标 `火+42（刻度 30 ✓ 地狱火）`。
- **会话态**：会话中。
- **实现批次**：批4 路4B。
- **数据落点**：会话快照 payload_json（材料链/连锁/刻度/PP/步骤，随 sessions 持久化）；items.json elements/traits/awaken；settings.alchemy.chain_map/element_req 来源 recipe.json。

### 4. /继承 ⟨特性1⟩,⟨特性2⟩,… 与 /继承超 ⟨金色特性⟩（第 2/3 层 · 特性继承）
- **参数解析**（P-04/SEP-04）：位置参数 1 = 特性列表（`,` 分隔）；`/继承超` **独立指令名**（非子词），位置参数 1 = 单一金色特性；普通默认 ≤3 项（可配 1-6），超特性走第 4 特性位独占（gold_slot_exclusive）；特性名内数值 `+` 允许（词条数值语境，如 攻击+15%，黄色提示不拦截）。
- **前置守卫**（GU-13~16）：GU-13 调合会话中（无会话模板同 GU-09）→ GU-14 PP 校验（普通 1/超 2，`pp_cost`；PP 会话重置 `pp_refresh`；不足→「PP 不足」）→ GU-15 特性位余量（「继承超 3 项」）→ GU-16 group 互斥组内最多 1 项 + repeatable（冲突拒绝并提示互斥组名）。
- **流程**（F-04）：特性须来自投料候选清单（不可凭空继承）→ 逐项扣 PP → 落普通位/金色第 4 位；负面特性（宗师）：继承强力特性需承受 1 个负面词条；结算时按 group/repeatable 复核。
- **消息模板**（M-04）：成功 → 面板特性位更新（`3 普通 + 第 4 位金色`）；失败=PP 不足/继承超 3 项。
- **会话态**：会话中。
- **实现批次**：批5 路5A。
- **数据落点**：会话快照（特性/PP）；traits.json（group/repeatable/rarity/source）；settings.alchemy.pp_cost/pp_refresh/gold_slot_exclusive。

### 5. /确认 /放弃 /调合续（第 2/3 层 · 会话终态）
- **参数解析**（P-05/SEP-05）：三命令均无参数；`确认/放弃/续` 为固定子词表内置常量，**独立指令名注册**（注册进 Router，见 §六）。
- **前置守卫**（GU-17~19）：GU-17 /确认 /放弃 需调合会话中（无会话模板 L175）→ GU-18 /调合续 需存在挂起(战斗)会话且无活跃会话（已有活跃 → 「已有一个调合会话进行中」）→ GU-19 /确认 时**全量复核**材料仍在背包（不足拒绝并提示差异，防过期快照）。

### 3.3 DEFAULT_QUANTITY_COMMANDS 接线

- **现状**（L149）：`{使用, 购买, 合成, 投料, 出售, 炼金, 调合}` —— 炼金/投料/合成**已有**（`*` 数量语法放行）。

- **强化保持禁 `*`**（no_quantity_commands={强化}，L152 不动）。

### 3.4 数量上限 max_qty（拍板⑤）

- `parse_command` 默认 `max_qty=99`（DEFAULT_MAX_QTY L155）；**M8 装配层必须从 settings.alchemy.max_qty 注入**（默认 **2147483647** = int32 max，拍板⑤），覆盖到 /合成 /复制（/炼金 批量 *N 同参）。
- 超限行为 = 提示「最多一次使用 N 个」**不拦截**（对齐分隔符 L73 与 ParsedCommand.hints 机制）。

### 3.5 A+B 两空格位置参数实现注意

- 涉及指令：/成品合成 /配方合成 /特性合成 /镶嵌 /拆珠（P-09/12/13/18）——**A+B 是文档记法，实现为两个空格位置参数**（对齐铁律 3 位置参数 ≤2）。
- 实现要点：
  1. 直接消费 `parsed.arg(0)` / `parsed.arg(1)`（两参均不含 `*`，为纯名称）；
  2. 名称禁空格/禁保留字符（命名铁律 L58），故空格切分无歧义；
  3. `+` 在**词条数值**语境允许（攻击+15%、回复量+5%——parsers `_ALLOWED_TOKEN_RE` L160 已含 `%` 与 `+`），解析器黄色提示不拦截；
  4. 成品合成支持同物两份（arg0==arg1 不拦截，是否允许由 kind=upgrade 组合表决定）；
  5. 数量上限提示文案里的 N 取自注入的 max_qty（见 3.4）。

### 3.6 其余接线

- 无参指令（/确认 /放弃 /调合续 /图鉴 /技能面板 /收获 /收取 /任务）：不涉及数量/列表/键值；可用 `command_specs={"指令名": {"min_args": 0}}` 声明缺参判定。

### 8.3 本域铁律（实现组逐条遵守）

1. **接口签名以真实代码为准**：parse_command / CommandSpec / Router.register / register_shop_commands 壳模式 / SessionManager 5 方法 / settle_exit_idempotent / idem_claim·idem_exists·write_idem_key（见 §三/§四/§五/§六，行号均为 qbot_rpg 真实定义）。
2. **勿自创幂等表**：复用框架 `idempotency_keys` 表 + `idem_claim` + `write_idem_key`（ATO-03）；调合会话终态仿 `settle_exit_idempotent`（delete_session+write_idem_key 同事务），勿另起炉灶。
3. **A+B 落两空格位置参数**：成品合成/配方合成/特性合成 是文档记法，实现为 2 空格位置参数；批量路径不抄 `+`；特性名内数值 `+` 保留（§3.5）。
4. **分隔符三件套**：数量 `*` / 列表 `,` / 键值 `=`，逐指令按 §二「参数解析」对齐，禁旧式空格列表/`×2` 写法。
5. **会话互斥写死**：单玩家 1 会话全局互斥（sessions.player_qid 主键）；战斗即时调合豁免（MUT-03）；战斗中调合指令拦截（MUT-04）。
6. **原子防双扣**：合成/炼金/分解类一律 单事务 + message_id 幂等（ATO-01~08）；批量 N 份同事务循环。
7. **/秘钥 不注册**：动态指令注册表 + 内容包注册清单均无此项；收到走通用未知指令处理（TC-32）。
8. **批次归属冲突时以 batch_plan 为准**：本契约批次列 = batch_plan 派工；/协力（附注①）与 /任务（附注②）两处缺口已显式标注，需排期补充或挂接，不得静默丢弃契约。
