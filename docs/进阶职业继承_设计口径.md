### 1.3 预期语义（提炼）

- **下级职业下挂进阶职业列表**：母职（如「法师」）配置它有哪些进阶职（如「火法师/冰法师」）。
- **转职进阶职 → 继承母职全部技能 + 获得进阶技能**：「继承」的对象是**技能**；转职到进阶职后，
  技能位里既有进阶职自己的技能，也有从母职继承来的技能。
- **配置驱动**：进不继承由「是否挂在母职下面」决定，**不写死**——独立职业（如「战斗法师」）
  不继承母职技能。
- 定稿**没有**提到属性成长继承、熟练度继承、等级继承。

**结论**：「进阶职业卡片（职业树继承）」的预期语义 = **技能继承（技能位装配层面）**；
属性成长**不在**继承范围（见 §3 数值口径）。

## 4. 设计口径（最小可行语义）

### 4.1 字段形态：`jobs.inherit`（进阶职一侧声明）

遵循「与既有 `advance` 同侧、同引用口径」与「少而深」，在**进阶职**条目上增加一个子对象：

```jsonc
{
  "id": "fire_mage",
  "name": "火法师",
  "advance":  { "from": "mage", "level": 10 },   // 批23：前置门槛（能不能转）
  "inherit":  { "from": "mage",                  // 本条：继承来源（转过去继承什么）
                "skills": ["mage_shield"] }      // 可选：只继承列出的技能；空/缺省 = 母职全部职业专属技能
}
```

- `inherit.from`：`ref job`，母职 id（必填；引擎缺失 = 不继承）。
- `inherit.skills`：`list<ref skill>`，可选白名单；**非空 = 只继承列出的技能 id**；
  **空/缺省 = 继承母职的全部职业专属技能**（即母职 `job_restrict` 命中的技能）。
- **不新增顶层字段**（与 `advance`/`transform` 同为 obj），遵守「少而深」。

**为什么声明在进阶职一侧（而非母职列表）**：现有最接近的 `advance.from` 已在进阶职一侧
（`qbot_rpg/content/job_models.py:330-341`），本条与之对称同侧，复用同一 `ref_target="job"`
引用口径与同一张 jobs 注册表；母职页面上的「下级职业列表」由**反向查询**（`inherit.from == 母职`）
即时得到，不引入第二份数据（避免双向不同步）。「挂在谁下面就继承谁」由**配置驱动**满足：
没写 `inherit.from` 的职业（如独立职业）自然不继承。

### 4.2 引擎语义（只扩既有装配入口）

- **继承 = 放宽装配可见性**，不是新装配系统：
  `assemble_slots` 新增一个**可选**输入（`player_ctx["inherited_skill_ids"]`）——一组
  「因继承而额外可见」的技能 id；`job_visible` 在保留原判定（通用全可见 / 当前职业命中）
  之上，**额外**允许这批 id 通过。不带该输入时**逐字节等价现状**（回归对拍）。
- **来源解析**（纯函数，`qbot_rpg/core/job_slots.py`）：
  - `resolve_inherit_chain(job_id, jobs_table)`：沿 `inherit.from` 向上收集祖辈（**传递闭包**，
    环安全，确定性排序）。
  - `inherited_skill_ids(job_id, jobs_table, skills)`：取链上每级祖辈的「职业专属可见技能」
    （`job_restrict` 命中该祖辈；通用技能本就全职业可见、不算继承），并套用**目标职业
    `inherit.skills` 白名单**（非空则取交集），按库序去重返回。
- **转职接线**：`rearrange_job_slots` 从 `player_ctx["jobs"]` 读职业表，算出继承 id 集，
  再调既有 `assemble_slots` 入口——**不新开一套装配**。
- **与 `advance` 配合**：`advance` 前置不满足 → 照旧在 `_advance_block` 拦截，**不执行转职**，
  行为不变；`inherit` 只在放行之后生效。
- **basic/active/passive/trigger 一致适用**：继承来的技能按其自身 `type` 进对应槽位，
  不为继承单开槽位语义。

### 4.3 与 `transform` 的边界（划清）

| 维度 | `transform`（形态变换） | `inherit`（职业树继承） |
|---|---|---|
| 时机 | **战斗内**临时 | **转职后永久**（玩家 `job_id` 变更） |
| 触发 | `transform_skill` / 时长 / 冷却 | 不触发，转职装配时一次性生效 |
| 技能来源 | `transform.skill_set` 形态技能组 | 母职技能的可见性放宽 + 进阶职自身技能 |
| 还原 | `revert` / `dispel_reverts` 回原形态 | 无「还原」；再转职按新配置全量重算 |
| 实现 | `job_form` / `apply_job_form`（`qbot_rpg/core/skill_slots.py:488`） | `job_visible` 额外可见集（本条） |
| 是否叠加 | 与 inherit **互不影响**；本批不接线 transform 与 inherit 的交互 | 不修改 `apply_job_form` 语义 |

### 4.4 门禁（只能更严）

- `inherit.from`：泛型 R-4 引用存在性（`ref_target="job"`）硬拦——引用了不存在的母职 → 红。
- `inherit.skills[]`：泛型 R-4 引用存在性（`ref_target="skill"`）硬拦。
- `inherit` 非对象 / `from` 非字符串：泛型 R-1 红拦（与 `advance` 同口径）。
- **既有内容包不带 `inherit` → 校验与行为零变化**（新增字段按门禁语义记「新增项」）。

## 5. 待用户裁决（不臆断）

| # | 歧义点 | 本批落地口径（工程补白） | 需用户确认 |
|---|---|---|---|
| Q1 | 继承是**单级**还是**沿职业树传递**（A→B→C，C 是否继承 A 的技能） | 按「职业**树**」语义实现**传递闭包**（C 继承 B 且继承 A；环安全） | 若只想单级，改为仅取 `inherit.from` 一级即可 |
| Q2 | `skills` 白名单的语义粒度（定稿只说「全部技能」） | 白名单非空 = 只继承列出的技能；空 = 全部职业专属技能 | 是否需要「替换/追加 mode」：本批**不实现** `mode`（无既有落点，避免臆造）；如需「继承覆盖/替换进阶职自身技能」请明示 |
| Q3 | 继承是否需要「曾经确实当过母职」的历史条件 | 不做历史条件：只看目标职业的 `inherit` 声明 + `advance.from` 前置（前置已能保证路径） | 若要求历史校验需加存档字段（成本更高） |
| Q4 | 继承是否含等级/熟练度 | 无落点：装配快照只有技能 id，无技能等级维度（`qbot_rpg/core/skill_slots.py:118-125`）；本批**不继承等级** | 若要「技能等级继承」，需先补技能等级维度的系统级设计 |

**一句话请示**：定稿只写了「继承全部技能」，本批按「配置驱动 + 传递继承 + 可空白名单，
不碰属性成长、不实现替换 mode」落地；若您要的是**单级继承**或需要 **mode（替换/追加）**，
