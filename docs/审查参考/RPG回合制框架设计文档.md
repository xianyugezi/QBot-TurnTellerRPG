## 1. 框架定位

### 1.1 一句话定位
> 一个"回合制 JRPG 机制引擎"：零代码用户通过**可视化编辑器**定义自己的游戏，
> 框架把配置跑起来，QQ 群聊里即开即玩。

### 1.2 框架 vs 内容包
```
┌─────────────────────────────────────────────┐
│ 框架 rpg_framework（机制，代码实现）         │
│   · 1v1 回合战斗引擎（一轮一条消息）          │
│   · 成长引擎 / 背包引擎 / 装备引擎（部位系统）│
│   · 时间系统（怪物刷新/出没时段）             │
│   · 存档（自动保存，碎片化续玩）              │
│   · Web 编辑器（插件内嵌）+ 内容包校验器      │
├─────────────────────────────────────────────┤
│ 内容包（配置，纯 JSON，由编辑器生成）         │
│   · 部位/职业/技能/物品/怪物/地图/掉落/公式   │
└─────────────────────────────────────────────┘
```

### 1.3 设计原则
1. **简单但有深度**：机制少（战斗/成长/背包/装备/时间），深度由配置组合产生
2. **小白优先（硬约束）**：
   - 零安装、零配置、零命令行（双击 + 点选 + 扫码）
   - 全中文、无术语、自动兜底（所有失败自动恢复/提示下一步）
   - 朋友端零门槛（玩的人只发 QQ 指令）
3. **一切可配置**：部位/职业/技能/属性/敌人/掉落/公式参数全部内容包配置
4. **编辑器即内容**：编辑器直接读写 content/ 目录，保存即生效（热重载），无导出导入

## 3. 核心引擎

### 3.1 1v1 回合战斗引擎

**战斗形态**：玩家单角色 vs 单个怪物（1v1）

**一轮流程（合并为一条消息返回）**：
```
[玩家] /攻击
[机器人] ⚔️ 你挥剑斩向史莱姆！造成 12 伤害（史莱姆 18/30）
         🟢 史莱姆反击！你受到 5 伤害（HP 25/30）
         你 HP 25/30 | 史莱姆 18/30
         你的回合：/攻击[技能序号] /道具 /防御 /逃跑
```
- **一轮一条消息**：玩家行动结算 + 怪物反击结算合并返回 → 消息量减半 → 防刷屏防封号
- 战斗结束单独一条（胜利/失败结算消息）

**怪物丢失机制（无超时设计）**：
```
- 战斗【无超时】：玩家随时回来继续（碎片化场景：通勤到站就走，回来接着打）
- 战斗期间怪物被其他人杀死 → 玩家操作时提示"怪物丢失"
  → 若地图有刷新：等刷新后继续操作 → 战斗继续
  → 无刷新：提示"怪物已消失"，战斗按退出处理
```

**指令（战斗内，精简后）**：
| 指令 | 说明 | 消耗 |
|---|---|---|
| `/攻击` | 普通攻击 | 0 |
| `/攻击 <序号>` | **使用技能列表对应技能**（攻击和技能合并，少记指令） | MP |
| `使用<序号>` | 使用背包道具（装备/药剂/战斗道具统一） | 物品（**不消耗回合**） |
| `/防御` | DEF×2 | 本回合行动 |
| `/逃跑` | 脱离战斗 | 本回合行动 |

**行动顺序**：玩家行动 → 怪物反击（固定玩家先手；速度只影响暴击/逃跑，简化 1v1）

**伤害公式**（内容包 formula.json 配置）：
```
物理：max(1, (ATK × 技能倍率 × 属性克制 - DEF) × 随机(0.9~1.1))
魔法：max(1, (MAG × 技能倍率 × 属性克制 - MDEF) × 随机(0.9~1.1))
属性克制（幻想生活软克制）：克制 ×1.3 / 被克制 ×0.7
```

**敌人 AI**：策略表配置（HP 阈值→行为分支）

### 3.3 背包引擎
- 物品堆叠/类型（内容包定义）
- **局内使用道具不消耗回合**（逃课方法），受【药剂冷却】（3.14）与【同类型药剂回合限次】（3.14.1）双重限制
- 【战斗内药剂使用规则（v2.10，用户拍板）】：
  · 不耗回合保留：/道具 使用不占用本回合行动、不触发怪物反击（不被攻击）
  · 同类型药剂一回合限 1 次：回血+回蓝可各用 1 次，回血不能 2 次（防靠喝药逃课）
  · 同类型判定：物品【药剂类型】potion_type（4.2 元数据；回血/回蓝/增益/其他，默认 auto 按效果推断）
  · 回合推进（玩家执行消耗回合的行动并结算完毕）→ 限次计数重置
  · 快照：potion_use_counts 入 3.18/A.5（中断恢复不重置）
- 物品【绑定】属性：绑定不可赠送/掉落（3.8 赠送 / 3.11 死亡惩罚联动）

### 3.4 状态异常（v2.6 补全叠加规则）
```
- 状态定义字段：
  · 类型：增益/减益/控制
  · 叠加上限：默认【不可叠加】→ 重复施加 = 高覆盖低（新状态覆盖旧状态）
  · 勾选"可叠加"后：支持层数叠加（设上限）
  · 持续方式：回合数 / 现实时长（秒）
  · 解除方式：自然结束 / 道具 / 技能 / 死亡 / 地图切换（多选）
- 【效果执行体（v2.7）】：
  effects: [
    {"type": "stat_modifier", "stat": "def", "value": -20, "percent": true},
    {"type": "dot", "stat": "hp", "value": "5%", "tick": "turn_end"},
    {"type": "control", "effect": "skip_turn", "chance": 30}
  ]
  · stat_modifier：修正指定属性（引用 stats.json）
  · dot：每回合结算点扣血/扣蓝（固定值或百分比）
  · control：跳过回合/无法行动（概率）
  · 结算时机：回合开始/回合结束（与 3.1 行动顺序衔接）
- 【原子动作词汇表（v2.9 汇总）】：3.4 执行体 + 以下动作供效果/特性/道具/技能/敌人行动复用：
  **直行动作**（主动执行，无概率无持续）：
  · damage：直接伤害（数值/表达式）
  · heal：回复（数值/百分比）
  · stat_modifier：属性修正（引用 stats.json）
  · dot：持续伤害（tick 回合开始/结束）
  · control：控制（skip_turn 概率）
  · status_apply：施加状态（引用 statuses.json；含 hit_rate/耐性修正）【v2.9 新增】
  · dispel：驱散/净化（寻址 target+filter+count，FIFO 消除）【v2.9 新增】
  · shield：护盾（吸收量/破盾条件）【v2.9 新增】
  · mark_add：印记施加（target self/enemy + mark + count；施加必中，重复施加叠层至上限）【v2.9 新增】
  · mark_remove：印记消除（marks_on+polarity+count；默认消 1 层+冷却 ≥2，作者改低仅提示）【v2.9 新增】
  · clear_marks：印记全消（marks_on+polarity+可选 mark；全消成本更高，冷却 ≥3）【v2.9 新增】
  · interrupt：打断（清目标连段；目标霸体 armor=true 免疫）【v2.9 新增】（唯一效果来源=effects.json 引用；技能/行动侧 tag/interrupt 布尔仅展示/派生语义的快捷字段，不双写）
  · summon：召唤/临时单位
  · convert：素材转换（N→M）
  · aoe：范围效果（1v1 中=对目标+提示）
  **结算修正器**（挂伤害管线，每次伤害自动生效，无概率无冷却）：
  · lifesteal：生命偷取（按伤害百分比）
  · pierce：穿透（无视对方一定百分比防御/精神，上限可配）
  · mitigation：减伤/减免（scope 参数化：普攻/技能/异常/暴击/属性）
  **触发容器**：
  · proc：概率触发（触发器+概率+冷却+子动作）
  · element_modifier：元素附加/转化（引用元素注册表）
  · 允许 x_ 前缀扩展（自定义动作，校验器放行；框架级动作不走 x_ 通道）
  · 动作字段注册表：逐动作转 4.2 字段元数据行，全模块共用一张表；校验仅查引用/概率三态/特效链环（数值仅提示）
- 战斗中状态行显示剩余回合（"中毒 2/3"），默认显示前 5 个（可配），超出追加"还有 N 个状态"
```

### 3.6 时间系统（怪物刷新/出没）
```
- 现实时间驱动（非回合数）：
  刷新时间 = 地图怪物每隔 X 分钟刷一只
  出没时间 = 时段限制（如"夜间 20:00-6:00"才出现的怪；支持跨天区间）
- 【怪物数量】：配置 N = 场上同时最多 N 只（杀光等刷新）；
  【配置 0 / 不配置 = 无限资源】（默认无限刷，无数量限制）
- 存档记录 last_spawn_time，玩家操作时按时间差补刷
- 【补刷上限】：离线超过 N 小时按 N 小时算（不无限累积）；有数量上限的地图补到上限即停
- 【时区】：统一 UTC+8（北京时间），其他时区用户自行适应
- 玩法示例：白天矿洞安全，晚上出幽灵怪（同一地图两套怪）
```

### 3.7 存档引擎（碎片化续玩）
```
- 自动保存：每指令处理后 / 战斗结算后（SQLite 事务）
- 【无上下线概念】：群聊是碎片化场景，任何时候进来直接续玩
- 【存档跟随 QQ 号（全局）】：玩家数据全局绑定 QQ 号
  - 跨群/跨私聊共享同一角色（世界状态全局共享，见 3.7）
  - 消息归属清晰
- 【换包策略（v2.6）】：切换启用内容包时三选一（编辑器设置）：
  ① 自动迁移（尽力映射：同 ID 保留，缺失物品红名显示+一键清除）
  ② 全服重置（确认后清空玩家数据）
  ③ 双存档并行（旧包存档保留，可切回）
- 存档含 content_pack_id + version，更新自动迁移（字段级：缺补默认/多忽略）
```

### 3.8 世界状态（全局世界，跨群共享）
```
- 【全局世界】：所有群 + 私聊 = 同一个世界
  - 一张地图、一个怪物池、一个野图 BOSS（全服共享）
  - 玩家位置/状态：全局共享（QQ 号绑定，跟群无关）
- 私聊判定：不看消息来源群，只看"玩家 QQ 号 + 全局世界"
  - 群 1 打了一半的野图 BOSS → 切私聊继续打（同一场战斗）
  - 私聊 = 无干扰操作空间（看背包/整理装备不刷群屏）
- 跨群竞争：野图 BOSS 全服一个，谁先打死谁赢（社交动力）
- 跨群并发互斥（2026-08-16 补）：同一玩家多群同时发指令 → 世界状态写入串行化（SQLite 事务，3.7 单角色）；战斗类指令按会话互斥（3.18 单会话：A 群战斗进行中，B 群战斗指令提示"已在战斗中"并指向 A 群；非战斗指令（/状态 /商店 /签到）不受限可并行）；提示归属=发起指令所在群；野图 BOSS 竞争按 3.8 先到先得
- 世界状态 key = 全局（不区分群）；玩家状态 key = QQ 号
```

### 3.9 GM 权限系统
```
- GM 权限：数据库配置（机主在编辑器/数据库设置），【不自动授予群管理】
- 无 GM 权限的玩家使用 GM 指令 → 直接无视（不报错不提示，避免暴露指令存在）
- GM 指令：/重载 <内容包> /备份 /恢复 /存档导出 /调试 等
- 权限分级：
  机主（数据库最高权限）= 全部
  GM（机主授予）= 重载/备份/恢复
  普通玩家 = 仅游玩指令
```

### 3.10 货币系统（自定义）
```
- 【货币种类/名称/数量完全自定义】（编辑器通用设置）：
  · 默认模板：金币（通用货币）+ 钻石（高级货币），可改名/增删
  · 例：自定义"铜币/银币/金币"三档，或"晶核/星尘"等任意名称
- 【货币持有上限】：默认不设上限；可配置（如活动货币设 100 上限）
- 用途区分：各货币用于什么（商店/强化/活动）由内容包配置，不硬编码
```

### 3.11 商店库存（限购系统）
```
- 默认无限库存（简单）
- 可配置限购：
  · 个人限购：每人每日/每时/每周/每月限购 N 个
  · 全体限购：全服共限购 N 个（售完即止，时间到重置）
  · 例："每月全体限购 10 个的稀有材料" → 抢购玩法
- 限购周期：每日 / 每时 / 每周 / 每月（时间系统驱动）
```

### 3.12 死亡惩罚与虚弱
```
- 默认【无惩罚】：被击败 → 复活回最近安全区 + 虚弱
- 【虚弱时间】：默认 1 分钟，期间无法进入非安全区地图（防立刻送死）
- 可配置惩罚（编辑器通用设置）：
  · 掉落货币（比例，可指定哪几种货币）
  · 掉落经验
  · 掉落物品数量（随机选背包物品）
- 【绑定物品不可掉落】：绑定物品免疫掉落惩罚
- 复活点：地图可配置"安全区/复活点"，死亡回最近安全区（新手村默认）
```

### 3.13 等级上限与战后恢复（v2.6）
```
- 内容包配置【等级上限】（如 45 级）；满级后经验不再增长（或经验转货币，可选）
- 升级时 HP/MP 回满（JRPG 惯例）
- 【战后恢复（默认关闭）】：胜利后回复 HP/MP 比例 + 安全区回复
  · 默认关闭（花钱治疗本身是资源循环的一部分）
  · 用户可开启：战后治疗比例 / 安全区停留回复
```

### 3.14 药剂冷却（v2.6）
```
- 药剂/道具可配置【冷却时间】，两种模式：
  · 回合冷却：战斗中冷却 N 回合；进入安全区后重置
  · 时间冷却（秒）：现实时间冷却——适合永久增加属性的药剂
    （长时间冷却限制使用频率，如"每日限用 1 次的成长药水"）
- 与"道具不消耗回合"并存：不耗回合但受冷却限制
```

### 3.15 BOSS 脱战回血
```
- BOSS/怪物脱离战斗（解除锁定 / 离开地图 / 战斗失败）→ HP 回满
- 防多人车轮战磨死 BOSS；野图竞争公平
- 与"怪物丢失机制"配合：抢怪者从头打（对方已脱离=回满）
```

### 3.16 出没时段边界（v2.6）
```
- 出没时段结束 → 该怪物【直接从场上移除】（不留残怪）
- 玩家战斗中该怪消失 → 提示"对方逃跑了"，战斗按退出处理
- 非出没时段暂停刷新计时；跨天时段（20:00-6:00）按结束>开始判定日期偏移
```

### 3.17 战斗中断恢复

  → 可继续或放弃

> 【recipe.json 合成引擎统一 schema（v2.9 登记 · 全量重叠检查组3 F2 修复）】
> 合成引擎 = **框架机制（代码）**，各系统 = **配置实例（JSON）**——机制与内容分离。
> 通用「N 入→1 出」合成（输入 N 个 + 消耗 → 输出 1 个高级），`kind` 三值：
>   · `craft`    配方生产（配方+材料 → 成品，即原合成层）
>   · `combine`  等量合并（N 个同质 → 1 个高级，如锻造 3:1 素材合成）
>   · `upgrade`  升阶（N 个同类 + 消耗 → 更高阶，如炼金珠三合一/特性合成/成品合成/配方合成）
> ```json
> {
>   "id": "recipe_xxx",
>   "name": "合成名",
>   "kind": "combine | upgrade | craft",
>   "inputs": [{"item": "item_id", "type": "material", "count": 3}],
>   "cost": {"coins": 0, "gem": 0},
>   "output": {"item": "item_id", "count": 1, "quality": "normal | fine | epic | legendary"},
>   "conditions": ["prof_level >= 5"]
> }
> ```
> - inputs[].item / inputs[].type 二选一（item=items.json 引用，type=物品类型通配）；count ≥ 2（combine/upgrade 建议 2~3）
> - cost = 货币/资源消耗（金币/宝石等，可空）；output.quality = items.json 四档品质（可选）；conditions = 解锁/门槛条件（复用条件引擎）
> - 指令统一（建议）：/合成 家族共用解析——/珠升阶 /书合成 /特性合成 /成品合成 /配方合成 等由 recipe.kind 路由到统一合成指令（如 /合成 <目标>），玩家少记入口（只建议不限制）

### 4.1.1 manifest 模块声明（v2.9，新增模块如何声明）
```json
{
  "name": "我的RPG",
  "version": "1.2.0",
  "schema_version": 5,
  "author": "作者名",
  "modules": [
    "manifest", "settings", "proficiency", "slots", "stats", "jobs",
    "skills", "skill_chains", "statuses", "effects", "marks", "traits",
    "items", "enemies", "action", "maps", "loot", "formula", "shop",
    "checkin", "enhance", "recipe", "quest", "forge", "dungeon", "npc", "profession", "achievements", "fishing"
  ]
}
```
- modules 数组 = 本包启用的模块文件清单（不含 .json 后缀），loader 按声明顺序加载
- 新增模块启用 = 在 modules 数组补一行（如 "effects"、"marks"、"skill_chains"、"action"、"npc"、"dungeon"）；不声明 = 对应系统不加载（向后兼容，旧包零改动可跑，新模块缺失仅提示）
- schema_version 随新模块引入升版（5，v2.11 引入 npc 时 3→4，v2.17/v2.18 引入 fishing/achievements 时 4→5）：框架按 schema_version 决定迁移路径（例：内联 effects 数组 → effects.json ID 引用，热重载自动迁移）
- 校验器：modules 声明的文件缺失 → 黄色提示不拒绝（见 4.5）；未声明的文件存在 → 不加载（防误启用）

### 4.2 字段元数据层（v2.7 新增，框架核心）
> 所有模块的**字段定义**是唯一数据源——编辑器表单、CSV 列头、JSON Schema、
> 校验规则四处共用，杜绝"各处手写漂移"。

```
字段元数据（每模块一张表）：
  字段名 | 中文名 | 类型（int/str/bool/enum/ref）| 默认值 | 范围 | 引用目标
例（items.json）：
  id        | ID        | str   | 自动生成  | -      | -
  name      | 名称      | str   | 必填      | ≤20字  | -
  type      | 类型      | enum  | consumable| 装备/消耗品/材料/任务  | -
  quality   | 品质      | enum  | 普通      | 普通/精良/史诗/传说   | -
  slot      | 部位      | ref   | -         | -      | slots.json
  job_restrict | 职业限制 | ref  | -         | -      | jobs.json
  price     | 价格      | ref   | 0         | ≥0     | settings.json 货币
  bound     | 绑定      | bool  | false     | -      | -
  cooldown  | 冷却      | obj   | 无        | 回合/秒 | -
  stats_bonus| 属性加成  | map   | {}        | -      | stats.json
  effects   | 特殊效果  | list  | []        | -      | 原子动作
```

**机制**：
- 编辑器表单 = 元数据自动生成（新增字段只需加元数据行）
- CSV 列头 = 元数据中文名自动导出（含 ID 列，可留空=新建）
- JSON Schema = 元数据动态生成（引用字段用动态 enum，从 registry 取）
- 校验器 = 元数据驱动（类型/范围/引用完整性）
- 自定义字段：作者可加 `x_` 前缀字段（编辑器自定义字段面板，校验器放行）
```

#### 4.2.3 虚拟属性键空间声明
```
键空间 = stats.json 已注册属性 ∪ 虚拟键 {crit_bonus, crit_mult_up, elem_res} ∪ {ele_atk_<e> | e ∈ formula.json 元素注册表}

消费方（校验器统一查键空间）：
  · items.json stats_bonus（装备/药剂词条）
  · stat_modifier 动作（状态/效果/特性的属性修正，引用 stats.json）
  · 派生条件 stat 字段 / 技能 mp_cost 资源轴映射
  · 效果动作参数（dot 的 stat、heal 的 stat 等）

引用目标（唯一数据源）：
  · stats.json 属性注册表（9 项默认模板 + 作者注册自定义属性）
  · formula.json 元素注册表（地水火风雷晶月，元素类键的枚举来源）

规则：
  · 动态键：元素注册表增删元素 → ele_atk_<元素> 键自动增减（无该键时按 0 处理不报错）
  · 自定义属性：作者在 stats.json 注册（或 x_ 前缀），注册后即入键空间
  · 校验行为：未注册键 → 黄色提示「属性『xxx』未注册，确认是自定义还是笔误？」（不拦截）
    ；元素键的元素不在注册表 → 黄色提示；类型错误 / 负数 → 红色拦截
```

#### 4.2.3.1 键空间互译表（条件键 ↔ 中文变量，同一注册表两种写法）

> 数值寻址键空间共三套表达（F7 仲裁）：条件引擎机器键 / 变量大全中文变量 / 4.2.3 虚拟属性键。
> 本表为【唯一互译声明】——条件键是机器键，中文变量是展示/公式键，二者是同一注册表的两种写法；
> 编辑器互译显示（编辑面板显示中文变量键，配置存储与校验一律用英文条件键）。

| 条件英文键（机器键） | 变量大全中文变量（展示/公式键） | 说明 |
|---|---|---|
| { var: "level" } | [当前等级] | 玩家等级 |
| { var: "item_count", param: X } | [背包:X] | 背包物品数量（泛化引用） |
| { var: "has_item" / "not_has_item" } | （无中文变量，条件专用布尔） | 是否持有 |
| { var: "gain_count", param: X } | [累计获得:X] | 累计获得（longline_counters） |
| { var: "kill_count", param: X } | [累计击杀:X] | 累计击杀（longline_counters） |
| { var: "dungeon_clear", param: X } | [副本通关:X] | 副本通关次数 |
| { var: "codex" } | [图鉴完成度] | 图鉴解锁百分比 |
| { var: "prof_level", param: X } | [熟练度:X] | 职业熟练等级（7 级体系） |
| { var: "reputation", param: 板ID } | [声望:X] | 声望等级 |
| { var: "job" } | [职业] | 职业 |
| { var: "[签到:连续天数]" } | [签到天数] | 连续签到天数（F.6 条件键 ↔ 变量大全④，同键互译） |
| { var: "season", param: X } | [季节:X] | 当前季节 == X（X ∈ 四季枚举；时间天气定稿 §4.0 登记） |
| { var: "period", param: X } | [时段:X] | 当前时段 == X（X ∈ 五时段枚举；时间天气定稿 §4.0 登记） |
| { var: "weather", param: X } | [天气:X] | 玩家当前所在图的当前天气 == X（X ∈ 注册天气集；时间天气定稿 §4.0 登记） |
| 事件原语 on_* / {type:event,...} | [事件:X] | 事件型（NPC 4.0 映射） |

规则（互译 + 单口登记）：
  · 互译关系 = 双向等价：条件键是机器键（存储/校验/引擎执行），中文变量是展示/公式键（编辑器面板、JS 公式占位符），
    同一注册表两种写法；新增键单口登记：进条件键空间（D.3）即自动生成变量大全条目，不双处登记
  · 【背包计数】统一为 item_count + param 一种写法：{ var: "item_count", param: X }；
    [背包:X] 仅为展示糖（编辑器/公式中的中文写法），不再另立 has_item 数量型/背包计数键
  · 中文变量（[我方攻击]/[当前回合数] 等战斗上下文变量）无对应条件键的，不强制映射——
    条件引擎只读快照/长线状态，战斗上下文变量仅公式引擎可用（见效果表达式变量体系定稿 1.4）
  · 详细全量表：NPC 定稿 4.3.1 互译表为同表镜像（字段口径以本节为准）

#### 4.2.4 原则：只建议不限制（范围列语义定版）
```
- 范围列 = 黄色提示阈值，只驱动提示文案，不驱动拒绝（与 4.5 校验器「数值范围」行同口径）
  · 超出范围 → 提示「超出常见区间，确认是故意设计？」（可加载，不拦截）
  · 例：power 999 / 生命 999999 / 消除技冷却过低 / 派生累计倍率 >1.5× / 印记条件过多
- 红色拦截（硬校验）仅限：类型错误、负数、必填缺失、引用不存在、死配置
  · 死配置 = 逻辑上永不生效：条件 min>max、eq>max_combo、reset 模式 eq=max、
    印记条件 vs 叠加上限矛盾、条件引用不存在的状态/属性、battle+revert 矛盾
- 软标注字段（difficulty / playstyle 等）永不红色报错；「简单职业引用复杂机制」仅黄色提示
- 校验器文案模板：黄色 = 提示（可加载），红色 = 报错（拦截）；报错一律人话（4.5 模板）
- x_ 前缀自定义字段/动作：校验器一律放行（编辑器自定义字段面板），仅查引用存在性
```

### 4.4 加载流程（v2.9）
```
1. loader 读 manifest → 按 modules 声明顺序加载 → 校验模块齐全（缺失仅提示不拒绝，见 4.5）
2. 逐模块加载 → validator 校验（引用完整性/互斥无环/数值范围）
   · 新模块注册顺序：effects → statuses → marks（效果家族先注册）→ skill_chains → action
   · 引用依赖：效果家族被 traits/items/skills/enemies 引用，须先入 registry；
     skill_chains 引用 skills 连段标签；action 引用 effects 原子动作
3. 注册 registry（ID 全局唯一）：
   · 效果注册表：effects/statuses/marks 三表统一登记（ID 跨表唯一，供挂载点统一引用）
   · 行动注册表：action.json（enemies.actions 按 ID 引用，一行动多怪复用）
   · 派生链注册表：skill_chains.json（连段标签/派生条件索引）
4. 热重载：编辑器保存 → 文件 mtime/哈希检测 → 该包即时生效
   · 新模块同样纳入 mtime 监控（effects/marks/skill_chains/action 保存即重载）
   · 旧配置自动迁移：内联 effects 数组 → effects.json ID 引用（语义字段取默认值，旧包零改动可跑）
   · 进行中对局持旧快照，新对局用新配置
```

### 4.5 校验器（人性化报错）
| 校验项 | 报错示例（人话） |
|---|---|
| 引用完整性 | "『巨剑』引用的部位『双手武器』不存在，请先在部位页面添加" |
| 部位互斥环 | "你的武器、盾牌、副手互相排斥形成了一个圈，谁也装不上，请删掉一条互斥" |
| 数值范围 | "生命值 999999，超出常见区间，确认是故意设计？"（提示不拦截，只拦负数/类型错误） |
| ID 唯一 | "已经有一个叫『铁剑』的物品了，换个名字吧" |
| 模块齐全（新模块缺失） | "没找到『effects.json』：效果/印记/派生/怪物行动系统不会启用。旧包照常玩，想用这些系统时再加文件即可"（黄色提示，不拒绝加载） |
| 模块齐全（声明/引用不一致） | "『marks.json』里引用了印记『fire_mark』，但印记表没加载——检查 manifest 的 modules 声明是否漏了 marks"（提示不拒绝） |
| AI 阶段引用 | "阶段 2 的阈值 30 大于阶段 1 的 60？确认顺序"（提示） |
| AI 连招引用 | "连锁动作『尾扫』在行动库里不存在"（硬拦——引用不存在） |
| AI 换区目标 | "换区目标『熔岩坑道』不是本副本的地图"（提示） |
| AI 触发参数 | "触发 hp_below 缺 value 参数"（硬拦——结构错误） |
| AI 概率总和 | "行动表概率总和为 0，怪物只会普攻？确认是纯脚本怪还是漏配"（提示） |
| AI 接续概率 | "连招接续概率 50% 低于 60%，玩家可能放弃记忆规则"（提示） |

**ID 唯一性规则（统一声明 · 一处声明三处引用）**

| 作用域 | 规则 | 说明 |
|---|---|---|
| 效果家族三表（effects / statuses / marks） | **跨表唯一** | 4.4 效果注册表统一登记（registry 统一），ID 跨表唯一，供挂载点统一引用 |
| 其余全部模块（items / skills / enemies / npc / maps / ...） | **表内唯一** | 同表 ID 不得重复（示例=物品）；跨表可同名（不同模块各自命名空间） |
| 技能-行动（skills.json ↔ action.json） | **同库唯一** | 两表共用 ActionCore（同一执行器），技能与行动同库内 ID 唯一，不得互相重复 |

> 引用方式（一处声明、三处引用）：
>  · 各系统定稿的「ID 唯一」校验行一律引用本规则，不再各自重复声明（"id 唯一"即表内唯一，见上表）
>  · 效果家族跨表唯一 = 4.4 加载流程「效果注册表：effects/statuses/marks 三表统一登记（ID 跨表唯一）」的唯一来源
>  · 技能-行动同库唯一 = 技能库定稿 §8.10「技能/行动 ID 唯一」的补充声明（同库共享 ActionCore 命名空间）
>  · 撞名语义：同表/同库撞名 = 红色拦截（寻址歧义）；跨表撞名（非效果家族）= 黄色提示（引用带表上下文，仅影响显示层）

- 遵循【只建议不限制】总纲：新模块（effects/marks/skill_chains/action）缺失 = 仅提示，不拦截加载、不阻止开玩；缺失语义 = 对应系统不启用（旧包向后兼容）
- 编辑器提供【一键补全缺失模块】快捷入口（生成空模板文件并自动补 manifest 声明），把「补模块」从报错负担变成可选操作

### 6.13 AI 辅助创作（可选功能，BYOK）
> 定位：AI 帮策划批量生成数据/文案/数值建议，**可选开启**（用户自带 API Key）。
> 游戏运行时【不接 AI】（纯规则引擎）；仅创作阶段可选用 AI 提效。

**接入方式（BYOK：用户自带 Key）**
```
- 编辑器【AI 设置】：填 OpenAI 兼容接口的 API Key + 模型名 + 接口地址
  （用户自己的 key，支持任意 OpenAI 兼容服务；不填 = 无 AI 功能，不影响使用）
- Key 仅存本机配置，不上传任何第三方
```

**AI 生成流程（一切过校验器）**
```
① 用户输入意图：
   "生成 200 件 1-15 级武器，战士和法师各一半"
   "帮我设计一个 30 级的 BOSS 幽灵王"
   "给这 10 件装备写介绍文案"
   "把铁剑攻击力调高一点，顺便生成 5 个强化版本"
② 框架组装 prompt：意图 + 当前内容包 Schema（JSON Schema 定义）+ 已有数据摘要
   （告诉 AI 现有 ID 规则/命名习惯/数值区间，避免生成重复或越界数据）
③ AI 输出 JSON（严格按 Schema）→ 校验器逐条校验
④ 预览页展示生成结果卡片列表（每条可勾选/编辑）
⑤ 用户确认 → 导入内容包 → 热重载生效
```

**AI 输出约束（Schema 强校验）**
```
- 每个生成模块有 JSON Schema（物品/怪物/地图/技能/职业/掉落/角色）
- AI 输出必须符合 Schema 才能导入（结构错误直接拒绝）
- 校验器复用人话报错："第 3 件武器『巨斧』攻击力填了 -5，攻击力最小是 1 哦"
- ID 冲突/名称重复 → 预览页标红提示
```

**AI 生成场景**
| 场景 | 说明 |
|---|---|
| 批量生成 | "200 件武器"一次生成（配合 CSV 更进一步） |
| 单条精调 | "设计一个 BOSS" / "补一条掉落" |
| 文案补全 | 物品/怪物/地图介绍文案（策划写数值 AI 写文案） |
| 数值建议 | "给我 10 件 20-30 级武器的攻防区间表"（AI 出参考，人定稿） |
| 对话式修改 | "铁剑攻击力太高了，调低点"（AI 返回修改后的 JSON） |

**安全边界**
```
- AI 只生成数据，不执行任何操作（无文件写入权限，全走预览确认）
- 生成数据必须过校验器 + 用户确认才入库
- AI 不可用（无 key/网络失败）→ 编辑器其余功能完全不受影响
- 运行时引擎永远不依赖 AI（纯规则，确定性）
```

**与 JSON 选型的关系**
```
- 底层存储 JSON（运行时稳定 + 编辑器原生）
- AI 输出 JSON（LLM JSON 模式 + Schema 校验，可靠性最高）
- 人写数据走编辑器 GUI；进阶走 CSV；AI 走 JSON 生成
- 三通道共用同一套校验器，同一份数据
```

### 7.2 指令触发模式（可配置）
```
① @机器人触发：必须 @机器人 + 指令才生效（防误触发，默认）
② 前缀触发：自定义前缀（如 !攻击 / ！攻击），前缀+指令生效
③ 直接触发（不 @ 不加前缀）：玩家直接发送指令词即触发（NoneBot2 支持）
   ——开关可选，打开后"背包"两个字直接生效，无需 @
④ 敏感词触发（完整匹配）：消息完整等于指令才触发
   可选"敏感词+子串"：消息带指令词即触发

### 7.3 自然语言技能指令（"攻击+技能名"）

### 7.4 分页与筛选语法（长列表通用）
```
语法：<功能> [页数] | <功能>筛选 <物品类型> [类型 <子类目>] [品质 <品质>]
示例：
  背包               → 第 1 页（5 条）
  背包2              → 第 2 页
  背包筛选装备        → 只看装备类
  背包筛选装备 类型 武器 → 装备类且子类目=武器
  背包筛选装备 品质 史诗 → 装备类且品质=史诗

- 分页默认 5 条/页（可配置）
- 筛选链：物品类型 → 类型(子类目) → 品质，可叠加
- 超长消息自动截断分两条发送（不吞消息）

### 11.4 更新机制（v2.7：git 分发）
```
【分发渠道 = git 仓库】（作者托管，玩家 git pull 更新）
- 仓库结构：框架代码 + content/（预置包）+ 内容包发布分支
- 更新流程：
  ① 启动器启动时检查本地 git 版本 vs 远端（git fetch + 版本比对）
  ② 有新版 → 弹窗"有新版本" → 自动 git pull → 校验 → 重启
  ③ 更新前自动备份存档（/备份）
  ④ 更新失败 → 保留旧版继续运行（绝不因更新起不来）
- 内容包更新：作者推送到 git → 玩家 pull 即同步（朋友端同一仓库）
- 服务器端：git pull 后重启服务
- 防小白：启动器封装 git 命令（玩家不接触命令行），
  仅显示"检查更新/更新完成"状态
```

## 15. 技术要点（v2.6 补全）

1. **NoneBot2 插件规范**：on_command 注册指令，Matcher 生命周期处理参数
2. **指令并发竞态防护**：
   - per-player 串行队列（同一玩家指令按到达顺序处理，防乱序/双结算）
   - 世界级共享资源（野图 BOSS/全体限购）用全局锁 + 事务 + CAS 更新
   - PVP 同一对玩家只允许存在一场战斗
   - 指令处理以 message_id 做幂等键（防重复结算）
3. **异步边界**：所有 >50ms 操作（内容包校验/CSV 导入/zip 打包/文件 IO）
   走 asyncio.to_thread；SQLite 用 aiosqlite 独立连接；
   耗时操作先回"处理中"提示再异步完成；验收标准：单条指令端到端 <200ms
4. **SQLite 并发**：单写连接队列 + busy_timeout；自动保存防抖合并
   （200ms 内合并多次变更为一次落盘，战斗结算强制落盘）；
   备份用 VACUUM INTO 或 checkpoint 后再复制；auto_vacuum + 定期 VACUUM
5. **热重载原子性**：先写临时文件再原子 rename，全部文件写完统一触发重载；
   内存保留上一份校验通过的 registry 快照，失败自动回退并人话提示；
   按文件 mtime 增量校验，只重载变更模块
6. **内容包 zip 导入安全**：解压到临时目录 → 条目路径白名单校验
   （拒绝 ../ 与绝对路径，防 zip slip）→ 条目数/总大小上限（防 zip 炸弹）
   → manifest 校验 → 全量校验通过后原子替换 + 触发重载
7. **QQ 消息层**：统一消息解析器（段级提取 at/图片/表情 + CQ 码转义防注入）；
   渲染层长度预算（超长自动分两条发送）；发送出口统一封装含失败重试与风控退避
8. **状态一致性**：战斗状态机（player_command/enemy_command/animating）防重复指令
9. **SQLite 事务**：每指令后事务提交，崩溃恢复
10. **时间控制**：指令防抖（1s）/频率控制（群每分钟 ≤20）
11. **定时任务**：nonebot_plugin_apscheduler 管理周期逻辑
    （限购重置/排行榜刷新/活动时段切换），与"操作时懒计算"并存，重置以定时器为准
12. **备份恢复事务化**：校验备份完整性 → 自动备份当前档 → 原子替换 → 失败自动回滚；
    备份保留时间用户可配（默认 30 天）
13. **日志**：RotatingFileHandler（大小+份数轮转）+ 脱敏（QQ 号/API Key）；
    磁盘低水位监控（<15% 预警）；回收站/备份自动清理策略
14. **多实例防护**：启动器单实例锁（pid 文件 + socket 占用检测）；
    端口探测清单（OneBot WS 3001 / 编辑器端口），冲突自动换并回写配置
15. **扩展预留**：manifest 加 schema_version 字段与迁移链；文案资源化（i18n 键值表）；
    FastAPI 预留 /ws 路由与事件广播接口
16. **测试**：pytest 单测伤害公式/状态机/存档往返；故障注入（回复前崩溃路径）

## 16. 风险与对策

| 风险 | 对策 |
|---|---|
| 配置自由度大→校验复杂 | 分层校验+人话报错+编辑器实时标红 |
| Web 固定视口实现复杂 | 统一组件库（表格/卡片/标签页复用） |
| 热重载导致进行中对局异常 | 版本快照隔离（旧局旧配置，新局新配置） |
| 刷屏封号 | 1v1 + 一轮一条消息 + 防抖 + 频率限制 |
| 时间系统跨日/时区 | 服务器时区配置项（默认 UTC+8）+ 出没跨天判定 |
| 小白配置坏数据 | 自动备份 .bak + 失败回退 + 校验拦截 |
| 公式表达式安全 | 白名单函数安全求值器 |

  · aoe：范围效果（1v1 中=对目标+提示）

结算修正器（挂伤害管线，每次伤害自动生效，无概率无冷却）：
  · lifesteal：生命偷取（按伤害百分比）
  · pierce：穿透（无视对方一定百分比防御/精神，上限可配）
  · mitigation：减伤/减免（scope 参数化：普攻/技能/异常/暴击/属性）

触发容器：
  · proc：概率触发（触发器+概率+冷却+子动作）
  · element_modifier：元素附加/转化（引用元素注册表）

- 允许 x_ 前缀扩展（自定义动作，校验器放行；框架级动作不走 x_ 通道）
- 动作字段注册表：逐动作转 4.2 字段元数据行（字段名/中文名/类型/默认值/范围/引用目标），全模块共用一张表
- 校验：动作引用存在性 + 概率三态合法 + 特效链环检测（图论环）；数值与组合强度仅提示不拦截
```
