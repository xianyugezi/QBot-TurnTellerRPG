## 二、功能设计

### 2.1 效果引用归一（execute_action 入口新增，纯增量）

在 execute_action 开头（atype 取后、分支前）插入归一：

```
def _normalize_effect_ref(action, ctx, runtime, depth):
    """效果引用归一：{effect: id, overrides} → 可执行 action 列表。
    返回 (actions_list | None, skipped_cond: bool)
    - 无 effect 键 → (None, False) 原样走既有分支（零行为变化）
    - 有 effect 键：
      defn = runtime._resolver(id, "effect") 查 effects 定义（Def 或 dict）
      defn 缺失 → 安全失败（ok=False，不崩，热重载删效果降级 A-6）
      defn 有 actions（L2/special/模板容器）→ 逐个子动作递归归一 + 执行（深度上限防递归）
      defn 无 actions → 定义字段 + overrides 合成单 action 继续 execute_action
      （合成映射见 2.3 常量表）
    """
```

### 2.2 效果条件门控（condition 键，纯配置）

- 引用条目可带 `"condition": {...}`（或合成 action 带 condition）：
  `{"effect": "smite_bonus", "overrides": {...}, "condition": {"target_marks": {"vulnerable": {"min": 1}}}}`
- 求值 = combo.evaluate_condition(condition, ConditionCtx(...), marks_lookup)；
  - ConditionCtx 从 ctx.snapshot 构造：self_statuses/target_statuses 从 snapshot[side].status_state
    实例收集 status_id；target_hp_pct = target.hp/max_hp*100；round_ = snapshot.get("turn",1)；count=0
  - marks_lookup：构造 `lambda kind, which, rule, mark_id: marks_count_ge(...)`——复用功能一
    的 marks_state 读取语义（_mark_count_on 同构，直接读 snapshot["marks_state"]），
    不依赖 MarksManager 注入（effects 层轻量自读，对齐 monster_conditions 功能一实现）
- 条件不满足 → 跳过该效果（不进 side_effects，不报错）；无条件 → 恒执行
- 缺省/未知 condition 键 → evaluate_condition 安全失败返回 False → 跳过（对齐既有安全失败口径）

### 2.3 可配置常量（effects.py 模块级，非硬编码）

```python
# 效果引用归一键（对齐 6a EFFECT_REF_KEY）
EFFECT_REF_KEY: str = "effect"        # {effect: id}
EFFECT_OVERRIDES_KEY: str = "overrides"
EFFECT_CONDITION_KEY: str = "condition"
EFFECT_ACTIONS_KEY: str = "actions"

# 定义字段 → 执行 action 字段映射（1b §1.1 + 模板；power/duration 等定义字段翻译为
# execute_action 消费字段。只映射 execute_action 分支实际消费的键）
_EFFECT_DEF_TO_ACTION_MAP: Dict[str, str] = {
    "power": "value",       # 效果定义 power(定稿滑条 10-500) → L0 action value
    "duration": "turns",    # 效果定义 duration → dot/shield 等 turns
    "stat": "stat",
    "target": "target",
}
# class=atomic（L0 动作）直通 type；class 缺失但 type ∈ L0 词汇 → 同样直通（test_demo 简化形态）
```

### 2.4 执行链改造点（effects.py）

1. `execute_action` 开头：`ref = _normalize_effect_ref(...)`；若返回 action 列表 → 逐个
   执行（递归 execute_action，depth+1），合并 side_effects；深度超限安全失败。
2. condition 求值放归一后、动作执行前（引用条目 condition 与合成 action condition 同判）。
3. `execute_proc_action` 子动作循环同样过归一（proc 内引用生效，补 L-06 族）。
