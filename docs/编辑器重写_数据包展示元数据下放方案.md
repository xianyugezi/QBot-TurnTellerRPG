# 数据包展示元数据下放方案（三方彻底分离 · 2026-09-13）

> 起因：用户问「框架、数据包、编辑器是不是三方分离的」。实测结论：**框架↔编辑器已分离（框架零依赖编辑器）**、
> **包↔代码已分离（9 包换包验收全 PASS）**，但**包专属的展示层元数据仍写在框架代码里**——
> `qbot_rpg/content/field_meta.py` 中 **102 处** `*_FIELD_LABELS`（中文名）/ `*_FIELD_HELP`（字段说明）/
> `*_GROUP_LABELS`（分组名），含 veinborn / test_demo 的具体键名。
> 后果：换一个新包时它没有中文名（编辑器兜底显示裸键），要变好看就得改框架代码 → 与「换包零改动」精神冲突。
> 用户 2026-09-13 拍板：**做**（下放）。

---

## 一、目标与判断标准

**目标**：包自己声明它的展示元数据；框架只提供**通用机制 + 兜底**。

**判断标准（可验收）**：
1. 新建一个内容包，在包内声明中文名/说明/分组 → **编辑器与框架均零改动**，界面即显示中文；
2. 迁移前后，`veinborn` / `test_demo` 的编辑器接口输出**逐字段完全等价**（对拍 diff=0）；
3. 框架不依赖任何具体包：`qbot_rpg/` 里不再出现 veinborn/test_demo 专属的**展示**键名（校验规则表除外，见 §三）；
4. 现有全量测试 + 换包验收脚本全绿。

## 二、边界划分（核心决策）

| 类别 | 内容 | 归属 | 理由 |
|---|---|---|---|
| **通用机制** | `FieldMeta` 类型系统（type/required/default/enum/ref_target/children）、分组/标签/说明的**渲染机制**、兜底（无声明→显示原始键）、`ModuleMeta` 装配 | **框架** | 与包无关的机制代码 |
| **包展示元数据** | 字段中文名 `FIELD_LABELS`、字段说明 `FIELD_HELP`、分组显示名 `GROUP_LABELS`、模块显示名 `MODULE_LABELS`、模块层级 `module_tree` | **包**（本轮下放） | 纯展示，且按包不同 |
| **校验规则表** | 各模块字段的 type/required/范围/枚举/引用目标（校验器与游戏逻辑共用） | **框架（本轮不下放）** | 属"规则"而非"展示"；下放会带来"包作者写坏规则"的风险。留作第二阶段议题，本轮只在文档里登记 |

**优先级规则**：包声明 > 框架兜底；框架侧同一键的**旧声明在本轮迁移后删除**（不留双份，避免两处打架）。
若某键包内未声明 → 编辑器按现有兜底渲染（显示原始键 + 类型按实际值推断），不报错。

**优先级细则（批A 落地，2026-09-13）**——同一包内可能有两处「包声明」，顺序固定为：

| 元数据 | 优先级（高 → 低） | 说明 |
|---|---|---|
| `module_labels` | `field_meta.json.module_labels` → `manifest.module_labels` → 模块键名 | 逐键覆盖 manifest 的同名键 |
| `module_tree` | `field_meta.json.module_tree` → `manifest.module_tree` → `manifest.module_groups` → 平铺 | **整体替换**（不做两处声明合并）；两者都不声明 → 平铺 + 模块键名 |
| `module_tree` 节点 `label` | 节点自身 → 上面两张 `module_labels` 表 | 与批A 之前的 manifest 口径一致 |
| `field_labels` / `field_help` | `field_meta.json` → 框架 `field_meta.py` 表 | 覆盖同模块同键值；未声明键保持框架现状 |
| `group_labels` | `field_meta.json` → 框架 `field_meta.py` 表 | 覆盖同模块同组键值；未声明组保持框架现状 |

实现锚点（批A）：读包声明 = `qbot_rpg/content/field_meta_pack.py::parse_field_meta`（严格）/ `load_field_meta`；
合并 = 同文件 `merge_field_meta_table`（纯函数，包优先）；接线 = `qbot_rpg/web/api.py::_pack_meta_table` /
`_pack_declaration` / `_module_meta` / `_display_labels` / `_declared_tree_spec`。未声明该文件的包
`_pack_meta_table` 直接返回框架表单例 → 行为零变化。


## 三、目标结构

```
content/veinborn/field_meta.json          ← 新增：包自己的展示元数据（纯数据，进包进 git）
content/test_demo/field_meta.json         ← 同上
qbot_rpg/content/field_meta.py            ← 保留：通用机制 + 校验规则表 + 兜底
qbot_rpg/content/field_meta_pack.py       ← 新增（可选）：读包声明并与框架表合并的通用入口
```

包声明形态（草案，允许按实际实现微调，但**必须是纯 JSON**）：

```json
{
  "schema_version": 1,
  "module_labels": { "skills": "技能", "items": "物品" },
  "module_tree": [{ "module": "skills", "children": ["effects", "statuses"] }],
  "field_labels": { "skills": { "power": "威力" }, "enemies": { "hp": "生命" } },
  "field_help":   { "skills": { "power": "技能倍率，按百分比算（100 = 一倍威力；常见 10~500）。" } },
  "group_labels": { "enemies": { "base": "基本", "stats": "数值与抗性" } }
}
```

### 四·补、批A 落地登记（2026-09-13）

- **新增** `qbot_rpg/content/field_meta_pack.py`：`parse_field_meta`（严格解析）+ `load_field_meta`
  （按 mtime/size/inode 缓存读文件，无文件 → `None`）+ `merge_field_meta_table`（包声明优先的纯合并）。
- **解析严格性**：未知顶层键、非法形态、`schema_version` 缺失/非整数/不受支持 → `PackFieldMetaError`，
  报错含**包名 + 出错键**；编辑器侧转 `EditorError`（人话，不静默吞）。
- **接线**（只读侧）：`qbot_rpg/web/api.py` 的模块树 / 条目列表 / 条目详情 / 条目索引 / 引用候选 /
  写链路定位全部改走 `_pack_meta_table(pack_dir)`；未声明该文件的包返回框架表单例，**行为零变化**。
- **包声明可覆盖的字段表面**：模块顶层 `fields`、map 形态模块的 `value_meta.children`（如 stats）、
  以及 obj/list 元素子字段（递归覆盖同键 label/help）；包为框架未登记字段声明标签/说明时补
  `soft_label` 纯展示字段（泛型校验短路，零行为变化）。
- **测试**：`tests/unit/test_editor_pack_field_meta.py`；含 veinborn / test_demo 的「启用读取层前后」
  接口对拍（无包声明 → 快照全等）+ 反向对照（加声明后确实变化）。
- **本批未做**（留后续批次）：不迁移任何框架侧既有声明、不改 `content/*/field_meta.json`、
  未把 `*_CHILD_LABELS` 之类嵌套声明显式建模为包 schema（批A 用「扁平键表递归覆盖」兼容）。

### 四·补二、批B 落地登记（迁移：展示元数据从框架下放进包，2026-09-13）

- **包声明**：`content/veinborn/field_meta.json`、`content/test_demo/field_meta.json` 进包进 git，

  引用候选/包列表）逐字段对拍；纳入 `tests/unit/test_editor_pack_field_meta_migration.py`。
  **实测差异条数 = 0**。
- **本批未做**：不下放**校验规则**（type/required/枚举/范围/引用目标，仍留框架，第二阶段议题）；

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| 迁移漏键/写错键 → 界面回退成裸键 | 批 C 的**逐字段对拍**（0 差异门禁）+ 迁移脚本从框架表**自动导出**而非手抄 |
| 框架侧删早了 → 中间态崩 | 同一 commit 先加包声明、再删框架声明；测试在同 commit 内跑 |
| 包声明格式漂移（各家写法不一） | 固定 schema_version + 解析层严格校验（未知字段报错），并把形态写进《编辑器重写_需求与约束》做契约 |
| 校验规则表长期留框架 | 本轮显式登记为第二阶段议题（含「包可覆盖类型/枚举」的可行性评估），不混进本轮 |

## 六、不做的事（本轮）

- 不下放**校验规则**（type/required/枚举/范围/引用目标）——留第二阶段；
- 不改游戏主链路（框架读包数据的路径不变，`content/loader.py` 行为不变）；
- 不为兼容旧格式保留双份声明（迁移即删，奥卡姆）。
