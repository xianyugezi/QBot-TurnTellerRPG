## 四、② 设计缺漏类（2 项）

### D1 🟡 P1 应改：结果类型白名单语义背离 —— boolean/string 出参被一律兜底 0（+ 1KB 上限未实现）
- **文件:行号**：`formula_engine.py` **L993-995**（evaluate_detail：`bool 或非 (int,float) → result_type → 0`）、**L884-890**（快路径同规则）、`_js_runner.js` **L79-83**（Node 侧：仅有限 number 通过）。
- **定稿应有**：`效果表达式变量体系定稿.md` **L38**：白名单 = number / boolean / string（≤1KB）；其他类型 = 失败兜底。即定稿认为公式出参可为 boolean（如作 0/1 条件量）或 string（≤1KB），仅超类型/超长才兜底。
- **实现现状**：凡 boolean/string 出参一律 → `result_type` warning → 0（与 H3 同源，行为侧对应）。`≤1KB` 截断/白名单逻辑在 Python 侧与 Node 侧均不存在。
- **影响（静态推导）**：若内容包存在“公式直接返回布尔/短字符串”的设计（定稿明示允许），将被静默吞成 0。现值库内 §三 示例均为数值出参，实战影响有限（故列 P1 非 P0）；但这是**本基准下唯一“定稿明确要求而实现没有”的硬性语义缺口**。
- **建议**：两选一：(a) 对齐定稿——Node/Python 侧放行 `boolean` 与 `string≤1KB`；(b) 走用户/仲裁豁免，将白名单正式改口径为“数值出参”，并在 docstring 以【工程补白】标注以换取定稿 L38 修订。**当前实现与定稿字面冲突，不可静默带病合入。**

### D2 🟡 P2 注意：单次求值超时 10ms 字面值被工程化为 30ms（违反“数值不变”字面，需仲裁确认）
- **文件:行号**：`formula_engine.py` **L69-76**：`FORMULA_TIMEOUT_MS=10`（契约字面）+ `_VM_CTX_SLACK_MS=20` → `_VM_EFFECTIVE_TIMEOUT_MS=30` 传入 `_js_runner.js` timeout。
- **定稿应有**：`效果表达式变量体系定稿.md` **L39**【§1.2】「单次求值超时：vm timeout **10ms**」。
- **实现说明**：docstring（L70-74）已充分标注工程理由（Node v22 runInNewContext 冷启动开销计入 watchdog，10ms 字面值会使冷进程公式全误判超时；30ms 仍可中断 `while(true){}` 死循环，实证）。细化 F-3「超时 → 0 + 不崩溃」语义成立。
- **评价**：语义意图（防 CPU 死循环/ReDoS）保留，**超时→0 兜底已实现**；但字面值 10→30 属“数值不变”纪律下的冲突，按审查纪律 4 应交用户/仲裁拍板，故列 P2（非 P0）。
- **兜底确认**：超时分支在 `_invoke_runner`（L934-937 捕获 `subprocess.TimeoutExpired` → `runner_timeout`）→ `evaluate_detail` L990-992 记 `eval_failed` → 0 + 日志。✓
