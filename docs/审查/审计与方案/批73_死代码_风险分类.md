## 0. 复核方法与口径（先说清"无调用"怎么判、动态引用怎么排）

### 0.1 本轮方法（比审计④更严）

审计④口径（其 §0）是"名字在**全部 .py 原文（含注释/字符串）**中出现次数 ≤ 定义次数"——
该口径**故意保守**（把 `__all__`、docstring、字符串都算作消费），所以它给出的 83 条是
"**连注释都没人提**"的名单。本轮为了判"**能不能删**"，把计数拆成三层：

1. **AST 语义级**：全仓 2582 个 `.py` 逐文件 `ast.parse`，把每个目标名按**出现语境**分类：
   `def` / `call.name`（裸名调用）/ `call.attr`（`obj.名(...)`）/ `attr` / `name` / `import` / `str`。
2. **同文件 vs 跨文件**：定义文件内的自引用（典型是 `__all__` 里的字符串）单列；
   真正决定"有没有调用者"的是**跨文件引用**。
3. **同名校验**：跨文件命中逐条打开，确认是否**同名不同物**（这是本轮最有价值的发现，见 §4.1）。
4. **动态引用专项**（本任务核心）：
   - `getattr/setattr/hasattr/delattr` 的**字面量参数**全量扫描（排除 `.venv`）；
   - `globals()` / `locals()` / `vars()` / `eval` / `exec` 调用点全量列出并**逐点打开**；
   - `importlib.import_module` / `importlib.util.spec_from_file_location` / `entry_points` /
     `pkgutil` / `__import__` / `load_entry` 全量扫描；
   - **`__all__`** 清单逐个导出模块比对；
   - `CommandSpec(handler=…)`、注册表 `name=`、关键字字符串实参扫描；
   - `tests/**`、`scripts/**`、`qbot_rpg_bridge/**`、`content/**`、`docs/**` 分层核查。

> `.venv/` 与 `__pycache__/` 已排除；构建产物不计。

### 3.1 黄-① `__all__` 型：代码零调用，但名字在模块 `__all__` 里（15 条）
