## §1 一句话结论

**这条路能走通**：在全新空包上，用户按右栏引导 4 步（开模块 → 选模块 → 新建 → 创建）就能写出第一条内容，且**真的落盘**（临时目录里生成了 `items.json` + `.bak`，内容正确）。
**但路上有 1 处阻断、3 处烦人、4 处锦上添花**：最要命的是**编辑态改 ID 会绕过校验、静默把非法 ID 写进文件**，随后界面只丢一句「读取条目 失败：条目不存在：items/item_001」，新手会当场卡死并可能已经改坏了内容包。

## §2 卡点清单（按严重度）

### 卡点 1 ·【阻断】编辑态改 ID 绕过校验，静默写坏数据 + 报错不可行动

- **现象**：在已存在条目的编辑面板里，把「条目 id」改成非法值（如带空格/感叹号的 `Bad ID!`），点「校验」显示**「校验通过。」**，点「保存」**成功写盘**——文件里的 `id` 真的变成了 `Bad ID!`；紧接着界面报一句 `读取条目 失败：条目不存在：items/item_001`，没有解释、没有「怎么办」。
- **复现**：
  1. 空包启用「物品」→ 左栏点「物品」→ 新建一条（ID 默认 `item_001`）；
  2. 打开该条目，把面板第一个输入框（条目 id）改成 `Bad ID!`；
  3. 点「校验」→ 显示「校验通过。」；点「保存」→ 报「读取条目 失败：条目不存在：items/item_001」；
  4. 查临时目录 `items.json`，`id` 已是 `Bad ID!`。
- **证据**：
  - 截图 `walk_nu_shots/F04a_id_edited.png`、`F04b_after_save_bad_id.png`；
  - 校验输出摘录：`校验通过。`（`F04` 步骤实时读取 `#p-body`）；
  - 写盘后读盘：`items.json` → `"id": "Bad ID!"`；
  - 对照：后端**明明有**正确的 ID 校验接口，同一非法 ID 的返回是红级 + 人话 + 改法：
    `POST /api/pack/empty_pack/module/items/id_check {"entry_id":"Bad ID!"}` →
    `{"ok":false,"level":"red","message":"ID「Bad ID!」含空格、斜杠或超长字符，不能用作条目标识。","how_to_fix":"请改用不含空格与斜杠的短标识（建议英文小写 + 下划线）。"}`
  - 结论：**这套校验只接在「新建」表单上，没接在「编辑态改 ID」路径上**。
- **建议改法**：编辑态 ID 输入复用 `id_check`（红/黄/绿即时反馈）；保存前对非法 ID 硬拦截；若已写坏，给出可行动提示（「改回合法 ID」或「用『回退到上一份备份』恢复」），而不是只报「条目不存在」。

### 卡点 2 ·【烦人】启用模块后「+ 新建条目」仍是灰的，中栏却已经显示这个模块

- **现象**：空包 → ⚙ 模块勾选「物品」→ 关闭面板。左栏出现了「物品」，中栏标题也变成了「物品 / 0 条 / 可持有·可使用·可丢弃的物品条目」，**看起来已经选中了**；但中栏的「+ 新建条目」是**禁用**的，鼠标点不动，界面上没有任何一句解释。用户必须**再去左栏点一下「物品」**，按钮才活。
- **复现**：见上；点击左栏模块行前后对比按钮状态。
- **证据**：
  - 截图 `walk_nu_shots/C01_after_toggle_items.png`；
  - 实测：`启用后 fresh 打开 → pg.is_disabled("#btn-new") == True`；`click('#mods .mod[data-module="items"]') 之后 → False`；
  - 代码佐证：`index.html:3068` `el("btn-new").disabled = !state.module || ...`——启用模块不会设置 `state.module`，所以按钮保持禁用。
- **建议改法**：启用模块后自动选中该模块；或至少让中栏在「模块已启用但未选中」时不要显示成已选中态，并给按钮一个明确说明（「先点左栏『物品』开始」）。

### 卡点 3 ·【烦人】残缺包（声明了模块但文件是空的）切包**静默失败**，界面继续显示上一个包的数据

- **现象**：`manifest.json` 声明了 `items / enemies / quest`，但 `quest.json` 是**空文件**。在内容包选择器切到「残缺包」后：选择器已经显示「残缺包」，**左栏却仍然是上一个包的模块与计数**（`manifest.modules · 1`）、中栏仍显示上一个包的条目「走查测试剑」，**全程没有任何报错、白屏或提示**。用户会以为自己在编辑残缺包，实际看到的是别的包。
- **复现**：
  1. 临时根放两个包：`empty_pack`（有内容）+ `broken_pack`（manifest 声明 3 模块，其中 `quest.json` 为空文件）；
  2. 打开编辑器 → 内容包选择器切到「残缺包」；
  3. 观察：网络层 `GET /api/pack/broken_pack/modules` → **500**、`/entry-index` → **500**；界面上无任何反映。
- **证据**：
  - 截图 `walk_nu_shots/G01_broken_pack.png`、`G02_broken_pack_immediate.png`；
  - 网络摘录：`500 /api/pack/broken_pack/modules`、`500 /api/pack/broken_pack/entry-index`；
  - 接口原始返回：`{"ok":false,"error":"读取/解析 JSON 失败：/tmp/walk_nu_.../broken_pack/quest.json（Expecting value: line 1 column 1 (char 0)）"}`——**带服务器绝对路径 + Python 英文异常**；
  - 界面状态：`#packs` 值 = `broken_pack`，而 `#mod-src` = `manifest.modules · 1`（上一个包的值），中栏仍是上一个包的条目。
- **补充（同场景的另一半）**：若只是**文件缺失**（声明 `items` 但 `items.json` 不存在），编辑器会**静默当成 0 条**，可以正常新建（截图 `G03_broken_missingfile.png`）。这一半可接受，但也应提示「声明的 items.json 尚不存在，保存时会新建」。
- **建议改法**：切包/读包失败时给显式、可行动的横幅（「这个包读不了：`quest.json` 是空文件；请修复该文件或删除这条模块声明」+ 文件名），并且**不要保留上一个包的内容**（宁可真空白 + 报错）。

### 卡点 4 ·【烦人】字段「Tip（说明）」覆盖不足，且部分超出「≤60 字·忌长文」纪律

- **现象**：以「新建物品」表单为例，共渲染 **115 个字段说明卡**，其中**只有 54 个有面向用户的「说明」**（约 47%）；其余 61 个字段（含 `name / type / quality / price` 等最常用的）没有任何一句话解释。另外有 **7 条说明超过 60 字**（最长 128 字），**9 条说明里混着 Markdown `**` 加粗符**，**7 条说明直接引英文配置键**（如 `settings.equipment_offhand.single_hand_scale`）。
- **复现**：空包启用「物品」→ 点「+ 新建条目」→ 统计 `HELP_CARDS`。
- **证据**（页面内实测，原始数据 `/tmp/nu_tips_stats.json`）：
  - `{"total":115,"withHelp":54,"required":0}`
  - 超长示例：「手数」说明 128 字；「相性」73 字；「回复强化%」69 字（含 `（批43 缺口登记）` 这类内部术语）；
  - Markdown 泄漏示例：`**加算**层数上限（不是百分比）：+2 = 上限提高 2 层…`；
  - 英文键泄漏示例：「手数」说明里的 `settings.equipment_offhand.single_hand_scale`。
- **建议改法**：优先补齐高频字段的 ≤60 字一句话说明；清理说明里的 `**` 与英文配置键（英文键放「排查信息」，不放面向用户的说明）。

### 卡点 5 ·【锦上添花】「必填」不可见：表单里 0 处必填标记，必填信息藏在悬停说明里

- **现象**：新建/编辑表单**没有任何可见的必填标记**（无「必填」字样、无 `*`、无 `required`/`aria-required` 属性）；实测**把「名称」清空仍然「校验通过。」**。必填信息只在字段悬停气泡的「填写要求：必填/选填」这一行里。
- **证据**：
  - 表单文本与输入属性实测：`input.required=False`（全部）、正文 `"必填" in body == False`；
  - 清空名称后校验输出：`校验通过。`（截图 `F02_validate_empty_name.png`）；
  - 说明卡里确有该行：`index.html:helpLines()` → `{k:"填写要求", v: card.required ? "必填" : "选填"}`。
- **建议改法**：必填项在字段行加可见标记；「填写要求」从悬停说明提到行内（至少对必填项）。

### 卡点 6 ·【锦上添花】保存/创建成功没有显式反馈

- **现象**：新建条目保存成功后，界面只是列表多了一条、右栏标题换成条目名、顶栏状态仍写「已保存」。**没有 toast / 「已写入 items.json」之类的成功提示**，用户不容易确认「到底存没存进去」。
- **证据**：创建后遍历 `.toast / [role=alert] / .notice` 等提示容器**均为空**；文件确实已写（`items.json` 663 字节 + `items.json.bak`），说明是**反馈缺失**而非保存失败。截图 `E01_after_create.png`。
- **建议改法**：成功时给一次轻量提示（「已写入 items.json（已自动备份）」）。

## §3 新手三问核对（我是谁 · 我在哪 · 下一步做什么）

> 结论：**空包右栏是全流程最好的引导**；但左栏与中栏在空包/空模块时基本不回答「下一步做什么」。

| 界面区域 | 我是谁 | 我在哪 | 下一步做什么 |
| --- | --- | --- | --- |
| 顶栏（全局） | ✅ 「身份= 机主 · 可编辑」+ 右侧「可编辑」 | ✅ 「pkg= 内容包选择器」+ 右「manifest.json」 | ➖ 无引导（合理，全局区） |
| 左栏「模块」 | ✅ 显示模块中文名 + 启用状态 | ✅ 顶部「manifest.modules · N · 平铺 · 未启用 M」 | ❌ 空包时 36 项全是「未启用」，**没有一句「点这里启用」**（虽然未启用行可点，但只有 hover title 里写「点击启用」） |
| 中栏「条目」 | ✅ 显示当前模块中文名 + 计数 | ✅ 「共 N 条」 | ❌ 0 条时只显示「（空）」，**不告诉用户下一步**（右栏替它说了，但中栏本身空着） |
| 右栏「编辑面板」 | ✅ 「物品 · 字段由元数据渲染」 | ✅ 标题 + `items.json` 备份信息 | ✅ **空包时明确**：「这个包还没启用任何模块 / 点右上角 ⚙ 模块，勾选你要做的内容类型… / 打开模块开关」按钮（截图 `A01_empty_initial.png`） |
| ⚙ 模块开关面板 | ✅ 身份只读时提示「当前身份为只读预览…」 | ✅ 「共 36 个模块 · 已启用 0 个」 | ✅ 面板头一句「勾选你要做的内容类型；不勾的模块不会出现在左侧模块树…」 |
| 新建条目表单 | ✅ 「新建条目 · 物品」 | ✅ 「保存写入 items.json」+ 分组/字段数 | ➖ ID 有「可用/规则」提示；但**必填不可见**、61 个字段无说明 |

**一句话**：「我在哪」六个区域全部有答案；「下一步做什么」只有右栏和模块面板答得好，**左栏和中栏是空的**——而新手第一眼看的恰恰是空的左栏和中栏。

## §5 给实现批的建议（≤8 条，按性价比排序）

1. **（阻断·最高性价比）编辑态改 ID 接上 `id_check`**：红/黄/绿即时反馈 + 保存前硬拦截；已写坏时给「改回合法 ID / 用备份回退」的可行动提示。复用现成接口，改动面小、收益最大。
2. **（阻断）切包/读包失败必须显式报错，且不保留上一个包的内容**：把 `quest.json` 空文件这类错误翻成人话（点名文件 + 怎么办），前端加横幅；宁可空白 + 报错，也不要「显示着 A 包、顶着 B 包名」。
3. **（烦人·体验）启用模块后自动选中该模块**（或消除「中栏显示已选中、按钮却是灰的」的矛盾），让新手勾完就能直接新建。
4. **（烦人·口径）补 Tip**：给 26 个无中文名字段补中文名、给 61 个无说明字段补 ≤60 字一句话；清理说明里的 `**` 与英文键（英文键移入「排查信息」）。
5. **（烦人）中栏空态补引导**：0 条时给出与右栏一致的下一步（「点『+ 新建条目』，或点左栏模块」）；并把已启用模块的「当前包未使用…」改成「这个模块还没有内容」。
6. **（锦上添花）保存成功给一次显式提示**（「已写入 items.json（已自动备份）」），让「存没存进去」一眼可见。
7. **（锦上添花）必填可见化**：字段行加必填标记，把「填写要求」从悬停说明提到行内。
8. **（锦上添花）批65 模块「推荐组合」落地**：在模块开关顶部给 2~3 个中文名新手组合，一键启用。
