# 内容包状态格子：你的包怎么读写自己的存档

> 面向：内容包作者 · 框架版本：批 D（2026-09-14，`db_schema_version = 2`）
> 一句话：框架给每个「玩家 × 内容包」准备了一格 JSON，你用自己的 `pack_id` 存取；
> 框架不认识你的包、也不解释你写了什么。

---

## 1. 你要用的东西

| 项 | 说明 |
|---|---|
| 存储位置 | 框架存档库的表 `player_pack_state`（每格一行，主键 `(player_id, pack_id)`） |
| 你的 `pack_id` | 你的内容包 id，**你自己定**，框架只当普通字符串（不要用它当业务键，一个包一个格） |
| 你的 `state` | 一个 JSON 对象；顶层键由你自由设计（成就进度 / 地图探索 / 自定义货币……） |
| 入口 | `qbot_rpg.storage.pack_state` 的 5 个异步函数，传入框架的 `Database`（常见 `repo.db`） |

```python
from qbot_rpg.storage.pack_state import (
    clear_pack_state,      # 清空这一格
    get_pack_state,        # 读这一格（不存在 → {}）
    list_pack_states,      # 列出本玩家所有包的格子
    patch_pack_state,      # 顶层浅合并（增量更新）
    set_pack_state,        # 覆盖写
)

PACK_ID = "your_pack_id"   # ← 换成你自己的包 id
```

---

## 2. 最小示例

```python
async def get_my_state(db, player_qid: str) -> dict:
    """读：没有玩过你包的玩家也会拿到 {}（不抛异常）。"""
    return await get_pack_state(db, player_qid, PACK_ID)


async def light_up(db, player_qid: str, spot_id: str) -> int:
    """记下一个点亮的地点，返回累计数量。"""
    state = await get_pack_state(db, player_qid, PACK_ID)
    lit = sorted(set(state.get("lit", [])) | {spot_id})
    await set_pack_state(db, player_qid, PACK_ID, {**state, "lit": lit})
    return len(lit)


async def remember_choice(db, player_qid: str, choice: str) -> dict:
    """增量更新：patch 只合并顶层键，返回合并后的完整状态。"""
    return await patch_pack_state(db, player_qid, PACK_ID, {"choice": choice, "seen": True})


async def reset_my_pack(db, player_qid: str) -> None:
    """清空你的格（只影响你自己的包，其他包与框架存档不受影响）。"""
    await clear_pack_state(db, player_qid, PACK_ID)
```

`db` 从哪里来：处理器上下文里的存储层 `Database`，常见写法 `repo.db`（也接受任何
`qbot_rpg.storage.connection.Database` 实例）。

## 3. 语义速查（务必按此使用）

| 操作 | 函数 | 语义 |
|---|---|---|
| 读 | `get_pack_state(db, player_id, pack_id) -> dict` | 不存在 / 空 / 内容损坏 → `{}`，**不抛**；返回的是独立副本 |
| 覆盖写 | `set_pack_state(db, player_id, pack_id, state) -> None` | 整格替换（没有的键会消失）；必须传 JSON 对象 |
| 浅合并 | `patch_pack_state(db, player_id, pack_id, patch) -> dict` | `新 = {**旧, **patch}`，**只合并顶层键**（嵌套对象整体替换）；格不存在时等价新建；同事务内完成「读旧 → 合并 → 写回」 |
| 清空 | `clear_pack_state(db, player_id, pack_id) -> None` | 删掉这一格；本来就没有也算成功 |
| 列举 | `list_pack_states(db, player_id) -> dict[pack_id, dict]` | 本玩家所有包各自的格子，按 `pack_id` 升序 |

**边界与报错**（都是明确的异常，不会静默写坏档）：

- 传的不是 JSON 对象（列表 / 字符串 / 数字 / `None` …）、含无法 JSON 序列化的值、
  含 `NaN` / `Infinity`、顶层键不是字符串 → `PackStateValidationError`；
- 单格序列化后超过 `PACK_STATE_MAX_BYTES`（64 KiB）→ `PackStateTooLargeError`；
  超限写入不会落库（原有内容保持不动）。请把大块数据拆成自己的顶层键，或只存必要索引；
- 玩家 id / 包 id 为空串或非字符串 → `PackStateValidationError`。

**事务与原子性**：

- 写操作内部走框架唯一写入口 `db.tx()`（单写队列串行），**不要自己裸连 SQLite**；
- 一次业务要同时改玩家存档和你的格子时，把两者放进同一个 `repo.tx()`：同任务内
  `set/patch/clear` 会并入这个外层事务，一起提交、一起回滚；
- 读走只读连接（WAL 快照），不会看到同一事务中尚未提交的写入；同一事务内需要读回
  自己刚写的值，请直接用返回值（`patch` 已返回合并结果）或先提交。

## 4. 换包、升级与你的格子

- 框架结构迁移（`db_schema_version` 1 → 2）只是**建出这张表**，不会动你已有的格子；
  新库开箱即有，旧库升级后同样存在（见 `docs/细化/细化_4a_存储层契约.md` 附录 A）。
- 不同 `pack_id` 的格子互不干扰：玩家换包后旧包的格子仍在，你可以自行读取做兼容/继承；
  框架不替你删。
- 你的 `state` 结构由你负责演进：建议在格子里放一个自己的 `"version"` 键，读取时按它
  做缺省补全（框架只保证整格 JSON 对象往返，不解释内部字段）。

---

## 5. 不要这样做

- ❌ **不要让框架给 `players` 表加你的专属列**（例如某个包名命名的列）。内容包字段一律
  进你自己那格 `state`；核心表加列会污染框架存档结构，也无法覆盖多个包。
- ❌ 不要把 `pack_id` 当成玩家属性或业务键（如把玩家分级写成不同 pack_id）；一个内容包
  一个固定 id。
- ❌ 不要跨包读写别人的格子来「共享数据」——需要共享请走框架既有机制；格子只解决
  「我的包自己的持久状态」。
- ❌ 不要在这里存会话中的临时对象（战斗快照等）；会话快照有专门的 `sessions` 机制。
