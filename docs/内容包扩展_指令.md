# 内容包自持指令（扩展点 E1 · 面向包作者）

> 这篇给**写内容包的人**看，不需要懂框架内部。你要做的事只有一件：
> 在**你自己的包目录里**放两个文件（一个声明、一个实现），机器人重启后就能用这些指令。
> 框架代码一行都不用改。
>
> 设计依据与边界见 `docs/游戏包扩展点_方案_E.md`。稳定 API 见 `qbot_rpg/ext_api.py`。

---

## 0. 它解决什么问题

内容包过去只有数据（json），不能自己加指令。于是"某个包专属的命令"只能塞进框架目录，
既污染框架、也难以和其它包共存。扩展点让包**自带指令**：声明 + 实现都留在包内。

**一句话判据**：换一个内容包、放同样结构的文件，框架零改动即可用。

---

## 1. 先启用（默认关闭，两道闸都要开）

包内 Python 是**可执行代码**，所以框架默认**完全不加载**它。启用需要**同时**满足：

| 闸 | 位置 | 缺省 |
|---|---|---|
| 第一闸 | 包内 `settings.json`（或装配方注入的 settings）里的 `ext.enabled` | `false` |
| 第二闸 | 启动参数 `--enable-pack-ext`，或环境变量 `QBotRPG_ENABLE_PACK_EXT=1` | 关 |

`settings.json` 里写：

```json
{
  "ext": { "enabled": true }
}
```

启动时额外加参数（命令行部署）：

```bash
python -m qbot_rpg_bridge.assemble --enable-pack-ext
```

或设环境变量（NoneBot 进程部署推荐）：

```bash
export QBotRPG_ENABLE_PACK_EXT=1
```

任一闸没开 → **框架连你的 `ext/` 目录都不会读，更不会 import 里面的 Python**，
你的指令就像不存在一样。这是刻意的安全默认。

> 注意：光在包自己的 `settings.json` 里写 `enabled: true` **不够**——包不能自己授权
> 自己执行代码；必须由部署的人再开第二闸。

---

## 2. 包目录长什么样

```
content/<你的包>/
├── manifest.json          # 既有内容包清单（不变）
├── settings.json          # 既有设置；加 ext.enabled 才启用扩展
├── ...                    # 既有数据模块（不变）
├── commands.json          # 新增：指令声明（纯数据，给非技术作者看）
└── ext/                   # 新增：包内扩展代码目录
    └── commands.py        # 新增：指令实现（handler 函数）
```

只有这两个新名字是约定：包根 `commands.json`、`ext/commands.py`。**其它位置框架不读。**

---

## 3. `commands.json`：声明指令

```json
{
  "commands": [
    {
      "name": "潮汐",
      "aliases": ["tide"],
      "usage": "潮汐 [查询|切换]",
      "help": "查看/切换当前潮位（本包专属）",
      "handler": "tide",
      "gm_only": false
    }
  ]
}
```

`commands` 是一个数组，每项一条指令。字段表：

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `name` | ✅ | 字符串 | 指令名，不含前导 `/`，不含空格或斜杠 |
| `handler` | ✅ | 字符串 | 实现文件里**导出的函数名**（合法 Python 标识符） |
| `aliases` | ❌ | 字符串数组 | 别名，和 `name` 一样会被路由命中；不得与任何既有指令/别名重名 |
| `usage` | ❌ | 字符串 | 用法提示（给人看，例如帮助页） |
| `help` | ❌ | 字符串 | 一句话说明（给人看） |
| `gm_only` | ❌ | 布尔 | `true` = 只有 GM/机主能用；缺省 `false` |

规则：

- **不能和框架既有指令名/别名重名**，也不能在包内自己重名/别名撞车——
  冲突一律**拒绝装载**（不会覆盖框架指令），启动日志会写清"哪条指令和谁冲突"。
- **未知字段会被拒绝**（例如把 `handler` 拼成 `handlers`），报错会提示允许的字段，
  避免"写了却不生效"。
- 同一个包的所有指令**同生共死**：只要有一条非法/冲突，整个包的扩展都不会生效。

## 4. `ext/commands.py`：实现 handler

每个 `handler` 名对应一个函数，**第一个参数是上下文 `ctx`，第二个参数是解析结果 `parsed`**，
返回值就是玩家能看到的文字。

```python
from qbot_rpg import ext_api   # 只能 import 这个稳定面


def tide(ctx, parsed):
    """潮汐：返回玩家可见文本。"""
    args = ctx.args                      # 参数列表，如 ["查询"]
    action = args[0] if args else "查询"
    if action == "切换":
        return f"🌊 潮位已切换（包 {ctx.pack_id} / 玩家 {ctx.player_id}）"
    return "当前：满潮"
```

约定：

- **返回值 = 玩家可见文本**（字符串）。也可以返回 `{"message": "..."}` 这类结构，
  但简单起见返回字符串就好。
- 需要读写**包状态**时，把函数写成 `async def`，用 `await ctx.get_state()` 等（见 §6）。
  框架同步、异步 handler 都支持。
- handler 里**抛异常不会让机器人崩溃**：框架会记日志，玩家看到一句
  "❌ 功能暂不可用"，其它指令照常。所以请自己捕获可预期的错误并返回人话。
- 别做耗时/长任务（不要 sleep、不要跑重活），保持快速返回。

## 5. `ctx`：你能读到的上下文

`ctx` 由框架提供，**只读**（改了不会写回存档）：

| 用法 | 类型 | 含义 |
|---|---|---|
| `ctx.pack_id` | 字符串 | 当前内容包 id（目录名） |
| `ctx.pack_version` | 字符串 | 包版本（来自 `manifest.json`） |
| `ctx.player_id` | 字符串 | 玩家 id；未注册 → 空串 |
| `ctx.registered` | 布尔 | 玩家是否已注册 |
| `ctx.player` | 只读映射 / `None` | 玩家快照（字段可读，改无效） |
| `ctx.settings` | 只读映射 | 本包 `settings.json` |
| `ctx.command` | 字符串 | 实际命中的指令名（别名展开后是原指令名） |
| `ctx.args` | 元组 | 位置参数，如 `("查询",)` |
| `ctx.args_text` | 字符串 | 参数原串，如 `"查询"` |
| `ctx.parsed` | 对象 | 框架解析原对象（`.command` / `.args` / `.tokens` / `.raw`） |
| `ctx.group_id` / `ctx.user_id` / `ctx.channel` | 字符串 | 消息来源 |
| `ctx.message` | 字符串 | 原文 |
| `ctx.is_gm` | 布尔 | 发送者是否 GM |
| `ctx.tpl(key, data)` | 函数 | 渲染模板（见 §7） |
| `ctx.rng` | `random.Random` | 确定性随机源（见 §8） |
| `ctx.log` | logger | 带包名的日志器 |

## 6. 包状态：把玩家进度存进存档

每个包、每个玩家有一个**独立的状态格子**（框架统一存储，别的包看不到你的格子）。
读写是异步的：

```python
async def tide(ctx, parsed):
    state = await ctx.get_state()          # 字典；不存在 → {}
    times = int(state.get("times", 0)) + 1
    await ctx.patch_state({"times": times})  # 浅合并写回
    return f"你第 {times} 次查询潮汐"
```

| 方法 | 作用 |
|---|---|
| `await ctx.get_state()` | 读本包本玩家的状态字典（损坏/不存在 → `{}`，不报错） |
| `await ctx.set_state({...})` | 覆盖写 |
| `await ctx.patch_state({...})` | 浅合并写（只合并顶层键）并返回合并结果 |
| `await ctx.clear_state()` | 清空 |

约束：状态必须是 JSON 对象；单格序列化后不能超过 64 KiB（超了会报错，别把存档写爆）。
未注册玩家不能写：`ctx.set_state` 会抛错，请先判断 `ctx.registered`。

> 进阶：不想用 `ctx.*` 便捷方法时，也可以直接用稳定面函数
> `await ext_api.get_pack_state(ctx.db, ctx.player_id, ctx.pack_id)` 等。

## 7. 模板：复用框架文案 + 包内覆盖

`ctx.tpl(key, data)` 按 key 渲染框架内置文案，**并自动带上你包内 `templates.json` 的覆盖**
（同 key 覆盖，未写 key 用默认）：

```python
return ctx.tpl("err_bad_command", {"fragment": ctx.args_text})
```

- 未知 key → 返回空串（不报错）。可覆盖的 key 只能是框架模板表里已有的 key；
  包内 `templates.json` 写了表外的 key 会被忽略并记日志。
- 占位符缺失时原样保留，不报错。

## 8. 确定性随机与日志

```python
roll = ctx.rng.randint(1, 100)   # 同一玩家同一局可复现（不要用 time/系统随机做种子）
ctx.log.info("潮汐指令：玩家=%s 结果=%s", ctx.player_id, roll)
```

需要不同用途的独立随机序列时，用 `ext_api.rng(ctx.pack_id, ctx.player_id, "用途名")`。

## 9. 常见问题

| 现象 | 原因 |
|---|---|
| 指令不存在、日志说"未启用" | 两道闸没同时开（见 §1） |
| 启动日志说"重名/冲突" | 指令名或别名和框架既有指令撞车；换名字 |
| 启动日志说"声明非法" | 缺 `name`/`handler`、字段类型错、有未知字段；按报错改 |
| 启动日志说"import 失败" | `ext/commands.py` 有语法/运行错误；按 traceback 改 |
| 指令能发但回"❌ 功能暂不可用" | handler 里抛了异常；看日志里的 traceback |
| 路径被拒绝 | `ext/commands.py` 是符号链接，或路径里带了 `..`；改成包内真实文件 |

## 10. 边界（框架刻意不做的事）

1. **不允许覆盖框架指令**——重名一律拒绝，没有"覆盖"开关。
2. **不允许包代码改结算/数值**——`ctx.player` 是只读快照；要持久化只能用本包状态格子。
3. **不做热加载**——改了扩展要重启（和改内容数据一致）。
4. **不做跨包互调**——包之间不能互相调用扩展；需要共享就把它提升为框架能力。
5. **不提供网络/子进程/任意文件读写 API**——`ext_api` 面刻意最小。
6. 包内扩展代码**只许 import** `qbot_rpg.ext_api`；框架其它部分是内部实现，不承诺兼容。

## 11. 最小完整例子

目录：

```
content/zz_probe_ext/
├── manifest.json
├── settings.json          # {"ext": {"enabled": true}}（再加第二闸）
├── items.json
├── commands.json
└── ext/commands.py
```

`commands.json`：

```json
{
  "commands": [
    {
      "name": "探针",
      "aliases": ["zzprobe"],
      "usage": "探针 [文字]",
      "help": "扩展装载探针（验证用）",
      "handler": "probe",
      "gm_only": false
    }
  ]
}
```

`ext/commands.py`：

```python
from qbot_rpg import ext_api


def probe(ctx, parsed):
    lines = [f"【扩展探针】包={ctx.pack_id}", f"玩家={ctx.player_id or '未注册'}"]
    if ctx.args:
        lines.append("参数=" + " ".join(ctx.args))
    lines.append(f"ext_api=v{ext_api.EXT_API_VERSION}")
    return "\n".join(lines)
```

启用后，玩家发 `探针 你好`（或别名 `zzprobe 你好`）即可看到回显。
