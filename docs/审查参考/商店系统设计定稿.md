## 一、核心哲学：商店 = 世界的货架

```
玩家三问（多想一步=体验失败）：
  ① 这里卖什么？——商品清单一眼看完（序号+名字+价格）
  ② 多少钱/用什么买？——价格与货币图标直接可见
  ③ 我怎么买？——一个指令：/购买 药水*5，一步到位

货架世界观（JRPG 直觉）：
  商店不是"界面"，是一张商品清单，一条消息交付完毕。
  货架摆在哪（NPC/地图/活动）、对谁开（货币/声望/等级/条件）、
  什么时候补货（每日/每周/一次性）——全部由配置组合决定，引擎零新机制。

五条体验铁律：
  ① 只建议不限制：没有商店也玩得下去（掉落/任务奖励兜底）
  ② 默认值兜底：漏配 = 无限库存/无限购/基准价/默认货币，绝不报错
  ③ 记住最少：玩家只记一个主指令（/商店），购买/出售两个子指令
  ④ 一次一屏：商品列表 ≤10 条一屏，超出翻页，不刷屏
  ⑤ 断了能续：当前商店机制（NPC 定稿 2.2），中断随时回来接着买
```

## 二、指令设计（用户拍板：/商店 + /购买 物品*数量）

```
/商店              查看当前商店商品列表（当前商店优先，无则全局默认商店）
/商店 2            序号切换（多商店时，如 NPC 挂多店）
/商店 铁匠铺        名称切换（名称禁空格，允许 ·/Ⅱ）
/购买 <物品>*<数量>  购买（* 数量，默认 1；/购买 药水*5）
/出售 <物品>*<数量>  出售（* 数量，默认 1；/出售 铁矿*20）
/商店 列表          可用商店一览（含类型图标/门槛标记）

- 分隔符规范 v1.1：空格切参数，* 连数量（数量上限默认 ≤99，可配）
- 名称优先：* 左侧先精确匹配物品名，失败再按序号（列表序号）
- 指令别名：内容包世界观定制（修仙世界"赶集/坊市"），settings.json command_aliases
- 快捷指令：/商店 /购买 高频，可入快捷白名单（战斗外全局模式可用）
```

### 2.1 回复模板（一条消息交付，用户拍板格式）

```text
LV3.阿明
1.疗伤药
商品单价：100(灵魂)
---------------
2.法力药
商品单价：100(灵魂)
---------------
3.神性碎片
商品单价：100(灵魂)
---------------
4.追悔之泪
商品单价：10000(灵魂)
---------------
5.万能钥匙
商品单价：10000(灵魂)
---------------
当前页：1/2(全部)
Tip:发送'购买+物品名'即可购买商品
```

**模板规则**：
```
- 首行：LV{玩家等级}.{玩家名}（用户拍板：LV1.1 = 玩家等级 1 + 玩家名；例 LV3.阿明）
  · 个性化标题（问候玩家，非商店层级）
- 商品行：序号.物品名 ｜ 商品单价：价格(货币名)（货币名=settings 货币键中文名）
- 分隔线：---------------（条目间）
- 底部：当前页：N/M(全部) + Tip 提示
- 货币显示：(灵魂)/(金币)/(宝石) 等——按条目货币
- 置灰不隐藏：门槛商品显示  标记（如"[需要 信赖]"）或价格行注明
- 一次一屏 ≤10 条（模板示例 5 条），超出翻页
```

**购买/出售指令（兼容紧凑格式）**：
```
'购买+物品名'  → 购买疗伤药（紧凑无空格，等价 /购买 疗伤药）
'购买 物品*数量' → 购买 疗伤药*5（规范格式，批量）
'出售+物品名'  → 出售铁矿
提示模板中的 Tip 用紧凑格式（'购买+物品名'），解析器双认
```

```
✅ 购买成功：药水×5（-250 金币），剩余 1,000 金币
❌ 金币不足：还差 20 金币
❌ 今日限购 3 个，已买 3 个
❌ 已售罄（下次补货：明早 ${refresh_time}）
❌ 声望不足：需要 信赖（当前 熟悉）
❌ 没有这个商品
❌ 商店不存在 / 这家店还没开门
```

## 三、数据结构 shop.json

### 3.1 商店定义（顶层）

```json
{
  "id": "blacksmith_shop",
  "name": "铁匠铺",
  "icon": "",
  "type": "npc",
  "currency": "coins",
  "level_required": 0,
  "reputation_required": { "level": 0 },
  "open_condition": null,
  "refresh": { "mode": "daily", "hour": 5 },
  "items": [],
  "pool": [],
  "price_fluctuation": 0,
  "visible": true,
  "desc": "老周的小店，炉火正旺"
}
```

| 顶层字段 | 中文名 | 类型 | 默认 | 说明 |
|---|---|---|---|---|
| id | 商店 ID | str | 自动生成 | 唯一，引用键 |
| name | 商店名 | str | 必填 | 禁空格，允许 ·/Ⅱ |
| icon | 图标 | str |  | 1 个 emoji |
| type | 商店类型 | enum | normal | normal/npc/reputation/event/blackmarket（见四） |
| currency | 默认货币 | ref | settings 第一货币 | settings.json 货币键（金币/宝石/灵魂/活动币…） |
| level_required | 等级门槛 | int | 0 | 0=不限 |
| reputation_required | 声望门槛 | obj | 无 | {level: N} 声望等级门槛（任务定稿五，5 级制） |
| open_condition | 开放条件 | obj | 无 | 统一条件引擎 {var,op,value}（NPC 定稿四） |
| refresh | 刷新配置 | obj | daily/05:00 | 见七 |
| items | 商品条目 | list | [] | 见 3.2 |
| pool | 黑市商品池 | list | [] | 黑市专用：每次刷新从中抽 N 个上架 |
| price_fluctuation | 黑市浮动率 | int | 0 | 黑市价格随机浮动 ±%（0=固定价） |
| visible | 是否可见 | bool | true | false=隐藏商店（条件解锁） |
| desc | 描述 | str | 空 | 列表页副标题 |


### 3.2 商品条目（items[]，用户拍板：全局/个体两种）

```json
// 全局商品（全服共享库存，所有人争抢）
{
  "item": "限定时装",
  "price": 100,
  "scope": "global",                    // 全局（默认）
  "stock": 200,                         // 全服库存（售罄=抢完，刷新回满）
  "refresh": { "mode": "daily", "hour": 5 }   // 库存回满时间（默认 05:00）
}

// 个体商品（每人独立计数，每天/周/月限购）
{
  "item": "疗伤药",
  "price": 100,
  "scope": "personal",                  // 个体
  "limit": 3,                           // 每人每周期 N 个
  "period": "day"                       // 周期：day/week/month
}
```

| 条目字段 | 中文名 | 类型 | 默认 | 说明 |
|---|---|---|---|---|
| item | 商品 | ref | 必填 | items.json 物品引用 |
| price | 单价 | int/obj | items 基准价 | 覆盖价；obj 混合支付 {coins:50, gems:5} |
| currency | 条目货币 | ref | 商店 currency | 覆盖商店货币 |
| **scope** | **商品范围** | enum | **global** | **global=全服共享 / personal=每人独立（用户拍板）** |
| stock | 全服库存 | int | 0 | **global 专用**：0=无限；N=全服共 N 件，售罄刷新回满 |
| refresh | 库存刷新 | obj | 商店 refresh | **global 专用**：库存回满时间（覆盖商店级） |
| limit | 个人限购 | int | 0 | **personal 专用**：0=不限；N=每人每周期 N 个 |
| period | 限购周期 | enum | day | **personal 专用**：day/week/month |
| reputation_required | 声望门槛 | obj | 无 | 覆盖商店级（专属商品更严） |
| min_level | 等级门槛 | int | 0 | 0=不限 |
| discount | 折扣 | int | 0 | 0~100，减价百分比 |
| sold_out_once | 一次性售罄 | bool | false | global 专用：售出后永久下架（不随刷新恢复） |

> 兼容：旧 stock/per_player 字段自动映射（stock→scope=global；per_player→scope=personal）
> 模板标记：[全服剩 N] ｜ [每日限购 3] ｜ 已售罄

### 3.3 价格体系（与 items.json 关系）

```
基准价：items.json price（物品的"身价"，掉落/赠送/出售通用）
覆盖价：商店条目 price（这家店卖贵/卖便宜，缺省=基准价）
出售价：基准价 × 出售比率（settings.json 通用出售比率，默认 30%）
        或 items.json sell_price 单条覆盖（"卖 10 万金币的金珠材料"）
混合支付：price 为对象 {coins:50, gems:5} → 两种货币同时扣（高级商品/黑市）
规则：条目不写 price = 按基准价卖；条目不写 currency = 按商店货币收
```

## 四、商店类型（5 类，同一套购买引擎）

| type | 名称 | 入口 | 特点 |
|---|---|---|---|
| normal | 普通商店 | /商店 兜底 | 常驻无门槛，全局默认货架（新手村杂货铺） |
| npc | NPC 商店 | /对话 → 看看货物；地图内 /商店 | 商人 NPC 挂载（shop_refs），当前商店机制（2.2） |
| reputation | 声望商店 | 满足声望门槛才可见 | 专属商品，任务系统声望产出解锁（五） |
| event | 活动商店 | 活动开启才可见 | 活动币结算，refresh once+时间窗限时 |
| blackmarket | 黑市 | 特殊入口（open_condition） | 商品池抽选+价格浮动，刷新重抽 |

```
要点：
- type 只影响【入口/可见性/刷新默认值】，购买/限购/库存逻辑完全同一套（不新增机制）
- 普通商店与 NPC 商店的关系：NPC 商店是"挂在地图上的普通商店"，
  打开后即成为当前商店；离开地图回退全局默认商店（normal 类型兜底）
- 黑市机制（配置组合，非新引擎）：
  ① 商品池 pool[] 配置候选商品（条目格式同 items[]，price 为基准价）
  ② 每次刷新：按 items 配置数量从池中抽 N 个上架
  ③ 上架价 = 基准价 × (1 ± 随机浮动率 price_fluctuation%)
  ④ 刷新重抽：昨天没买的今天可能没了（稀缺感），商店本体不变
- 声望商店：visible 默认 true 但商品整体被门槛挡住时，列表显示
  "[需要 信赖]" 而不是整店消失（看得见买不着 = 目标感）
```

## 五、货币体系（金币/宝石/活动币多货币）

```
货币定义（框架 3.10，settings.json）：
  · 货币列表：名称/图标/持有上限（默认不设）/用途备注
  · 默认模板：金币（通用货币）+ 宝石（高级货币），可改名/增删
  · 例：活动币（签到/任务/活动产出，持有上限 100 防囤积）

商店侧引用：
  · 商店级 currency：整店默认收什么钱
  · 条目级 currency：单商品覆盖（活动商店混卖：药水收金币、限定皮肤收活动币）
  · 混合支付 price 对象：两币同扣（黑市高阶商品）

结算流程（/购买）：
  1. 解析货币键 → 查玩家余额（存档货币表）
  2. 余额充足：扣款 → 入包；余额不足：提示差额（"金币不足，还差 20"）
  3. 持有上限联动：货币到上限后产出类系统（掉落/签到/出售）自动提示
     "金币已满，无法再获得"（可配，默认不提示）

经济闭环示例：
  打怪掉材料 → /出售 铁矿*20（回收金币）→ /购买 药水*5（备战）
  完成任务 → 声望+50 → 解锁声望商店 → 购买专属装备
  签到/活动 → 活动币 → 活动商店限时兑换
```

## 六、商品范围（用户拍板：全局/个体两种商品）

```text
全局商品（scope=global，全服共享）：
  · stock：全服库存（0=无限；N=全服共 N 件）
  · 售罄 = 全服抢完（"已售罄"），刷新时间到回满
  · 计数存世界状态（key = shop_id + item_id，跨群共享 3.8 全局世界）
  · 例：每月全服 10 件的稀有材料 → 抢购玩法
  · sold_out_once=true：售出后永久下架（不随刷新恢复）

个体商品（scope=personal，每人独立）：
  · limit：每人每周期 N 个（0=不限）
  · period：day/week/month（时间系统驱动，重置点可配 默认每日 05:00，与 quest_daily 同刻对齐）
  · 计数存玩家存档（碎片化续玩不丢）
  · 例：疗伤药每人每日限购 3 → 防无限买药逃课

规则：
  · 两种 scope 混用（同店既有争抢品也有个人限购品）
  · 周期重置：时间系统统一惰性检查（操作时按时间差补算）
  · 限购只管买入：出售不计入限购计数
  · 标记：[全服剩 N] ｜ [每日限购 3]（列表可见）
  · 提示："已售罄（下次补货：明早 ${refresh_time}）" ｜ "今日限购 3 个，已买 3 个"
```

## 七、商店刷新（每日/每周/一次性）

```json
// 刷新配置 refresh
{ "mode": "daily",  "hour": 5 }                    // 每日 05:00（默认；hour 取统一 settings refresh_time，与 quest_daily 同刻对齐）
{ "mode": "weekly", "weekday": 1, "hour": 5 }      // 每周一 05:00
{ "mode": "once",   "start": "2026-09-01 00:00", "end": "2026-09-07 23:59" }  // 一次性限时
{ "mode": "none" }                                 // 不刷新（库存耗尽即止）
```

```
刷新语义（三件事同时发生）：
  ① 全体库存回满（stock 归 N）
  ② 个人限购计数清零（per_player 归 0）
  ③ 黑市商品重抽（pool 抽选 + 价格重浮动）
一次性售罄（sold_out_once）条目不恢复——永久下架

实现要点（与 3.6 时间系统同思路）：
  · 存档记录 last_refresh，玩家操作商店时按时间差惰性补刷
  · 跨天时段（weekly 跨周）按结束>开始判定日期偏移
  · 时区统一 UTC+8
  · 统一配置键 refresh_time（默认 05:00，可配）：商店/任务/签到三表同刻对齐，刷新时刻统一取 refresh_time、不再写死
  · once 模式：start 未到 = "这家店还没开门"；end 已过 = 自动下架（活动商店）
  · 不配置 refresh = 永不刷新（配合 stock 0 = 无限库存无限购，最简单形态）
```

## 八、与 NPC 当前商店机制衔接（NPC 定稿 v1.3 2.2）

```
衔接规则（写死）：
  ① 玩家 /对话 → 选择"看看货物"（action: shop）→ 打开 NPC 的 shop_refs 商店
  ② 打开瞬间：记录【当前商店】= 该 NPC 的 shop_refs[0]（地图级状态）
  ③ 玩家仍在该地图：/商店 → 直接进当前商店（不用重找 NPC，中断不丢）
  ④ 离开该地图：当前商店清除 → /商店 → 全局默认商店（normal 类型）
  ⑤ 一 NPC 挂多商店（shop_refs 数组）：/商店 2 切换第二家

NPC 侧配置（npc.json，无需新字段）：
  · interactions: [{ "action": "shop", "text": "看看货物", "shop_refs": ["blacksmith_shop"] }]
  · 顶层 shop_refs 兼容（v1.3 已有）
  · 商人 NPC 类型默认带 shop 交互（漏配 shop_refs = 打开默认商店，不报错）

购买语境（沉浸感）：
  经 NPC 商店购买成功 → "老周把药水递给你：药水×5（-250 金币）"
  经 /商店 直购 → 标准模板（无 NPC 语境）

声望折扣（NPC 定稿：商人可选）：
  · npc.json 可配 discount 字段（好感度/声望折扣，可选模块，默认关）
  · 折扣与条目 discount 叠加规则：取更优（作者可配取乘积）
```

## 九、购买/出售流程（引擎层）

### 9.1 购买管线（/购买 药水*5）

```
解析（指令分隔规范 v1.1）：
  * 左侧名称精确匹配 → 失败按列表序号 → 再失败按别名/x_ 扩展
校验链（顺序即提示优先级）：
  ① 商店存在且可见（含 open_condition/时间窗）→ "这家店还没开门"
  ② 门槛：等级 / 声望（商店级与条目级取更严）→ "声望不足：需要 信赖"
  ③ 个人限购 → "今日限购 3 个，已买 3 个"
  ④ 全体库存 → "已售罄（下次补货：明早 ${refresh_time}）"
  ⑤ 货币余额（含混合支付两币）→ "金币不足，还差 20"
  ⑥ 数量上限（默认 ≤99）→ "最多一次购买 99 个"（提示不拦截）
结算（原子操作，防双扣）：
  扣货币 → 物品入背包（堆叠）→ 扣库存/记限购 → 存档（SQLite 事务）
  会话快照（3.18）机制保证幂等：网络重发不双扣
```

### 9.2 出售管线（/出售 铁矿*20）

```
价格：基准价 × 出售比率（默认 30%）或 items.json sell_price 覆盖
  · 出售 = 立刻到账（碎片化，无二次确认）
  · 大额出售（回收 >N 金币，N 可配）→ 黄色提示"确认出售？金额较大"（可选，默认关）
禁止出售（校验拦截）：
  · 绑定物品（items bound=true，3.3 绑定联动）
  · 任务关键物品（items sellable:false 或 x_ 标记，作者可配）
  · 数量不足 → "背包里只有 12 个铁矿"
回复："✅ 出售成功：铁矿×20（+240 金币），剩余 1,240 金币"
```

### 9.3 商品列表（/商店）

```
格式：店名 + 商品行（序号. 名称 价格[货币图标] [标记]）+ 玩家余额 + 操作提示
标记优先级：声望不足（显示所需等级名）/ 售罄 / 限购满 / 折扣（原价划线）
分页：≤10 条一屏，超出 "1/3 页：/商店 2 翻页"
置灰不隐藏：买不起也显示（看得见 = 目标感；声望/等级不足显示需求）
```

## 十一、校验器（4.5 + 设计总纲：只建议不限制）

```
硬拦（红色，拒绝加载）：
  · item 引用不存在（items.json 无此 ID）
  · price 负数 / 非数字 / 结构错误（对象缺货币键）
  · currency 不在 settings.json 货币注册表
  · stock / per_player / discount 负数
  · JSON 结构错误 / 必填字段缺失（id/name/items 数组）
  · refresh.mode 非枚举值 / once 缺时间窗

黄提示（不拦截，可加载）：
  · 声望门槛永不可达（任务系统无对应声望产出源）→ "这个门槛永远达不到？确认"
  · 商店没有任何商品 → "这家店空空的？"
  · 全服库存过小（stock 1~4）→ "抢购玩法确认？"
  · price = 0 的常驻商品 → "免费商品确认？"
  · 黑市浮动率 >30% → "价格波动较大，确认？"
  · 限购周期 = hour 且库存无限 → "小时限购+无限库存，确认？"
  · 未使用的商店（无 NPC 挂载且非 normal 默认）→ "这家店没人知道怎么进？"
  · 物品同时出现在多商店且价格不一致 → "同物不同价，确认？"
  · 混合支付总价过高 → 数值模拟器试算提示

默认值兜底（漏配 = 合理默认，绝不报错）：
  price=items 基准价 ｜ currency=商店货币 ｜ stock=0 无限 ｜ per_player=0 不限 ｜
  refresh=daily 05:00（统一 refresh_time）｜ 门槛全 0 ｜ discount=0 ｜ 黑市浮动=0
```

## 十三、系统衔接一览

| 系统 | 衔接点 |
|---|---|
| 背包（3.3） | 购买入包/出售出包；绑定物品不可售；堆叠规则复用 |
| 货币（3.10） | settings.json 货币键；商店/条目货币引用；持有上限联动 |
| 限购（3.11） | 库存（全体）+ 个人限购 + 四周期，本设计为正式落地 |
| NPC（v1.3） | shop_refs + action:shop + 当前商店机制（2.2）+ 声望折扣 |
| 任务（五） | 声望值产出 → 声望等级 → 声望商店门槛解锁 |
| 签到/掉落 | 活动币产出 → 活动商店消费（经济闭环） |
| 时间（3.6） | 刷新周期/限购周期惰性补刷；UTC+8；跨天/跨周判定 |
| 指令规范（v1.1） | /购买 药水*5 数量语法；名称优先解析；指令别名 |
| 存档（3.7） | 个人限购计数入玩家存档；库存入世界状态（全局共享） |
| 编辑器（6.9） | 商店页 + 商品表格；级联删除；即改即生效 |
| 校验（总纲） | 只拦真非法值，其余黄提示；默认值兜底 |
